# Lace Benchmarking

## What is Lace
- AI coding assistant at `~/git/lace` (TypeScript, Node.js)
- Speaks Ent protocol (NDJSON JSON-RPC 2.0) over stdio
- Persona system: built-in personas at `packages/agent/config/agent-personas/`
- Provider catalog at `packages/agent/src/providers/catalog/data/`

## Harbor Adapter
- `lace_agent.py` — harbor `BaseInstalledAgent` subclass
- `lace-harness.mjs` — Node.js harness speaking Ent protocol to lace agent
- `install-lace.sh.j2` — container setup (installs Node.js 22, ripgrep, deploys bundle)
- `deploy-lace.sh` — local build + rsync to eval server
- Bundle: ~187MB (170MB node_modules)

## Benchmark Persona
- Created `benchmark.md` persona (10K chars vs 28K for lace.md)
- Strips all interactive rules (TDD, git workflow, "ask for clarification")
- Harness also prepends autonomous instruction prefix to task prompt

## Headless Binary (compiled Bun)
- **CRITICAL**: Must use generated entrypoint, NOT `main.ts` directly
- Build steps:
  1. `cd ~/git/lace && bun scripts/generate-all-imports.ts` — creates `build/temp/embed-all-files.ts` with all asset imports
  2. Create headless entrypoint: copy `build/temp/embed-all-files.ts` → `embed-headless.ts`, replace last line (`import '../../packages/web/server-production'`) with `import '../../packages/agent/src/main'`
  3. `bun build --compile --outfile build/out/lace-agent-linux --target=bun-linux-x64 --sourcemap=none --asset-naming="[dir]/[name].[ext]" build/temp/embed-headless.ts`
- macOS: same but no `--target` flag
- `--asset-naming` flag is REQUIRED for embedded files to resolve correctly
- Build takes <200ms, produces ~112MB binary
- **Why `embed-assets.ts` alone doesn't work**: The `with { type: 'file' }` imports in `embed-assets.ts` are side-effect imports. Bun's `build --compile` only processes `with { type: 'file' }` imports in the entrypoint's transitive graph properly when they're generated by `generate-all-imports.ts`. Using `embed-assets.ts` as a side-effect import from `main.ts` does NOT populate `Bun.embeddedFiles`.
- `deploy-lace.sh` runs `tsc` first which has pre-existing errors — bypass by manually deploying

## Gate Prompt Experiment (2026-03-09)
- **Problem**: "Before You Stop" advisory checklist was ignored by model
- **Solution**: Rewrite benchmark-h22.md workflow with 3 formal gates (doubleoctagon nodes in digraph)
- **GATE 1 (Readiness)**: After explore — must know tools, verifier expectations, required/forbidden files
- **GATE 2 (Sub-task done)**: After each sub-task — must have RUN something proving it works
- **GATE 3 (Actually done)**: Before done — verification passes, output dirs match GATE 1 plan
- Full experiment doc: `docs/experiments/2026-03-09-lace-benchmark-baseline.md`
- Persona file: `~/git/lace/packages/agent/config/agent-personas/benchmark-h22.md`

### Gate v1 Results (18 close-calls + agent errors)
- **+10 flips, 0 regressions** vs baseline

## OpenRouter Support (2026-03-12/13, NOT committed to lace)
- **Goal**: Run evals with cheaper models via OpenRouter (qwen3.5-flash: $0.10/$0.40 per 1M tokens vs gpt-5.4: $2.50/$15.00)
- **3 required code changes in lace** (all uncommitted):
  1. `providers/instance/manager.ts`: Add `openrouter-default` auto-creation in `getDefaultConfig()` when `OPENROUTER_API_KEY` env var present
  2. `providers/registry.ts`: Add `case 'openrouter':` to `createProvider()` switch (falls through to OpenAIProvider)
  3. `providers/openai-provider.ts`:
    - `isNativeOpenAI()` helper — only true for api.openai.com
    - `store: isNative` instead of `store: true` (OpenRouter rejects `store: true`)
    - `tool_choice: "required"` → `"auto"` for non-native OpenAI (OpenRouter rejects "required")
    - Broadened `isResponsesAPINotSupportedError` to catch all 404s (not just specific messages)
    - Gate input slicing on `effectivePreviousResponseId` (OpenRouter ignores `previous_response_id`)
- **Harness change**: Add `openrouter: ['OPENROUTER_API_KEY']` to `envKeys` map in credential submission
- **Adapter change**: Add `"openrouter": "OPENROUTER_API_KEY"` to `provider_env_keys` + `--agent-cmd /opt/lace/lace-agent-linux`
- **Key insight: chaining fix eliminates ~50% of API calls for OpenRouter** — without it, model receives orphaned tool results (no context since chaining is stateless), returns empty, triggers bare-text retry cycle
- **Model ID**: Must use `qwen/qwen3.5-flash-02-23` (from catalog), not `qwen/qwen3.5-flash`
- **Staging dir**: `/home/jesse/git/terminal-bench/runs/lace-qwen-chainfix/` (Bun binary approach)
- **Legacy staging**: `/home/jesse/git/terminal-bench/runs/lace-gate-v5/` (node bundle approach, hacky pre-seed)
- **OPENROUTER_API_KEY** in `~/git/terminal-bench/.env` on magic-kingdom
