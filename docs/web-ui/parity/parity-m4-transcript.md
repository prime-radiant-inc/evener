# Transcript renderer — behavior-parity checklist (M4)

Scope: `cmd/serf-hub/assets/renderer-tools.js` (full file), `cmd/serf-hub/assets/renderer-format.js`
(full file), and the item-rendering paths of `cmd/serf-hub/assets/renderer.js` (turn lifecycle,
message/steering/system rendering, think blocks, tool-call rows, subagent module, images/lightbox,
scroll stickiness, liveness, streaming tail, older-turn paging). Composer/queue chrome, the
ask_user dock, task-sidebar panel, and diagnostics/escalation recovery actions are out of scope for
this file — they live in the same `renderer.js` but are separate feature areas.

Every line below is a single observable behavior with its file:line citation. Check it off only
once the rewrite has been verified (not just "looks similar") to reproduce it.

## Highlights — read before implementing

- **Stale comment inverts the real default-expand rule.** `renderer.js:3167` says "Default expanded
  for diffs (edit/write/patch); collapsed for all others," but `defaultExpanded = renderer.expand
  === true` (`renderer.js:3168`) and **no** descriptor in the registry — including `diffRenderer`
  (`renderer-tools.js:614`), `editRenderer` (`renderer-tools.js:648`), and `patchRenderer`
  (`renderer-tools.js:667`), all of which set `expand: false` — ever sets `expand: true`.
  `renderer-tools.js:609-611`'s own comment on `diffRenderer` gets it right ("Diffs collapse by
  default"). **Every tool row, including diffs, starts collapsed.** The only default-expanded state
  in the whole system is `shellRenderer.bodyEnd`'s runtime override on a failed command
  (`renderer-tools.js:589`, `state.el.dataset.expanded = "true"`). Do not build "diffs open by
  default" from the stale comment.
- **Two dead "design B" constants/functions sit beside the real behavior.** `SUBAGENT_SEVERITY`
  (`renderer.js:4045`, a worst-first sort table) and `SUBAGENT_VISIBLE_ROWS: 6`
  (`renderer.js:3428`, a row-count fold threshold) are defined but never read anywhere in the file.
  The comment directly above `SUBAGENT_SEVERITY` even names the abandoned design ("mockup #8 alt
  B... worst-first"), and the function nine lines below it (`refreshSubagentModule`,
  `renderer.js:4047`) explicitly does the opposite: fixed spawn-order, never resorted, folds by
  done/not-done rather than by a row-count cap. Similarly `renderLivePlan`/`taskFoldGroup`
  (`renderer.js:4810`, `renderer.js:4939`) implement a "one persistent floating plan card" design
  that is never called; the task_list tool call actually renders through `appendTaskUpdateCard`
  (`renderer.js:4974`), which appends a **fresh** card on every mutation. Do not port
  `SUBAGENT_SEVERITY`, the 6-row cap, or the persistent-card design — port what
  `refreshSubagentModule`/`appendTaskUpdateCard` actually do.
- **Two independent liveness clocks with different numbers.** Session-level liveness
  (`renderer.js:108-110`) is quiet at 20s / stalled at 180s, ticked every 3s. Per-subagent-row
  liveness (`ageSubagentRow`, `renderer.js:3736`) is quiet at 10s / silent at 45s, driven by the
  *same* 3s timer but with its own thresholds and its own trigger (a real activity-text change, not
  raw wall-clock silence). Do not unify these into one threshold set.
- **Two independent duration formatters, subtly different.** `formatToolDuration`
  (`renderer-format.js:636`) floors sub-1000ms durations at `Math.max(1, Math.round(ms))` so nothing
  ever prints "0ms"; `formatDurationForTerminal` (`renderer-tools.js:542`, used only for the shell
  terminal footer) has no such floor and can print "0ms" for a sub-millisecond command. Otherwise
  the two use identical 1000ms/10000ms tier breakpoints and rounding — this looks like accidental
  duplication, not an intentional divergence, but the rewrite must preserve the floor's absence in
  the shell footer specifically if it wants byte-for-byte parity.
- **`formatBytes` never scales units.** `renderer-format.js:573-577` always prints the raw integer
  ("2000000 bytes"), never KB/MB. A "friendlier" rewrite of this helper would be a parity break, not
  a fix.

## 1. Tool-renderer registry — shared machinery (`renderer-tools.js`)

- [ ] `toolRendererFor(tool)` looks up `toolRenderers[tool]`, falling back to `toolRenderers.__default__` (`defaultRenderer`) for any unregistered tool name — `renderer-tools.js:17-19`, registry at `renderer-tools.js:818-843`.
- [ ] Registry aliasing: `grep`/`grep_files`/`grep_search` all map to the same `grepRenderer`; `list_dir`/`list_directory` both map to `lsRenderer`; `shell`/`exec_command`/`run_shell_command` all map to `shellRenderer`; `delegate_send`/`job_send_message` both map to `jobSendMessageRenderer` — `renderer-tools.js:822-841`.
- [ ] `task_list` and `communicate` have **no** registry entry at all — they are intercepted before reaching `toolRendererFor` (see §12) — `renderer-tools.js:703-705` (comment explains `task_list`'s absence; `communicate` has no such comment and must be inferred from `renderer.js:1604,1656`).
- [ ] Each descriptor's `mode` is one of `"cheap"`, `"card"`, or `"default"`, but the renderer only ever branches on `mode === "cheap"` vs. everything else (`renderer.js:3085,3088,3187`) — `"card"` and `"default"` are documentation labels, not distinct code paths.
- [ ] `friendly` (verb text) falls back to the raw tool name when the descriptor omits it (`defaultRenderer.friendly` is `undefined`) — `renderer-tools.js:144` region / `renderer-tools.js:773-778`, consumed at `renderer.js:3144`.
- [ ] `renderDiff(el, content)` clips unified diff text to 1600 chars (`truncate=true`) before splitting into lines, appending `"\n…"` when clipped — `renderer-tools.js:22-24,28-30`.
- [ ] `renderDiffLines` classifies each line into `add` (`+` not `+++`), `del` (`-` not `---`), `hunk` (`@@`), or `ctx` (default), stamping both `className` and `dataset.lineKind` — `renderer-tools.js:26-43`.
- [ ] `cheapToolBody` builds a `<details class="tool-body cheap-tool-body tool-body--preview">` with a fixed `"details"` summary label, a `<pre class="cheap-tool-args">` (pretty-printed JSON args) and a `<pre class="cheap-tool-output">` — `renderer-tools.js:46-61`.
- [ ] `cheapToolBodyDelta` clips live output to 8000 chars into `outputPre.textContent` on every delta — `renderer-tools.js:63-67`.
- [ ] `cheapToolBodyEnd` prefers `data.error` over the captured output, clips to 8000, force-opens the `<details>` on error, and hides the output `<pre>` entirely when the final text is blank — `renderer-tools.js:69-75`.
- [ ] `splitOutputLines` splits on `\n` and drops one trailing empty element (from a final `\n`) but not more than one — `renderer-tools.js:78-84`.
- [ ] `tailFoldOutput(text, max)`: no-ops under `max` chars; over budget, prefixes an honest elision line — `"earlier output not retained — showing the last " + max.toLocaleString("en-US") + " chars"` — then the last `max` chars via `tailSlice` — `renderer-tools.js:95-101`.
- [ ] `outputPreviewBody(className, outputClassName, el)` builds a generic `<div class="tool-body output-preview-body tool-body--preview <className>"><pre class="<outputClassName> output-preview"></div>` shape shared by job-output/job-message/job-list/patch bodies — `renderer-tools.js:103-111`.
- [ ] `updateExpandableSummary` sets the caret summary text to `"hide N line(s)"` when open, `"expand · N more line(s)"` when closed, with correct singular/plural — `renderer-tools.js:113-117`.
- [ ] `looksBinary(text)`: samples the first 1000 chars, flags binary when NUL (`0`) or U+FFFD replacement-char density exceeds 10% of the sample — empty string is never binary — `renderer-tools.js:119-132`.
- [ ] `dropNote(label)` renders `<div class="tool-output-dropped">` with the warning icon (`window.SerfIcons.warning`) followed by the label as a plain text node (not HTML-injected) — `renderer-tools.js:138-144`.
- [ ] `setExpandableOutput`: binary output (`opts.binary` or `looksBinary()`) hides the `<pre>` entirely and shows only the drop note with default label `"binary output — not shown as text"` (any pending "more" block is removed) — `renderer-tools.js:152-162`.
- [ ] `setExpandableOutput` non-binary path: first 5 lines render inline and stay visible (`body.pre.style.display` cleared unless there are zero lines); lines 6+ fold into a fresh `<details class="tool-output-more">` rebuilt from scratch each call (old one removed first) — `renderer-tools.js:163-184`.
- [ ] `setExpandableOutput`'s `<details>` toggle listener re-derives the hidden-line-count label on every `toggle` event (not just at creation) — `renderer-tools.js:178-179`.
- [ ] `opts.dropped` appends a second, distinct drop note *after* the expand affordance (both can coexist) with default label `"output truncated at the source — the dropped bytes were never captured"` — `renderer-tools.js:185-188`.
- [ ] `setExpandableDiff` mirrors `setExpandableOutput`'s 5-line/expand split but renders through `renderDiffLines` (diff-classified spans) instead of plain text, and has no binary/dropped-note handling — `renderer-tools.js:191-215`.
- [ ] `readLineRange(args, out)`: `offset` defaults to 1 when absent/non-positive; `limit` defaults to counting `\n` occurrences in `out`; renders `"lines START"` when no count is derivable, else `"lines START-END"` — `renderer-tools.js:217-224`.
