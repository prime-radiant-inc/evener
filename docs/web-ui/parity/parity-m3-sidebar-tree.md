## Cross-cutting hazards found during this audit

These are the findings most likely to bite a rewrite that "looks equivalent." Each also appears as a checkbox in its proper section below.

1. **`docs/web-ui/design-system.md` §5 is stale against the shipped code.** It never mentions the NeedsYou or Pinned tiers at all (its tier list is "ACTIVE / RECENT / OLDER / ARCHIVED SESSIONS / TEST RUNS"), and its "RECENT"/"OLDER" language reads as project-level buckets that do not exist in code — the real implementation has ONE flat, recency-sorted `Projects` list with no age-based bucketing; a project auto-expands purely on *current live/needs-you state*, never on age. See §2.0, §2.3.
2. **Two whole wire fields are dead weight for the sidebar.** `tree.live[]`/per-node `.live` and `tree.sources[]` ship on every `/api/tree` response but `sidebar.js` reads neither. See §1.
3. **Per-tier overflow counts are computed but never surfaced.** `more_current`/`more_recent`/`more_archived` ship on every project; nothing in `sidebar.js` reads them, so sessions past the 50-per-tier cap vanish silently with no "+N older" UI despite the Go doc comment describing one. See §2.3.
4. **`model.lazyCache` is write-only.** Populated on every `/api/tree/project?key=` fetch, never read back anywhere — every expand and every resync re-fetches a project's sessions over the network regardless of how recently they were already fetched. See §11.
5. **A row's displayed age never refreshes once built.** `patchRow` updates state/icon/title/favorite/ask but not `.age` — a long-lived row's relative-age text ("3m"/"2h") freezes at whatever it was at first paint and is never updated by any resync, only by a full DOM rebuild. See §15.
6. **Project-header disclosures are keyboard-unreachable as a whole.** Every other disclosure type (section header, cluster fold, inactive-subagent disclosure) is a real `<button>`; the project header is a `<div role="button">` with no `tabindex` and no `keydown` handler — a pre-existing, code-comment-acknowledged gap. See §14.
7. **Project-level archive/unarchive bypasses all the shared mutation guarantees.** It's a bare `fetch(...).then(scheduleResync)` — no `postJSON`, no toast-on-failure, no `.ok` check, no optimistic pending overlay — unlike every session-level mutation. See §5.
8. **`rename()` computes a stripped session id it never uses.** Unlike `favorite()`/`archive()`, which post the `local:`-stripped bare id, `rename()` posts the FULL ref in its URL; a `sid` variable is computed and discarded. Functionally harmless (server-side ref parsing normalizes either form) but a real client-contract inconsistency worth knowing before copying the pattern. See §7.
9. **NeedsYou and Pinned sort in opposite directions.** NeedsYou's within-band tiebreak is oldest-updated-first (ascending); Pinned/Favorites is newest-updated-first (descending) — same file, same general shape, easy to invert by accident. See §2.1, §2.2.
10. **Two more ordering gotchas live only in the HTTP handler, not in `hubcore`.** "Test runs" bucket order is two *separately* recency-sorted runs concatenated (active-sourced test-run projects, then archived-sourced ones) rather than one global sort; brand-new "orphan-live" sessions with no persisted meta yet are appended at the very END of `Projects`/a project's `sessions`, not recency-merged in. See §2.3, §2.5.

### Doc vs. code divergences (design-system.md §5)

- The doc's tier list ("ACTIVE / RECENT / OLDER / ARCHIVED SESSIONS (N) / TEST RUNS (N)") omits the two cross-project tiers that render ABOVE all of it today: NeedsYou and Pinned/Favorites (§2.0-§2.2). Neither tier name nor a "Pinned" header string appears anywhere in `sidebar.js` or `style.css`.
- The doc's "RECENT — touched in ~last day; collapsed" / "OLDER — collapsed" read as project-level groupings. In code there is no such grouping: `Projects` is one flat recency-sorted list (§2.3), and a project's own auto-expand is driven by whether it currently has a live/needs-you session, never by how old it is.
- The doc's "collapsing to '+N subagents' past ~3" does not match the code's actual current-vs-inactive subagent split (§3): even a single inactive (ended/closed/errored) subagent folds behind its own disclosure; there is no minimum-3 threshold for that fold (3 is instead the unrelated `clusterMin` for repeated-title session clustering).

## 1. Wire contract — `GET /api/tree`

- [ ] Response top-level fields: `generated_at`, `sources[]`, `live[]`, `needs_you[]`, `favorites[]`, `projects[]`, `archived_projects[]`, `test_runs[]`, `attentionSummary{needsYou,error,working}` (camelCase only on that one field) (`hubapi/types.go:25-36`)
- [ ] `TreeNode` wire fields: `row_id, ref, host_id, session_id, title, project, state, kind, tier?, branch?, cluster_count?, favorite?, rename?, live, ask_pending?, updated_at?, age?, model?, children?` (`hubapi/types.go:83-103`)
- [ ] `TreeProject` wire fields: `key, name, working_dir?, rollup_state?, rollup_live?, rollup_attn?, default_expanded?, more_current?, more_recent?, more_archived?, worktrees?, is_archived?, session_count?, sessions` — `sessions` has NO `omitempty`; a hydrated project always serializes `"sessions":[...]` (even `[]`), while an un-hydrated archived-project stub is explicitly nil'd server-side, which Go's `encoding/json` renders as `"sessions":null` (`hubapi/types.go:63-81`; nil-vs-stub at `cmd/serf-hub/web_api_tree.go:101-104`)
- [ ] `?summary=1` returns only `{generated_at, attentionSummary}` — used by the notification module's baseline fetch and on every hub reconnect; never serializes the full (potentially megabyte-scale) tree just to read badge counts (`cmd/serf-hub/web_api_tree.go:51-62`; consumed at `cmd/serf-hub/assets/notifications.js:222-227`)
- [ ] `GET /api/tree/project?key=<projectKey>` returns one bare `TreeProject` (404 JSON `{error}` if the key isn't in the memoized tree); used for lazy per-project hydration, reads from the already-memoized tree rather than a fresh full meta scan (`cmd/serf-hub/web_api_tree.go:209-231`)
- [ ] `sessions:null` + `session_count:N` on a `TreeProject` is the wire signal for "not-yet-hydrated stub"; the client's stub check is exactly `!p.sessions && p.session_count` (`cmd/serf-hub/web_api_tree.go:101-104`; client check at `cmd/serf-hub/assets/sidebar.js:739, 820`)
- [ ] `tree.live[]` (top-level array) and every node's `live` boolean are present on every response but read by NOTHING in `sidebar.js` — the flat "Live" rail the field once fed is explicitly dead per its own Go doc comment (`cmd/serf-hub/internal/hubcore/tree.go:27-28`; zero `.live`/`tree.live` occurrences in `cmd/serf-hub/assets/sidebar.js`)
- [ ] `tree.sources[]` (host list: `{id,label,kind,online}`, always includes a synthetic `{id:"local",kind:"local",online:true}` entry) ships on every response but is also never read by `sidebar.js` (`cmd/serf-hub/web_api_tree.go:413-435`)
- [ ] `more_current`/`more_recent`/`more_archived` per-project overflow counts ship on the wire but `sidebar.js` never reads them — there is no client-side "+N older" affordance today despite the Go doc comment describing one (`hubapi/types.go:71-73`; computed at `cmd/serf-hub/internal/hubcore/tree.go:698-700`)

## 2. Tiers and ordering rules

### 2.0 Top-level render order
- [ ] The sidebar renders exactly 5 blocks top-to-bottom, in this fixed order, each entirely omitted (no header, no empty state) when its source bucket is empty: NeedsYou rows, Favorites/Pinned rows, active Projects, "Archived sessions" section, "Test runs" section (`cmd/serf-hub/assets/sidebar.js:384-396`)
- [ ] NeedsYou and Favorites/Pinned rows render as bare top-level rows with NO section header/label wrapping them — visually they're just "the first N rows," distinguished only by row content (state icon/tint) (`cmd/serf-hub/assets/sidebar.js:390-391`; no header element is ever built for either — see the doc-divergence note above)

### 2.1 NeedsYou (cross-project triage)
- [ ] Membership: every LIVE, top-level (non-subagent, non-nested-fork-original) session whose normalized state is `awaiting`, `warning`, or `errored` (`cmd/serf-hub/internal/hubcore/tree.go:792-831`)
- [ ] An explicit user archive decision (`archived:true`) suppresses a session from NeedsYou even while it's still live and still awaiting — archive is a "clearing verb"; age-based auto-archive alone does NOT suppress it (`cmd/serf-hub/internal/hubcore/tree.go:809-813`, comment at `tree.go:796-799`)
- [ ] Ordering is 3 fixed bands, band-descending, then oldest-updated-first within a band: (2) `errored` always first regardless of ask-pending; (1) any `awaiting`/`warning` row with `ask_pending:true`; (0) every other `awaiting`/`warning` row ("your move") (`hubapi/attention.go:82-98`; sort at `cmd/serf-hub/internal/hubcore/tree.go:853-864`)
- [ ] Within a band the tiebreak is ASCENDING `updated_at` (`.Before`, oldest-blocked-first) — the opposite direction from the Pinned tier's tiebreak (§2.2) (`cmd/serf-hub/internal/hubcore/tree.go:863`)
- [ ] Whole tier is omitted from the DOM when empty; no "Needs you" header ever renders, empty or otherwise (`cmd/serf-hub/assets/sidebar.js:390`)

### 2.2 Favorites / "Pinned"
- [ ] Wire field is `favorites`; server-side doc comments and identifiers call this the "Pinned tier" — the two names are interchangeable for this one tier only (`cmd/serf-hub/web_api_tree.go:158-160`)
- [ ] Membership: any session (any project, any state) with an explicit favorite decision, drawn only from each project's Current+Recent sessions — archived-tier favorites are excluded from this tier (they surface only via §8's archived-sessions section) (`cmd/serf-hub/web_api_tree.go:165-175`)
- [ ] A session already present in NeedsYou is excluded from Pinned even if favorited, so a session never doubles up in both top tiers (`cmd/serf-hub/web_api_tree.go:170-172`)
- [ ] Ordering: `updated_at` DESCENDING (most-recently-updated first) — opposite tiebreak direction from NeedsYou (§2.1) (`cmd/serf-hub/web_api_tree.go:176-178`)
- [ ] Subagent children of a pinned session are still emitted directly below it via the normal child-projection rules (§3) — pinning a parent doesn't pin or specially hide its children (`cmd/serf-hub/assets/sidebar.js:391`, feeding `pushChildren` at `sidebar.js:423-438`)

### 2.3 Projects (active) — one flat list, per-project session tiers
- [ ] Exactly one flat `projects[]` array, ordered by each project's `LastActivity` (max last-activity across its own top-level sessions) DESCENDING — there is NO project-level "recent vs. older" bucket/section; every active project lives in the same list regardless of age (`cmd/serf-hub/internal/hubcore/tree.go:658-669, 725-741`)
- [ ] Ties in `LastActivity` keep insertion order (`sort.SliceStable`), and insertion order is already the recency-sorted `sessionMetaLess` order, so ties resolve consistently (`cmd/serf-hub/internal/hubcore/tree.go:741`)
- [ ] A project lands in `projects[]` (active) rather than `archived_projects[]` when it has ≥1 Current or Recent session AND has no manual project-level archive decision; otherwise it's archived (`cmd/serf-hub/internal/hubcore/tree.go:686-694`)
- [ ] Each project's OWN sessions are independently classified per-session into `current` (last activity ≤24h), `recent` (24h–14d), or `archived` (>14d, or an explicit per-session decision overriding the age rule either direction) (`cmd/serf-hub/internal/hubcore/tree.go:89-91, 108-123, 671-684`)
- [ ] `current` and `recent` sessions are NOT visually distinguished from each other — both render as ordinary rows in one continuous list under the project header; nothing in `sidebar.js` branches on `tier==="current"`/`"recent"` for rendering (only for the archive-menu wording and the reveal-chain search) (`cmd/serf-hub/web_api_tree.go:588-593` emits Current then Recent back-to-back with no boundary marker)
- [ ] `archived`-tier sessions are diverted OUT of an active project's inline list entirely (`skipArchived=true`) — they never render under the live project header; they surface only via the cross-cutting "Archived sessions" section (§8) (`cmd/serf-hub/assets/sidebar.js:397-401, 411`)
- [ ] Each tier is capped at 50 rows (`maxSidebarSessionsPerTier`), keeping the most-recent 50; the overflow (`MoreCurrent`/`MoreRecent`/`MoreArchived`) is computed and shipped on the wire but rendered NOWHERE client-side today — capped-away sessions simply disappear with no "+N older" indicator (`cmd/serf-hub/internal/hubcore/tree.go:92-96, 698-700`; unread client-side)
- [ ] A project's auto-expand (`default_expanded` on the wire) is `true` exactly when it currently has ≥1 top-level task-tree in `active` state or in an attention state (`awaiting`/`warning`/`errored`) — driven by LIVE state, not recency/age; a project touched 5 minutes ago with everything now idle starts collapsed just like one touched a month ago (`cmd/serf-hub/internal/hubcore/tree.go:716-717`; wired to the wire field at `cmd/serf-hub/web_api_tree.go:581`)
- [ ] The rollup-rank computation walks EVERY session in the project (current+recent+archived, before the tier split) — an archived-tier session that's somehow still actively running can still contribute to `rollup_live`/`rollup_attn`/`default_expanded`, even though its own row is hidden from the inline list (`cmd/serf-hub/internal/hubcore/tree.go:629-656` operates on the pre-split `sessions` list; tier split happens after, at `tree.go:674-684`)
- [ ] Rollup magnitude counting is per TOP-LEVEL TASK-TREE, not per row: a session's own state plus the max `RollupRank` state across its whole descendant subtree together count as ONE unit toward `rollup_live` (working) or `rollup_attn` (awaiting/warning/errored) — a session with 10 busy subagents still only adds 1 to the count (`cmd/serf-hub/internal/hubcore/tree.go:629-656`)
- [ ] The rollup dot's rank table (`RollupRank`) deliberately differs from the live-list rank table (`AttentionRank`): rollup ranks `warning` above `active` (a stuck warning must surface over routine activity), while `AttentionRank` ranks `active` above `warning` — kept in one file specifically so the two tables can't silently drift apart (`hubapi/attention.go:11-50`, comment at `attention.go:30-34`)
- [ ] "Orphan-live" sessions — live in the roster but with no persisted `SessionMeta` yet (a brand-new spawn racing the tree build) — are appended at the very END of `projects[]` (as a new project entry, or spliced onto an already-emitted project's `sessions`) in live-list iteration order, NOT recency-merged into the sorted block above (`cmd/serf-hub/web_api_tree.go:117-156`)
- [ ] Subagent children of a project's sessions are sorted by the same `sessionMetaLess` contract as top-level sessions and capped at 50 per parent — with NO overflow indicator computed at all for the overage, unlike the Current/Recent/Archived caps (`cmd/serf-hub/internal/hubcore/tree.go:584-589`)
- [ ] "Snapshotted original" fork children are sorted the same way but NOT capped (no analogous truncation exists for forks), and are appended AFTER subagent children in a session's `Children` array — subagents always render above forks when a session has both (`cmd/serf-hub/internal/hubcore/tree.go:590-592, 608-609`)

### 2.4 Archived Projects (bottom group) — see §8 for the disclosure UI itself
- [ ] `archived_projects[]` holds whole projects that are manually archived OR have zero Current/Recent sessions of their own, sorted by `LastActivity` descending exactly like the active list (`cmd/serf-hub/internal/hubcore/tree.go:686-694, 730, 742`)
- [ ] Every project in `archived_projects[]` ships as a session-less stub on `/api/tree` (`sessions:null`, `session_count:N`) — the archive is unbounded, so its sessions never ride the main snapshot; the sidebar lazy-loads them on expand (§11) (`cmd/serf-hub/web_api_tree.go:97-104`)

### 2.5 Test Runs
- [ ] A project is `IsTestRun` when it has ≥1 session and EVERY session in it has `Origin=="test"` (i.e. `SERF_SESSION_ORIGIN=test`) (`cmd/serf-hub/internal/hubcore/tree.go:711`, doc at `tree.go:55-59`)
- [ ] Bucket-routing precedence is decided in the HTTP HANDLER, not in `hubcore`: `IsTestRun` wins over `IsArchived` — a project that is both gets routed to `test_runs[]`, never to `archived_projects[]`. This precedence rule lives entirely in `web_api_tree.go`, not in `BuildTreeAtWithProjects` (`cmd/serf-hub/web_api_tree.go:78-113`, comment at `web_api_tree.go:78-84`)
- [ ] Because of that precedence check, `test_runs[]`'s ordering is two CONCATENATED recency-sorted runs — every test-run project sourced from `tree.Projects` (active, recency-desc) followed by every test-run project sourced from `tree.ArchivedProjects` (recency-desc) — not one global recency sort across the bucket (`cmd/serf-hub/web_api_tree.go:85-92`)
- [ ] A test-run project's own `is_archived` flag carries through unchanged regardless of which bucket it lands in, so its ⋯ menu still correctly offers "Unarchive" if it also happens to be archived (`cmd/serf-hub/assets/sidebar.js:282-289`)
- [ ] Test-run projects render through the exact same `pushSection`/`pushProject`/`buildProjectHeader` path as any other project — same disclosure, same lazy-hydration-on-expand if the project is ALSO an archived stub (`cmd/serf-hub/assets/sidebar.js:541-543`)

## 3. Subagent children & repeated-title clustering

- [ ] A subagent whose normalized state is one of `active/awaiting/idle/warning/notLoaded` is a "current" child and renders INLINE, directly below its parent row, indented one level, recursing for its own children (`cmd/serf-hub/assets/sidebar.js:148, 153-155, 423-431`)
- [ ] A subagent whose state is `ended/closed/errored` is "inactive" and is NEVER rendered inline — it only ever appears inside its parent's own "Inactive subagents (N)" disclosure, collapsed by default (`cmd/serf-hub/assets/sidebar.js:149-152, 432-438`)
- [ ] The inactive-subagent fold has NO minimum-count threshold — even a single inactive subagent gets folded behind its own disclosure (contrast with clustering's `clusterMin=3` below, a different, unrelated mechanism; also contra `docs/web-ui/design-system.md:260-261`'s "past ~3" language) (`cmd/serf-hub/assets/sidebar.js:432-438`)
- [ ] Each parent gets its OWN independent inactive-disclosure + rows pair, keyed off that parent's `row_id` — expanding one parent's inactive group never affects, flattens, or shares state with any other parent's group, including nested ones (`cmd/serf-hub/assets/sidebar.js:144-147, 434-437`)
- [ ] A "current" child whose raw state isn't one of the 5 recognized current states (and also isn't terminal) is downgraded to display state `notLoaded` before rendering (`cmd/serf-hub/assets/sidebar.js:158-166`)
- [ ] Clicking a subagent/fork child row does NOT navigate the main `#workspace` pane — it opens the whole ancestor chain (from the first not-already-open ancestor down through the clicked node) as SIDE PANES via `window.SerfPanes.openAfter`, walking `openHrefs()` to skip anything already open and inserting each new pane after the previous one in the chain (`cmd/serf-hub/assets/sidebar.js:584-616`)
- [ ] A direct child of the main (already-in-`#workspace`) session opens its side pane with no "after" anchor (first in the pane strip); a nested (grandchild+) child inserts after its immediate parent's pane (`cmd/serf-hub/assets/sidebar.js:595-599`, comment at `sidebar.js:592-596`)
- [ ] Separately, a `.subagent-row-wrap .open-beside-btn` (a "survivor" control carried verbatim from the pre-rewrite sidebar, delegated at the document level) opens a single side pane via `SerfPanes.open`, guarding `preventDefault`/`stopPropagation` so the row's own link doesn't also navigate; absent/no-op when `window.SerfPanes` is unavailable (e.g. inside a pane iframe) (`cmd/serf-hub/assets/sidebar.js:1135-1155`; keyboard Enter/Space equivalent at `sidebar.js:1157-1167`)
- [ ] Repeated-title clustering is a SEPARATE mechanism from subagent folding: it applies only to plain top-level SESSIONS (`Kind=="session"`, never subagent/fork/cluster), only in `idle`/`ended` state, and only with no children of their own (`cmd/serf-hub/internal/hubcore/tree.go:1025-1033`)
- [ ] A title folds into one cluster row only when EVERY session sharing that exact title (within the same project) is individually clusterable AND there are at least 3 of them (`clusterMin=3`); if even one same-titled session is live, needs-you, or has children, NONE of that title's sessions fold (`cmd/serf-hub/internal/hubcore/tree.go:953-964, 985`)
- [ ] The synthetic cluster row's ID is a project-scoped SHA-256-derived `cluster:<8 hex chars>` of `project + "\0" + title`, deliberately scoped so identical titles in different projects never collide and never hash to an empty/colliding ID (`cmd/serf-hub/internal/hubcore/tree.go:1014-1021`)
- [ ] The cluster row takes the slot of the title's first (most-recent) appearance in the recency-ordered list; folded members keep their own recency order as the cluster's `Children` (`cmd/serf-hub/internal/hubcore/tree.go:960-962, 993-1009`)
- [ ] A cluster fold renders as a `<button class="sb-row cluster-header">` (NOT a session link — no href/hx-* attributes), showing the shared title and a "×N" count; its members render ONLY once the cluster's own `row_id` is in `model.expanded`, and then render as ordinary, independently-navigable session rows (no `__child` de-weighting, unlike subagent children) (`cmd/serf-hub/assets/sidebar.js:450-466, 618-643, 650-652`)

## 4. Attention badges

### 4.1 Tab title + favicon (`notifications.js`, first IIFE only)
- [ ] A baseline `attentionSummary` (`{needsYou,error,working}`) is fetched via `GET /api/tree?summary=1` on init and on every AppWire reconnect; no OS notification or sound fires until that baseline has landed at least once — specifically so reopening/reloading the hub never re-alerts on attention that already existed before the page opened (`cmd/serf-hub/assets/notifications.js:217-227, 258-261`, doc comment at `notifications.js:8-13`)
- [ ] Tab title becomes `"(N) {section·}serf hub"` where N = `needsYou+error` (never counts `working`), only when the "title" preference is on; the section prefix reflects either the active `/settings/<section>` URL or the current workspace header text (`cmd/serf-hub/assets/notifications.js:104-124`)
- [ ] Favicon is a neutral dark dot (`#7e8593`) plus a small corner badge dot colored by the HIGHEST-priority active level, checked in this exact order: `error` (`#f7768e`) > `needs_you` (`#e0af68`) > `working` (`#7aa2f7`) > none. There is no "idle" dot color — idle never draws a corner badge (`cmd/serf-hub/assets/notifications.js:40-44, 151-161`)
- [ ] Both title and favicon colors are pinned DARK-THEME constants regardless of the page's active light/dark theme, because the favicon renders against dark browser chrome either way (`cmd/serf-hub/assets/notifications.js:35-39`)
- [ ] Turning the "favicon" preference off reverts to a single plain grey dot with no badge, regardless of summary state (`cmd/serf-hub/assets/notifications.js:151-155`)
- [ ] `serf/attention/changed` notifications update title+favicon UNCONDITIONALLY on every receipt (even before baseline, even while focused) — only the noisier OS-notification/sound side effects are gated (`cmd/serf-hub/assets/notifications.js:256-261`)

### 4.2 Per-row instant patch (`sidebar.js`)
- [ ] `serf/attention/changed`'s `changed[]` entries instantly patch `data-attention="<level>"` onto every currently-rendered row whose `data-ref` is EXACTLY `"local:<threadId>"` — this only ever matches local-host rows; a remote/appwire row's `data-ref` (its full qualified ref) can never match this hardcoded `"local:"` prefix, so remote rows never get the instant patch (they still get the coalesced resync a moment later) (`cmd/serf-hub/assets/sidebar.js:1124-1131`)
- [ ] Receiving `serf/attention/changed` ALSO unconditionally schedules a coalesced full resync — the instant per-row patch is a latency optimization layered on top of, not instead of, the normal resync path (`cmd/serf-hub/assets/sidebar.js:1121`)

### 4.3 Project rollup badges (`sidebar.js`)
- [ ] A project header shows a live-count badge (blue "working" icon + `rollup_live`) and/or an attention-count badge (amber "yourMove" icon + `rollup_attn`), separated by a "·" only when both are non-zero; entirely absent when both are 0 (`cmd/serf-hub/assets/sidebar.js:751-766`)
- [ ] `data-state="<rollup_state>"` is stamped on the rollup element purely as a CSS/test hook; the badges' own classes carry the actual color (`cmd/serf-hub/assets/sidebar.js:747-750, 754`)

### 4.4 OS notification + sound (`notifications.js`)
- [ ] OS/sound fire only for a transition INTO `needs_you`/`error` from something else (never on a bare level with no prior state) — computed from each `changed[]` entry's `level`/`prevLevel` (`cmd/serf-hub/assets/notifications.js:264-267`)
- [ ] Firing additionally requires ALL of: a baseline already loaded, the document currently unfocused, this tab is the elected "leader" tab, and (unless `loudScope==="all"`) the transition is either an `error` or carries `askPending:true` — a generic `needs_you` settle with no ask pending is held back under the default `loudScope:"asks"` (`cmd/serf-hub/assets/notifications.js:261-269`, doc comment at `notifications.js:22-25`)
- [ ] OS notification title is `"serf · {title|threadId}"`; clicking it focuses the window and navigates to `/s/<threadId>` (not the full qualified ref — this only resolves correctly for local sessions) (`cmd/serf-hub/assets/notifications.js:170-186`)
- [ ] Sound is a single 800Hz oscillator tone, gain 0.1, ~120ms duration, only while the document is unfocused; both the OS notification and the tone independently no-op while the tab has focus (`cmd/serf-hub/assets/notifications.js:170-173, 188-215`)
- [ ] Leader-tab election uses a held Web Lock (`navigator.locks.request("serf-hub-os-leader", {ifAvailable:true})`) — the first tab to acquire it never releases it (its callback's promise never resolves), so it stays leader for its whole lifetime; environments without the Web Locks API fire OS/sound from EVERY tab (duplicate alerts preferred over silent ones). There is no `BroadcastChannel` anywhere in this mechanism (`cmd/serf-hub/assets/notifications.js:229-246`)
- [ ] Preferences (`title/favicon/os/sound/loudScope`) persist in `localStorage["serf-hub.notifications"]`, versioned via `localStorage["serf-hub.notifications.v"]="3"`; a v3 migration backfills any missing boolean to `false` and any invalid `loudScope` to `"asks"` exactly once (`cmd/serf-hub/assets/notifications.js:29-31, 74-89`)
- [ ] Toggling a preference (`serf-hub:notifications-changed` custom event) re-applies title/favicon immediately without a reload, and re-requests OS permission if the user just turned "os" on while permission is still `"default"`; if the browser denies it, the `os` preference and its settings checkbox/label are reverted programmatically (`cmd/serf-hub/assets/notifications.js:297-330`)
- [ ] `notifications.js` initializes eagerly at parse time (not on `DOMContentLoaded`) so no early attention broadcast during page load is missed; `htmx:afterSettle` re-applies title/favicon after every workspace swap (e.g. navigating inside Settings) (`cmd/serf-hub/assets/notifications.js:359-364, 332-341`)
- [ ] Out of scope for this checklist: `notifications.js`'s second IIFE (`serf/auth/updated`, `serf/launch/updated`, `serf/marketplace/updated`, `serf/plugin/updated`) refreshes Settings/credentials panels — it has no sidebar/tree coupling and is not enumerated further here (`cmd/serf-hub/assets/notifications.js:386-437`)

- [ ] Every session row and every project header carries one `⋯` icon-button (`aria-label` "row menu" / "project menu" respectively, `aria-haspopup="menu"`) that opens a small popover anchored to it (`cmd/serf-hub/assets/sidebar.js:110-119, 714-723`)
- [ ] Opening any menu first force-closes whatever menu was already open — only one menu open anywhere in the sidebar at a time (`cmd/serf-hub/assets/sidebar.js:223-224`)
- [ ] Desktop (`>767px`): the menu is an absolutely-positioned `.sb-menu` anchored just below-left of its trigger, appended to `document.body`; the first `.sb-menu-item` receives focus (`cmd/serf-hub/assets/sidebar.js:225-227, 244-251, 259-261`)
- [ ] Phone (`≤767px`, `matchMedia` checked at open time): the menu instead renders as a full-width bottom sheet (`.sb-menu-modal`) inside a fixed tap-to-dismiss scrim (`.sb-menu-scrim`); `SerfFocusTrap` traps Tab/screen-reader scope inside the sheet and restores focus to the trigger on close (`cmd/serf-hub/assets/sidebar.js:225, 236-243, 254-258`)
- [ ] Menu items carrying `hidden:true` are simply not rendered (used by "Rename" — see §7) (`cmd/serf-hub/assets/sidebar.js:230`)
- [ ] Clicking a menu item always closes the menu FIRST, then runs the item's action (`cmd/serf-hub/assets/sidebar.js:233`)
- [ ] Outside-click dismiss is armed via a `setTimeout(...,0)`-deferred `document` click listener (capture phase) specifically so the SAME click that opened the menu doesn't immediately close it (`cmd/serf-hub/assets/sidebar.js:222, 252`)
- [ ] If the row/header containing the currently-open menu's trigger is removed by a reconcile pass (e.g. it archived away mid-menu), the menu force-closes and focus moves to a surviving sibling (previous, else next) (`cmd/serf-hub/assets/sidebar.js:354-359`)
- [ ] Keyboard inside an open menu: `Escape` closes and returns focus to the trigger; `ArrowDown`/`ArrowUp` cycle focus through `.sb-menu-item`s WITH wraparound at both ends (`cmd/serf-hub/assets/sidebar.js:263-270`)
- [ ] Session row menu items, in order: "Open" (navigates), "Open beside" (side pane via `SerfPanes.open`, unconditionally shown even when `SerfPanes` is absent — it just no-ops if missing), "Favorite"/"Unfavorite" (label reflects current state), "Rename" (hidden unless `n.rename`), "Archive"/"Unarchive" (label driven by `n.tier==="archived"`) (`cmd/serf-hub/assets/sidebar.js:272-281`)
- [ ] Project header menu items, in order: "New session" (→ `/new?dir=<working_dir>`), "Settings" (→ `/settings/project?cwd=<working_dir>`), "Archive"/"Unarchive", "Delete…" (`cmd/serf-hub/assets/sidebar.js:290-297`)
- [ ] **Divergence**: the project menu's Archive/Unarchive action is a bare `window.fetch` that schedules a resync in its `.then` regardless of HTTP status — it does NOT go through the shared `postJSON` helper, so it gets none of `postJSON`'s toast-on-failure or `.ok` check, and none of the optimistic pending-overlay treatment session-level `archive()` gets (§8) (`cmd/serf-hub/assets/sidebar.js:293-295`; contrast with `sidebar.js:915-920, 930-941`)
- [ ] The verb shown ("Archive" vs "Unarchive") for a project row is driven by the server-supplied `is_archived` boolean when present, falling back to a client-stamped `__archived` flag only for the older payload shape — needed because a project can be BOTH a test-run and archived, and TestRuns wins the bucket, so "which section rendered this row" alone would get the verb backwards for that case (`cmd/serf-hub/assets/sidebar.js:282-289`)

## 6. Favorite / pin

- [ ] Toggled only from the row ⋯ menu ("Favorite"/"Unfavorite") — no dedicated star/pin icon renders directly on a row (`cmd/serf-hub/assets/sidebar.js:277`)
- [ ] Optimistic: the tree clone gets `n.favorite = on` applied everywhere that `ref` appears (top-level, subagent child, or cluster member — one recursive walk over the whole tree) immediately, before the network call resolves; a re-render fires synchronously off that optimistic clone (`cmd/serf-hub/assets/sidebar.js:907-911, 866-880`)
- [ ] The optimistic overlay clears once a subsequent resync's tree reflects the same favorite value on that ref (confirm-on-reflect, not confirm-on-POST-success) — see §15 for the shared pending-overlay contract (`cmd/serf-hub/assets/sidebar.js:910-911`)
- [ ] Wire call: `POST /api/favorite {kind:"session", id:<ref with "local:" prefix stripped>, favorited:<bool>}`; server also accepts `kind:"project"` but `sidebar.js` never sends that (`cmd/serf-hub/assets/sidebar.js:907-913`; server contract at `cmd/serf-hub/web_api_favorite.go:9-45`)
- [ ] A favorited row gets `data-favorite=""` (both build- and patch-time) (`cmd/serf-hub/assets/sidebar.js:107, 140`)
- [ ] Favoriting doesn't itself move a row anywhere visually except via the next resync recomputing the Pinned tier server-side (§2.2) — there is no separate client-side re-sort (`cmd/serf-hub/assets/sidebar.js:907-914`, tier computed server-side at `web_api_tree.go:158-178`)

## 7. Rename

- [ ] Available only when the server marks the node `rename:true`, which is true only for LOCAL sessions (`isLocalRouteID`) — Codex-bridged/remote rows never expose "Rename" (the menu item is `hidden`, not merely disabled) (`cmd/serf-hub/web_api_tree.go:631-635, 611`; hidden check at `cmd/serf-hub/assets/sidebar.js:278`)
- [ ] Triggered from the row ⋯ menu; replaces the row's `.title` span in place with a plain `<input>` pre-filled with the current title, focused and fully selected (`cmd/serf-hub/assets/sidebar.js:299-305`)
- [ ] `Enter` commits; `Escape` cancels by discarding the edit and re-rendering the last-known tree; `blur` also commits (clicking away saves rather than discards) (`cmd/serf-hub/assets/sidebar.js:306-309`)
- [ ] Commit is a no-op (no network call at all) if the trimmed value is empty or unchanged from the original title (`cmd/serf-hub/assets/sidebar.js:306`)
- [ ] Optimistic: `n.title` is set everywhere that ref appears in the tree clone immediately; the overlay clears once a resync's tree reflects the new title (confirm-on-reflect, same contract as favorite) (`cmd/serf-hub/assets/sidebar.js:923-925`)
- [ ] Wire call: `POST /api/sessions/<urlencoded FULL ref>/rename {name}` — uses the full ref (e.g. `local%3Aabc123`), NOT the `local:`-stripped bare id; a `sid` variable computing the stripped form is assigned but never used here, unlike `favorite()`/`archive()` which do use their stripped `sid`. Functionally harmless: the server's ref parser normalizes either form to the same route id (`cmd/serf-hub/assets/sidebar.js:921-927`; server-side normalization at `cmd/serf-hub/web_api_tree.go:682-695`)
- [ ] Server-side: a LIVE session's rename routes through the daemon (`SetThreadName` RPC, daemon-truth) and returns `204`; an ENDED session's rename edits its persisted `SessionMeta` file directly (`Name`, `NameSource:"user"`, `NameUpdatedAt`) and also returns `204` — `sidebar.js`'s `rename()` never inspects the response body either way, it just `.catch()`s and lets the coalesced resync (triggered by `postJSON`'s POST-2xx path) reflect the change (`cmd/serf-hub/web_api_rename.go:44-57, 88-109`; client swallow at `sidebar.js:927`)
- [ ] A rename that races a session from ended→live mid-request re-routes through the daemon path server-side rather than silently overwriting a meta file about to be clobbered by the live session's own autosave (`cmd/serf-hub/web_api_rename.go:69-87`)

## 8. Archive & the "Archived sessions" disclosure grouping

- [ ] Session-level archive toggles from the row ⋯ menu; label is "Archive" when `n.tier !== "archived"`, else "Unarchive" (`cmd/serf-hub/assets/sidebar.js:279`)
- [ ] Optimistic ONLY in the archiving direction (`on===true`): the row is stamped `__drop=true` in the tree clone, which every render-path filter (`flatten`, `pushProject`, `pushChildren`, `pushCluster`, `pushArchivedSection`, `visibleCount`, `forEachNode`) treats as "not present" — the row visually vanishes immediately. Unarchiving (`on===false`) has NO optimistic effect at all; the row only reappears once a resync actually reflects it (`cmd/serf-hub/assets/sidebar.js:915-920`)
- [ ] The archive pending-op has NO `confirm` predicate (unlike favorite/rename) — it's a "disappearance-type" op per the code's own taxonomy: removed from the pending set explicitly once the POST resolves 2xx, not once a later resync confirms the row is gone (`cmd/serf-hub/assets/sidebar.js:915-920`, taxonomy comment at `sidebar.js:854-858`)
- [ ] Wire call: `POST /api/archive {kind:"session"|"project", id, working_dir?, archived:<bool>}` → `200 {"ok":true}`; `working_dir` required only for `kind:"project"`. Also proactively pokes the attention watcher server-side so the title/favicon badge doesn't lag a full tick behind the sidebar (`cmd/serf-hub/assets/sidebar.js:915-919`; server contract at `cmd/serf-hub/web_api_archive.go:11-75`)
- [ ] The cross-cutting "Archived sessions (N)" section is ONE top-level disclosure, collapsed by default, folding away every archived-tier session hub-wide regardless of project; renders NOTHING (no header) when both its sub-buckets are empty (`cmd/serf-hub/assets/sidebar.js:493-507`; design intent at `docs/web-ui/design-system.md:264-269`)
- [ ] Its header count N sums two sources: whole archived-project stubs (using `session_count` before hydration, else counting live `sessions`) plus every active project's archived-tier session count — both excluding `__drop`-ped (optimistically-hidden) rows (`cmd/serf-hub/assets/sidebar.js:508-511, 517-521`)
- [ ] Expanding it reveals two kinds of children: (a) whole archived PROJECTS as session-less stubs that lazy-hydrate on their own expand (§11) — unchanged pre-existing behavior; (b) for every ACTIVE project that has ≥1 archived-tier session, a synthetic per-project sub-heading (own row_id `header:archived:<projectKey>`, own independent expand/collapse state) revealing ONLY that project's archived sessions — these already ride the main `/api/tree` snapshot, so no extra fetch is needed (`cmd/serf-hub/assets/sidebar.js:493-501, 522-540`)
- [ ] An active project's own header NEVER lists its archived-tier sessions inline, even when expanded — they're reachable exclusively through the Archived-sessions section's per-project sub-heading (`cmd/serf-hub/assets/sidebar.js:397-401, 411`, design intent at `docs/web-ui/design-system.md:269`)
- [ ] The per-project archived-sessions sub-heading's ⋯ menu is bound to the REAL project object (`__menuProject`), not the synthetic group wrapper, so project actions (archive/unarchive verb, delete) stay correct even though the row itself is a synthetic projection (`cmd/serf-hub/assets/sidebar.js:527-538`)
- [ ] Project-level archive is a manual DECISION stored independently of any session's tier; a project with only Current/Recent sessions can still be manually archived, immediately moving the WHOLE project (every tier of session) to `archived_projects[]`/the bottom group (`cmd/serf-hub/internal/hubcore/tree.go:693-694`)

## 9. Project deletion

- [ ] Triggered from the project ⋯ menu's "Delete…"; a `window.confirm` dialog reads exactly: `"Delete project {name}? {N} session(s), {worktrees} worktree(s). Worktrees are not touched."` where N is `p.session_count || (p.sessions||[]).length` (`cmd/serf-hub/assets/sidebar.js:310-312`)
- [ ] No optimistic UI at all — the whole flow is confirm → POST → resync (or redirect) (`cmd/serf-hub/assets/sidebar.js:313-318`)
- [ ] Wire call: `POST /api/project/delete {key, working_dir}` → `200 {deleted:[ids], skipped:[{id,reason}]}`, or `409 {"error":"project has live sessions","live":[shortIDs]}` if anything under the project is live at request time (whole-project fast-fail — nothing is deleted in that case) (`cmd/serf-hub/assets/sidebar.js:313-318`; server contract at `cmd/serf-hub/web_api_project_delete.go:34-38, 111-123, 193`)
- [ ] Server-side validates the `{key, working_dir}` pair against the CURRENT memoized tree entry before deleting anything (never inverts a lossy display-name slug back into a path on a destructive call), and separately re-resolves canonical project membership from the full unfiltered session set (not the capped/sidebar-tier view) before selecting deletion candidates (`cmd/serf-hub/web_api_project_delete.go:72-86, 88-109`)
- [ ] Per-session deletion re-checks liveness under the SAME ownership lock resume uses, immediately before removing files — a session that raced to live between the initial 409 check and its own turn is skipped (reported in `skipped[]` with reason `"resumed live"`), never destructively removed out from under a live daemon (`cmd/serf-hub/web_api_project_delete.go:126-152`)
- [ ] On success, if the CURRENTLY OPEN session's path (`window.location.pathname === "/s/" + <a deleted id>`) is among `deleted[]`, the browser redirects to `/new`; otherwise a normal resync is scheduled. There is no toast/confirmation UI for the `skipped[]` list — a partial deletion is silent to the user beyond the tree simply updating (`cmd/serf-hub/assets/sidebar.js:313-324`)
- [ ] Deleting a project also scrubs its project-level archive AND favorite decision rows (so a later project reusing the same canonical ID doesn't inherit stale state), and pokes the attention watcher (`cmd/serf-hub/web_api_project_delete.go:180-192`)

## 10. Collapse / expand behaviors

### 10.1 Row-level disclosures — shared expand/collapse model
- [ ] Two independent `Set`s track user intent: `model.expanded` (keys the user explicitly opened) and `model.collapsed` (keys the user explicitly folded) — this split exists specifically because a project can be server-default-expanded, and a bare "not in expanded" can't distinguish "never touched" from "user folded a default-open project"; without `collapsed`, a live/attention project could never be folded back up (`cmd/serf-hub/assets/sidebar.js:8-13`)
- [ ] Effective-expanded resolution: an explicit user collapse always wins over everything; otherwise an explicit user expand OR the server's `default_expanded` wins (`cmd/serf-hub/assets/sidebar.js:778-783`)
- [ ] `default_expanded` (§2.3) applies ONLY to project-header disclosures (including archived-project stubs and the per-project archived-sessions sub-headings, which reuse `buildProjectHeader`) — sections ("Archived sessions", "Test runs"), cluster folds, and inactive-subagent disclosures have no server default and always start collapsed until the user (or the deep-link reveal chain, §13) opens them (`isExpanded`/`defaultExpandedFor` used only by project headers at `cmd/serf-hub/assets/sidebar.js:704, 728`; sections/clusters/disclosures read `model.expanded.has(key)` directly at `sidebar.js:489, 512, 630, 645, 175, 188`)
- [ ] `toggleExpanded(key)` is the ONE shared toggle used by every disclosure type (project header, section, cluster fold, inactive-subagent disclosure); it looks up a project default for any key, which transparently resolves to `false` for a non-project key (section/cluster/child keys never match a project's `.key`), so the shared function behaves correctly for every caller with no per-type branching (`cmd/serf-hub/assets/sidebar.js:794-811, 788-793`)
- [ ] Toggling ANY key persists to `localStorage["serf-hub.sidebar.expanded.<key>"]`: `"true"` if user-expanded, `"false"` if user-collapsed a default-open item, key REMOVED entirely once the user's state matches "no explicit preference" (e.g. collapsing something with no server default) (`cmd/serf-hub/assets/sidebar.js:823-829`)
- [ ] On every full tree render, expansion preference is restored from localStorage for: every project key (active+archived+test-run), every archived-sessions-group key (`archived:<projectKey>`), both fixed section keys, and — recursively over the WHOLE tree — every inactive-subagent-disclosure key that has ≥1 child (`cmd/serf-hub/assets/sidebar.js:837-852`)
- [ ] Expanding a project key that turns out to be an un-hydrated stub (`!sessions && session_count`) triggers an immediate lazy-load fetch (§11); this check re-runs after `toggleExpanded` AND independently after every fresh `fetchTree()` for whatever keys were restored from localStorage, so a page reload with a previously-expanded archived project re-hydrates it without waiting for a resync (`cmd/serf-hub/assets/sidebar.js:810, 812-822, 1080`)

### 10.2 Whole-sidebar tri-state (rail / pane / auto)
- [ ] Three persisted modes — `auto` (default), `rail` (fully collapsed), `pane` (fully shown) — stored under the LEGACY localStorage key `serf-hub.sidebar.rail`, with a one-time value migration: old `"true"`→`rail`, old `"false"`→`pane`, unset→`auto` (`cmd/serf-hub/assets/sidebar.js:1254, 1261-1271`)
- [ ] "Collapsed" is TOTAL: there is no 56px icon rail left in the layout — the sidebar leaves the flow entirely; only a nav chip remains to reopen it (`cmd/serf-hub/assets/sidebar.js:1251-1253`; design intent at `docs/web-ui/design-system.md:294-299`)
- [ ] `auto` mode resolves to `rail` below 1200px and `pane` at/above it (`SIDEBAR_DESKTOP_QUERY = "(min-width:1200px)"`), EXCEPT the phone band (`≤767px`) always forces `pane`-equivalent regardless of the persisted mode, because the off-canvas drawer (§10.3) owns the sidebar on phone — the pinned mode preference itself is left untouched so it re-applies once the viewport grows past phone again (`cmd/serf-hub/assets/sidebar.js:1255-1281`)
- [ ] `⌘B`/`Ctrl+B` cycles `rail → pane → auto → rail …`; ignored while focus is on an editable element (input/textarea/select/contenteditable), and ignored entirely at ≤767px viewports (`cmd/serf-hub/assets/sidebar.js:1299-1302, 1341-1358`)
- [ ] A `[data-sidebar-rail-toggle]` button click performs the same cycle; its `aria-label`/`title` re-sync after every mode change and after every `htmx:afterSwap` to read `"sidebar: <mode>"`, or `"sidebar: auto (<effective>)"` when in `auto` (`cmd/serf-hub/assets/sidebar.js:1326-1334, 1360-1376`)
- [ ] The persisted mode is applied as early as possible (synchronously at script-load, before the tree even fetches) to avoid a flash of the wrong layout (`cmd/serf-hub/assets/sidebar.js:1305`)
- [ ] Crossing the 1200px breakpoint live only re-resolves the effective state while in `auto`; crossing the 767px phone breakpoint always re-resolves regardless of mode (a pinned `rail` preference must still lift into the phone drawer) (`cmd/serf-hub/assets/sidebar.js:1307-1324`)

### 10.3 Mobile off-canvas drawer (`≤767px`)
- [ ] `body[data-sidebar-open]` is the sole flag the phone drawer's CSS keys on; a `[data-sidebar-toggle]` click toggles it (`cmd/serf-hub/assets/sidebar.js:1178-1224`)
- [ ] Opening it on a phone viewport additionally arms `SerfFocusTrap` on `#sidebar`, anchored back to the trigger element for focus restoration on close; NOT trapped on tablet/desktop collapsed states (⌘B and the nav chip stay reachable there without a trap) (`cmd/serf-hub/assets/sidebar.js:1178-1192`)
- [ ] Closes on: outside click (anything not inside `#sidebar` or on `[data-sidebar-toggle]`), any `htmx:beforeRequest` whose trigger is inside `#sidebar` (tapping any sidebar link/row auto-closes the drawer before the navigation even starts), and `Escape` — EXCEPT `Escape` is swallowed when focus/the event target is inside `#search-dialog`, or when a `<dialog id="search-dialog">` is currently `.open`, so search's own Escape handling isn't stepped on (`cmd/serf-hub/assets/sidebar.js:1207-1214, 1227-1242`)

## 11. Lazy loading & caching

- [ ] `/api/tree` on first load and on every resync ships whole active/archived-project data EXCEPT archived-project stubs, whose `sessions` field is `null` and whose visible count is only `session_count` (§2 above; `cmd/serf-hub/web_api_tree.go:97-104`)
- [ ] Expanding a stub (or restoring a previously-expanded stub's state from localStorage on load) triggers `GET /api/tree/project?key=<key>`, which reads from the SAME memoized tree the last `/api/tree` call built (never a fresh full meta scan), splices the returned `sessions` into that project's entry in `model.tree`, reconciles any still-pending optimistic ops against the newly-arrived sessions (a rename/favorite on an archived session may only now be confirmable), and re-renders (`cmd/serf-hub/assets/sidebar.js:812-822, 1106-1117`; server memoization at `cmd/serf-hub/web_api_tree.go:183-207`)
- [ ] EVERY coalesced resync (§12) additionally re-fetches `/api/tree/project?key=` for every currently-expanded project key, unconditionally — an expanded project's session list is refreshed on every resync, not just once on first expand (`cmd/serf-hub/assets/sidebar.js:1096-1105`)
- [ ] `model.lazyCache` (a `Map`) is written on every project fetch but NEVER read back anywhere in the file — there is no cache-hit path; every expand and every resync re-issues the network request regardless of whether that project's data was already fetched moments ago (`cmd/serf-hub/assets/sidebar.js:14, 1109`; zero `.get(` call-sites against it)
- [ ] Concurrent `/api/tree` requests (e.g. startup fetch racing an early resync) share ONE in-flight promise (`inflightTree`) rather than each downloading the full tree independently — de-dupes the network TRANSFER, which can be megabytes on a large hub; a separate monotonic `model.seq` guard discards a stale RESULT if a newer fetch already started (transfer de-dupe and staleness-guard are two distinct, layered mechanisms) (`cmd/serf-hub/assets/sidebar.js:1060-1082`)
- [ ] The initial skeleton (6 `aria-hidden` placeholder rows) is APPENDED, never replacing `#sidebar`'s existing children — it coexists with the static `.sidebar-header` block `app.html` renders, since `sidebar.js` treats `#sidebar` as a shared container it does not own exclusively (`cmd/serf-hub/assets/sidebar.js:20-31`)
- [ ] If the very first `/api/tree` fetch fails, the failure is silently swallowed (`.catch(function(){})`) — the skeleton persists indefinitely with no error UI and no automatic retry until something else triggers a resync (a qualifying notification, the 60s idle interval, or a reconnect) (`cmd/serf-hub/assets/sidebar.js:1081`)
- [ ] A failed RESYNC (as opposed to the first load) explicitly keeps the last-good rendered model on screen rather than clearing anything — documented intentional behavior, not an oversight (`cmd/serf-hub/assets/sidebar.js:1098`)

## 12. Resync triggers

- [ ] A fixed set of AppWire notification methods each schedule a coalesced resync: `thread/started`, `thread/closed`, `thread/status/changed`, `serf/thread/name/changed`, `serf/job/started`, `serf/job/finished`, `serf/attention/changed`, `thread/model/changed`. Any other notification method is ignored by `sidebar.js` (`cmd/serf-hub/assets/sidebar.js:1119-1122`)
- [ ] `serf/attention/changed` additionally does the instant per-row patch (§4.2) BEFORE scheduling its resync — the only method with a fast-path side effect beyond scheduling (`cmd/serf-hub/assets/sidebar.js:1121`)
- [ ] Every successful sidebar-initiated mutation POST (`postJSON`'s `.then` on any 2xx) unconditionally schedules a resync — favorite/archive/rename all funnel through this. Project-level archive/delete (raw `fetch`, not `postJSON`) schedule their own resync manually in their own `.then` instead (`cmd/serf-hub/assets/sidebar.js:930-936`; project archive at `sidebar.js:293-295`; delete at `sidebar.js:313-318`)
- [ ] `scheduleResync()` coalesces bursts: repeated calls while a resync timer is already pending are no-ops; the timer's delay is `max(0, 2000 - (now - lastResyncTime))` — a trailing debounce that ALSO guarantees ≥2s of spacing since the previous resync actually ran (not merely ≥2s since the last schedule call) (`cmd/serf-hub/assets/sidebar.js:1084-1089`)
- [ ] A resync is also scheduled unconditionally on AppWire reconnect (`SerfAppwire.onConnectionRestored`) and on a flat 60-second idle interval regardless of any other activity (`cmd/serf-hub/assets/sidebar.js:1379-1380`)
- [ ] A resync (unlike the very first `fetchTree()`) runs `reconcilePending` (drops any pending optimistic op whose `confirm()` now passes against the freshly-fetched tree) BEFORE rendering, then re-renders, then re-fetches every currently-expanded project's children (§11) (`cmd/serf-hub/assets/sidebar.js:1090-1099`)
- [ ] `htmx:afterSwap` firing on `#workspace` (any in-app navigation) re-runs ONLY `syncActiveRow` (§13) — it does NOT itself trigger a tree resync (`cmd/serf-hub/assets/sidebar.js:1385-1387`)

## 13. Deep-link & URL behavior

- [ ] A session row's navigation target is `/s/<routeID>`, where `routeID` is the bare `session_id` for a LOCAL host ref (`hostID==="local"`), or the FULL `hostID:sessionID` ref string for anything else. Computed client-side by re-parsing the wire `ref` field with the same char-class/`".."`-rejection rules the server's own `hubapi.ParseRef` enforces (`^[A-Za-z0-9._~-]+$` per segment, reject `..` in the session-id segment) — falls back to the wire `session_id` field if the ref fails to parse (`cmd/serf-hub/assets/sidebar.js:35-51`; server-side ref grammar at `hubapi/refs.go:11, 25-30, 38-53`)
- [ ] Clicking a row is BOTH a real `<a href="/s/...">` navigation AND an htmx-intercepted `hx-get` to `/_partials/s/<routeID>/workspace` that swaps into `#workspace`; `hx-push-url` pushes the CLEAN `/s/<routeID>` href (never the `/_partials/...` URL) into browser history, so back/forward and a hard refresh always land on the canonical session route (`cmd/serf-hub/assets/sidebar.js:82-87`)
- [ ] After any `#workspace` swap, `syncActiveRow` marks the row whose `href` exactly matches the current (trailing-slash-stripped) `location.pathname` with `data-active`, clearing it from every other row — a plain href-string-equality scan over every rendered `.sb-row[href]` (`cmd/serf-hub/assets/sidebar.js:966-969, 985-996`)
- [ ] If the active session isn't currently visible in the rendered rows (collapsed behind a section, project, cluster fold, or inactive-subagent disclosure), the sidebar searches the ENTIRE tree for a node whose route ID matches the URL, computes every disclosure key needed to reveal it, force-expands each one (clearing any conflicting user-collapse), persists that to localStorage, and re-renders — a genuine deep link auto-opens whatever it's nested inside (`cmd/serf-hub/assets/sidebar.js:970-984, 998-1057`)
- [ ] The reveal search covers every tier: NeedsYou, Pinned, active projects (splitting an active project's own chain by tier — a match in its archived-tier sessions reveals through "Archived sessions" → that project's archived sub-group, not through the plain active-project chain), archived projects, and test runs — including nested cluster members and subagent children at any depth (`cmd/serf-hub/assets/sidebar.js:998-1037`)
- [ ] The auto-reveal side effect is gated to at most once per distinct pathname (`autoRevealedPath`) — a session genuinely absent from the tree cannot cause a render loop, and a session that's found-but-already-visible skips the (potentially tree-wide) search entirely (`cmd/serf-hub/assets/sidebar.js:960-965, 970-972`)
- [ ] "Open beside" / subagent-chain opening (§3) uses a SEPARATE URL family, `/thread/<encoded ref>`, for side panes — distinct from the main `/s/<routeID>` route the sidebar's own row links use (`cmd/serf-hub/assets/sidebar.js:581-583`)

## 14. Keyboard & accessibility

- [ ] Session rows are real `<a href>` elements — natively Tab-focusable, native Enter activates the href (intercepted by the same `hx-get` a click would trigger) (`cmd/serf-hub/assets/sidebar.js:76-87`)
- [ ] The row/project `⋯` menu buttons, cluster-fold buttons, section-header buttons, and inactive-subagent-disclosure buttons are all real `<button>` elements — natively Tab-focusable with native Enter/Space activation; the cluster/section/disclosure ones ALSO carry an explicit redundant `keydown` handler for Enter/Space, added specifically (per the code's own comment) because this is newer code that "gets real keyboard support rather than inheriting" the gap described next (`cmd/serf-hub/assets/sidebar.js:636-641, 674-678, 180-184`, comment at `sidebar.js:669-673`)
- [ ] **Gap**: project-header disclosures (`.project-header[role=button]`, including archived-project stubs and the per-project archived-sessions sub-headings) are `<div>`s with NO `tabindex` and NO `keydown` handler — the div itself is not Tab-reachable at all; the only keyboard-reachable control inside that row is its own `⋯` menu button. This is a pre-existing, code-comment-acknowledged gap (`sidebar.js:661-663`'s comment explicitly contrasts it with the section header's deliberately-added support), not something a naive read of the ARIA attributes alone would reveal (`cmd/serf-hub/assets/sidebar.js:690-726`; zero `tabIndex`/`tabindex` occurrences anywhere in the file)
- [ ] `aria-expanded` is set on every disclosure control (project header, section header, cluster fold, inactive-subagent disclosure), computed via `isExpanded()` for project headers (factoring in `default_expanded`) and via raw `model.expanded.has(key)` for the other three kinds (§10.1) — both build AND patch code paths set it identically, regression-pinned for the "collapsed project, `default_expanded` omitted by JSON `omitempty`" case specifically (must render the literal string `"false"`, not `"undefined"`) (`cmd/serf-hub/assets/sidebar.js:704, 728, 630, 645, 665, 682, 175, 188`; regression test at `cmd/serf-hub/jstest/test-sidebar-aria.js:1-48`)
- [ ] `aria-controls` links an inactive-subagent disclosure to its rows container; the disclosure's chevron and every project/cluster chevron are `aria-hidden` decorative spans (the header/button itself is the real toggle target, not the glyph) (`cmd/serf-hub/assets/sidebar.js:176, 177, 632, 709`)
- [ ] The `⋯` buttons carry `aria-haspopup="menu"` and a descriptive `aria-label` ("row menu"/"project menu"); the opened popover carries `role="menu"` with `role="menuitem"` children (`cmd/serf-hub/assets/sidebar.js:113-114, 717-718, 228, 232`)
- [ ] The tree root is one `<nav aria-label="Sessions">` wrapping every row/header/disclosure (`cmd/serf-hub/assets/sidebar.js:376`)
- [ ] Escape has two independent, uncoordinated listeners: one closes an open row/project `⋯` menu (returns focus to its trigger); one closes the mobile drawer (skipped while focus/target is inside the search dialog, or a `<dialog id="search-dialog">` is `.open`) — both can fire off a single keypress if both a menu and the drawer happen to be open at once, since neither listener knows about the other (`cmd/serf-hub/assets/sidebar.js:263-267, 1234-1242`)

- [ ] Row titles carry a native `title` attribute (hover tooltip) holding the untruncated text, since the visible text is CSS-ellipsized; the status icon carries a `title` attribute equal to `stateWord(state, askPending)`, the SAME display vocabulary the TUI uses (`hubapi.StateWord`) — a screen reader/tooltip reader gets "Working"/"Your move"/"Question waiting"/"Error"/"Warning"/"Idle"/"Ended"/"Not loaded", never a raw internal state token (`cmd/serf-hub/assets/sidebar.js:101-102, 104-105, 61-73`; shared vocabulary source at `hubapi/attention.go:58-80`)

## 15. Reconciliation & optimistic-update guarantees

- [ ] Every render reconciles against the previous DOM keyed by `data-row-id` (the wire descriptor's `row_id`) — existing keyed elements are PATCHED in place and repositioned via `insertBefore`, never destroyed-and-recreated, specifically so hover state, scroll position, and an open row menu survive a render that doesn't affect that row (`cmd/serf-hub/assets/sidebar.js:1-3, 327-362`)
- [ ] `patchRow` updates `data-state`, the status icon (only if its tooltip word actually changed), `.title` text (only if changed), and the `data-favorite`/`data-ask` attributes — it does NOT update the `.age` text. A row's displayed relative age is set once, at the moment that DOM node is first built, and never refreshed by any subsequent patch — including the 60-second idle resync — only a full rebuild (the row's key leaving and re-entering the rendered set) picks up a fresh `ageString()` computation (`cmd/serf-hub/assets/sidebar.js:106, 124-142`)
- [ ] Optimistic mutations (favorite/rename/session-archive) are tracked in `model.pending` (keyed `"fav:<ref>"`/`"name:<ref>"`/`"arch:<ref>"`) and re-applied on top of EVERY subsequently-admitted tree, resync after resync, until each op's own completion rule fires — "mutation-type" ops (favorite, rename) complete when a resync's tree reflects the new value; "disappearance-type" ops (archive) complete on POST-2xx, since absence from a later tree can't be distinguished from "hasn't resynced yet" (`cmd/serf-hub/assets/sidebar.js:854-864, 888-904`)
- [ ] Every pending op has a hard 30-second eviction safety net regardless of confirmation state, re-rendering once evicted — a backstop, not the normal completion path (`cmd/serf-hub/assets/sidebar.js:888-896`)
- [ ] The pending overlay is applied via a full `JSON.parse(JSON.stringify(tree))` deep clone before each op's `apply(clone)` runs, in `Map` insertion (call-order) order — the live/canonical `model.tree` itself is never mutated by an optimistic op (`cmd/serf-hub/assets/sidebar.js:859-864`)
- [ ] The recursive node-walk backing every optimistic op (`forEachNode`/`forEachNodeDeep`) traverses subagent children AND cluster members through the exact same `.children` field — an optimistic favorite/rename/archive on a nested child or a folded cluster member is applied exactly as it would be for a top-level session, with no special-casing (`cmd/serf-hub/assets/sidebar.js:866-880`)
- [ ] A `postJSON` failure (any rejected promise, including a non-2xx response) surfaces a generic `"Action failed"` error toast via `window.SerfToast` (when present) and re-throws — callers that don't `.catch()` it (favorite, archive) let it propagate as an unhandled rejection beyond the toast; `rename()` explicitly swallows it with its own empty `.catch()` (`cmd/serf-hub/assets/sidebar.js:930-941`, rename's swallow at `sidebar.js:927`)
