#18 — Multi-image (the N-image sub-list)

The hard-case example nails one inline image: a neutral card with a caption (filename · dims), its provenance, and a lightbox. But a generated set — four mockups, six screenshots — has no layout, so it stacks as N full-width cards that dominate the 720px reading column and bury the agent's prose. These four directions all collapse the set into one quiet block that opens to the same lightbox.

Held constant: one containment device (a single neutral card, never a card-of-cards); conversation still leads — the block is subordinate to prose; the caption stays filename · dims · provenance; provenance marks origin, not status, so it spends no color (user-pasted / tool-read / generated are all neutral dots); the only blue is the interactive affordance (a thumbnail to open, a "+N more"); deep view is the lightbox.
AHorizontal thumbnail strip → lightbox
The set folds to a single-row strip of small thumbnails headed by "4 images", scrollable when there are many. Any thumb opens the lightbox with prev/next (try it — arrows, Esc, click). Densest footprint of the four; the agent's prose stays the loud layer right above it. Trade-off: 104px thumbs are too small to read a screenshot in place — you must open the lightbox to actually see content.

BContact-sheet grid (2×N), each captioned
A 2-column grid inside one neutral card, each cell large enough to compare at a glance and carrying its own filename · dims · provenance caption. Best when the images are the deliverable and the user needs to evaluate them side-by-side without opening each one. Trade-off: the tallest of the four — at 6+ images it eats real column height, so it works against "conversation leads" for large sets (cap rows, then "show all N").

CPrimary inline + "+N more" chip
Show one image at readable inline size — exactly the hard-case treatment — then collapse the rest behind a "+3 more" chip (with tiny stacked previews) that opens the lightbox onto image 2. Keeps the single-image grammar intact and degrades gracefully: 1 image is just the card, N images is the card + a chip. Trade-off: privileges one image as "primary" — wrong framing when the set is a peer comparison (that's B's job).

Trade-off: only earns its keep when provenance is genuinely mixed; a homogeneous set (all generated) collapses to a single group and is just a worse strip (A).
