#14 — New-content pill & error-findability

The shipped ↓ N new pill flickers (its count rides scrollHeight, which grows in bursts as output streams while you read up — a jittering corner badge is a blinking element, which the principles forbid), it is kind-agnostic (3 new tool lines look the same as a session that just went blocked or a tool that errored), and there are no scroll-track markers to find a buried error or needs-you in a long transcript. Each alternative below is a real, scrollable transcript of the same session: scroll up and you'll have a buried ✕ error and a buried ◆ needs-you off-screen. Watch how each treatment reacts. Blue = the calm count; amber ◆ = needs you; red ✕ = error. No blinking anywhere; amber/red appear only for needs-you/error.

Recommendation: B (split calm/urgent color) as the default pill, with C (minimap ticks) layered on for the "where, exactly" answer in long transcripts. All four share the same foundation that fixes the literal bug: a debounced, sticky count that never jitters (principle 5). On top of that, B is the smallest change that makes the pill honest about kind — a ◆ needs you or ✕ error below the fold reads instantly, and the arrow flips to point the right way — which is the core of error-findability for the common case of one attention item. C is the complement for multiple buried items or for pinpointing position: it answers "where and how many" both above and below the fold without scrolling, and it's the only treatment that surfaces attention you've already scrolled past. D is elegant for power users working a queue but adds machinery and hides the "where," so it's a keyboard-affordance layer, not the default. A alone is correct but insufficient — it kills the flicker yet stays kind-agnostic, the very gap this topic exists to close. Across all four: the count is blue/neutral and recedes; amber ◆ and red ✕ are spent only on needs-you and error, always glyph-paired; nothing blinks — state changes are opacity/color transitions and a single one-shot "arrived" ring, never a pulse.
