What changed from round 1, and why

  • Neutral ink everywhere a watch appears. The count sits in the plain .rail-gloss, not the alive-tinted span. Round 1 spent --alive on a watch in A and B and --accent in C, which the four-hue rule forbids. Danger survives only for runaway drops.
  • The gate change is explicit. showsActivity gains watches > 0, so a session whose only pending work is an armed watch still gets its count. This is a deliberate amendment to “a quiet row is one line”, and it is the one round-1 assumption every reviewer flagged.
  • Count goes before the branch. Branch stays the ellipsis sacrifice; the count is never the thing that gets cut.
  • A drawn clock, not a typed glyph. No code point in the app's font ranges covers ◷ (round 1's glyph), and the rail names rows from their content — so round 1's row would have announced a stray character. Here it is an inline SVG plus a visually-hidden “Watch:” for assistive tech.
  • No countdown, no progress track, no duration. The runtime keeps a ticker, not a next-fire instant; there is no TTL field at all. So there is no “in 4m” and no “×6h” — cadence is shown as what it is (every 15m, on output) and state as armed.
  • Running work keeps the top of the panel. Watches are their own group after running work — an armed watch is inventory, not attention. The exception is the one abnormal state, promoted to a “Needs a look” group.
  • Ended watches live in the panel, not the rail. No third disclosure on a session row; the panel gets one collapsed “Ended watches (N)” line.
  • “Many” is capped with a +N more watches note, matching the rail's existing overflow grammar.

Data plan (verified against the code)

  • Already live: jobManager.liveWatchSummaries() returns {id, source, condition, deliveries, createdAt} for the session's visible watches, and recentWatchEntry carries onto {end_reason, ended_at} for ended ones. Cadence and note already exist inside watchConditionSummary's prose.
  • Cheap plumbing: project that projection to the hub (DetailedStatus → EvenerDiagnostics → NavigationSessionSummary.watches), and split note and cadence into structured fields instead of parsing the condition string. Delivery timestamps exist (WatchSendState.CreatedAt) but DeliveryView drops them; add the field.
  • Definition to pin down: “active” = in the live registry and visible to this session, excluding fired-pending-end entries; a receiver watch counts for its receiver, not its owner, or the subtree rollup double-counts.
