Mockup #7 — System / skill churn & silent-success

Lifecycle events — a skill activating, a plugin loading, a hook firing, a system prompt loading — are bookkeeping. They must recede under the conversation, never out-shout it. Four directions for de-emphasizing and coalescing the run, each rendered in context with real agent prose so the trade is judgeable.

Fixes for the shipped UI: (1) system/skill events render at divider weight — full-width rules flanking a centered "Skill activated" summary, louder than the prose they interrupt; (2) each carries a meaningless "N chars" count of the payload; (3) silent-success tools (a write or touch that returns nothing) have no rule — they vanish, so you can't tell the file was written.
Targets: quiet one-liners · coalesce the run · honest silent-success · no "N chars" · never divider-weight.

Why it's wrong: the divider rules give a bookkeeping line more visual weight than the agent's actual finding above it, and "56 chars" measures the payload string — a number no human reading the transcript can use. A run of these chops the prose into ribbons.
AQuiet dim one-liner

The literal §4 rule. Each lifecycle event is a single dim, rule-free line: a faint mono glyph + a sans label + the machine id (still dim), all at --ink-3. No count, no box, no divider. It sits below the prose the way a stage direction sits below a line of dialogue — present, but never read first. Tradeoff: a long setup run (8–10 events) still produces 8–10 lines; quiet, but it adds vertical length between turns.

BCoalesced "N system events"

A run of adjacent lifecycle events folds into one quiet collapsible line — "4 system events · loaded release skill + 3 more" — that names the most consequential one and hides the rest. Click to expand the individual one-liners (the Alt-A treatment). A 10-event setup costs one line at rest. Tradeoff: the gist must pick a "headline" event; if the run is heterogeneous the summary can under-describe what loaded until you expand.

C✓-only silent success

Aims at the silent-success gap: a write or touch that returns nothing currently leaves no trace. Give it one quiet line stating what it changed — a neutral ✓ + the file path, the consequential part read up to --ink-2, and no byte/char count. The lifecycle run still uses the Alt-A one-liner, so this composes with the others. Tradeoff: a turn that writes many files (codegen, scaffolding) produces a ✓ line per file; cluster them ("✓ wrote 6 files") past a threshold — but that's topic #6's job, referenced here, not re-solved.

DLifecycle in a Details panel

The most aggressive de-emphasis: lifecycle leaves the transcript entirely. The conversation keeps one collapsed marker ("setup: 4 →"); the full event list lives in a right-docked Details drawer — the same surface the top-bar Details ⋯ overflow opens. The transcript becomes pure conversation; bookkeeping is one click away when you want it. Tradeoff: out of sight, out of mind — a skill loading the wrong version, or a hook silently failing, won't catch your eye inline. Best paired with promoting any errored lifecycle event back into the transcript (red), per the error rules.
