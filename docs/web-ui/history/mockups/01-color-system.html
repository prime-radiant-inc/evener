Color & status system

Mockup #1. The shipped style.css conflates the palette — amber doubles as red, --error aliases needs-you, green and purple leak in as idle/subagent hues, and --text-dim fails contrast as body text. These four alternatives show how the four-meaning system should work. Every status is glyph-paired (colorblind-safe) and every text/background pair below clears WCAG AA.

Base tokens from ./tokens.css. Topic CSS is inline. States exercised in every slice: live · needs-you · error · done · idle.

Live / active
Working, running, interactive: links, primary action, focus ring. The only color that should be moving.
--accent · #7aa2f7 · blue
Needs you
Awaiting your input: a question, a permission prompt, a blocked session. Amber, never red.
--attention · #e2b06a · amber
Error
The agent or a tool failed to run. Not "found bad news" — that's a done result with bad text in it.
--error · #f7768e · red
Done / settled
The expected, finished state. Recedes to neutral — absence of color is the signal.
--done · #7e8593 · neutral (= --ink-3)

Idea: the literal golden system — color marks only live (blue), needs-you (amber), error (red); everything finished goes neutral and loses its rail. The eye lands on the three saturated rows and the four-row feed of done steps quietly recedes. Glyphs (⟳ ◆ ✕ ✓ ○) ride alongside so color is never the sole channel.
Tradeoff: minimal and disciplined, but a long run of done steps is rendered in one flat neutral — you can't tell "succeeded" from "succeeded-with-a-warning" at a glance without reading the result text. Alts C and D probe whether that neutrality is too austere.

Idea: pin a distinct shape to each meaning, not just a hue — ring/diamond/cross/check/hollow. Idea: keep A's color discipline but harden the neutral ramp so "recedes" never means "illegible." Body text bottoms out at --ink-3 (AA, 5.2:1); --ink-4 is demoted to hairlines, borders, and idle dots only — exactly the misuse (--text-dim on dark) that the shipped UI got wrong.
Tradeoff: a three-step text ramp is slightly less "quiet" than four — settled rows sit a touch brighter than a designer might want. That's the deliberate cost: legibility for the all-day user beats a prettier-but-unreadable dim. Pairs naturally with A or B.

Idea: a direct A/B of the central principle. Left tints every successful step green; right keeps done neutral. In the left column the four ordinary successes glow as loudly as the one real problem — the error and the needs-you blur into a wall of color and the eye has nowhere to land. On the right, the two rows that need you (red ✕, amber ◆) are the only color on the screen and pop instantly.
Tradeoff: the neutral-done column is unmistakably more scannable, but it can feel "colorless" in a calm, all-green run where nothing is wrong — there's no positive reward signal. The resolution: reserve --success for rare genuine good-news highlights (e.g. "all 312 tests pass" after a long red streak), never for routine done.

Recommendation: ship A + C + B's glyph contract. A is the correct base (four meanings, color scarce, done recedes); C is non-negotiable accessibility (--ink-4 is hairlines-only, body text clears AA); B's distinct-shape-per-state makes the system robust under colorblindness and monochrome and costs nothing once adopted. D is the proof, not a shippable option — it settles the "tint vs. neutral" debate in favor of neutral and pins --success to rare good-news highlights only.
