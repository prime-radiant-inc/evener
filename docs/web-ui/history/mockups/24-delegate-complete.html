The delegate notification card, restated around one idea: the head names the delegate and the outcome; the body is the report. Three changes, applied to every delegate notification shape, not just the completed one: no echo metadata in the expanded state (the delegate id and status say what the head already said), the subagent's message rendered as a message — sans serif prose, not a JSON dump, the structured output as a table, and identity on the inline head: the name is the same hover-card trigger every id in the transcript already is. Real strings from a live session throughout; raw frames stay in the raw disclosure. Toggle the theme — both must hold.

CThe rest of the family — same treatmentproposed · desktop

Every delegate notification takes the same shape: head carries identity + outcome, body carries only a real report. Reporting endings (completed, failed with an error past its first line) show the message; machinery endings (stopped by its coordinator, stopped by the user, a failure whose whole error is its ending) have no report to show — their packet message is a stub phrase the head's ending already says ("stopped by parent", "Stopped by the user."), so the row renders as a static line: no chevron, nothing to expand. An exhausted run keeps its budget message — it names the limit the ending does not. The quiet watchdog keeps its one sentence. Legacy frames (durable history recorded before the packet carried structured_result) parse the envelope out of the message and render identically — same parser path, no fork. No delegate card carries a raw disclosure; the daemon's own frame remains the verbatim record.
