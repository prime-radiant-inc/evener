#12 — Test-runs bucket & finding old work

The Test runs auto-bucket correctly herds ~88 disposable serf-e2e-* sessions out of the way — but the moment you actually need a specific past run, it's a flat, undated, unsorted, unsearchable pile. And Recent / Older give no way to answer "find that refactor from last week in serf." Each alternative below is a real rendering of the expanded bucket and/or a finder over Recent/Older. Status follows the four-color rule: a failed run is red (it broke); a passed run is the expected, settled state → neutral (never green); blue is reserved for live/interactive.

For contrast — today's bucket (the problem)

Expanding Test runs today drops you into a flat, undated, unsorted, unsearchable list of ~88 identical-looking serf-e2e-* ids — no outcome, no date, no way to find the one you need. It's a wall, not a finder.

Recommendation: combine B + C as the default expanded bucket, with A's scoped search at the top and D's Recently-viewed tier above Recent. Date sub-grouping (B) is the zero-input backbone — recency is how you reach for "this morning's run." Outcome glyphs (C) cost nothing per row and make the one axis that actually sends you back into a run — it failed — scannable, with a one-tap fail filter. A's scoped ⌘K is the escape hatch once the list is long and you know the topic; it layers cleanly on top of B+C rather than replacing them. D's Recently-viewed tier is the real answer to "that refactor from last week" for real projects (not test runs) and is worth shipping independently; branch grouping is the more speculative half (per-device, extra nesting) and can follow if it earns its keep. Throughout: a passed run is neutral, a failed run is red, live is blue — --success green stays reserved.
