Mockup #21 — Cold start

The empty session and the gap between Send and the first agent frame are the product's first impression — and today they are a void. Four directions for a calm, crafted welcome and a cold-start gap that reads "loading," never "broken."

Fixes for the shipped welcome: (1) the empty pane is a near-empty void ("Welcome to serf-hub" + two buttons) — sparse and uncrafted; (2) after the first Send there is no defined state — empty transcript + quiet composer reads as "is it working or broken?"; (3) nothing distinguishes an honestly-starting agent from a hung one.
Targets: crafted empty state · cold-start gap that reads "loading" · honest liveness (no reassurance-loop lie). Each direction shows the empty session (left) and the just-sent first message (right).

AOptimistic echo

On Send, the user's message is committed to the transcript immediately as a quiet You tag — never emphasized, since the user knows what they typed. A calm "starting…" liveness line stands where the first agent frame will land, so the send visibly "took" the instant they hit return. Tradeoff: it's optimistic — if the send actually fails, the echoed message must be reconciled (mark it failed + offer retry); the UI promises before the daemon confirms.

BSkeleton turn

The cold-start gap shows a faint placeholder turn — ghost lines sized like real agent prose, with a slow neutral shimmer. The shape says "this layout is filling in," so the gap reads loading, not broken or empty. No spinner, no color; the skeleton swaps out the instant real tokens arrive. Tradeoff: a skeleton implies structure that may not match what arrives (the agent might think first, not write prose); overused, skeletons feel generic. Keep it to one modest block, not a full fake page.

COnboarding affordances

The empty transcript is a small crafted welcome instead of a void: a one-line orientation, two or three example prompts that prefill the composer on click, and the model picker surfaced. It answers "what can I do here?" The cold-start side shows the affordances dissolving the instant the first turn begins — they never linger as clutter. Tradeoff: scaffolding earns its place only on a truly empty session; it must vanish on first send and stay gone for repeat users, or it becomes noise. It also invites curation of "good" example prompts.

DNarrated cold-start liveness

The cold start is narrated as honest stages, each driven by a real signal: Connecting to agent… (daemon handshake) → Thinking… (first model tokens). Completed stages settle to neutral with a check; the current stage is the only blue, moving thing. This answers "is it working?" precisely — and because each stage waits on a real event, a stall shows (the stage simply doesn't advance) rather than being masked by a spinner. Tradeoff: requires the daemon to emit those lifecycle signals; honest staging means if connection is slow the user sees it sit on "Connecting…" — which is the point (§2.7), but is less reassuring than a fib.
