#18 — Rich content: diff / patch

Four directions for showing what the agent changed in a file. Today an edit is a bare mono edit cache.go line with no diff — yet reviewing the change is one of the main reasons a person watches a coding agent at all. Each alternative renders the same small Go edit so they compare apples-to-apples.

Held constant: +/− carries the meaning, color only reinforces it (dual-channel, colorblind-safe); the add/remove hues are desaturated and deliberately separate from the semantic colors — a removed line is not an error, an added line is not good news; one containment device per block (a neutral box or a left rail, never both); the diff is machine text, so it is mono and demoted — the agent's prose still leads.
Palette guard: + added − removed — must stay distinct from — success (good news) error (broke)
ACollapsed +N −N → unified diff
The edit collapses to one scannable line — edited cache.go · +6 −2 — and expands to a full unified diff in a single neutral box. Gutter signs do the work; the tints are barely-there desaturated teal/rose so a glance never confuses a removed line with a failure. This is the default: dense in the column, full detail one click away. Trade-off: a multi-hunk patch can get tall once expanded — fine for one focused edit, want collapse-once-scrolled-past for big ones.

DInline-in-prose hunk
The hunk sits directly under the sentence that explains it, on a single quiet left rail (the one containment device — no box), so the change reads as part of the agent's narration rather than a separate widget. Best when the agent is walking you through a focused, one- or two-line fix and the why matters as much as the what. Trade-off: doesn't scale — a turn with several edits would stack rails and bury the prose; for many or large changes, fall back to A/C's collapsed lines.
