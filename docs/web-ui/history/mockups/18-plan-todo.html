Mockup #18 — Plan / todo list

serf has a task_list tool, but the shipped UI renders the plan as an afterthought string — "tasks  no tasks" — an empty-state label louder than any real plan, with no checklist grammar at all. Four directions for a real pending / in-progress / done checklist and a clean empty state.

Targets: three glyph-paired states so it is colorblind-safe and done recedes (only the one current item is colored); one containment device per direction; and an empty state where no plan ⇒ the control is simply absent — never a "no tasks" string.

✓done — neutral, recedes ⟳in progress — blue, the live item ○pending — dim, not started
AState-glyph checklist

A flat checklist in the transcript flow. No box, no rail line — the column of glyphs is the only structure (the lightest possible emphasis). Each item is one sans line: glyph · step · optional mono detail. Done lines fall back to neutral and recede; the single current item is the only blue, its ⟳ breathing. Tradeoff: with no container it can blur into surrounding prose on a busy turn, and a long plan adds real vertical height to the reading column.

CInline plan block (one neutral box)

When the agent declares a plan it renders as one neutral box — the same single containment device the subagents module uses — placed exactly where the plan was announced. Items check off in place as the turn runs. The box anchors the plan to its moment in the conversation, reading like "here is the contract for this turn." Tradeoff: the box is a heavier device than A and, being inline, it scrolls away on a long turn — you lose sight of progress unless you scroll back (which is exactly the gap D fills).

DPinned collapsible plan rail (for long turns)

For a long multi-step turn the plan docks as a pinned rail on the workspace edge — it never scrolls away, so progress stays visible while you read deep in the transcript. It collapses to a thin spine (a proportional progress fill: neutral for done, a blue tip for the current step) when you want the room back, and expands to the full checklist on demand. Tradeoff: it's a piece of persistent chrome that steals horizontal width — it only earns its keep on genuinely long turns; on a short one it's overkill (use A or C). Toggle it below.

★Recommendation

C (inline block) as the default, promoting to D (rail) on long turns. The plan belongs in the conversation at the moment it's declared — C reads as the turn's contract and uses the same single neutral box as the subagents module, so the grammar stays consistent. When a turn grows long enough that C scrolls out of view, the same plan re-docks as D's pinned rail so progress stays glanceable. A is the right fallback for tiny plans where even a box is too much; B's chip is a nice option to layer on later but hides the steps behind a click. All four share the three glyph-paired states and the "no plan ⇒ no control" empty rule.
