Workflow prototype, no credentials saved or requests sent

Design notes & prototype limits
  • Keep the developer’s directory and task in place. Saved provider configuration enables model choice independently of verification. Failure and unsupported checks stay visible without forcing setup again.
  • Use the existing connection-dialog pattern. Describe the access method before asking someone to select a provider.
  • The API check only lists models. It does not prove generation access, available quota, billing health, or a successful first reply.
  • Saved access below is simulated in memory only. Cancel after saving does not undo the simulated save. Reload resets everything; draft persistence and durable start reconciliation remain separate gaps.
  • Only the API-key journey is interactive end to end. Sign-in and local/custom setup are explanatory previews. The models, metadata, directory, check results, and reply are fixtures, not live data. Model choices remain scoped to the selected provider instance. Catalogue loading, empty, and error states are separate from auth checks.
  • No automatic server or browser startup is assumed. The terminal output is proposed wording, not implemented behavior. No product code is changed. The existing Welcome.tsx redirect is preserved: only focused / with no session and confirmed missing provider redirects to /new, preserving query and hash. Configured users retain welcome.
  • Blank launch creates an idle empty-session preview, not a waiting reply. Access resolves independently, explicit advanced sandbox overrides win, and unknown inherited values remain visible.
  • Native HTML controls are used only in this throwaway document. Production must use Evener widgets. Font stacks use local fallbacks, with no downloads.
