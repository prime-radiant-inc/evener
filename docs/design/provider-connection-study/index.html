Provider setup / Six directions

From “configure an instance”
to “connect my models.”

Six interaction patterns for the same simple task. Choose a familiar provider, supply its access details, and get back to work. Optional machinery stays closed.

Working recommendation

Quick connect as the shared flow

A is the most direct baseline. B and F offer settings-specific alternatives; C explores dedicated onboarding; D and E start with a different user question. Open a direction and try the flow.

A / Compact, shared flow

Quick connect

Choose a provider. The same panel becomes a single explained credential step, then a result.

Best for: one consistent flow from settings, launch, and the model chooser. Tradeoff: hides the directory while connecting.

Try this flow →See the key step
B / In-place settings

Inline cards

The selected provider expands right in the settings page. Your other connections stay in view.

Best for: adding another provider. Tradeoff: the page grows around the form, especially on a phone.

Try this flow →See the key step
C / First-run journey

Guided setup

A full-page welcome flow makes the beginning, remaining steps, and finish explicit.

Best for: a dedicated first-run experience. Tradeoff: more ceremony for people who just want to add a key.

Try this flow →See the key step
D / Start with the model

Model first

“I want Claude” becomes a visible provider choice and its connection step, right beside the draft.

Best for: empty model selection. Tradeoff: model families have multiple providers and billing routes.

Try this flow →See the key step
E / Start with your access

Access first

Choose ChatGPT sign-in, a provider API key, or local/company access before choosing the provider.

Best for: people who know what access they have. Tradeoff: asks beginners to classify their credentials first.

Try this flow →See ChatGPT sign-in
F / Stable two-pane directory

Provider directory

A searchable list stays on the left. Only the connection details change on the right.

Best for: provider management and frequent changes. Tradeoff: more structure and a wider desktop footprint.

Try this flow →See the key step
