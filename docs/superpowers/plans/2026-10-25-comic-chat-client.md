# Comic Chat Client Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a self-contained `/comic` hub client with literal speech and thought balloons, expandable subagent comics, sending, stopping, questions and approvals.

**Architecture:** Mount either the workspace or Comic Chat over the existing browser connection, navigation, transcript and mutation owners. Extract the small lifecycle and composer boundaries both surfaces need; keep comic projection, layout and reading position presentation-owned. Start with a real read-only conversation, then add panel composition and the shared controls.

**Tech Stack:** Existing React 19, TypeScript, Vite, Zustand, AppWire client, widget library and VirtualList; Vitest plus real Chrome/hub/daemon guards. No new runtime dependency.

**Spec:** `docs/superpowers/specs/2026-10-25-comic-chat-client-design.md` and its binding `docs/superpowers/specs/2026-10-25-comic-chat-thoughts-subchats-design.md` amendment. Product source baseline: `dc6c93e0810857db3359983854c8510e0b4a3709`.

## Global Constraints

- “Leave the regular web client available and visually unchanged.”
- “Font use stays personal, and font files stay outside git.”
- “No Windows title bars, menu bars, desktop framing or beveled controls.”
- “Deliver genuine Comic Sans regular and bold by `@font-face`, without relying on fonts installed on the visitor's machine.”
- “No new widget or widget prop is planned.”
- “Opening a conversation is a read. It must not launch or resume a daemon.”
- “Markdown source remains literal in balloons; no summarizer or model rewrites the conversation.”
- “At 760 CSS pixels and below, use one column and recompose the panels.”
- “Never auto-approve.”
- “Never commit the fonts, download them automatically during build/test, or publish a font-bearing build as an Evener release.”
- “Shipping it does not authorize deploying or restarting Jesse's hub.”
- Preserve tool-produced images with attribution and source order while hiding routine tool text. Keep the unfiltered model authoritative for questions and approvals.
- “Display only the content already provided by the canonical transcript.” Thinking is expanded by default, in source order, with no fabricated or revealed redacted text.
- “Casting is deterministic, independent of fetch order, page position, status and run generation.” Route using proven owner/delegate identity and the authoritative child ref, never names or parsed prose.
- “The expanded child is a reader, without a second inline composer.” Explicitly expanded children use shared foreground, paging and activity owners; collapse releases only owned demand. No eager recursive fetch.
- “The chosen entity snapshot owns its status and run generation.” Historical updates stay historical; never join a resumed run to an earlier report.
- First version covers existing sessions, text input and inline child readers. Creation, configuration, forks, new uploads, voice and general job/watch inspection stay in the regular UI. Preserve structured drafts and existing recovery without inventing new attachment lifetime promises.
- Import the SDK by `@evener/appwire-client` and its exported subpaths. Controls come from the widget barrel; no raw form widgets or selectors reaching into widget DOM.
- Read `docs/product/README.md`, `docs/product/subsystems.md`, `docs/developing-evener/testing.md` and `docs/developing-evener/design-system.md` before implementation. Tests assert behavior and fixture data, never production copy.

## Review Focus

1. Encoded remote refs, malformed URLs and same-named or ambiguously owned delegates must preserve host identity and never open an arbitrary child (Tasks 1, 2, 3 and 10).
2. An old response arriving after collapse, client replacement or session selection must not clear another draft, publish into a new reader or resolve its questions (Tasks 3, 7, 8 and 10).
3. A tiny viewport, late font load or a single huge grapheme must preserve every speech/thought character and the away reader's position, including during child streaming (Tasks 4, 5 and 10).
4. Structured recovery edited from another client must retain metadata and reject stale ownership rather than duplicate or silently drop input (Tasks 6 and 7).
5. Reconnect or refresh after several older pages must recover a later-page parent or nested-child anchor, including its expanded path, without replaying a send or recursively loading unopened children (Tasks 5, 10 and 9).
