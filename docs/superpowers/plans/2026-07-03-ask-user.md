# `ask_user` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the `ask_user` tool per `docs/superpowers/specs/2026-07-03-ask-user-question-tool-design.md` (spec HEAD `db2e1bf7c` — read it in full before any task): the root agent asks structured questions; the asking round ends the turn in a new `awaiting` state; the answer is the next user message; web + TUI render forms; invisible non-interactive and in subagents.

**Architecture:** One new session state (`SessionAwaiting = "awaiting"`) produced by a single round-boundary check where `deliverIfCommunicated` already decides turn-end. `ask_user` is an ordinary tool (ack result, per-round pending set); answers ride the existing `turn/start`. Holds (entry gate, drain-ladder gate, goal kicks, compact) keep anything from answering on the user's behalf. No new wire methods, events, or capabilities.

**Tech Stack:** Go (module `agent` + `cmd/serf` + `cmd/serf-hub` + `cmd/serf-tui`), vanilla JS renderer + JSDOM tests, bubbletea TUI, markdown scenario cards.

## Global Constraints

- `SessionAwaiting SessionState = "awaiting"` — byte-equal to `appwire.ThreadStatusAwaiting`. Never any other string.
- Never auto-proceed: no timers, no synthetic answers, anywhere.
- Registration gate: `!cfg.NonInteractive && !isSubagentSession` (spawn carrier OR `meta.IsSubagent`). Root-only, interactive-only, always.
- No new appwire methods, notification kinds, event kinds, or capability fields.
- TDD red-first for every task. Per-task: `golangci-lint run` on changed packages. Commit per green task.
- Phase gates (end of each phase): `make test`, `make lint`, `go test ./agent/... -race` — run them, paste output, no fake-green. A failing assertion is never weakened or deleted; if blocked, stop and escalate.
- One writer per tree: implementers run **sequentially** in this worktree (`.claude/worktrees/ask-user-question`, branch `worktree-ask-user-question`).
- Match surrounding code style; comments say WHAT/WHY only.
- The spec (§ references below) is authoritative. When a plan detail and the spec disagree, the spec wins; flag the discrepancy in the task report.
