# Issues #4980 and #4981: compact_context request path and note_to_self description

## Scope and acceptance

Fix two documentation-drift defects with no production behavior change:

1. **#4980** — `docs/design/context.md`, `### Agent-force path` (line 121), says the
   `compact_context` tool calls `requestForceCompact(instructions)`. The tool calls
   `deps.requestSkillCompaction(ctx, note, instructions, selection)`
   (`agent/session_tools_compact.go:80`). `requestSkillCompaction` arms the
   transient round-tail trigger itself (`s.forceRequested = true;
   s.pendingInstructions = instructions`, `agent/session_skill_compaction.go:228-229`).
   `requestForceCompact` (`agent/session_self_compact.go:215`) still exists as a
   transient round-trigger primitive but has no production caller: only tests call
   it, and `resumeSkillCompaction` re-arms the same fields directly
   (`agent/session_skill_compaction.go:489-490`). No call edge exists between the
   tool path and `requestForceCompact`.
2. **#4981** — `agent/session_tools_compact.go:34-35`, the `note_to_self`
   parameter description, says an empty note with no `compaction_instructions`
   skips compaction. The implemented scheduling decision also requires an absent
   `reload_skills` selection
   (`clearOnly := note == "" && instructions == "" && selection.State == "absent"`,
   `agent/session_skill_compaction.go:166`).

Acceptance: both documents describe the two implemented behaviors under review
exactly; no production behavior changes; `make docs-check` passes; the focused
compact-context tests and `make build` pass. One PR closes both issues.

## Implemented behavior to document

`requestSkillCompaction` (`agent/session_skill_compaction.go:165-245`):

- Clear-only (`note == "" && instructions == "" && selection.State == "absent"`):
  clears the pinned note, returns generation 0, and cancels only the pending
  automatic operation associated with the cleared note. It arms no compaction;
  a forced operation and its round trigger survive.
- Otherwise: mints the next operation generation, supersedes a pending automatic
  operation, stores the note with a generation-owned `forced`
  `schema.SkillCompactionOperation` carrying the instructions and reload
  selection, arms the transient round-tail trigger (`forceRequested`,
  `pendingInstructions`), and persists. A request over an existing forced
  operation, or over one already published and awaiting delivery, is rejected
  without mutating note, selection, or operation. A failed metadata save retires
  the operation and its trigger and returns a typed `*skillCompactionSaveError`.
- At the tool-round tail (`agent/session_lifecycle.go:2521`),
  `applyPendingForceCompact` consumes the trigger, prefers the pending forced
  operation's own instruction snapshot over the transient copy, captures that
  forced operation, and calls `foldWithForceCompact`, which runs
  `Manager.ForceCompact(ctx, history, instructions, emitFn)` and publishes the
  folded history. `ForceCompact` emits a checkpoint `EventContextCompaction`
  unconditionally (`agent/internal/contextmgr/context_manager.go`), and
  `actualCompaction` is exactly "staged EventContextCompaction payloads exist"
  (`agent/session_compaction.go:489-491, 793-795`), so the compact path always
  counts as a compaction even when no turn is folded. The winning publication
  claims the captured operation when it still matches the live pending operation
  by generation and note generation; a supersede or cancellation claims nothing,
  while a clear-only call leaves a forced operation pending and does not prevent
  the claim. Publication-race retry exhaustion retires the captured forced
  operation; a transcript refusal returns without cancelling, leaving the
  operation pending for a restart to re-arm.

`reload_skills` parsing (`agent/skill_reload_selection.go:19-39`): absent or
`null` is `absent`; a JSON array is `valid` (including `[]`, meaning reload
none) or `invalid` (malformed or unknown skill). Presence, not length, decides
the clear-only rule; an invalid present selection still schedules.

## Chosen change

1. `agent/session_tools_compact.go` — rewrite the `note_to_self` parameter
   description: an empty string clears a pending note; with
   `compaction_instructions` also empty and `reload_skills` absent or null it
   requests no new compaction, though one requested by an earlier call still
   runs; a present selection, even `[]`, requests a compaction.
2. `docs/design/context.md` — rewrite `### Agent-force path` to match the
   behavior above: the real call path through `requestSkillCompaction`, the
   clear-only and rejection rules, the `requestForceCompact` non-use, and the
   round-tail dispatch and publication claim.

No test pins the description or the doc text. The scheduling rule is already
covered behaviorally by
`TestSkillReloadSelection_CompactToolSelectionOnlyRequestsCompaction`
(`agent/skill_reload_selection_test.go:224`) and
`TestCompactTool_ClearNote_NoForce` (`agent/session_tools_compact_test.go:31`).
Per `docs/developing-evener/testing.md` ("Prompt Prose Is Not a Test Oracle"),
model-facing tool descriptions are pinned only by a whole-output golden; no
golden covers `compact_context`'s definitions today, so the rewrite is verified
by review, not by a new fragment assertion. There is no red/green test for a
description-only change.
