# Sidebar Rebuild & Thread Management — Design (v4)

Date: 2026-07-04 (v2: round 1, A 11 / B 11 tie; v3: round 2, A 11 / B 7; v4: round 3, G 5 / H 5 tie — 10 distinct, zero overlap, all folded)
Status: Draft — awaiting Jesse's spec review
Workstream: 3 of 6 from the 2026-07-03 web-UI UX diagnostic. Mandate: "nothing is sacred; good is better than keeping back-compat."

## Problem — each symptom, mechanized

- **Slow.** The sidebar is one htmx element re-fetching the entire server-rendered tree and replacing its whole DOM (app.html:36-41) on an 11-event allowlist that includes `item/started`/`item/completed` (sidebar.js:287-309) — every tool call in a watched session rebuilds the sidebar behind a 50ms debounce (sidebar.js:277-285). Server side has no cache: every request re-sorts/re-classifies every indexed session including archived (tree.go:285-673); `BuildTree` runs independently at two sites (handleSidebar, handleAPITree) and `DeriveAttention` at two (handleAPITree, the attention watcher) with nothing shared; a configured Codex remote source costs a synchronous network hop per render (web_api_tree.go:132-155).
- **Content disappears; expansion lost.** Non-live projects ship empty children every render (sidebar.html:114); a manual expand lazy-fetches rows (sidebar.js:116-142); the next full swap discards them and only the active session's project ever auto-refetches (sidebar.js:92-106). Latent races compound it: no `hx-sync`/in-flight guard (stale response overwrites newer), and the disclosure snapshot is one shared unscoped variable (sidebar.js:211).
- **Flashes.** "loading…" text on first paint — the sidebar is hard-excluded from the skeleton system (skeleton.js:15-20); every refresh destroys and recreates all row nodes; scroll offset survives by accident while content shifts under it.
- **Hard to read; bad hit targets.** 10px metadata on the two lowest-contrast tokens (`--text-dim` ≈2.9:1 fails AA, `--text-muted` ≈4.7:1 borderline; style.css:4-30, 69-76); the chevron's clickable box is ~12px because a documented desktop override strips the 32px tap-min (style.css:687-692) and the fixing rule is dead CSS — the template never applies `.btn-icon` (sidebar.html:77-78 vs style.css:711-724); subagent rows ≈17px tall.
- **Latent identity defect (round-1 A1/B1):** projects are keyed by `filepath.Base(workingDir)` (tree.go:211-217, grouping at :341), so `/a/foo` and `/b/foo` merge into ONE node whose WorkingDir is "first non-empty seen" (:349-353) — and project archive decisions key on that basename too (tree.go:503), so archiving "foo" archives both today. Any name-keyed destructive verb inherits this. v2+ fixes identity itself (below).
- Also: sidebar.js's own header comments are false on three counts (dead stagger path, wrong trigger description; sidebar.js:6-10, 170-177) — the rebuild deletes them.

## Decisions

1. **Client-rendered, keyed (Jesse, 2026-07-04).** The sidebar stops being an htmx partial; data is the state, the DOM is a projection. The Go sidebar templates and `/_partials/sidebar{,/project}` routes die.
2. **Rename in scope, daemon-truth (Jesse, 2026-07-04).** `serf/thread/name/set`; `NameSource` gains `"user"`; both auto-namer paths skip user-named sessions.
3. **Project identity = full working directory (v2, forced by round 1).** Basename becomes display-only; keys, decisions, and delete all bind to the path.
4. Carried: project-level delete only; no name-prefix matching for test runs (2026-06-17 spec's successor — a first-class origin marker — is what ships); pinned tier below needs-you; native `confirm()` for delete in v1.

## Foundation

**Project identity.** `BuildTree` groups by `EffectiveWorkingDir` (full path; the worktree restore-root substitution, tree.go:193-208, already folds worktree sessions into their origin path). `TreeProject.Key` becomes a slug of the full path (`<basename>-<8-hex sha256(path)>` — readable and collision-*resistant*, not "collision-free"; every destructive use is therefore path-validated, see Delete). `Name` stays the basename for display; the client disambiguates co-basename projects with a parent-dir hint from `WorkingDir`. Project archive decisions write path-keyed IDs; legacy basename-keyed rows are honored on read as a fallback matching any project with that basename, and an explicit path-keyed row always wins over a legacy row (round-2 fold: precedence stated). **The orphan-live grouping path in `handleAPITree` (web_api_tree.go:74-105) is rewritten onto the same rules** — today it groups by `filepath.Base(le.WorkingDir)` with the legacy slug and no worktree substitution (round-2 A10); `"(no project)"` gets the defined key `no-project`.

**Tree JSON.** `/api/tree` (hubapi.TreeResponse) grows additive fields. Its consumers are the new web sidebar and notifications.js's baseline fetch — **not the TUI**, which builds its dashboard from appwire `ThreadList` (`fetchHubTree`, hub_commands.go:147-154). TreeResponse: `+NeedsYou []TreeNode`, `+Favorites []TreeNode`, `+ArchivedProjects []TreeProject`, `+TestRuns []TreeProject`. TreeProject: `+RollupLive/+RollupAttn int`, `+DefaultExpanded bool`, `+MoreCurrent/+MoreRecent/+MoreArchived int`, `+Worktrees int`. TreeNode: `+Tier string`, `+Branch string`, `+ClusterCount int`, `+Favorite bool`. **Cluster nodes get a stable synthetic ID** (`cluster:<8-hex sha256(title)>`, scoped by their project) — today they ship with an empty ID (tree.go:768-777), which under row keying would collide every pair of clusters in a project into the RowID `project:<key>:` (round-2 A7/B4; refs.go:25-30 renders an empty ref as ""). Cluster members already ride `Children`. Subagent children gain the same per-tier 50-cap as top-level rows. Collapsed projects ship rowless — **response shaping happens post-memo**, so `/api/tree/project?key=` is served by indexing the memoized full tree, not by re-running a fresh full-meta scan per expand (round-2 A4: `BuildProjectTreeAt` filters all metas and reruns `BuildTreeAt` per call, tree.go:685-695 — with per-expanded-project refetch on every resync that would have re-imported the exact O(all-metas) cost the memo removes). Web ages render client-side from `UpdatedAt`; the memoized tree still carries `Age` strings up to one time-bucket stale (round-2 A6 — the v2 "never caches volatile strings" claim was false as stated; the bucket bounds it and the web ignores them).

**Renderer** (sidebar.js rewritten). Hand-rolled keyed reconciliation — **nodes keyed by the server's scope-qualified `RowID`** (`scope:projectKey:ref`, web_api_tree.go:384-387), never by bare session ID: the same session legitimately appears in Needs-you *and* its project tier (and Pinned), and bare-ID keying cannot hold duplicate keys in one tree (round-2 B3). Type+key match patches in place; unchanged keys keep DOM node identity, so hover state, open menus, transitions, and scroll geometry survive updates by construction. Client model: tree data + expansion set + lazy-children cache + fetch sequence counter + pending-mutation overlay (below). Rows remain real `<a href>` links keeping their htmx workspace-swap attributes — the renderer calls `htmx.process()` on newly created nodes; active-row marking and active-project auto-expand are reimplemented against the model, driven off `htmx:afterSwap` on `#workspace`. `aria-expanded` on all toggles; first paint renders skeleton rows immediately. If a reconcile removes the row anchoring an open ⋯ menu, the menu closes deliberately and focus moves to the nearest surviving row. Expansion state is stored under the new path-derived keys with a one-time best-effort migration from today's basename-keyed `serf-hub.sidebar.expanded.*` entries — **run after the first tree render, not at page load** (the old→new mapping needs each project's path, which only the first payload provides; co-basename collisions copy the old value to all matching new keys; round-3 G4).

**Update contract.** Qualifying events: `thread/started`, `thread/closed`, `thread/status/changed`, `serf/job/started`, `serf/job/finished`, `serf/attention/changed`, connection-restored. Dropped: `item/*`, `turn/*`, `thread/queueChanged`. Honest instant-path: `serf/attention/changed`'s `changed[]` carries the coarse 4-value level (attention.go:51-62) and only fires on level transitions (:139-148) — it adjusts *existing* rows' attention tint and the badges instantly, nothing else; row creation/removal, tier membership, and 6-value state fidelity reconcile at the resync, ≤2s later. Everything else schedules a coalesced resync: ≥2s spacing, trailing, sequence-guarded, plus a 60s idle resync. On resync the client re-requests children for projects *it* has expanded (served from the memo, above). **Auto-namer titles are an un-evented fact and excluded from the ≤2s claim** (round-3 H4): the namer only writes meta, no notification exists, and `/api/tree` reads `AllMetas()`, refreshed by the 60s rebuild ticker — a fresh session's generated title is bounded by that ticker, exactly as today (pre-existing staleness, not a regression; `PastIndex.UpdateMeta` is the future hook if a push is ever wanted).

**Mutations & the pending overlay.** The sequence guard alone cannot protect optimistic updates (round-1 A3/B2). Every optimistic op enters a pending-ops map re-applied on top of every admitted resync until it completes — **with per-op completion predicates (round-2 A3)**: mutation-type ops (favorite, rename) complete when a resync reflects the changed field; disappearance-type ops (archive, delete) complete on POST 2xx, because absence from subsequent payloads *is* their success state. **Every mutation POST-2xx also schedules an immediate coalesced resync** (round-3 H1 — favorite/rename fire no qualifying event, so without this the only confirming resync is the 60s idle one, and the 30s eviction would roll back every successful op with a false-error toast; archive-of-an-idle-session would visually revert the same way. Today's sidebar self-refreshes after its POST — sidebar.js:361-369 — and the rebuild keeps that behavior. The store-write inputs-version bump and rename's `UpdateMeta` guarantee that post-POST resync reflects the op). The 30s eviction remains as a safety net only; eviction or POST failure rolls back with a toast.

**Server.** One memoized tree: **`BuildTree` plus the attention *summary*** compute once per (inputs-version, 30s time bucket); response shaping and volatile derivations happen post-memo. **The watcher stays on its own fresh per-tick `DeriveAttention`** (round-3 H2): `handleAPITree` discards the derived map and needs only the summary (web_api_tree.go:40), while the watcher *mutates* its map in place for wedge overrides (`ApplyWedgeOverride`, wedge.go:121-130) and `StaleActives` deletes recovered ids — sharing a cached map would corrupt badge state and permanently stick a transiently-wedged session on `error` (the roster reports it `active` throughout, so no inputs-version bump would ever heal it). The inputs-version is new plumbing: `PastIndex` gains a change hook **fired only when a rebuild observes an actual content delta** (round-3 G5 — `Find` full-rebuilds on any cache miss, past.go:432-443, and detail endpoints call `Find` on arbitrary ids, so an unconditional hook would let stale-link lookups bust the memo the redesign exists to add); the roster's `Watch` loop bumps on membership/state delta; archive/favorite store writes bump; `PokeAttention` bumps. **`PastIndex` also gains `UpdateMeta(id, meta)`** — a targeted upsert that **re-inserts the entry at its new sorted position and rewrites the affected `sort_rank` range** (round-3 H3: the title is a sort-key component, session_order.go:30-33, and `all` is order-maintained with FTS `sort_rank` encoding position — a single-row patch would leave search ordering stale until the next rebuild) — because no targeted refresh exists today and rename cannot afford a synchronous full `Rebuild()` on its response path (round-2 A5/B1). Remote sources move to an async cache (~30s + poke).

## Features

**Row menu (⋯).** One popover on chip-picker's positioning/dismiss/singleton patterns (dir-picker.js:7-72), keyboard navigation, ≥24px reveal button. Session rows: Open, Open beside, Favorite/Unfavorite, Rename, Archive/Unarchive. Project rows: New session, Settings, Archive/Unarchive, Delete…. Rename shows only when the row's source supports it (capability below).

**Favorites.** New `favorite` table cloned from the archive store's shape, kind="session"; `POST /api/favorite` mirrors `/api/archive`. Both stores gain `Delete(kind, id)`. Pinned tier: unarchived favorited sessions, most-recent first, excluding sessions currently in Needs-you. Rows show ★ via `TreeNode.Favorite`; cross-tier appearances are distinct RowIDs by construction.

**Project delete.** `POST /api/project/delete {key, workingDir}` — the body carries the exact working directory and the server validates it against the key's current tree entry before acting (round-2 A11: never invert a lossy slug on a destructive path). The handler resolves the session set **from `PastIndex.All()`** — `[]PastEntry`, which carries each session's `StateDir` (past.go:22) — filtered to that `EffectiveWorkingDir`; `AllMetas()` strips StateDir and cannot yield file paths (round-2 A1), and the rendered tree's 50-per-tier caps would orphan overflow (round-1 A5/B4). Per session, in a loop: re-check liveness immediately before removal **via the probe-resolved `Roster.Find`** — not the rendezvous file's `SessionID`, which goes stale after `POST /clear` (roster.go:22-35; round-2 A9) — abort that session's removal on a genuine resume, then delete `sessions/<id>.meta.json`, `sessions/<id>.transcript.jsonl`, **`sessions/<id>.log.jsonl`** (the namer/plugin/hook log sibling — session_namer.go:382, session_init.go:1007,1046; round-2 B2), and the `sessions/<id>/` directory; scrub that session's archive+favorite rows. After the loop: **scrub the `("project", path)` archive/favorite decision rows** — otherwise a lingering archived-project decision silently hides any future project recreated at the same directory (round-2 B7) — **and the legacy `("project", basename)` row when no other project currently shares that basename** (round-3 G3: the read-fallback would otherwise re-hide the recreated project through the legacy row, defeating B7's own guarantee). The same lifecycle rule applies to un-archive: writing `(path, false)` also deletes a matching legacy basename row — visible-wins, which simultaneously un-shadows any co-basename projects the legacy row was silently archiving. Then remove now-empty per-session dirs and opportunistically the emptied bucket, then `PastIndex.Rebuild()` + `PokeAttention` (the rebuild is also the FTS scrub). Response: `{deleted: [refs], skipped: [{id, reason}]}`; if the currently-open workspace session is among deleted, the client redirects to `/new` with a notice. Whole-project fast-path 409 with names when anything is live at entry. `worktrees/` never touched; confirm states session and worktree counts.

**Test runs.** `schema.SessionMeta` gains `Origin string`, plumbed through the shared session-create path (`serf serve` and one-shot `serf run`). Classification: a project lands in "Test runs (N)" iff it has ≥1 session and every session carries `Origin=="test"`; a hub-spawned unmarked session deliberately reclassifies the project (hiding real work is the worse failure). **TestRuns takes precedence over ArchivedProjects** when a stale all-test project satisfies both (round-2 B6). Group offers per-project Delete and "Delete all test runs". The agentic-testing recipe exports the marker; the unmarked backlog is cleared via a one-time local script driving the delete endpoint.

**Rename.** New appwire method `serf/thread/name/set` — **with its `appwire.Methods` catalog entry, regenerated `docs/appwire-protocol.md`, and a `Rename` capability on `ThreadCapabilities`** (both routers are catalog-cross-checked; no rename capability exists anywhere today — round-2 B5). **The client-facing gate is a resolved per-row `Rename bool` on `hubapi.TreeNode`** (round-3 G2: the sidebar renders from `/api/tree`, and neither `hubapi.TreeNode` nor `hubapi.SessionCapabilities` carries any rename bit — `hubCapabilitiesFromAppwire` is a field-by-field copy that would silently drop an appwire-only addition, and the tree build never performs the per-thread `ReadThread` that carries `ThreadCapabilities`). Resolution is source-kind-derived, not per-daemon-probed: local rows → true (ended always renameable via the hub path; live serf daemons via the method), Codex-bridged rows → false. A legacy live daemon that 404s the method surfaces a "daemon too old" toast — the hub never falls back to editing a *live* session's meta file. Live path: the daemon sets `Name`/`NameSource="user"`/`NameUpdatedAt`, persists meta, **and updates the in-memory `s.naming.{value, source}` under `s.mu`** — the auto-namers gate on the in-memory state (`shouldNameFromCompaction` returns true while the source reads "prompt", session_namer.go:294-301), so a meta-only write still gets clobbered by the next compaction (round-2 A8). The hub, on the daemon's 2xx, applies `PastIndex.UpdateMeta` + memo bump before responding (round-1 A2, mechanism corrected round-2). Ended path: the hub edits the meta file **behind the same probe-resolved `Roster.Find` re-check immediately before the write** — a bare not-live check reintroduces the resume race as a lost update (round-2 A2); if the session turns live, the hub routes through the daemon method instead — **and then applies the same `PastIndex.UpdateMeta` + memo bump before responding** (round-3 G1: v3 specified the refresh only for the live path, leaving the ended path's completion predicate unsatisfiable — the rename would roll back with a false-error toast at eviction while the file sat silently edited, surfacing only at the next unrelated rebuild). Both namer launch sites skip when the naming source is `"user"`. UI: menu → inline edit (Enter commits, Esc cancels).

**Typography & density.** 11px floor; `--text-dim` banned below 12px; row meta 11px on a ≥4.5:1 pairing verified in both themes; whole project header becomes the toggle target (buttons `stopPropagation`); ≥24px hit boxes on all sidebar controls at desktop; subagent rows and the "Completed (N)" toggle ≥24px; title 13px and 2-line clamp stay.

## Error handling

Resync failure keeps the last good model rendered; sequence guard + pending overlay make reordered responses harmless including across mutations. Delete is idempotent per file, reports partial failures without aborting, and always ends in a rebuild. Rename on a just-ended session races safely (live path 404s at the daemon; client retries via the hub path after resync); the ended path's pre-write re-check closes the reverse race. Sources without the Rename capability simply never show the menu item.

## What survives

Tier semantics and windows, the archive store + `/api/archive` (plus new `Delete`), event delegation, rail mode, resizer, `serf/attention/changed` as the badge authority. localStorage expansion state survives via the one-time key migration.

## Out of scope

TUI adoption of tiers/favorites/menu (it reads appwire `ThreadList`, not `/api/tree`); drag-reorder of Pinned; multi-select bulk operations; per-session delete; a custom confirm modal; right-click context menus; list virtualization.
