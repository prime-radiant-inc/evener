# Sidebar Rebuild & Thread Management — Design (v2)

Date: 2026-07-04 (v2 after adversarial round 1: A 11 / B 11, tie — all 22 findings legitimate, 16 distinct, all folded)
Status: Draft — awaiting Jesse's spec review
Workstream: 3 of 6 from the 2026-07-03 web-UI UX diagnostic. Mandate: "nothing is sacred; good is better than keeping back-compat."

## Problem — each symptom, mechanized

- **Slow.** The sidebar is one htmx element re-fetching the entire server-rendered tree and replacing its whole DOM (app.html:36-41) on an 11-event allowlist that includes `item/started`/`item/completed` (sidebar.js:287-309) — every tool call in a watched session rebuilds the sidebar behind a 50ms debounce (sidebar.js:277-285). Server side has no cache: every request re-sorts/re-classifies every indexed session including archived (tree.go:285-673); `BuildTree` runs independently at two sites (handleSidebar, handleAPITree) and `DeriveAttention` at two (handleAPITree, the attention watcher) with nothing shared; a configured Codex remote source costs a synchronous network hop per render (web_api_tree.go:132-155).
- **Content disappears; expansion lost.** Non-live projects ship empty children every render (sidebar.html:114); a manual expand lazy-fetches rows (sidebar.js:116-142); the next full swap discards them and only the active session's project ever auto-refetches (sidebar.js:92-106). Latent races compound it: no `hx-sync`/in-flight guard (stale response overwrites newer), and the disclosure snapshot is one shared unscoped variable (sidebar.js:211).
- **Flashes.** "loading…" text on first paint — the sidebar is hard-excluded from the skeleton system (skeleton.js:15-20); every refresh destroys and recreates all row nodes; scroll offset survives by accident while content shifts under it.
- **Hard to read; bad hit targets.** 10px metadata on the two lowest-contrast tokens (`--text-dim` ≈2.9:1 fails AA, `--text-muted` ≈4.7:1 borderline; style.css:4-30, 69-76); the chevron's clickable box is ~12px because a documented desktop override strips the 32px tap-min (style.css:687-692) and the fixing rule is dead CSS — the template never applies `.btn-icon` (sidebar.html:77-78 vs style.css:711-724); subagent rows ≈17px tall.
- **Latent identity defect (round-1 A1/B1):** projects are keyed by `filepath.Base(workingDir)` (tree.go:211-217, grouping at :341), so `/a/foo` and `/b/foo` merge into ONE node whose WorkingDir is "first non-empty seen" (:349-353) — and project archive decisions key on that basename too (tree.go:503), so archiving "foo" archives both today. Any name-keyed destructive verb inherits this. v2 fixes identity itself (below).
- Also: sidebar.js's own header comments are false on three counts (dead stagger path, wrong trigger description; sidebar.js:6-10, 170-177) — the rebuild deletes them.

## Decisions

1. **Client-rendered, keyed (Jesse, 2026-07-04).** The sidebar stops being an htmx partial; data is the state, the DOM is a projection. The Go sidebar templates and `/_partials/sidebar{,/project}` routes die.
2. **Rename in scope, daemon-truth (Jesse, 2026-07-04).** `serf/thread/name/set`; `NameSource` gains `"user"`; both auto-namer paths skip user-named sessions.
3. **Project identity = full working directory (v2, forced by round 1).** Basename becomes display-only; keys, decisions, and delete all bind to the path.
4. Carried: project-level delete only; no name-prefix matching for test runs (2026-06-17 spec's successor — a first-class origin marker — is what ships); pinned tier below needs-you; native `confirm()` for delete in v1.

## Foundation

**Project identity.** `BuildTree` groups by `EffectiveWorkingDir` (full path; the existing worktree restore-root substitution, tree.go:193-208, already folds worktree sessions into their origin path). `TreeProject.Key` becomes a slug of the full path (`<basename>-<8-hex sha256(path)>` — readable, collision-free); `Name` stays the basename for display, and the client disambiguates co-basename projects with a parent-dir hint from `WorkingDir`. Project archive decisions write path-keyed IDs; legacy basename-keyed rows are honored on read as a fallback matching any project with that basename (existing archived state survives; new decisions override). This cures the pre-existing archive-both defect and makes every project-scoped verb collision-safe.

**Tree JSON.** `/api/tree` (hubapi.TreeResponse) grows additive fields. Its consumers are the new web sidebar and notifications.js's baseline fetch — **not the TUI**, which builds its dashboard from appwire `ThreadList` (`fetchHubTree`, hub_commands.go:147-154; round-1 A10 corrected the v1 claim). TreeResponse: `+NeedsYou []TreeNode`, `+Favorites []TreeNode`, `+ArchivedProjects []TreeProject`, `+TestRuns []TreeProject`. TreeProject: `+RollupLive/+RollupAttn int`, `+DefaultExpanded bool`, `+MoreCurrent/+MoreRecent/+MoreArchived int`, `+Worktrees int`. TreeNode: `+Tier string`, `+Branch string`, `+ClusterCount int`, `+Favorite bool`. Subagent children gain the same per-tier 50-cap as top-level rows (today uncapped in every payload, tree.go:400-454). Collapsed projects ship rowless; `/api/tree/project?key=` returns one project's rows. Web ages render client-side from `UpdatedAt` (live-ticking; the server `Age` string stays for other consumers but the memo below never caches volatile strings).

**Renderer** (sidebar.js rewritten). Hand-rolled keyed reconciliation — nodes keyed by project key / session ID; type+key match patches in place; unchanged keys keep DOM node identity, so hover state, open menus, transitions, and scroll geometry survive updates by construction. Client model: tree data + expansion set + lazy-children cache + fetch sequence counter + **pending-mutation overlay** (below). Rows remain real `<a href>` links keeping their htmx workspace-swap attributes — the renderer calls `htmx.process()` on newly created nodes; active-row marking and active-project auto-expand (today syncActiveRow, sidebar.js:652-692) are reimplemented against the model and driven off `htmx:afterSwap` on `#workspace` as today. `aria-expanded` on all toggles; first paint renders skeleton rows immediately. If a reconcile removes the row anchoring an open ⋯ menu, the menu closes deliberately and focus moves to the nearest surviving row (round-1 B8). Expansion state is stored under the new path-keyed IDs with a one-time best-effort migration from today's basename-keyed `serf-hub.sidebar.expanded.*` entries (round-1 B9 — the v1 "same keys" claim was false).

**Update contract.** Qualifying events: `thread/started`, `thread/closed`, `thread/status/changed`, `serf/job/started`, `serf/job/finished`, `serf/attention/changed`, connection-restored. Dropped: `item/*`, `turn/*`, `thread/queueChanged` — none carries anything the sidebar renders. **Honest instant-path (round-1 A6/B7):** `serf/attention/changed`'s `changed[]` carries the coarse 4-value level (attention.go:51-62) and only fires on level transitions (:139-148) — so it adjusts *existing* rows' attention tint and the badges instantly, and nothing else: row creation/removal, tier membership, and full 6-value state fidelity (awaiting-vs-warning, idle-vs-ended) reconcile at the resync, ≤2s later. Everything else schedules a coalesced resync: ≥2s spacing, trailing, sequence-guarded, plus a 60s idle resync. On resync the client re-requests children for projects *it* has expanded — expansion is client-truth, so the lazy-children hole cannot exist.

**Mutations & the pending overlay (round-1 A3/B2).** The sequence guard alone cannot protect optimistic updates — a resync dispatched *before* a mutation but landing after it carries a higher sequence and stale truth. Fix: every optimistic op (favorite/archive/rename/delete) enters a pending-ops map re-applied on top of every admitted resync until confirmed (the POST succeeded and a subsequent resync reflects it) or rolled back (POST failed → revert + toast). Tested with exactly the pre-mutation-in-flight race.

**Server.** One memoized tree: `BuildTree`+`DeriveAttention` compute once per (inputs-version, 30s time bucket) — the bucket bounds wall-clock staleness for tier windows and rollups (round-1 B3: a version-only memo would freeze Current→Recent→Archived transitions and ages on a quiescent host); volatile per-request strings are computed post-memo. **The inputs-version is new plumbing, stated as such (round-1 A4/B5):** `PastIndex` gains a change hook fired by every `Rebuild()` including the implicit one inside `Find` (named to avoid colliding with the existing worker→observer `observers` map, past.go:44-50); the roster's `Watch` loop bumps on membership/state delta; archive/favorite store writes bump; `PokeAttention` bumps. Every consumer (`/api/tree`, the watcher) reads the memo. Remote sources move to an async cache (~30s + poke); no tree request ever blocks on a network hop.

## Features

**Row menu (⋯).** One popover on chip-picker's positioning/dismiss/singleton patterns (dir-picker.js:7-72), keyboard navigation, ≥24px reveal button. Session rows: Open, Open beside, Favorite/Unfavorite, Rename, Archive/Unarchive. Project rows: New session, Settings, Archive/Unarchive, Delete…. The hover-only archive box dies; archive keeps its endpoint and optimistic dimming.

**Favorites.** New `favorite` table cloned from the archive store's shape (archive.go:48-55), kind="session"; `POST /api/favorite` mirrors `/api/archive`. Both stores gain the `Delete(kind, id)` they lack today (`Set`/`Decisions` only — round-1 A7/B6), used by project delete's scrub. Pinned tier: unarchived favorited sessions, most-recent first, excluding sessions currently in Needs-you (no duplicate rows). Rows show ★ via `TreeNode.Favorite`.

**Project delete.** `POST /api/project/delete {key}` — the key resolves to a full working directory (Decision 3), and the handler resolves the session set **from the uncapped meta index** (`AllMetas` filtered to that `EffectiveWorkingDir`), never from the rendered tree — the tree's 50-per-tier caps would silently orphan overflow sessions in exactly the >50-session residue projects this feature targets (round-1 A5/B4). Per session, in a loop: **re-check liveness immediately before removal, corroborated by the rendezvous record (SessionID match), not bare PID** — `processAlive` is `Kill(pid,0)` (roster.go:91-96), and a recycled PID must not block deletion forever while a genuine resume mid-delete must abort that session's removal (round-1 A9; the residual race — a daemon starting during the loop — is surfaced by the trailing rebuild and reported as partial). Then delete `sessions/<id>.meta.json`, `.transcript.jsonl`, and the `sessions/<id>/` directory, each path from that session's own indexed StateDir; scrub archive+favorite rows via the new store `Delete`; then `PastIndex.Rebuild()` + `PokeAttention` — **the rebuild is also the FTS scrub** (FTS supports only wipe-and-rebuild, past.go:216-264; a per-row FTS delete does not exist and is not needed). Whole-project refusal remains for the fast path (any live session → 409 with names). `worktrees/` is never touched; the confirm states session count and worktree count. **The response lists deleted session refs; if the currently-open workspace session is among them, the client redirects to `/new` with a notice** (round-1 A11).

**Test runs.** `schema.SessionMeta` gains `Origin string` (`origin,omitempty`), plumbed through the **shared session-create path so both `serf serve` and one-shot `serf run` honor `SERF_SESSION_ORIGIN`** (round-1 B10). Classification rule, stated: a project lands in the collapsed "Test runs (N)" group iff it has ≥1 session and *every* session carries `Origin=="test"` — a hub-spawned unmarked session deliberately reclassifies the project into the normal list, because hiding real work is the worse failure. Group offers per-project Delete and "Delete all test runs". The agentic-testing recipe exports the marker. Existing unmarked backlog: one-time local script driving the delete endpoint, provided to Jesse, not shipped.

**Rename.** `serf/thread/name/set` for live sessions — daemon sets `Name`/`NameSource="user"`/`NameUpdatedAt`, persists meta — **and the hub, on the daemon's 2xx, refreshes that session's entry in the past index and bumps the memo before responding** (round-1 A2: without it, `AllMetas` stays stale until the 60s rebuild ticker, main.go:229-240, and the first resync visibly reverts the rename for up to a minute). Ended sessions: hub edits the meta file directly, guarded by a not-live check, then rebuild. Both namer launch sites (session_namer.go:186,223) skip when `NameSource=="user"`. UI: menu → inline edit (Enter commits, Esc cancels).

**Typography & density.** 11px floor; `--text-dim` banned below 12px; row meta 11px on a ≥4.5:1 pairing; whole project header becomes the toggle target (buttons `stopPropagation`); ≥24px hit boxes on all sidebar controls at desktop; subagent rows and the "Completed (N)" toggle ≥24px; title 13px and 2-line clamp stay.

## Error handling

Resync failure keeps the last good model rendered; the sequence guard plus pending overlay make reordered responses harmless including across mutations. Delete is idempotent per file, reports partial failures without aborting, and always ends in a rebuild. Rename on a just-ended session races safely (live path 404s at the daemon; client retries via the hub path after resync). Old daemons: rename method absent → menu item hidden for that source.

## What survives

Tier semantics and windows (currentWindow/archiveWindow/50-cap), the archive store + `/api/archive` (plus new `Delete`), event delegation, rail mode, resizer, `serf/attention/changed` as the badge authority. localStorage expansion state survives via the one-time key migration.

## Out of scope

TUI adoption of tiers/favorites/menu (it reads appwire `ThreadList`, not `/api/tree` — untouched by construction); drag-reorder of Pinned; multi-select bulk operations; per-session delete; a custom confirm modal; right-click context menus; list virtualization (payload caps + keyed reconciliation suffice at current scale).
