Tasks panel — redesign mockups

Real data: session local:0343wE3LB14m5xoC2CBMiD (recoverable tool output), 20 tasks, 16 done, snapshot 2026-08-09 13:02 PDT. Timestamps use the wire's created_at / updated_at / completed_at, which the current parser drops.

Current (baseline)

What ships today. Every expanded field is a stacked caption-over-mono pair at full width — five fields ≈ ten lines before notes. Collapsed rows carry no signal about recency or updates.

A — Live rows (recommended base)

Collapsed: two-line rows — title + relative time on line one, latest update excerpt on line two. Expanded: one wrap-able meta strip (type · reasoning · deps), one timestamps line, prompt behind its own fold, updates as a timeline with the latest marked. Trade-off: rows are two lines instead of one, so the collapsed list is taller — but every row now earns its height.

B — Dense grid

Collapsed: strict single-line rows (a ¶ marks tasks with updates). Expanded: a two-column label/value grid — roughly half the vertical cost of today's stacked list. Trade-off: the least air; long prompts and notes squeeze into the value column, and the latest update is invisible until expanded.

C — Focus groups

A's rows, grouped by status: in-progress up top, open next, the 16 done behind one collapsed line. The live 20% of the list stops drowning in settled history. Trade-off: creation order is lost (ids jump within groups), and "what happened recently" across statuses needs the done group opened. Compose-able with A.

FINAL — Live rows + focus groups

Chosen direction: A's two-line live rows, grouped C-style — in-progress up top, open next, settled (done + cancelled) behind one collapsed line. The prompt is a session-style inline disclosure: Prompt ▸ then however much of the prompt fits on the line; opening reveals the full text below. Expanded rows keep the meta strip, timestamps line, and updates timeline. Settled rows stay single-line so history costs one line per task.
