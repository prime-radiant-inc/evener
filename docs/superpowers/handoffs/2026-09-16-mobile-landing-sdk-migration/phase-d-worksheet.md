## Established shapes (read these before briefing any row)

- **Framework-free store factory (C3, `appwire-client/typescript/keybindingRegistry.ts` on #1448):** `createKeybindingsRegistry(parse)` returns `{ getState, getInitialState, setState, subscribe, parseKeybinding }`; state holds the actions as methods; `setState` shallow-merges and notifies every subscriber; `getInitialState` is there so zustand's `useStore`/`useSyncExternalStore` bind without the package importing either. The web's one instance lives in an app file (`src/keybindings/appRegistry.ts`, 11 lines: `createKeybindingsRegistry(parseKeybinding)`); native builds its own in `keybindingRules.ts:51`. **Every D row's core is this triple plus store-bound actions; each app owns one instance in an adapter file.**
- **Injected port (C3 `keybindingChord.ts:25`):** `type KeybindingParser = (s: string) => readonly KeybindingPress[]`; tinykeys satisfies it structurally. Same move for `localStorage`, `fetch`, `location.reload`, `crypto`, schedulers.
- **Narrow client port (`activityList.ts:14`):** `type ActivityClient = Pick<AppwireClient, "request" | "onNotification">`. `AppwireClientLike` (`clientLike.ts:14`) is `request`+`onNotification` typed off `AppwireClient`, so it satisfies every such Pick. All 15 native twins currently type their client as `ConversationClientLike` from `mobile/src/services/conversation.ts:54` (`request`, `onNotification`, optional `forceStop`/`resumeThread`) — a package module cannot import that, so each row swaps to a Pick (D1's plan text already says so).
- **D30 spec in the plan** is the template for a store row: core factory + pure helpers in the package, web adapter keeps the old path and hook, native adapter file, isolation test with two instances, old test stays the oracle.
- **Publication rule (plan, phase D header):** `tsconfig.build.json` `files` entry (arms reachability, #1224 closed) + reachable from `index.ts` or a declared subpath + a qualification smoke/type-use entry. A module missing any of the three passes the gate silently.
