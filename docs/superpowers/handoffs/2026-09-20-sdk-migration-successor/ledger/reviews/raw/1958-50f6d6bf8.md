## Issues found

**Severity: low** — `agent/session_ask_test.go:3969` (test comment on `TestRoundEntryResolvesAskBoundary_SkipsBookkeepingTurnsToFindTheRealEntry`)

The comment lists "an unrelated non-carrier TurnFailure" among the non-decisive bookkeeping kinds that `roundEntryResolvesAskBoundary` should walk past. The implementation does the opposite: `roundEntryResolvesAskBoundary` (`agent/session_tools_ask.go:437`) treats `schema.TurnFailure` as entry-capable and returns `turnResolvesAskBoundary`'s verdict — `false` for a non-carrier failure — stopping the entry walk there. The function's own doc comment (`session_tools_ask.go:422`) and the code agree; only the test comment is inconsistent.

This is not a code bug — the code is in fact correct and the comment is wrong. Stopping at a non-carrier `TurnFailure` is load-bearing: a failed drained steer must not make a later generic completion appear to have resolved the pending ask. The current "stop and return false" makes the outer scan continue and correctly accumulate the ask.

Suggested fix: correct the comment to state that a non-carrier `TurnFailure` is deliberately entry-capable and must not be treated as transparent pass-through, and add a test exercising the interleaved failure shape so the behavior is pinned rather than only documented.
