## Summary

The series extends native offline draft handling in three ways:

1. **`appwire-client`**: extracts the draft-field projection shared by `restoreDraft` into an exported `decodeKeybindingDraftFields`, and adds a value-returning `readDraftOutcomeWithValue` that classifies a draft port in one guarded read.
2. **`mobile-native/nativePreferenceDrafts.ts`**: replaces the string-tagged `storedNull`/`unparseable` sentinels with symbol brands (which JSON.parse can never reproduce, closing the collision the old string tags allowed), extracts the production storage backend into `rawStringDraftBackend`/`RawStringStorage` so tests exercise the same parse/identity logic, and adds `draftUnreadableAfterDiscard`.
3. **`NativePreferencesProvider`**: adds an independent cold-offline probe (`offlineDraftUnreadable`, `offlineStorageUnavailable`) plus `discardUnreadableKeybindingsDraft`, which uses the store-free `discardStoredKeybindingDraft`, re-reads to classify what is actually there now, and nudges a live model's own recovery seam when a live store classified the same record.

The tests cover the offline probe, stored-null, unreadable-record discard, storage failure, readable-replacement refusal, live reclassification, and hub-switch reset. I found no high- or medium-severity defects: the nudge path is safe (the live store's CAS refuses to remove a record it did not classify, and `assertDiscardable` rejects a genuine port failure), the symbol brands are not JSON-reproducible, and the transcript path still rejects the unparseable marker through `validateCheckpoint`.

**Low** — `decodeKeybindingDraftFields` has no production caller
File: `appwire-client/typescript/keybindingsStore.ts:432` (exported at `index.ts:226`)
The commit message says the point of this extraction is to share "draft classification and decoded fields," but the only in-repo reference is the new unit test. `NativePreferencesProvider` imports `discardStoredKeybindingDraft`/`isReadableKeybindingDraft` but never the decoder, so the exported projection changes no runtime behavior. If the intent was for an offline caller to render a readable stored draft, that caller is not wired; the public API now advertises a projection nothing consumes. Either wire it into the offline path that needs decoded fields, or defer exporting it until there is a caller (a shipped root export is hard to remove later). No functional harm today, but the series' stated sharing goal is not met.

**Low** — Provider doc references a snapshot field that does not exist
File: `mobile-native/src/NativePreferencesProvider.tsx:43-45`
The `offlineDraftUnreadable` JSDoc says it is "Superseded by `snapshot.keybindings.draftUnreadable` the moment a model publishes." `NativePreferencesSnapshot.keybindings` is `PreferenceState<ConfirmedKeybindings>`, which exposes `storageUnavailable` but no `draftUnreadable` (`keybindingsDomain` in `nativePreferences.ts` drops the store's `draftUnreadable` flag). A consumer following this doc cannot compile against the named field, and the only live signal available conflates an unreadable record with a genuine port failure. Suggested fix: correct the comment to name `storageUnavailable`, or project `draftUnreadable` through `keybindingsDomain` if the live "Discard unreadable draft" distinction is meant to be visible while connected.

So the user-facing "discard unreadable draft while offline" action this series builds is not reachable in the app. If the series is intentionally provider-scoped, this is fine; otherwise the screen wiring is the missing half of the feature.
