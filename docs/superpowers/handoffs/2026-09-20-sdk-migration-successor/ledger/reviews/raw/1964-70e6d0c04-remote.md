## Summary

The series reworks how the native app classifies and reports a stored keybindings draft. It replaces the ad-hoc draft backend in `NativePreferencesProvider` with the shared `rawStringDraftBackend`/`parseDraftBytes` implementation, adds an "unreadable record vs. genuine port failure" distinction (`draftUnreadable`, `offlineDraftUnreadable`, `offlineStorageUnavailable`), adds a store-free discard (`discardUnreadableKeybindingsDraft`) and a retained-snapshot reconciler (`reconcileRetainedDraftProjection`) so a snapshot from a previous client reflects what is actually stored, and splits keybindings diagnostics into `draftError`/`hubError`/`loadError` so a draft-sourced error no longer erases a hub-sourced one. Tests cover the offline probe, discard, retained reconciliation, and diagnostic ownership.

## Issues

**Medium — Intent-implementation gap: the offline draft recovery added here is unreachable from any screen.**

`mobile-native/src/NativePreferencesProvider.tsx:49-65` and `168-292` add `offlineDraftUnreadable`, `offlineStorageUnavailable`, and `discardUnreadableKeybindingsDraft`, and the field comment explicitly says it "lets the 'Discard unreadable draft' action render before any hub has answered." No consumer exists: a repo-wide search finds these identifiers only in the provider and its new test. `KeybindingPreferencesScreen.tsx` reads `preferences.snapshot?.keybindings` (line 91), but on a cold offline start `snapshot` is `null` (the model publishes only after a ready handshake), so the screen renders only the `Loading keyboard shortcuts` spinner (`!domain || domain.loading`) and `ErrorMessage` gets `null` (line 170). Its "Discard changes" action (line 329) is gated on `domain?.draft`, and an unreadable record has `draft: null`, so even a retained snapshot offers no discard path.

Concrete harm: with no connection and a corrupt local draft — precisely the scenario these commits target — the Shortcut settings screen shows an indefinite spinner with no explanation and no way to recover, so the feature added by this series has no user-facing effect.

Suggested fix: in `KeybindingPreferencesScreen`, derive `const unreadable = domain?.draftUnreadable ?? preferences.offlineDraftUnreadable;` and, when `unreadable` and no live model is available, render a "Discard unreadable draft" action that calls `preferences.discardUnreadableKeybindingsDraft()` (surfacing `offlineStorageUnavailable`/`"storageUnavailable"` distinctly from a successful removal).
