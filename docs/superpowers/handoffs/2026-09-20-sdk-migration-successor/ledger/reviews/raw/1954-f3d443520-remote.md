## Summary

The two commits extend the extension-store list fence (`writeRevisioned`) with an optional `onFailure` handler, and use it in `removeMarketplace` to reconcile state from the hub's `marketplaceUnregisteredCloneRemains` rejection's `data.applied` payload (the unregister already landed; only clone deletion failed). The handler is gated by the store's `generation` so a reset/dispose/replaced connection still publishes nothing, and the `onFailure` writer carries the same browse-catalog retirement the success path does. Tests cover applied reconciliation, `appliedUnavailable`, plain failures, reset fencing, and older/newer write orderings.

I verified the wire shape against the Go side (`appwire/types.go`'s `MarketplaceUnregisteredCloneRemainsData`, `cmd/evener-hub/app_plugins.go`): `listMarketplaces` always returns a non-nil slice (`make([]MarketplaceEntry, 0, …)`, so an empty list serializes as `[]`, not `null`), while `AppliedUnavailable` leaves `Applied` as the zero value with `marketplaces: null`, so the client's `appliedUnavailable`-first check and `Array.isArray` guard distinguish the two correctly. The new `onFailure` parameter is optional and leaves all other `writeRevisioned` callers' retract-on-failure behavior unchanged.
