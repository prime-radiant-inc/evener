## Summary

The single commit extracts the transcript-display cross-tab synchronization logic (BroadcastChannel messaging plus the `storage`-event fallback) out of `transcriptDisplay.ts` into a new, self-contained factory module `stores/transcriptDisplay/crossTabSync.ts`. The store now constructs a `BrowserSync` instance with injected `channelName`, `localKeys`, `getState`, `applyLocal`, and `onDetach` callbacks, and calls `browserSync.attach()` / `detach()` / `broadcastLocal()` in place of the previously module-local functions. The state-mutation logic that must remain coupled to the store (`publishEffectiveTransition`, effective-layer computation) stays in the store and is passed in via `applyLocalFromBrowserSync`.

The extraction is behavior-preserving: message validation (`isLocalMessage`), fingerprint checks, same-tab suppression via `sourceId`, malformed-value rejection, null-clears, and the `storage`-event layout derivation (`endsWith(".mobile")`) are all carried over verbatim. Existing behavioral tests in `stores/transcriptDisplay.test.ts` exercise the sync paths through the public store API and continue to cover the moved logic. No file in the diff references removed symbols, and `localKeys` is correctly satisfied by `LOCAL_KEYS` (`Record<ViewportClass, string>`); the `isLayout`/layout-key helpers duplicated between the two modules are trivial and pre-existing in shape.
