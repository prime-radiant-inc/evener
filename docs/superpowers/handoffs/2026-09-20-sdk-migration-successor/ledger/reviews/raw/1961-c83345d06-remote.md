## Summary

The series fixes `mergeOlderItemPage` in the shared AppWire TypeScript reducer so that when an older item page is prepended, turn fragments are coalesced by *transitive* overlap rather than a single pass of first-match merging. Previously a fresh turn could link two groups that neither linked directly (e.g. `O1[x]`, `O2[y]`, `F1[y,z]`, `F2[z,x]`), leaving duplicate turns/items. The new `coalesceTurnFragments` builds overlap groups over original fragment identities, merges older fragments first (oldest as base, later older applied), then applies all fresh fragments in order so live state keeps precedence, and finally orders groups by first appearance (older groups before fresh-only groups). Three tests cover the transitive chain, fresh-only coalescing with field precedence, and fresh-field application after a chain.

I traced the algorithm against the prior implementation for non-transitive cases (ordering, precedence, older-only, fresh-only, transitive via older) and it is behavior-equivalent except where it intentionally merges additional transitively-connected groups. Item/turn merge precedence, ordering, and the `mergeToolCallsByCallId` post-pass are preserved. The new tests exercise real behavior (item membership, dedup count, turn id/usage precedence, group order), and the helper types line up with the generated wire types (`itemsView` required on `Turn`, `EvenerUsage.inputTokens` optional).
