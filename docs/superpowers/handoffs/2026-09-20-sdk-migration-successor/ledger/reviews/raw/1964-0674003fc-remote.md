## Summary

This series has three threads: (1) it factors the keybinding draft projection out of `restoreDraft` into `draftFieldsFrom`/`decodeKeybindingDraftFields` and exports the latter from the shared AppWire client; (2) it refactors the native draft backend into a shared, testable `rawStringDraftBackend` over a `RawStringStorage` and replaces the string-tagged `StoredNull`/`Unparseable` sentinels with symbol brands that `JSON.parse` cannot forge; and (3) it grows `NativePreferencesProvider` with offline/retained-draft recovery: an independent storage probe (`offlineDraftUnreadable`, `offlineStorageUnavailable`), a store-free `discardUnreadableKeybindingsDraft`, and `reconcileRetainedDraftProjection` for the snapshot of a superseded client, plus `draftError`/`hubError`/`loadError` on `KeybindingsPreferenceState`. The added tests are broad and exercise real failure/recovery paths.

The plumbing is internally consistent and the symbol-brand change is a genuine correctness fix (a stored `{}` or a checkpoint carrying a `kind` field can no longer be mistaken for a marker). I found one functional gap.

## Findings

**medium** — Unreadable keybinding drafts are still unreachable from the UI; the new offline recovery path has no consumer  
`mobile-native/src/NativePreferencesProvider.tsx:43-65` adds `offlineDraftUnreadable`, `offlineStorageUnavailable`, and `discardUnreadableKeybindingsDraft`, whose comment says it exists so the "Discard unreadable draft" action can render on a cold offline start. No code in `mobile-native` reads any of those three members (a grep over the tree finds only the definition and the provider's own tests). Worse, even the pre-existing live path can't reach it: `mobile-native/src/KeybindingPreferencesScreen.tsx:245` gates both "Save changes" and "Discard changes" behind `{domain?.draft && (`, but an unreadable record sets `draft` to `null` in both `restoreDraft` (`appwire-client/typescript/keybindingsStore.ts:737`) and `reconcileRetainedDraftProjection`'s `"unreadable"` case (`NativePreferencesProvider.tsx:102-111`).  
What goes wrong: a user whose stored keybindings draft fails to decode sees only the "Could not restore the saved shortcut draft. Check current shortcuts to retry." error with no way to clear the record — "Check current shortcuts" just re-reads the same corrupt bytes — and `busy` (`KeybindingPreferencesScreen.tsx:107`) keeps editing disabled indefinitely, online or offline. The store-level `discardDraft` and the new store-free discard are both capable of fixing this; nothing invokes them.  
Suggested fix: render a discard control when `domain?.draftUnreadable` (or the offline flags with no snapshot) is set, wired to `model.discardKeybindingsDraft()` when a live model exists and to `discardUnreadableKeybindingsDraft()` otherwise.

---

**low** — Duplicated restore-failure message literal can drift from the store's copy  
`mobile-native/src/NativePreferencesProvider.tsx:76` defines `DRAFT_RESTORE_FAILED_MESSAGE = "Could not restore the saved shortcut draft. Check current shortcuts to retry."`, a duplicate of the private `DRAFT_RESTORE_FAILED_MESSAGE` in `appwire-client/typescript/keybindingsStore.ts:269`, and the unreadable branch of `reconcileRetainedDraftProjection` (`NativePreferencesProvider.tsx:108`) uses it.  
What goes wrong: the retained/offline snapshot and the live store report the same condition through two independently maintained literals, so a future copy change in the store silently makes the retained projection show stale text.  
Suggested fix: export the message (or a `keybindingsDraftErrorMessage(...)` helper) from `keybindingsStore` and consume it here.
