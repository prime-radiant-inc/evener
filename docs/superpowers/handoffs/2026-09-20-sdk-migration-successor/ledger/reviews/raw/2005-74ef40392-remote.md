## Summary

The series makes interrupt handling durable and distinguishes two concepts that were previously conflated under `SteeringKindInterrupted`:

- The **admitted interrupt boundary** (the durable `SteeringKindInterrupted` marker) is now written through `appendSteeringTurnDurablyForOwner` *before* the pending ask is cleared and the session settles `Idle`; if that write fails, the pending ask and `Awaiting` state survive (the generic failure tail settles `turn_failed`/`Awaiting`), matching restore.
- The **streamed salvage explanation** (`settleInterruptedRound`) now carries the new `SteeringKindInterruptedSalvage`, so it no longer resolves the ask in the Go restore scan or the TypeScript `deriveAskQuestions`; the web label and generated wire types are updated, and tests cover write failure, retained-write adoption, and streamed salvage.
- Cancellation boundary settling was moved out of `processOneInput`'s `ctx.Done()` returns so the outer handler can admit the marker first.

The core production logic reads correctly: `finishProcessingAtBoundary` is transition-guarded, the failure tail runs for a joined marker error (the error text does not match `isProviderTerminalError`'s prefix), the retained (`ErrRetainedUnsynced`) case is adopted rather than rejected, and `endInputAtTurnFailure`'s `sessionEndEmitted` gate is reset at each input admission. I did not find a correctness bug in the Go lifecycle/session path.

## Issues

**Low — mobile-native was not updated for the new kind, so its "Interrupted" label disappears**
`mobile-native/src/timeline.ts:8-20` switches on `steeringKind` and returns a label for `"interrupted"` only; `"interrupted-salvage"` falls to `default: return undefined`. Before this series, the salvage explanation carried `"interrupted"`, so it rendered as a labeled, routine notice on mobile; now it becomes an unlabeled notice and `isInterruptedNotice` (`timeline.ts:38-45`) returns false, which also changes `timelineGap`'s routine classification (`timeline.ts:63`). The web sibling was given a label (`SteeringItem.tsx`: `"interrupted-salvage": "Interrupted draft"`), so this is a cross-platform parity regression, and the parametrized label test (`mobile-native/src/timeline.test.ts:122-138`) does not include the new kind, so nothing catches it. Concrete harm: mobile users lose the interrupt-draft label and compact spacing for the salvage explanation. Fix: add a `case "interrupted-salvage"` (e.g. `"Interrupted draft"`) to `steeringNoticeLabel`, decide deliberately whether `isInterruptedNotice` should include it, and add the kind to the test table.

---

**Low — the new TUI test does not exercise `interrupted-salvage` at all**
`cmd/evener-tui/question_overlay_test.go:107-121` constructs its fixture as `{Kind: transcript.MsgSteering, Text: salvage}` with no steering kind — `transcript.ChatMessage` (`internal/transcript/types.go:117`) has no `SteeringKind` field, and `pendingAskQuestions` (`question_overlay.go:114-129`) never inspects a kind. The "does not resolve" assertion therefore passes identically for any steering text and duplicates the existing `TestPendingAskQuestions_SteeringDoesNotResolve`; the `msgrender` assertion only confirms that steering text is rendered verbatim, which is also kind-independent. The test name/comment claim salvage coverage it cannot provide, giving false confidence if the TUI later becomes kind-aware. Fix: either drop the test as redundant (salvage resolution is covered by the Go restore test and `deriveAskQuestions.test.ts`) or extend the TUI transcript model to carry `steeringKind` and assert on it.
