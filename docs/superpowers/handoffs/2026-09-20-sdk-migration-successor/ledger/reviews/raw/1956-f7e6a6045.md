## Summary

The series adds offline recovery plumbing for the native keybindings draft: it moves draft parsing/identity comparison into a shared `rawStringDraftBackend` so production and tests exercise one implementation, brands stored-`null`/unparseable markers with symbols (making them unforgeable by parsed JSON), refactors `restoreDraft` through `draftFieldsFrom`, exports `decodeKeybindingDraftFields`/`readDraftOutcomeWithValue`/`draftUnreadableAfterDiscard`, and has `NativePreferencesProvider` probe the stored keybindings draft independently of connection state, exposing `offlineDraftUnreadable`, `offlineStorageUnavailable`, and `discardUnreadableKeybindingsDraft`. Tests cover the backend, markers, helpers, and the provider states.

The logic in the diff itself is coherent: the store-free discard (`discardStoredKeybindingDraft`) correctly degrades genuine port failures vs unreadable records, the follow-up re-read is used to decide the notice and whether to nudge a live model, the nudge condition avoids discarding a live model's already-readable draft, and the marker predicates are collision-safe.

## Findings

**Severity: medium** — Offline recovery state/action has no consumer, so the series' feature is unreachable in the app.

`mobile-native/src/NativePreferencesProvider.tsx:232-234` adds `offlineDraftUnreadable`, `offlineStorageUnavailable`, and `discardUnreadableKeybindingsDraft` to the context with comments stating they exist so the “Discard unreadable draft” action can render before any hub answers (e.g. lines 42-45, 95-97). But no production code reads them: a repo-wide search finds references only in `NativePreferencesProvider.tsx` and `NativePreferencesProvider.test.tsx`. `KeybindingPreferencesScreen.tsx:91-101` derives everything from `preferences.snapshot?.keybindings` and `preferences.model`, both null while offline, so the screen still renders no recovery action in exactly the cold-offline case the new probe is meant to cover. The user with a corrupt stored draft and no connectable hub remains stuck, which is the behavior the feature was added to remove. The same omission extends to `decodeKeybindingDraftFields` (`appwire-client/typescript/keybindingsStore.ts:432`), added and tested but never called by any production path, so the “share … decoded fields” half of the change never reaches an offline caller and can drift from `restoreDraft` unnoticed.

Suggested fix: wire a consumer (the keybindings screen or a shared banner) to prefer `snapshot.keybindings.draftUnreadable` when a model/snapshot exists and fall back to `offlineDraftUnreadable` when it does not, invoking `discardUnreadableKeybindingsDraft` in the offline path (and using `decodeKeybindingDraftFields` for any offline draft rendering). If the UI work is intentionally a follow-up, the provider fields/test-only additions would be better staged with that change rather than landing dead.
