**Problem**: The `foldWarningParams scans each stored warning string once` test spies on `RegExp.prototype.exec` and asserts the exact order of field scans (`["Title".length, "Hint".length, "Source".length]`). The order is an incidental artifact of how the object literal is constructed; reordering the internal field computations produces identical output and identical efficiency but fails this test.
**Fix**: Keep the scan-count invariant but drop the ordering constraint—use `expect(scannedLengths.slice().sort()).toEqual([...])` or just `expect(scannedLengths).toHaveLength(3)`.
