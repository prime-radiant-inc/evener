## Review Findings

- **Severity**: Medium  
  **Location**: `agent/session_lifecycle.go:2525-2528`  
  **Problem**: Direct user input clears pending asks after `appendUserInputTurnRefusingPoison` returns nil, but that helper treats some non-poisoned transcript write failures as success even when no record was written. The live session can therefore resolve the ask while restore still sees it pending.  
  **Fix**: Use a write path that distinguishes recorded/adopted writes from failed writes, and clear `askPending` only after the user turn is confirmed recorded.

---

- **Severity**: Medium  
  **Location**: `agent/session_tools_ask.go:98-129`  
  **Problem**: Live steering classification passes empty text evidence, while restore uses the turn text fallback. A legacy kindless, provenance-less human-note steer can clear the live pending ask but be treated as non-resolving after restart; the carrier pre-clear has the same issue.  
  **Fix**: Pass the steer text to `steeringAnswersAsk` and use the pending mutation’s input text when classifying a carrier.

---

- **Severity**: Medium  
  **Location**: `agent/session_lifecycle.go:1287`  
  **Problem**: Interrupt handling clears `askPending` before appending the interrupt marker, but the marker uses `recordTurn`, which publishes in-memory history before a non-durable transcript write and only warns on failure. If the write fails or is lost before sync, restore cannot recognize the interrupt and resurrects the ask.  
  **Fix**: Persist the interrupt boundary through a write-before-history durable path and handle persistence failure without claiming the ask was durably resolved.

## Summary

The change aligns ask-boundary handling across live execution and restore, but several failure and legacy-provenance paths still allow live and restored pending-ask state to diverge.
