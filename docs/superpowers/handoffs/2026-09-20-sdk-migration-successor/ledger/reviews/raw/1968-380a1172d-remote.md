## Review Summary

The six commits rework how an older pagination page is folded into the loaded thread model. The previous implementation appended unmatched older turns ahead of the model and merged only direct matches, so turns split across page boundaries (or coalesced transitively through shared items) could be duplicated or mis-ordered. The new implementation replaces that with two phases:

- `coalesceTurnFragments` builds groups of older/fresh turns connected transitively by `turnsMatch` (turn id or shared item identity), merging each group with the existing older-then-newer precedence.
- `placeCoalescedTurns` places fresh-anchored groups in model order, assigns older-only "retained" turns to a gap between anchors based on the greatest preceding anchor rank and the earliest compatible succeeding anchor, then merges groups with by-position weaving so no fresh or older ordering is violated.

The change is supported by extensive behavior tests, including a placement matrix asserting item uniqueness, fresh-order preservation, retained-order preservation, and anchor-compatibility invariants.

I traced the coalescing transitivity (a new fragment joins every existing group it matches, so the induction maintains the transitive-closure invariant), the gap/region partition (region keys are exactly `{0} ∪ (anchors \ {a0}) ∪ {fresh.length}`, and retained gaps provably cannot equal `a0` or decrease, so no group is dropped or reordered), and the precedence chain (`mergedOlder` then fresh fragments, with `mergePageTurn(older, newer)` consistently oriented). I also confirmed `toHaveLength` works on a `Set` under the project's Vitest/Chai (Chai's `assertLength` reads `.size` for `Set`/`Map`).

I could not establish a concrete production defect with evidence in the diff; the residual ambiguities (turns that span noncontiguous positions, or unpositioned fresh turns) are design trade-offs explicitly exercised by the new tests.
