## Summary

The series adds the write half of a native `MutationOutboxStorage` adapter over expo-sqlite (`MutationOutboxSQLite`) plus a 436-line test suite that mirrors the web IndexedDB oracle against `node:sqlite`. It covers `enqueueIntent`, `markAttempted`, `markUnknown`, `settleReceipt`, `settleApplied`, and `transferToRecovery`, using an atomic `INSERT ... ON CONFLICT ... RETURNING` sequence allocator, primary-key rejection on enqueue (matching IndexedDB `add`), full-row `put` semantics on transitions, and `SAVEPOINT`-based rollback for compound writes. The read half is explicitly deferred to D25d-1b, and the class is intentionally unused until then. The final aggregate diff cleanly achieves that goal; the atomic allocator, null-encoding, and rollback fixes are all present and tested.

I found no high- or medium-severity issues. One low-severity scoping gap follows.

---

**Severity: low** — `mobile-native/src/mutationOutboxStorage.ts` `settleReceipt` (~line 264) and `settleApplied` (~line 311)

The web oracle's `settleReceipt`/`settleApplied` both call `#discardSupersededNoteRecovery`, which retires earlier `notes/human/set` recovery rows for the same `targetRef` with a lower `intentSequence` in the same canonical-settlement write (`cmd/evener-hub/frontend/src/stores/mutationOutboxIndexedDB.ts:243-257`). The native implementation has no equivalent, so if native ever submits `notes/human/set` (a method the shared dispatcher explicitly handles — `appwire-client/typescript/state/mutation/dispatcher.ts:84,144,159`), a refused earlier note's recovery row will survive a later accepted note and remain visible as a stale failed entry. The file's header comment acknowledges this omission as deliberate ("shared-notes recovery-superseding, none of which the port declares"), and because the class is dead code until D25d-1b, there is no impact today. It is worth carrying into D25d-1b (or a follow-up ticket) before the adapter is wired, since the domain rule is host-independent.
Suggested fix: add the note-superseding sweep to `settleReceipt` and `settleApplied` inside their existing transactions (delete `mutation_recovery` rows where `method = 'notes/human/set'`, `target_ref = source.targetRef`, and `intent_sequence < source.intentSequence`).
