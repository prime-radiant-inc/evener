## Summary

The series closes a correctness gap in marketplace removal across the manager, hub, CLI, and TypeScript SDK:

- `internal/plugins.RemoveMarketplace` now persists the unregistration *before* removing the clone from disk, so a failed save is a plain refusal (registry and clone intact) while a failed clone removal is an applied-with-litter outcome reported via the new sentinel `ErrMarketplaceUnregisteredCloneRemains`. It also never derives `marketplaceDir(name)` or touches the filesystem on a lookup miss, closing a path-traversal/over-deletion risk from names like `""` and `".."`.
- The hub classifies that sentinel into a typed `appwire.WireError` carrying `Data.Applied` (the updated list) and a new `evenerErrorInfo` value; if the reconcile re-list itself fails, it keeps the typed outcome with `AppliedUnavailable` instead of degrading to a plain error.
- The CLI reports "removed ... clone files remain" while exiting non-zero.
- The SDK store adds an `onFailure` hook to `writeRevisioned`/`mutate` that reconciles the list and browse cache from `data.applied`, fenced by the same list revision and generation so an outrun/newer write wins and a `reset()` publishes nothing.

The tests cover lookup-miss safety, save-before-clone ordering, path scrubbing, the typed wire outcome at both boundaries, reconcile-read failure, CLI behavior, and the revision-fence orderings. I found no issues meeting the reporting bar.
