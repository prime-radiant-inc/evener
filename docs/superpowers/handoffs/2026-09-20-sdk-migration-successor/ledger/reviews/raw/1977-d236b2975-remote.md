- **Location**: `agent/session_state.go:416-418`
- **Problem**: A human-note carrier can leave `askPending` set while a notification or other autonomous work is pending. `armAwaitingAtSettle` then refuses to upgrade the idle state because that work is pending, causing `WireState` to report `active`; subsequent autonomous wakes are gated by the pending ask, so the client loses the awaiting signal.

## Summary

The series closes the gap between the live session's pending-ask (`askPending`) resolution boundary and the one a restart re-derives from the transcript.

- `turnResolvesAskBoundary` factors the decisive-turn predicate (user input, interrupted steer, an answering user steer, or a `SteeringCarrier`-tagged `TurnFailure`) into one function shared by `deriveRestoredState` and `deriveRestoredAskPending`; `steeringAnswersAsk` similarly unifies the live mid-round clear, the carrier-claim check, and the restore scan so a human-note steer never counts as an answer.
- `deriveRestoredAskPending` now accumulates `ask_user` questions across rounds whose entry did not itself resolve the boundary (a human-note carrier can append a new question without answering an older one), reversing round order to match live append order, and uses `roundEntryResolvesAskBoundary` (tolerant of interleaved bookkeeping turns) to decide whether a generic completion is decisive.
- Steering provenance (`steeringOriginForTurn`) and a shared `steeringOriginBoundary` clamp let a kindless legacy human-note turn be classified by its journal record or write-path text shape, while scoping a forked child's provenance lookup to its own turns so a reused client-mutation id cannot reclassify an inherited turn.
- On the live side, `askPending` is no longer cleared unconditionally at turn entry: it is cleared for a claimed answering carrier at entry (already durably admitted) and for ordinary user input only after the user turn is durably admitted, and terminal failure/yield/refusal boundaries settle through `finishProcessingAtFailureBoundary`, which keeps the session `SessionAwaiting` while a question is still pending. `awaitingOrHasPendingAsk` samples state and pending set under one lock.

The logic is internally consistent: both restore scans stop at the same first decisive turn, so `SessionIdle` and a non-empty pending set cannot disagree, and reverse-round accumulation reproduces live append order.
