## Summary

The series makes marketplace removal's clone-cleanup failure a first-class "applied with litter" outcome. On the Go side, `RemoveMarketplace` now persists the unregister before deleting the clone (so a save failure is a plain refusal and a clone-removal failure leaves the registry already updated), wraps that cleanup failure in a new `ErrMarketplaceUnregisteredCloneRemains` sentinel, and the hub/CLI classify it: the hub returns a typed `WireError` whose `Data` carries the fresh list (or `appliedUnavailable` when the re-list itself fails), and the CLI reports the completed removal plus the leftover files while still exiting non-zero. `MarketplaceUnregisteredCloneRemainsData` documents the payload. The TypeScript store gains `marketplaceRemovalOutcome`, `writeRevisioned` gains an `onFailure` publisher that uses the failing request's revision, and `removeMarketplace` reconciles the list/browse cache from `data.applied` under the existing fence. The web sheet warns, closes its confirm, guards against a repeat removal while an unavailable applied list is reconciled, and `MarketplacesPluginsSection` owns that guard across the load-error unmount and client swaps. Tests cover the manager, hub, CLI, store, and UI boundaries.

The aggregate diff achieves the stated goal. I found one test-isolation defect.

---

**Severity: medium** — `cmd/evener/plugincmd_test.go:108` (specifically `root := t.TempDir()` at line 115)

`TestPluginMarketplaceRemove_CloneRemovalFailureReportsRemovedWithLitter` does not isolate `XDG_CONFIG_HOME`, unlike its sibling `TestPluginMarketplaceRemove` (which calls `t.Setenv("XDG_CONFIG_HOME", t.TempDir())` before `runPlugin`). `runPlugin` runs `cmdutil.EnsureUserConfigDirs()` before `runPluginMarketplace`; that calls `checkLegacyDataDirs`, which reads the **real** home's `~/.config/serf`, `~/.local/state/serf`, `~/.serf`, and `~/.evener`. On any machine carrying unmigrated Serf/Evener legacy data, `runPlugin` returns that migration error before reaching the removal, so the test fails at `errors.Is(err, plugins.ErrMarketplaceUnregisteredCloneRemains)` without ever exercising the litter path; and on every run it creates real `~/.config/evener`/skills/plugins directories as a side effect. The `newPluginManager` stub only isolates the manager's store root, not the pre-guard.

Suggested fix: add `t.Setenv("XDG_CONFIG_HOME", t.TempDir())` at the top of the test (matching the existing removal test), so both the legacy check and `EnsureUserConfigDirs` operate entirely under the temp dir.
