## Summary

The series reworks how `mergeOlderItemPage` places turns when an older pagination page is merged into the current model.

- `coalesceTurnFragments` now returns `CoalescedTurn` records that carry the source indices (`olderIndexes`, `freshIndexes`) of every fragment, instead of just merged `TurnModel`s. This makes it possible to know where a coalesced turn was anchored in both the page and the model.
- A new `placeCoalescedTurns` places coalesced turns in model (fresh) order, and weaves turns that exist only in the older page ("retained" turns) into the gaps between fresh anchors using transcript positions (`firstTurnPosition`/`compareTurnPositions`). Retained runs with no position are attached to their next positioned successor (`nextPositionedTurn`), and `previousAnchor`/`nextCompatibleAnchor` keep retained runs monotonically ordered by maximizing the fresh rank seen so far.
- `mergeOlderItemPage` now runs `placeCoalescedTurns` before `mergeToolCallsByCallId`, and the tests add a large set of positional-placement scenarios plus a parameterized placement-invariants matrix that asserts no item loss/duplication and ordering of fresh/retained turns.

I traced the placement algorithm against the added tests and several additional orderings (empty fresh set, no anchors, noncontiguous anchors within one coalesced turn, crossed anchors, unpositioned runs with and without positioned successors, prefixed/suffixed retained runs). Gap keys correspond one-to-one with segment boundaries, every coalesced group is emitted exactly once, gap values are non-decreasing in older-index order, and the fresh-only/anchored interleaving preserves fresh order. I found no correctness, security, or regression issue in the changed code. The checks in the parameterized matrix test (Set-size/length equality, per-source-item uniqueness, fresh-order preservation, retained-order preservation, and predecessor-anchor ordering) are meaningful and not tautological.
