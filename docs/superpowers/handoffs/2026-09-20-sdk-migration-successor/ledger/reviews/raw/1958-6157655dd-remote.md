## Summary

The series lands the restore-side "ask boundary" oracle for pending `ask_user` questions. It factors the three shapes that resolve a pending ask — a `TurnUserInput`, a user-sourced non-note `TurnSteering` (including `SteeringKindInterrupted`), and a `TurnFailure` tagged `SteeringCarrier` — into a single `turnResolvesAskBoundary`, shared by `deriveRestoredState` and `deriveRestoredAskPending` so they cannot independently drift. It adds `roundEntryResolvesAskBoundary` so a generic completion inside a round opened by a non-resolving carrier (human-note update) does not falsely close the boundary, accumulates ask rounds across non-resolving carrier rounds to mirror live `append` semantics, scopes steering provenance to the session's own turns via `steeringOriginBoundary` (fork collision fix), and replaces `steeringSourceAnswersAsk` with `steeringAnswersAsk` that also consults `isHumanNoteSteer`'s text-shape fallback. Callers in `session_init.go`/`session_state.go` are updated with `divergenceTurn` and `steeringOrigins()`, and a large set of restore-contract tests plus fuzz-call updates are added.

I traced the accumulation ordering, the interaction with `deriveRestoredState`'s "agent moved last ⇒ awaiting" rule, the carrier-skip entry clear, and the fork-boundary scoping; I found no runtime correctness, security, or regression defect. State `Idle` still implies an empty pending set, and every live `askPending` clear path (entry clear, mid-round resolving steer, interrupt) has a corresponding restore boundary.

The doc bullet for the resolving-boundary case states the function "returns (nil, false); the pending set must stay empty", but that branch now executes `return finish()`, which returns a non-empty slice whenever newer non-resolving carrier rounds accumulated questions (exactly the case the same function's `finish`/`roundsNewestFirst` comment describes, and exactly what `TestAskUser_RestoreAccumulatesPendingQuestionsAcrossNonResolvingRounds` exercises: scanning past a human-note round that posted `ask2`, then hitting the older resolving `TurnUserInput` returns `[ask1, ask2]`, not `(nil, false)`).

Concrete harm: this bullet directly contradicts the code path it documents and the comment immediately above `roundsNewestFirst`, so a future maintainer reading only the summary can "simplify" the branch back to `return nil, false` and silently reintroduce the lost-ask bug (#1906/#1907) this change exists to fix.

Suggested fix: reword the bullet to say the boundary itself contributes no questions and returns `finish()`, which is `(nil, false)` only when no newer non-resolving round accumulated questions, otherwise the accumulated pending set; the "idle, not an ask round" phrasing applies to the boundary turn, not to the returned set.
