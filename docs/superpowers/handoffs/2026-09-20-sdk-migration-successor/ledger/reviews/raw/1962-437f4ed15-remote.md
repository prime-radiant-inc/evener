## Summary

The series fixes a class of bugs where a live session would settle `SessionIdle` while an `ask_user` question was still genuinely unanswered, causing the live `State()`/`WireState()` to disagree with the state a restart would derive from the same transcript (and telling clients "idle" when the session still needs the user).

The changes:
- Add `finishProcessingAtFailureBoundary`, a pending-aware variant of `finishProcessingAtBoundary` that settles `SessionAwaiting` when `askPending` is non-empty, and route every early-return terminal path through it: provider failures (`handleModelError`), the generic non-provider failure/budget tail, poisoned-transcript refusal, tool-round budget exhaustion, no-tool empty/bare-text exhaustion, and the observer/notification yield boundaries.
- Force `armAwaitingAtSettle` to target `SessionAwaiting` whenever a question is pending, so clean-completion settles (e.g. a human-note carrier that merely communicates) cannot mask the ask.
- Replace the two-lock `State() == SessionAwaiting || askPendingCount() > 0` read in the drain-ladder gate with a single-lock `awaitingOrHasPendingAsk()`.
- Make `roundEntryResolvesAskBoundary` treat a non-carrier `TurnFailure` as transparent bookkeeping rather than a round entry, mirroring how the outer restore scan already passes over such turns, and add tests covering each boundary (live state asserted against the restore-derived state).

I verified the boundary interactions: `EntryUserInput` clears `askPending` before `acceptUserInput` runs, so the MaxTurns/queue error paths cannot diverge; notification no-op/`finishIdle` paths are unreachable while an ask is pending because the admission gate refuses non-user wakes; resolving steers and interrupts clear the pending set so the failure boundary correctly stays idle; and the `roundEntry` change cannot drop an earlier pending ask in any reachable transcript shape (a pending ask requires either a resolving entry, which clears it, or a non-resolving carrier `TurnSteering`, which the walk reaches before any earlier `TurnUserInput`).
