## roborev: Combined Review (`ba45d39`)

## Verdict: One High-severity projection crash from unguarded `title.trim()`, plus medium and low findings around warning rendering and shared-helper typing.

---

### **High**

- **`transcriptProjector.ts:176` (consumes `reducer.ts:1707`) — `itemSummary` crashes on non-string warning `title`**
  `itemSummary` calls `item.warning?.title?.trim()` with no type guard. Malformed wire warnings can supply a numeric or object `title`; `WarningItem.tsx` was hardened against this, but `projectThread` (which routes `warning`/`steering` items through `itemSummary`) was not, so the same frame still throws.
  **Fix:** Apply the same `typeof value === "string"` guard used in `hasWarningText`/`WarningItem`, or sanitize `title`/`hint` to `string | undefined` in the `warning` fold of `reducer.ts` so the model never stores non-strings. Add an end-to-end projection test for a numeric/object `title`.

  *(Reported by Reviews 1 and 2; Review 1 rated Medium, Review 2 rated High — same location and root cause.)*

### **Medium**

- **`deriveAskQuestions.ts:106`; `reducer.ts:822` — Absent `askPending` coerced to `false`, breaking old-daemon asks**
  `liveAskQuestions` now returns `[]` when `model.askPending` is false, but hydrate coerces an absent wire field to `false`. The wire contract marks `AskPending` as additive and absent on old daemons, and `ask_user` predates the field, so an older daemon with a genuine unanswered ask loses its dock entirely.
  **Fix:** Distinguish an explicit wire `false` from an absent/unknown value. When hydrate omits `askPending`, fall back to the existing transcript scan instead of returning `[]`. Add a hydrate test for an unanswered ask with the field omitted.

### **Low**

- **`reducer.ts` (~1699–1702) — Warning fold `text: ""` drops title/hint on mobile**
  The fold now writes `text: ""` whenever a warning has a non-blank `title`/`hint` but no `message`. This is correct for web (`WarningItem.tsx` renders `item.warning.title`/`hint`), but `mobile/src/conversation/project.ts` never reads `item.warning` — it falls through to default activity projection (`item.text || item.output`), so a message-less warning frame (e.g. a title-only "Sandbox blocked") becomes an empty row on the phone. Real daemon producers set `Message`, so this is limited to the malformed/partial frames the series intentionally keeps "visible, not silent."
  **Fix:** Have mobile's warning projection surface `item.warning.title`/`hint` (e.g. append to activity detail when `item.text` is empty), or otherwise give mobile parity with `WarningItem.tsx` before the reducer stops carrying the raw frame.

- **`transcriptProjector.ts:152`; `mobile/src/conversation/project.ts:234` — `isActiveItem` typing blocks mobile adoption**
  The exported `isActiveItem` is intended to unify web/mobile activity-state logic, but it requires a full `ItemModel`. Mobile's remaining duplicate accepts `ItemFailureSignals` and is called with wire `ThreadItem` values, so it cannot adopt the shared helper without casts.
  **Fix:** Since the helper only reads `item.status`, type it as `ItemFailureSignals`, place it with `isInProgressStatus` in `itemFailure.ts`, and replace the mobile duplicate with the shared export.
