## roborev: Combined Review (`36cfd48`)

## Verdict
Solid centralization of ask/reasoning/warning/identity behavior, but the phone projector can crash on malformed warning frames and several cache, migration, and projection gaps remain.

## High

- **Warning crash from untyped `title`/`hint`** — `mobile/src/conversation/project.ts:573-574` (`projectItem` warning branch)  
  The new branch filters `[title, item.text, hint]` with `part.trim() !== ""` without a type guard. `WarningParams.title`/`hint` are only string at the type level; the wire is untyped and `reducer.ts` copies them through unchanged (after `hasWarningText`, which rejects non-strings but doesn't sanitize). A frame like `{title: 42}` or `{hint: null}` reaches this branch and `42.trim()` throws a `TypeError`, aborting `projectConversation`/`projectTimeline`. The web renderer was hardened in the same series (`WarningItem.tsx` now does `typeof value === "string" && value.trim() !== ""` with tests for numeric/null/object values), but the phone only exercises string values, so the two hosts disagree on the same malformed frame. Today the crash is latent until the D23c-2b row cutover (warnings aren't persisted on the read path), but this is the shared projector under test.  
  **Fix:** Mirror the web guard — only treat `typeof part === "string" && part.trim() !== ""` as content before joining.

## Medium

- **Question signature incompatible with persisted drafts** — `mobile-native/src/QuestionSheet.tsx:53`, `mobile-native/src/questionAnswers.ts:78-86`  
  The new question signature doesn't match what `DraftRepository` already stores; existing saved answers compare as different definitions and are silently discarded after upgrade.  
  **Fix:** Preserve the legacy signature format for persistence or add a backward-compatible migration.

- **Stale `items` projection on `askPending` change** — `mobile/src/state/conversation.ts:2445-2448`, `2816-2824`  
  Status notifications update `askPending` in the model but republish the old `items` projection unchanged, so native question rows can linger after resolution or fail to appear when a pending ask is announced.  
  **Fix:** Re-project `items` whenever model-only state such as `askPending` changes.

- **Live reasoning deltas ignore `summaryIndex`** — `mobile/src/state/conversation.ts:2670-2705`  
  Live reasoning deltas concatenate all paragraphs into one output, diverging from the canonical per-summary rendering until a reread.  
  **Fix:** Derive the live row from `reasoningSummaries` using `joinedReasoningParagraphs`, or re-project from the updated model.

- **`liveAskQuestions` collapses `undefined` to empty** — `appwire-client/typescript/deriveAskQuestions.ts` (`liveAskQuestions`)  
  `if (!model.askPending) return []` treats `undefined` as not-pending. Partial `ThreadModel` fixtures and any caller that previously called `liveAskQuestions({turns})` silently flip from returning asks to returning none; the diff has to patch `qualify-package.mjs` and every frontend fixture to add the flag.  
  **Fix:** Require the flag explicitly in the type, or distinguish `undefined` from `false` (e.g., fall back to the item scan when the field is absent).

- **`turnRowCache` serves stale rows on in-place item mutation** — `mobile/src/conversation/project.ts` (`rowsForTurn` / `turnRowCache`)  
  Cache validity only checks `askState` (`asks.has(callId)` per consumed call). Item text/status, `reasoningSummaries`, `warning`, and `turn.error` changes are invisible unless the `TurnModel` reference changes. Tests in the same diff mutate `ItemModel` in place, so a second projection of the same turn reference would serve stale rows.  
  **Fix:** Key the cache on the `turn.items` reference plus error/warning-affecting fields, or store and compare the `items` array reference alongside `askState`.

- **Live warning path keeps legacy failure row** — `mobile/src/state/conversation.ts:2781-2802`  
  The live path still creates an unbounded legacy failure row, ignoring the new warning fallback and hint behavior, so malformed warning frames can produce inconsistent output even when they don't crash.  
  **Fix:** Route live warnings through the canonical reducer projection and shared truncation.

## Low

- **`rawWarningFrame` allocates before truncating** — `appwire-client/typescript/reducer.ts`  
  Bounds output to 2000 chars but only after `JSON.stringify(params)` plus `Array.from()` over the whole frame, so an oversized/malicious warning still pays full string plus code-point array allocation before truncation.  
  **Fix:** Truncate incrementally while iterating code points up to the limit instead of materializing the full array first.

- **`liveAsksFor` leaks a mutable `Map`** — `mobile/src/conversation/project.ts` (`liveAsksFor`)  
  Returns the cached mutable `Map` instance directly as `ReadonlyMap`. A caller that mutates it corrupts the memo for all later callers sharing the same `turns` reference.  
  **Fix:** Return a copy/frozen view, or document that callers must not mutate the returned map.

- **Duplicate identity/truncation helpers drift risk** — `mobile/src/state/conversation.ts:56-98` (and `project.ts:900-960`)  
  The commit wires `truncateItem`/`capItems` to the shared `project.ts` helpers but leaves duplicate copies of `attachmentSourceId`, `attachmentSourceIdentity`, `timelineIdentity`, `ownTimelineIdentities`, `timelineIdentities` in `conversation.ts`, plus a second `truncateText`/`MAX_ITEM_BYTES`/`RETAINED_ITEM_CAP` implementation. Both `capItems` (project.ts) and the store's page-merge/admission logic key off these identity rules, so a future change to one copy can silently make the cap and the merge disagree about which rows are duplicates — the exact bug class the shared helpers exist to prevent.  
  **Fix:** Import the `project.ts` exports in `conversation.ts` (as already done for `capItems`/`truncateItem`) to remove the drift risk.
