## roborev: Combined Review (`78ccc02`)

## Verdict: 3 medium, 3 low — the `askPending` wire-authority change needs a tri-state fix before merge.

### Medium

- **`askPending` short-circuit hides asks on old daemons / source-backed threads** — `appwire-client/typescript/deriveAskQuestions.ts:106` (`if (!model.askPending) return [];`), sourced from `appwire-client/typescript/reducer.ts:822` (`askPending: thread.evener.askPending ?? false`).

  `EvenerThread.AskPending` is `json:"askPending,omitempty"` and its Go doc says the field is absent on old daemons and source-backed threads, decoding as `false` (`appwire/types.go:760-763`). Before this change the dock derived pendency from the transcript; after it, `hydrateThread` folds the absent field to `false`, the short-circuit returns `[]`, and no ask dock renders even when the transcript contains a completed, unanswered `ask_user` item. *(Reported by reviews 1 and 3.)*

  **Fix:** Keep the field tri-state (`boolean | undefined`) through hydrate and only short-circuit on an explicit `false`; fall back to the transcript scan when the wire never supplied the field.

- **New turns-reference contract has no production consumer** — `appwire-client/typescript/reducer.test.ts:4736`.

  The native store's `evener/steering/injected` path falls through to `publishModel()` only and never compares `conv.turns` with the previous turns, so an injected steer targeting an active turn outside the loaded window still does not trigger the reread needed to display it.

  **Fix:** Add the native-store integration — detect the unchanged turns reference for placement-dependent frames (or expose an explicit "unplaced frame" signal) and request a rehydrate; cover it with a host-level test using an out-of-window active turn.

- **Warning text not consistently bounded** — `appwire-client/typescript/reducer.ts:1182`.

  A valid oversized `message` or `warning` string is stored unbounded in `ItemModel.text`, while the fallback materializes the entire serialized frame into an `Array.from` code-point array before truncating. With the transport's large frame limit this can allocate memory proportional to the full payload despite the 2000-character output bound.

  **Fix:** Apply one code-point-bound helper to the final warning text and truncate with an early-exiting iterator rather than materializing every code point. Add a behavioral test for an oversized valid warning message.

### Low

- **Vacuous "oversized warning frame" test** — `appwire-client/typescript/reducer.test.ts`.

  The test uses `warning: "x".repeat(10_000)`, a non-blank string, so `warningMessage(params)` returns it and `rawWarningFrame` is never reached. `item.text.length` is ~10 000 and `JSON.stringify(params).length` is ~10 055, so `toBeLessThan(...)` is trivially true and the test would still pass if the bound were removed. The actual bound is exercised only by the surrogate-pair test below it.

  **Fix:** Change the fixture to a message-less shape (e.g. `warning: 42` with a large `extra`, as the surrogate test does) so the assertion constrains the fallback length.

- **Vacuous mobile project tests** — `mobile/src/conversation/project.test.ts:1208`, `:1240`.

  Both tests rely on `liveAskQuestions` reaching the scan, but their fixtures never set `askPending`, so the helper's default is `false` and the new short-circuit returns `[]` before the user-message/errored-ask logic runs. The tests pass regardless of whether the resolution or error-exclusion logic is correct. The behavior is still covered in `appwire-client/typescript/deriveAskQuestions.test.ts:109` and `:220`, so this is a duplicate that has gone vacuous rather than a coverage hole.

  **Fix:** Add `{ evener: evenerThread({ askPending: true }) }` (as the two sibling tests in the same block already do) to keep the assertions meaningful.

- **Exported `isActiveItem` is unused on mobile and type-incompatible with its callers** — `appwire-client/typescript/transcriptProjector.ts:152` / `appwire-client/typescript/index.ts:472`.

  The JSDoc says the helper is exported so the web and phone share one implementation, but the phone's copy still exists (`mobile/src/conversation/project.ts:234`) and does not import the exported one, so the export is currently unused and the two implementations can still drift. Separately, the exported `isActiveItem` requires a full `ItemModel`, but the mobile callers use `ItemFailureSignals` including raw `ThreadItem` values that do not satisfy `ItemModel`, so the phone cannot adopt the helper without wrappers. *(Reported by reviews 3 and 4.)*

  **Fix:** Type the parameter as `ItemFailureSignals` (ideally placing the helper with the other item liveness/failure predicates), switch mobile callers to the package export, or drop the export if the dedupe isn't being wired through.
