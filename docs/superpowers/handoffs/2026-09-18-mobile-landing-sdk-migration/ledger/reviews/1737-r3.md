## Combined PR Review

**Verdict:** One native crash risk and several correctness/duplication gaps remain; the ask-pending gating and row caching logic are sound.

---

### **High**

- **`mobile/src/conversation/project.ts:572`** — Warning projection calls `.trim()` on `item.warning?.title`/`hint` without a type guard. The reducer stores these verbatim from an untyped wire frame, so a malformed frame with a numeric or object title throws `TypeError` and aborts the entire timeline projection. Web's `WarningItem.tsx` already guards with `typeof part === "string"`, and the reducer's `hasWarningText` tolerates the same case — this change claims parity but misses the type check. **Fix:** Use `typeof part === "string" && part.trim() !== ""` in the filter (e.g. reuse a `present`-style helper), and add a non-string case to the existing warning tests. *(Reported by all three reviewers.)*

---

### **Medium**

- **`mobile/src/conversation/project.ts:1058`** — Question refs are truncated before being stored in the native conversation. Since `pendingQuestions` and answer composition read these same refs, oversized option labels or headers can be sent back truncated and no longer match the agent's original question. **Fix:** Keep canonical question refs separate from bounded display copies; use canonical refs for validation and answer composition.

- **`mobile/src/state/conversation.ts:2498`** — The reducer preserves existing input images when a completion omits an image list, but the native live-row path derives attachments directly from the incoming frame and drops existing attachment rows. The live display can lose images until the next reread. **Fix:** Derive live attachments from the folded model item, or retain existing attachments when incoming input images are absent or empty.

- **`mobile/src/conversation/project.ts:946` / `mobile/src/state/conversation.ts:485` / `mobile/src/services/conversation.ts:53`** — The "centralized" cap/truncation constants (`MAX_ITEM_BYTES`, `TRUNCATION_MARKER`, `RETAINED_ITEM_CAP`) and helpers (`truncateText`, row-identity) are now declared in three modules instead of one. The store's `truncateItem` closure calls its own `truncateText` (which still uses `TextEncoder` while `project.ts` now uses `utf8Length`), so future bound or marker changes in the projector silently stop applying to the store's rows and page-cap math. **Fix:** Have `state/conversation.ts` and `services/conversation.ts` import the single definition from `conversation/project.ts`, or delete the now-unused `services` copy.

---

### **Low**

- **`mobile/src/conversation/project.test.ts:2091`** — The test "renders no question row when the ask arguments do not parse" builds a wire thread without `askPending: true`. Since `hydrateThread` defaults `askPending` to false and `liveAskQuestions` now gates on it, the assertion passes vacuously without exercising the parse-failure path. **Fix:** Pass `{ evener: evenerThread({ askPending: true }) }` like neighboring pending-ask tests so the assertion proves unparsable args produce no row even when pending.
