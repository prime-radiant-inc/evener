## roborev: Combined Review (`603341a`)

**Verdict:** Three High issues and one Medium issue found across ask-pending resolution, package qualification, and steering carrier restore.

## High

- **Live status notifications omit `AskPending`** — `appwire-client/typescript/deriveAskQuestions.ts:105-106`; `internal/appprojector/appwire_projection.go:1632-1637`
  `liveAskQuestions` now requires `ThreadModel.askPending`, but the live AppWire status producer omits `AskPending` from every `thread/status/changed` notification. The reducer preserves the previous value when the field is absent, so newly completed `ask_user` calls won't appear as question rows and resolved asks can retain stale pending state. Fix: populate `ThreadStatusChangedParams.AskPending` on every relevant transition (including explicit `false`) and add an end-to-end projection test for both ask creation and resolution.

- **Package qualification script crashes** — `appwire-client/typescript/scripts/qualify-package.mjs:62,66,69`; `deriveAskQuestions.ts:106`
  `liveAskQuestions` now starts with `if (!model.askPending) return [];`, but `qualify-package.mjs` calls it with a minimal hand-built model that has no `askPending`. The `undefined` short-circuit returns `[]`, making `[0].key` throw `TypeError: Cannot read properties of undefined`. Since the script is plain JS (not type-checked), nothing catches this until it runs. This deterministically fails `make test-api-package`, which both CI and `merge-approval-gate` invoke. Fix: add `askPending: true` to the fixture model in each smoke call (matching the already-updated `deriveAskQuestions.test.ts`/`askDock.test.ts`), or gate on `model.askPending === false` rather than falsiness.

- **Steering-carrier skill-selection failure restores stale ask** — `agent/session_queue.go:1302`
  A steering carrier whose skill selection fails persists an untagged `TurnFailure`. `processOneInput` already cleared `askPending` when the carrier was accepted, but restore skips untagged failures and resurrects the prior ask, producing live/restored state divergence. Fix: thread carrier context into the steering-selection failure path and persist the same explicit carrier resolution boundary; test the full queued-carrier path with a failing skill selection and assert live and restored pending state agree.

## Medium

- **Truncated question rows double as answer model** — `mobile/src/conversation/project.ts:961`
  `pendingQuestions` reads the truncated `conversation.items`, so an oversized option label can be sent as a truncated invalid choice or collide with another truncated label, despite code and tests claiming answers use canonical refs. Fix: separate bounded display questions from canonical answer refs; compose answers from canonical model data while mapping selections to original options, and add a test through `pendingQuestions` and answer composition for an oversized label.
