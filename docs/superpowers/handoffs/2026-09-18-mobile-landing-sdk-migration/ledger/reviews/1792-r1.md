## roborev: Combined Review (`c808392`)

## Verdict: One high-severity data-loss gap, several medium concurrency/contract issues, and minor polish needed before merge.

## Critical
None.

## High

- **Restored drafts use in-memory generation, not persisted identity** — `appwire-client/typescript/keybindingsStore.ts:669`
  Restored drafts are stamped with the current in-memory generation, which is never persisted. A checkpoint from an old hub session can be accepted as current when a new hub reports the same revision, and a storage recovery after a generation change can restamp an already-known stale draft. This preserves the exact same-revision data-loss case the change is meant to prevent.
  Fix: persist a stable base-state identity (e.g., a digest of confirmed rules) and compare before accepting a restored draft; preserve an already-known generation during storage recovery and require review on mismatch. Add a test covering restoration or storage recovery across a generation boundary with equal revisions.

## Medium

- **`saveDraft` races with in-flight `patchOverrides`** — `appwire-client/typescript/keybindingsStore.ts:1134-1197, 1346-1360`
  `saveDraft` can start while a direct `patchOverrides` request is in flight, because direct writes neither publish `saving` nor join the draft write queue. It claims a newer write token, fences the direct response, and both PATCHes race or conflict.
  Fix: serialize both write paths through one shared coordinator, or reject `saveDraft` whenever any direct write is pending.

- **`discardClassified`/`replaceClassified` can delete or overwrite a record the repository never classified** — `appwire-client/typescript/draftCheckpointPort.ts:138`
  When `!hasLastClassified` (e.g., after `load()` observed an empty port), `discardClassified` falls back to a fresh-load delete and `replaceClassified` falls back to an unconditional save. If another writer stores a valid checkpoint before the call, the fallback silently destroys or overwrites it — even though this repository showed the user nothing. The store path is likewise unprotected: `discardDraft` → `assertDiscardable` (`keybindingsStore.ts:1269`) does not require `state.draft !== null`. The repository-level test only exercises the fallback with a corrupt object, so the valid-record case is unguarded.
  Fix: when `!hasLastClassified`, attempt a classifying `load()` and only remove if decoding throws `UnreadableDraftError`; for a readable record, re-classify and return `false` so the caller re-reads/surfaces it. Keep `discardStoredDraft` as the explicit "remove anything, no store" entry point.

- **`discardStoredDraft` casts arbitrary raw bytes to `Checkpoint`** — `appwire-client/typescript/draftCheckpointPort.ts:38`
  For unreadable records the `load()` value is raw bytes, not a decoded checkpoint, yet it is passed to `removeIf` as a `Checkpoint`. The native test even requires `as never` to exercise it. Custom implementations of the exported port contract may assume the declared checkpoint shape and fail.
  Fix: model record identity as `unknown` or a dedicated raw-record identity type in `DraftPort` and `KeybindingDraftStorage`; remove the unsafe cast and test-only `as never`.

- **`KeybindingDraftStorage` contract is a source-breaking, undocumented change** — `appwire-client/typescript/keybindingsStore.ts:66`
  `removeIf` now must return `boolean` and `replaceIf` is newly required; existing JS implementations returning `undefined` are interpreted as refusals, which can incorrectly adopt or drop a draft. The package version and migration docs were not updated, and the new public `KeybindingsDraft` state type is not exported from the package root.
  Fix: ship this as an explicitly versioned and documented breaking change, export `KeybindingsDraft` from `index.ts`, or use a separate atomic-storage interface if compatibility is approved.

- **Malformed JSON bytes are lost, making `discardDraft()` repeatedly refuse removal** — `mobile-native/src/NativePreferencesProvider.tsx:39-52`
  Valid but malformed JSON is parsed before reaching the repository, so the original bytes are lost. `matches()` then compares stored bytes against `JSON.stringify(parsedValue)`; records with different formatting fail the comparison, and `discardDraft()` repeatedly refuses to remove the unreadable record.
  Fix: preserve and compare the original serialized storage value, or provide a storage identity token that survives parsing.

## Low

- **`discardStoredKeybindingDraft` drops the underlying boolean** — `appwire-client/typescript/keybindingsStore.ts` (`discardStoredKeybindingDraft`)
  The wrapper discards the boolean from `discardStoredDraft`, so a storeless host cannot distinguish "removed" from "no-op."
  Fix: return the underlying boolean.

- **Unreadable-discard action appears enabled but does nothing while disconnected** — `mobile-native/src/KeybindingPreferencesScreen.tsx:183,186`
  The action is disabled only on `loading || saving || writeUncertain`, and `run` additionally returns unless `scope.connected` and `model` are non-null. When disconnected, the provider sets `model: null` while retaining the snapshot, so `draftUnreadable` renders a button that silently does nothing. On a cold offline launch no snapshot exists at all, so there is no discard UI. This is exactly the case `discardStoredDraft`'s doc says a host must support, yet the exported `discardStoredKeybindingDraft` helper has no caller.
  Fix: add `!preferences.connected` to `disabled` (matching the adjacent refresh action), or wire `discardStoredKeybindingDraft` into the provider so the discard can run without a connected model.

- **Comments encode review-round history instead of current invariants** — `appwire-client/typescript/keybindingsStore.ts:83`
  New comments reference "round 24" and similar temporal context, and tests reference "RoboRev round." This violates the project's comment rule against temporal context.
  Fix: replace those references with concise statements of the invariant or failure mode being protected.
