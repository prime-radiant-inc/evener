## High

### `EditMarketplace` save failures with a successful rollback still leak absolute store paths to RPC clients
`internal/plugins/marketplaces.go:439-445`

All four reviewers flagged this. The `fail` closure only scrubs the error when the outer rollback *also* fails:

```go
swapErr, undoErr := undoSwap(), runUndo(undo)
_ = marketplaceRemoveAll(staging)
if swapErr == nil && undoErr == nil {
    return MarketplaceRef{}, err   // raw error returned unchanged
}
return MarketplaceRef{}, m.storeChangeRollbackFailed(name, err, errors.Join(swapErr, undoErr))
```

When rollback succeeds (the normal case, per `TestEditMarketplace_MarketplacesSaveFailureRestoresTheOldClone`/`...RestoresTheStore`), `err` is returned verbatim. For the non-renaming re-source path, `err` comes from `m.saveMarketplaces(mk)` (line ~507), which returns `marketplaceAtomicWriteFile`'s error verbatim; `atomicWriteFile` builds messages like `"creating temp %s: %w"` / `"renaming %s -> %s: %w"` using absolute destination/temp paths (`internal/plugins/atomic.go:39,58,71`). For the rename path, `saveRename` (line ~625) wraps the same raw error with `%w`. Because `marketplaceRefusalToWire` returns non-sentinel errors as-is, the absolute path reaches the RPC client — defeating the leak fix this commit targets.

The new tests only cover the rollback-*failure* case (`TestEditMarketplaceRollbackFailureNamesNoPath`), so this gap is untested.

**Fix**: Scrub the cause in the success-rollback branch too — log `err` raw server-side and return a generic error naming only the marketplace and the store file (e.g. `marketplace %q: saving %s failed; see the hub's log for detail`). Preserve the store file name in the returned message, since `TestEditMarketplace_MarketplacesSaveFailureRestoresTheStore` asserts `strings.Contains(err.Error(), marketplacesFileName)` — `saveFailed`'s current wording would not satisfy that. Add a successful-rollback test using a real `*fs.PathError`.

## Low

### `storeChangeRollbackFailed` doc comment names `ensureFetched`, which never reaches it
`internal/plugins/marketplaces.go:272, 280`

Two reviewers flagged this. The comment claims the shape is hit by `AddMarketplace`, `ensureFetched`, and `EditMarketplace`'s `fail` closure, but `ensureFetched` has no rollback — on save failure it returns `m.saveFailed(name, err)` (line ~166) and leaves the freshly cloned directory in place (as its own test comment at `marketplaces_path_scrub_test.go:19-23` describes). A maintainer reading this comment would expect a rollback path in `ensureFetched` that doesn't exist.

**Fix**: Remove `ensureFetched` from the comment so it names only the double-failure callers (`AddMarketplace` and `EditMarketplace`'s `fail` closure).

### New no-git marketplace fixture duplicates an existing helper
`internal/plugins/marketplaces_path_scrub_test.go:227`

The new no-git marketplace fixture duplicates `makeMarketplaceRepoDirNoGit` in `internal/plugins/doctor_test.go:656`.

**Fix**: Reuse the existing helper or consolidate both into one shared test fixture.
