### Medium

**`directWriteInFlight` is not tracked by generation/token — two distinct failure modes**

`appwire-client/typescript/keybindingsStore.ts:765-777, 1106-1147`

Two related defects stem from the same root cause: the `directWriteInFlight` flag is cleared unconditionally by whichever request's `finally` runs, without checking whether that request still owns the flag.

- **Flag stuck set (Review 1):** A fenced request that remains pending after a generation reset or support flap never reaches its `finally`, leaving `directWriteInFlight` set indefinitely. All subsequent `saveDraft` calls remain permanently unavailable.

- **Flag cleared by stale request (Review 4):** If `reset()` runs while an old `patchOverrides` request is pending, a newer direct write can start and set the flag. The old request's `finally` then unconditionally clears the newer write's flag, allowing `saveDraft` to start while the newer direct PATCH is still in flight — recreating the race this flag was added to prevent.

**Suggested fix:** Track the in-flight direct write by its claimed token/generation and clear the flag only if that owner is still current. A regression test should cover a deferred old request, `reset()`, a newer direct write, and a subsequent `saveDraft`.
