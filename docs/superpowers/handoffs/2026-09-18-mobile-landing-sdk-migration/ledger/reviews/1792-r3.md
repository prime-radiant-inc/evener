## roborev: Combined Review (`db77103`)

**Summary:** Atomic draft checkpoint handling and unreadable-draft recovery land with a generation-conflict laundering bug and a broken offline discard path.

## High

- **Editing an existing draft launders a cross-generation conflict** — `appwire-client/typescript/keybindingsStore.ts:1294`
  Editing an existing draft always restamps it with the current ready generation. After a hub replacement that coincidentally reports the same revision, any edit clears the generation-based conflict and allows `saveDraft` without the required `rebaseDraft`, potentially overwriting the new hub's settings.
  **Fix:** Preserve the existing draft's `generation` (including `null`) when modifying it; assign the current generation only when creating a draft with no existing draft. Add a same-revision generation-change test that edits the conflicted draft and asserts the conflict remains.

## Medium

- **Offline discard silently no-ops when a model is bound but the connection is down** — `mobile-native/src/KeybindingPreferencesScreen.tsx:187-200` (with `run` at `:109-110`)
  The fallback branch is documented as covering "the connection dropped after this record was shown," but reaching it requires `model === null`. In the dropped-connection case `model` stays non-null (the provider keeps `bound` until `client` is replaced, and `ConnectionProvider` keeps `session.client` after a socket close). The handler takes the `if (model)` path, calls `run(...)`, and `run` returns immediately because `scope.connected` is false. The button is enabled (no `!preferences.connected` guard), so the user gets a dead control and can never clear the unreadable record while offline — even though `model.discardKeybindingsDraft()` would succeed offline since `assertDiscardable` does not require support. This wrapper is currently untested.
  **Fix:** Call the store-free path whenever the store-based call cannot run — e.g. `if (model && preferences.connected) model.discardKeybindingsDraft(); else preferences.discardUnreadableKeybindingsDraft();` — and add a provider/screen test that exercises discard while disconnected.

## Low

- **Successful store-free discard leaves the stale restore-failure error visible** — `mobile-native/src/NativePreferencesProvider.tsx:131-149`
  When the record is classified unreadable, `restoreDraft` publishes `draftError: DRAFT_RESTORE_FAILED_MESSAGE`, exposed as `error`. The store-free fallback spread only resets `draftUnreadable` and `storageUnavailable`, so after a successful discard `domain.error` still reads the restore-failure message and `ErrorMessage` keeps rendering it. The store-based `discardDraft` path clears `draftError`; the store-free path should too.
  **Fix:** Add `error: null` to the updated `keybindings` snapshot, mirroring `restoreDraft`/`discardDraft` success.

- **`discardStoredKeybindingDraft` returning false leaves a stale unreadable notice** — `mobile-native/src/NativePreferencesProvider.tsx` (`discardUnreadableKeybindingsDraft`)
  When `discardStoredKeybindingDraft` returns `false`, the snapshot is left untouched, so an externally removed or replaced record leaves a stale unreadable notice with an action that repeatedly does nothing, instead of re-classifying like `discardDraft` does on refusal.
  **Fix:** Refresh or clear the stale `draftUnreadable` state when nothing was removed, or surface that the record changed.
