## roborev: Combined Review (`db3b131`)

**Verdict: Mechanically sound extraction, but the new raw-identity/discard logic is partly unreachable, untested, and leaks a type-contract violation into the port.**

## Critical

None.

## High

None.

## Medium

- **`discardClassified()` ignores whether `removeIf` actually removed the checkpoint** — `draftCheckpointPort.ts:114-119`, `keybindingsStore.ts:1197-1205`
  If another store replaces the checkpoint, the replacement remains persisted but the current store clears its in-memory draft and hides it until remount.
  *Fix:* Return the removal result and reclassify/adopt the current stored checkpoint when removal is refused.

- **`discardStoredDraft` passes a raw `unknown` to `removeIf(checkpoint: Checkpoint)`, violating the port's typed contract** — `draftCheckpointPort.ts:30`
  A conforming adapter may assume a decoded checkpoint and throw or no-op on malformed data, defeating the helper's documented purpose.
  *Fix:* Make raw-value removal part of the port contract (`removeIf(value: unknown)` or a separate `removeRawIf`), and update the keybinding storage interface and test double accordingly.

- **New raw-identity and discard logic has no direct test coverage** — `draftCheckpointPort.ts:60-120`, `testing/draftStorage.ts:24`, `keybindingsStore.test.ts:353`
  Reported by three reviewers. No test exercises: discard after external replacement (removes nothing), discard after save (removes the new record), load of an extra-field record followed by `removeIf` clearing storage, corrupt-record discard via `discardClassified`, or the exported `discardStoredKeybindingDraft` helper. The `memoryDraftStorage` `initial` parameter — clearly added to seed an extra-field record — is never passed.
  *Fix:* Add behavior tests with the byte-comparing fake: seed `memoryDraftStorage<KeybindingDraftCheckpoint>({ ...checkpoint, futureField: 1 })`, build a store, call `discardDraft()`, assert `drafts.stored()` is `null`; cover replacement-preservation and malformed-record removal.

## Low

- **`rawFrom` is unreachable in the current codebase** — `draftCheckpointPort.ts:78,92,106`
  `rawFrom` is populated only in `load()` (keyed by the decoded checkpoint object), but the sole `removeIf()` caller (`keybindingsStore.ts:1184`) passes a save-produced object that was never a `rawFrom` key. `discardClassified()` bypasses `removeIf()` entirely, so `rawFrom.get(...)` is always `undefined` and the `?? decode(checkpoint)` fallback is the only branch taken.
  *Fix:* Delete `rawFrom` and have `removeIf` always `decode()` (matching the sole caller), or wire a caller that passes a load-produced checkpoint and add coverage proving the raw identity is used.

- **`discardStoredKeybindingDraft` is a generic alias, not bound to `KeybindingDraftStorage`** — `index.ts:214`
  The keybinding-specific name accepts any checkpoint type.
  *Fix:* Export a specialized wrapper typed as `(storage: KeybindingDraftStorage) => void`.

- **`invalidDraft()` throws `UnreadableDraftError` for both user-input validation and storage decode** — `keybindingsStore.ts:312`
  Conflates validation failure with an unreadable stored record.
  *Fix:* Keep user-input validation throwing plain `Error`; only throw `UnreadableDraftError` from the storage decode path.

- **`stored()` casts the corrupt `{invalid:true}` value to `Checkpoint`** — `testing/draftStorage.ts:24-30`
  Hides non-checkpoint state from type-checking; the prior helper returned `unknown`.
  *Fix:* Type `stored()` as `unknown` or add a separate accessor for the raw stored value.

- **`createDraftRepository<Checkpoint>` is unconstrained but uses `WeakMap<object,unknown>`** — `draftCheckpointPort.ts:60-75`
  A primitive checkpoint type would throw on `set` (`checkpoint as object`).
  *Fix:* Constrain with `Checkpoint extends object`.
