## roborev: Combined Review (`953d176`)

**Verdict: Test is valuable, but has two medium-severity issues to fix before merge.**

## Medium

- **Data race on `oneShotAskUserAdapter.used`** — `server/askpending_live_notification_test.go:37,51,54`
  - `used` is read and written without synchronization while the asynchronous session namer goroutine (`agent/session_lifecycle.go:2510` → `launchInitialPromptNamer` → `nameSessionFromText`, `agent/session_namer.go:302-323`) and the main model turn both call the same `llm.Client`. The namer invokes `Complete` with no tools while the main turn writes `a.used = true`; because Go's `||` evaluates `a.used` first, the namer goroutine reads shared state on every path, and `llm.Client.Complete` (`llm/client.go:325`) holds no lock. This will intermittently fail the required `test-race` CI gate.
  - Existing server-test adapters avoid this deliberately: `fakeAdapter` guards mutable state with a mutex (`agent/session_test.go:36-47`), and `mutationProjectionAdapter`/`steeringOwnerReplayAdapter` early-return for the toolless namer request before touching counters (`server/appwire_rejoin_test.go:242-259`, `server/appwire_steering_owner_replay_test.go:152`).
  - **Fix**: Protect `used` with a `sync.Mutex` (matching `fakeAdapter`) or reorder so the toolless namer request short-circuits before reading shared state (`if !offersAskUser || a.used`).

- **`ConsumeEventsLossless` wrapped in `go` races registration** — `server/askpending_live_notification_test.go:116`
  - `ConsumeEventsLossless` already starts its drain goroutine and returns once lossless registration is in effect. Wrapping the call in `go` races registration against `ProcessInput` and can leave buffered events unconsumed if the goroutine loses to session close.
  - **Fix**: Call `sess.ConsumeEventsLossless(...)` synchronously; remove the surrounding `go`.
