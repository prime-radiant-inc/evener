## Summary

This commit (piece 1 of 3 of the reasoning-export work) centralizes two cross-host helpers into the shared `@evener/appwire-client` package:

1. **`joinedReasoningParagraphs`** moves from the frontend's `reasoningFormat.ts` into `appwire-client/typescript/reducer.ts` (next to `pendingTextJoined`, which it uses), and is now exported from the package root. `reasoningFormat.ts` re-exports it so `ThinkBlock.tsx` keeps a single import site.
2. **`isActiveItem`** moves from two duplicated definitions in `transcriptProjector.ts` (web) and `mobile/src/conversation/project.ts` (native) into `appwire-client/typescript/itemFailure.ts`, exported from the root. Both hosts now import it, and callers updated to pass `turn.status` instead of the full turn object.

I verified the two prior `isActiveItem` implementations are semantically identical to the unified one:
- Web old: `isInProgressStatus(item.status) || (isInProgressStatus(turn.status) && item.status === undefined)`
- Mobile old: defined status decides, else turn status
- New: `isInProgressStatus(item.status) || (isInProgressStatus(turnStatus) && item.status === undefined)`

These agree on all branches (defined-and-inProgress, defined-and-settled, undefined), so this is a behavior-preserving refactor. Import wiring is consistent (`project.ts`, `conversation.ts`, `transcriptProjector.ts`), no stale references to the removed definitions remain, `ItemFailureSignals`/`isInProgressStatus` imports are still used, and existing frontend tests exercise the moved reasoning helper through the re-export including live chunk-view cases.
