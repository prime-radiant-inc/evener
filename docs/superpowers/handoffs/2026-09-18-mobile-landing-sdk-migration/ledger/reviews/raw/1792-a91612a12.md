## Review Findings

- **Severity**: Medium
- **Location**: `appwire-client/typescript/keybindingsStore.ts:1397-1402`
- **Problem**: When `removeIf`/`replaceClassified` refuses because another writer replaced the checkpoint, `setState(refused)` omits the settlement fields, so `saving` remains `true` from the in-flight save. Subsequent refreshes also avoid settling while `saving` is true, leaving the editor permanently blocked.
- **Fix**: Merge the `settled` fields with the restored state, ensuring `saving` is cleared while adopting the replacement draft.

---

- **Severity**: Medium
- **Location**: `mobile-native/src/nativePreferenceDrafts.ts:45-49`
- **Problem**: The semantic fallback comparison can mistake different unreadable records for the same record. For example, raw stored bytes `null` become the value `"null"`; if a concurrent writer replaces them with JSON string `"null"`, the parsed JSON comparison succeeds and the replacement can be deleted or overwritten.
- **Fix**: Preserve raw-byte provenance with an explicit sentinel and require exact byte matching for raw values.

---

- **Severity**: Medium
- **Location**: `appwire-client/typescript/keybindingsStore.ts:696-698, 826-829`
- **Problem**: Persisted drafts lose their generation identity, are restored with `generation: null`, and are automatically stamped as trusted by the first authoritative payload. A fresh native store after a hub restart can therefore accept a stale draft when the new session reuses the same revision, allowing it to overwrite current settings without raising a conflict.
- **Fix**: Persist a stable hub/session identity, or keep restored drafts untrusted and require explicit review/rebase before saving.

## Summary

The change adds shared draft persistence, unreadable-record recovery, atomic settlement, and generation-aware keybinding drafts, but has settlement-locking, compare-and-swap, and persisted-generation safety issues.

- **Severity**: Medium
  **Location**: `mobile-native/src/NativePreferencesProvider.tsx:108`
  **Problem**: The cold-offline storage probe calls `nativeKeybindingDrafts(...).load()` inside `useEffect` without exception handling. The draft port explicitly permits `load()` to throw, so an unavailable storage backend can throw during the effect and crash or break the provider instead of surfacing a storage-unavailable state.

- **Severity**: Low
  **Location**: `mobile-native/src/nativePreferenceDrafts.ts:136`
  **Problem**: `nativeTranscriptDrafts.load()` treats every backend value equal to the string `"null"` as absent. Since `parseDraftBytes` returns `"null"` both for stored JSON `null` and for a stored JSON string `"null"`, the latter corrupt checkpoint is silently treated as no draft, contrary to the transcript repository’s contract to reject invalid checkpoints.
  **Fix**: Preserve the distinction between JSON null and a parsed JSON string—for example, use a tagged JSON-null sentinel understood by matching/removal—so transcript loading accepts true JSON null but rejects a corrupt string checkpoint.
