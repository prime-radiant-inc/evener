## Summary

The series closes a gap in transcript-display PATCH handling across the hub, web, and native clients. Previously, a durable write failure occurring *after* the atomic rename (the patch had already applied and the store had already published the new revision) was returned as a plain internal error. Callers treated it as a rejected write, so other clients stayed on the old revision and the requesting client was blocked behind a `writeUncertain` state.

The commits:
- Add `appwire.ErrorTranscriptDisplayPostApply` and `TranscriptDisplayPostApplyData`, and wrap post-rename failures in `hubcore.TranscriptDisplayPostApplyError` (mirroring `KeybindingsPostRenameError`).
- Make the hub RPC handler broadcast the applied layout and return the applied canonical value in the error data when a post-apply fault occurs.
- Teach the web store to reconcile from the applied value (with the existing stale-token/generation fence) instead of surfacing a hub error/clearing blindly.
- Teach `NativePreferences.saveTranscript` to adopt the applied value rather than entering `writeUncertain`.
- Add store/RPC/web/native tests, including the stale post-apply fence.

The aggregate diff matches the stated intent and mirrors the established keybindings-store pattern consistently.

## Review Findings
- **Severity**: Low
  - **Location**: `mobile-native/src/nativePreferences.ts:109`
  - **Problem**: `postApplyPatch` trusts the `transcriptDisplayPostApply` discriminator but does not verify `data.layout === "mobile"` before adopting `data.applied`. A malformed or mismatched post-apply payload can therefore be treated as a confirmed mobile write, clear the uncertain-write checkpoint, and unblock further edits.
  - **Fix**: Require the error payload’s layout to match `"mobile"` before decoding `applied`, and add a rejection-path test for a post-apply payload scoped to another layout.

## Summary
Transcript-display patches that apply before a follow-up durable failure now broadcast and carry the applied canonical state, while web and native clients reconcile that state instead of treating the write as rejected.
