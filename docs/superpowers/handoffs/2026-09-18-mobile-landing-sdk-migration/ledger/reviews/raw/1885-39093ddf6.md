## Summary

The series moves the "session vs loaded" token labelling into the shared `appwire-client` package (`tokenUnitLabel`), has the native transcript footer derive Input/Output from the shared `sessionTokens` fallback while rendering the thread's cumulative `Cached`/`Total` figures with their own independent unit, and keeps the mobile conversation store's `turns`/`olderCursor` in sync with its own item paging so that a thread with no cumulative usage sums the turns it has actually loaded. `loadOlder` now returns the page's own turns for the store to merge, and `rehydrate` preserves turns/cursor that fall outside its bounded reread window.

---

**Medium — `rehydrate` re-conflates the store's capped paging cursor with the wire's history cursor, so session tokens get mislabelled after an at-cap page load**

`mobile/src/state/conversation.ts:1886` (`olderCursor: mergedCursor ?? undefined`), with `mergedCursor` set from `currentSnapshot.olderCursor` at line 1786.

`loadOlder` deliberately separates the two cursors: `conversation.olderCursor = result.nextCursor` (the wire truth) while `store.olderCursor = nextCursor`, which is forced to `null` once the retained-item cap is hit (lines 2062–2068). On the next `rehydrate`, the code assigns `conversation.olderCursor = mergedCursor`, and when `preservePageHistory` is true (`pageOwnedIds.size > 0`), `mergedCursor` is overwritten with `currentSnapshot.olderCursor` — i.e. the store's paging cursor, which is `null` at the cap. So after an at-cap `loadOlder` followed by any rehydrate, `conversation.olderCursor` becomes `undefined`.

Concrete harm: `sessionTokens` (appwire-client/typescript/threadUsage.ts:95) treats a falsy `olderCursor` as proof the in-hand turns are the whole transcript and returns `scope: "session"`. In the partial-cap case (e.g. the round-4 test's 400 items + 200 older → 500 retained, where 100 older rows and their turns survive), the preserved `turns` are still only a suffix of the transcript, yet the web details panel and native footer now label that partial sum `tokens` instead of `tokens (loaded turns)` — the exact overstatement this series exists to prevent. This also directly contradicts commit c8b8785's stated goal ("honor the wire's older-history cursor … on rehydrate"); the added test only asserts the cursor immediately after `loadOlder`, never after a subsequent rehydrate.

Suggested fix: keep the two concerns separate. The store field should remain the paging cursor (`olderCursor: mergedCursor`), but the conversation field should carry the accumulated wire cursor, e.g. prefer the preserved conversation's cursor when page history is retained: `olderCursor: preservePageHistory ? (currentConvForMerge?.olderCursor ?? mergedCursor ?? undefined) : (mergedCursor ?? undefined)`. Add a test that runs `rehydrate` after an at-cap `loadOlder` and asserts `conversation.olderCursor === "more"` and `sessionTokens(conv)?.scope === "loaded"`.

---

**Low — preserved older turns are gated on item page ownership, so an at-cap page that discards all incoming rows also drops the turns it contributed**

`mobile/src/state/conversation.ts:1876-1881` (`if (preservePageHistory && currentConvForMerge !== null)`), where `preservePageHistory` is defined at lines 1698-1700 as `pageOwnedIds.size > 0`.

`pageOwnedIds` is populated from the page's *items* and then pruned by `pruneEvictedIds` for anything the cap evicted (lines 1245-1246). When the conversation is already at the cap, `loadOlder` prepends the page's rows only to have the cap discard all of them, so `pageOwnedIds` is pruned to empty. `rehydrate` then evaluates `preservePageHistory` as false and sets `mergedTurns = conversation.turns` (the reread's bounded window), discarding the older turns that `loadOlder` had merged into `conversation.turns` — even though those turns are still logically retained (turns are not capped). The turn-summed fallback then understates the loaded total until `loadOlder` is called again, which cannot happen because the store cursor is now `null`. Suggested fix: gate turn preservation on whether the store holds turns outside the reread window (or on a turn-specific page-owned marker) rather than only on surviving page items.

---

No security issues found. The new `tokenUnitLabel` export and the `accountingFor` cache/total handling are consistent with the `EvenerUsage` optional-field contract in `types.gen.ts`.
