## Summary

The three-commit series moves shared client behavior into the AppWire TypeScript package and hardens two client-side edge cases:

- **Reasoning export:** `joinedReasoningParagraphs` is relocated from the frontend's `reasoningFormat.ts` into `appwire-client/typescript/reducer.ts` and exported from the package root; the frontend now re-exports it so `ThinkBlock`/`reasoningFormat` remain the single import surface.
- **Shared active-item predicate:** `isActiveItem` is consolidated from duplicate copies in `transcriptProjector.ts` and `mobile/src/conversation/project.ts` into `itemFailure.ts` (taking `ItemFailureSignals` + turn status), and both hosts import it from the package. The consolidated logic is semantically identical to both prior implementations, and the mobile store's `conversation.ts` import is updated accordingly.
- **Image folding:** `imagesToItemImagesForSession` documents and relies on the "empty input list = absent" reading so an empty `images: []` frame cannot erase an older page's images via `mergePageItem`, with tests covering hydrate, `item/completed`, `turn/completed` full restate, and `mergeOlderItemPage`. Output images deliberately keep their opposite (removal-signaling) reading.
- **Warning text:** A message-less warning frame now falls back to a bounded (`RAW_WARNING_FRAME_MAX_CHARS = 2000`, code-point-safe) rendering of the frame itself unless a non-blank `title`/`hint` exists, in which case `text` stays blank and the structured fields render (web `WarningItem`); mobile's generic activity fallback adds `warningFallbackText` so a title/hint-only warning no longer becomes a blank row. `itemSummary` guards `warning.title` against non-string runtime values.

No issues found.

The changes are internally consistent: the shared `isActiveItem` is behavior-preserving for both call sites, the warning-text branch is consistent with `WarningItem.tsx`'s existing render contract and its tests, and the new tests exercise observable merge/projection behavior rather than restating code.
