######## member 2 (pi default)
## Summary

The series scrubs absolute plugin-store paths from errors returned by the marketplace manager's public verbs, so callers/RPC clients see a message naming the marketplace and the store file instead of this machine's filesystem path (raw detail goes to `m.stderr()`). It does this with three new helpers (`saveFailed`, `rollbackFailed`, `storeChangeRollbackFailed`), makes `saveRename` report which store file actually failed, reorders `RemoveMarketplace` so the metadata save precedes clone removal (a clone-cleanup failure now surfaces as an error stating unregistration succeeded), and reports rollback failure distinctly in `EditMarketplace`'s `fail` closure. A new `marketplaces_path_scrub_test.go` covers each write/rollback failure with real `*fs.PathError`s, and existing tests plus the coverage fuzz test are updated for the signature/behavior changes.

## Issues

No issues found.

The core behaviors are consistent with the stated goal: `saveFailed` is applied on every marketplace save path, `failedFile` from `saveRename` correctly distinguishes `installed_plugins.json` from `known_marketplaces.json`, the `errStoreBetweenNames` identity is preserved through `%w`, and the `EditMarketplace` `fail` closure still returns the unaltered cause when the outer undo is a no-op (preserving `TestEditMarketplace_FailedUndoNamesWhatItCouldNotRestore`). The migration call sites intentionally continue to return raw `saveRename` errors, consistent with the scope of these marketplace verbs.
