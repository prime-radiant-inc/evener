## Summary

This 45-commit series refactors the keybindings draft editor and the hub ready-generation plumbing in `@evener/appwire-client`, then extends the native layer to recover from unreadable draft records.

What the final aggregate diff does:

- **Extracts two shared SDK modules.** `draftCheckpointPort.ts` generalizes the checkpointed draft repository (`DraftPort<Checkpoint>`, `createDraftRepository`, `discardStoredDraft`, `UnreadableDraftError`) so the keybindings store and a future transcript store share the decode/compare-and-swap/identity handling. `settingsHubGeneration.ts` extracts the fence-begin/end + notification wire/unwire and the payload-retirement/lost-write settle primitives (`retireSettingsHubPayload`, `settleUnsettleableWrite`, `createSettingsHubGeneration`).
- **Fixes generation-scoped draft staleness.** `KeybindingsDraft` carries a `generation` stamped only by an authoritative payload (or an explicit rebase), so a hub replacement that coincidentally reports the same revision is still flagged stale; `editDraft` preserves an existing stamp instead of laundering the conflict.
- **Hardens write settlement.** `settledWrite` re-marks a checkpoint atomically via `replaceClassified`, adopts a replacement when the CAS refuses, distinguishes a lost hub from a superseded write (`fence.lostHub`), gates the two write paths on one token (`directWrite` reservation), and always clears `saving` on a reconciler throw.
- **Adds an unreadable-record recovery path.** `draftUnreadable` separates a dead port from an unreadable record; the native provider detects it independently of a live model, and the screen offers a store-free "Discard unreadable draft" that refuses to delete a record a concurrent writer replaced with a readable one.
- **Native ports gain boolean CAS.** `deleteIf`/`replaceIf` return whether they matched, `parseDraftBytes` surfaces unparseable/JSON-null bytes as present-but-unreadable records, and shared test fakes replace the per-store copies.

The extensive test additions exercise the new behaviors (generation stamps across hub replacement, refusal adoption, support flaps, concurrent writers, offline discard, noncanonical byte compares). I found no logic error, security issue, or regression with concrete evidence in the diff: the spread ordering in `applyHubOverrides` correctly lets a settle's adopted draft override the pre-settle snapshot, the `directWrite` reservation is always cleared by the queued `run`'s `finally`, and the `settledWrite` guards (`writeSerialAtStart`, `savingAtReadStart`) correctly prevent a read from settling a write it raced.

No issues found.
