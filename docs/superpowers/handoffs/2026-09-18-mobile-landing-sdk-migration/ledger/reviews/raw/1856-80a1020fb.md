## Summary

The series extracts the web's mutation-projection generation fencing into a reusable, package-only `createMutationProjectionFence` in `appwire-client/typescript/state/mutation/projection.ts`, adds its types to the package's public surface, and adds a thorough test suite. The final design:

- `refresh(port, ref?)` assigns a generation (all-targets refreshes also raise a global floor), performs the durable read, and returns either `false` (read failure or reset epoch mismatch) or a `{ snapshot, apply() }` handle.
- `apply()` re-evaluates the per-target generation floor at call time, so a live `advance()` or a newer refresh landing after the read resolved still wins.
- `advance(ref)` records a commit's generation without a read; `reset()` bumps an epoch and clears generations; `epoch()` exposes it for callers.

The behavior mirrors the existing `pendingTurnsStore.readProjectionIntoStore` logic (generation assignment before the read, no rollback on a failed newer refresh, per-target floors) and strictly tightens it with the deferred re-check, so it does not introduce a behavioral regression. The tests cover single/all-targets acceptance, read failure, reset invalidation, epoch reuse after reset, `advance` after resolution, a newer all-targets start fencing, a failed newer refresh fencing an older one, and a commit after a failed refresh.
