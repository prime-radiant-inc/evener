## Summary

The commit series (#1731 piece 2/3) does two things. First, it fixes input-image "folding" for live lifecycle events: the mobile conversation store (`mobile/src/state/conversation.ts`) previously derived attachment rows from the raw wire `ThreadItem`, so an `item/started`/`item/completed` carrying no `images` field (or `images: []`) dropped the attachment row the reader was looking at. It now consults the reducer-folded `ItemModel` (via `findFoldedItem` + the newly exported `itemAttachments`), matching the hub's own `MergeInputImages` rule (empty/absent input images say nothing; output images are the opposite, where a non-nil empty list is an explicit removal). The reducer's existing rule is documented, and tests cover live settles, page merges, and transcript-key replacement across wire ids.

Second, it hardens and centralizes warning-text handling. `hasWarningText` and `foldWarningParams` are added to the package, warning `title`/`hint`/`source` are normalized to string-or-absent at the source, a message-less frame falls back to the bounded, surrogate-safe raw JSON frame (`rawWarningFrame`, 2000 code points), and the web (`WarningItem.tsx`, `transcriptProjector.ts`) and mobile (`conversation.ts`, `project.ts`) consumers read that validated shape instead of raw `params`. A mobile reasoning-display fix (prefer authoritative `item.text` over a possibly stale seeded `reasoningSummaries`) is also included.

The functional changes are internally consistent with the hub's wire semantics, and the added tests exercise real behavior rather than tautologies.

## Findings

**Severity: low** — `mobile/src/state/conversation.ts:2545-2546`

The comment directly above the changed attachment logic still states the old contract:

```
// Lifecycle events replace the whole source item, including any
// companion attachment row. An empty image list removes it.
```

The code two lines below now deliberately does *not* remove the attachment row when the wire item omits or empties its *input* images (it reads the folded `ItemModel` instead); only an explicit empty `outputImages` list removes. A future maintainer acting on this comment could reintroduce the exact bug this series fixes. Suggested fix: reword to say an empty/absent *input* image list keeps the existing row, while an explicit empty *outputImages* list removes it (input removal has no wire signal).
