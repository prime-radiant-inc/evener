## Summary

This 35-commit series refactors the keybindings draft editor and its settings-hub plumbing into shared, generic primitives, then adds a new transcript-display hub store:

- **Extracted primitives** (`appwire-client/typescript/`): `draftCheckpointPort.ts` (generic `DraftPort`/`DraftRepository` with atomic `removeIf`/`replaceIf` and a tri-state classification), `checkpointedDraftEditor.ts` (shared `assertDraftDiscardable`/`persistCheckpointedDraft`/`discardCheckpointedDraft`), and `settingsHubGeneration.ts` (ready-generation begin/end wiring, payload retirement, lost-hub settle).
- **Keybindings store**: drafts now carry a `generation` stamp so a hub replacement that coincidentally reuses a revision is still detected stale; `restoreDraft` never stamps the live generation itself; settled writes adopt a checkpoint replaced under them via `replaceClassified`; uncertain writes are re-marked rather than re-persisted; `editDraft` preserves the existing stamp; direct and checkpointed writes share one write token so neither fences the other's reply out; `draftUnreadable` distinguishes an unreadable record (discardable) from a dead port.
- **Native (mobile)**: `deleteIf` now reports whether it removed the record, a `replaceIf` was added for atomic settles, `parseDraftBytes` surfaces unreadable records as raw bytes instead of throwing or silently reading "absent", and an offline store-free discard path plus UI action were added.
- **New** `transcriptDisplayStore.ts`: the hub-defaults + direct-write core (per-layout confirmed defaults, previews, conflict adoption, generation-aware stale guard via `awaitingFirstPayload`), with tests; it is groundwork for a later piece and not yet exported/wired.

The tests cover the races the commits target (replaced checkpoints, lost replies, support flaps, generation resets, stale replies, fallback storage, unreadable-record discard), and I found no logic error, security issue, or regression with concrete evidence in the diff.
