## Summary

The commit simplifies `useHubConnection` by replacing the `ConnectionTarget` interface and field-by-field `sameTarget` comparison with a single `JSON.stringify` key (`targetKey`) and by storing the concrete `AppwireClient` in the `connectedFor` ref instead of reading it back out of the store. It moves the per-run store/ref reset from the effect body into the effect cleanup (which React always runs before the next body), and adds `state: "connecting"` to the client-swap write so the freshly built, not-yet-dialed client doesn't briefly surface the core's `"idle"`. The test suite is refactored around a `mount()` helper, and the two "never returns the previous client" tests (switched hub / bumped retry) are merged into one parameterized `it.each`.

I traced the generation/race behavior (pre-cleanup render, cancelled-guarded async token fetch, cleanup resetting both ref and store, StrictMode double-invoke, ref-vs-store synchronization, and the `JSON.stringify` key's collision resistance for the `string | undefined` fields) and the store-merge semantics in `state/connection/core.ts`. The ref and store are always written together, every `setState` produces a new snapshot so no ref-only update can be missed by `useSyncExternalStore`, and the key includes every field that opens a new connection, so the stale-client window remains closed. The parameterized test still captures the intermediate race render and is not vacuous. No functional, security, or coverage regressions found.
