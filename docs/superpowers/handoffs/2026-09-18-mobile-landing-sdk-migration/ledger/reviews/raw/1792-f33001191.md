## Summary

The 32-commit series refactors the keybindings draft editor's persistence into a reusable `draftCheckpointPort`, extracts the ready-generation fence (adding `lostHub`), and fixes a cluster of settle/race behaviors:

- `KeybindingDraftStorage` becomes `DraftPort<KeybindingDraftCheckpoint>` with atomic `replaceIf`, and checkpoint identity is tracked as raw bytes so byte-comparing native ports can still remove a record whose decoded form drops unknown fields.
- Drafts now carry a `generation` stamp so a draft composed against a previous hub session is not mistaken for current when the new hub coincidentally reports the same revision; `restoreDraft` never stamps a live generation, and only an authoritative payload or an explicit rebase earns one.
- An unreadable *record* is distinguished from an unreachable *port* (`draftUnreadable` / `UnreadableDraftError`), is discardable, and no longer locks the section; `parseDraftBytes` lets the native backend surface it as a present record.
- Both write paths share one write token ( `directWrite` claim), settle helpers publish `saving`/`writeUncertain` even when a reconciler throws, and `settleWrite` adopts a checkpoint that another writer replaced under a write.

The implementation is well covered by new tests in `draftCheckpointPort.test.ts`, `nativePreferenceDrafts.test.ts`, and the expanded `keybindingsStore.test.ts`, and I did not find a high- or medium-severity defect.

---

**Severity: low** — `appwire-client/typescript/draftCheckpointPort.ts:66`

`discardStoredDraft` maps a *refused* conditional removal to `"absent"`:

```ts
return storage.removeIf(value) ? "removed" : "absent";
```

`DiscardStoredDraftResult`'s contract says `"absent"` means "there was nothing stored to discard", and `"refused"` is reserved for a record that still decodes as valid. A `removeIf` that returns `false` means neither: the record is still present but its bytes changed between the `load()` on line 63 and the removal (e.g. another writer replaced the unreadable record with a different unreadable one, or the port's byte compare cannot reproduce the stored encoding). Concretely, `NativePreferencesProvider.discardUnreadableKeybindingsDraft` (`mobile-native/src/NativePreferencesProvider.tsx:132-160`) treats every non-throwing outcome as a reason to clear `draftUnreadable`/`storageUnavailable`/`error`, so the "Discard unreadable draft" affordance disappears while an unreadable record remains on disk, until a later restore happens to re-read it.

Fix: return a distinct outcome (or re-`load()` after a `false` and return `"refused"`/`"changed"`) so callers can tell "already gone" from "still there, but not the bytes I named".
