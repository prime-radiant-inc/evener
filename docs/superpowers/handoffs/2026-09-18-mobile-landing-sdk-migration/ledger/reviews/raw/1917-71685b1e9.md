## Review Findings
- **Severity**: High
- **Location**: `mobile-native/src/mutationOutboxStorage.ts` `enqueueIntent`
- **Problem**: Persisted `payload` omits `clientMutationId` while the oracle (`MutationOutboxIndexedDB.enqueueIntent`/`resendRecovery`) stores `payload: {...intent.payload, clientMutationId}`. The dispatcher sends `record.payload` as RPC params then requires `receipt.clientMutationId === record.clientMutationId`, so a natively enqueued intent can never correlate.
- **Fix**: Inject the minted id into the stored payload before insert, matching the oracle, and update the reload test to expect it.
---
- **Severity**: High
- **Location**: `mobile-native/src/mutationOutboxStorage.ts` constructor `#createMutationId` default
- **Problem**: Defaults to bare `crypto.randomUUID()`, but `appwire-client/typescript/state/mutation/secureUUID.ts` explicitly provides no default source because a host may have no global WebCrypto and must pass `randomUUID`/`getRandomValues` explicitly. On Hermes without a global this throws at first enqueue.
- **Fix**: Take an injectable `SecureRandomSource`/id factory defaulting to `createSecureUUID`-style fallback instead of naming the global, as the web store does.
---
- **Severity**: Medium
- **Location**: `mobile-native/src/mutationOutboxStorage.ts` `enqueueIntent`, `settleReceipt`, `transferToRecovery`
- **Problem**: Each does 2 dependent writes as separate statements with no transaction, while the oracle uses multi-store IndexedDB transactions and `mobile-native/src/draftRepository.ts` uses `SAVEPOINT draft_write`. A crash between sequence-bump/insert or insert/delete leaves a sequence gap or the same id in two tables.
- **Fix**: Wrap each pair in a SQLite transaction/`SAVEPOINT` with rollback on failure, following the draft repository pattern.
---
- **Severity**: Medium
- **Location**: `mobile-native/src/mutationOutboxStorage.ts` `settleReceipt`
- **Problem**: Only reads the outbox table and returns `false` otherwise, while the oracle resolves `outbox ?? recovery ?? optimistic` and settles from whichever holds the id. A duplicate/late receipt for an already-moved record reports failure, inconsistent with this file's own 3-table `settleApplied`.
- **Fix**: Look up all three tables and delete from whichever holds the id, returning `true` when any held it.
## Summary
Native outbox port mirrors the read/write contracts but drops the payload id, assumes a global RNG, and leaves multi-table transitions non-atomic and receipt settlement single-table.
