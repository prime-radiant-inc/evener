## Review Findings

- **Severity**: Medium
- **Location**: `appwire-client/typescript/keybindingsStore.ts:1162,1268`
- **Problem**: `patchOverrides()` queues its work with `writeQueue.then(...)` but does not mark `directWrite` until the queued callback runs. A same-turn `saveDraft()` can therefore claim the write first; the queued direct write then sees `saving` and is rejected, so the earlier `patchOverrides()` call never sends its PATCH.
- **Fix**: Track pending direct-write reservations when `patchOverrides()` is called, and include them in `saveDraft()`’s gate (or serialize both APIs through one shared queue).

## Summary

The changes extract shared draft persistence and add atomic checkpoint handling, but leave a same-turn race between queued direct writes and draft saves.

######## member 2 (pi default)
## Summary

The 25-commit series extracts the checkpointed-draft machinery out of `keybindingsStore.ts` into a generic, reusable `draftCheckpointPort.ts` (`DraftPort`, `DraftRepository`, `discardStoredDraft`, `UnreadableDraftError`), then rebuilds the keybindings store on it. Along the way it:

- Replaces the load-then-save "remark" of a settled checkpoint with an atomic `replaceClassified`/`replaceIf` compare-and-swap, so a concurrent writer's checkpoint is adopted rather than overwritten.
- Tracks classification identity (`classification` + `rawFrom`) so an edited/extra-field checkpoint is removed by the exact bytes that are actually stored, and so `discardClassified`/`replaceClassified` never act on a record the store never classified.
- Defers the settle side effect until after a successful reconcile (`applyHubOverrides`'s `settle` thunk, `applyHubOverridesSettling`, `settleWrite`), so a wedged registry/stale payload cannot reclassify a checkpoint for a settle that never lands.
- Adds a shared `directWrite` claim and a `ReadyGenerationFence.lostHub` predicate to keep the two write paths (direct PATCH vs. checkpointed save) from fencing each other's replies out, and to distinguish "support lost" from "superseded" when a reply lands.
- Makes the native draft backends report their compare/remove and compare/replace verdicts as booleans, and shares the in-memory draft-backend fakes.

I traced the new classification/settle/directWrite logic against the added tests (replaced-checkpoint adoption, refusal-based re-read, post-rename and conflict settle paths, generation/support fencing, native `deleteIf`/`replaceIf` propagation) and the existing keybindings/recovery tests; the implementations match the documented invariants, and the new `discardStoredDraft` export is reachable from the package root for the qualification gate.

No issues found.
