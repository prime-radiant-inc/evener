## Summary

The 37-commit series migrates the keybindings draft editor onto a shared, generic `createDraftRepository`/`DraftPort` in `appwire-client/typescript/draftCheckpointPort.ts`, and adds an unreadable-draft recovery path end to end.

Key changes:
- **Shared repository** (`draftCheckpointPort.ts`): a generic port/repository that normalizes checkpoints through a decoder in both directions, tracks the raw bytes it classified (so byte-comparing ports can still name a record), and makes every write a compare-and-swap (`save` → `replaceIf`/`insertIfAbsent`, `discardClassified`, `replaceClassified`). Adds `canonicalJson`, `UnreadableDraftError`, `DiscardStoredDraftResult`, and the store-free `discardStoredDraft`.
- **Keybindings store**: `restoreDraft` now distinguishes an unreadable *record* (`draftUnreadable`) from a dead *port*; `saveDraft`/`patchOverrides` coordinate through a shared write token plus a synchronously reserved `directWrite` claim; a new `settleWrite` unifies every deferred-throw settle (including post-rename and conflict branches) so `saving`/`writeUncertain` publish even when the local reconciler throws; `settledWrite` gained a `savingAtReadStart` guard and CAS-refusal adoption; `discardDraft` gained a narrower `assertDiscardable` gate that permits discarding an unreadable record.
- **Native**: the Storage backend now returns tagged `parseDraftBytes` markers (`UnparseableDraftBytes`, `StoredNullRecord`) so corrupt records are present-but-unreadable rather than dead-port throws; `deleteIf` reports whether it removed; new `insertIfAbsent`/`replaceIf`; `NativePreferencesProvider` probes the offline record independent of any model and exposes a store-free discard; the screen renders the unreadable-draft action and offline storage failure, with decisions extracted to `keybindingOfflineRecovery.ts`.
- **Tests**: a generic `testing/draftStorage.ts` fake replaces the keybindings-specific one, plus a shared native `fakeDraftBackend` and extensive new unit coverage (repository CAS semantics, canonical compare, marker collisions, settle/refusal/fencing paths).

The final aggregate diff is internally coherent and achieves the series' goal. I traced the CAS/classification bookkeeping (`rawFrom`/`classification`), every `settleWrite`/`settledWrite` cleanup and refusal branch, the `directWrite` reservation/fencing interactions, and the native marker round-trips; the invariants hold (refusals adopt on-disk state, unreadable records remain discardable, write uncertainty is settled only by an authoritative read that started before the write left, and the offline path cannot delete a record it didn't classify).
