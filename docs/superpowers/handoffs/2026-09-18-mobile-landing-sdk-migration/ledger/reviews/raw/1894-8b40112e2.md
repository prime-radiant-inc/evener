## Summary

The six commits harden the SDK's handling of untrusted `warning` notification frames so a transport-sized (up to 128 MiB) malformed payload cannot force large allocations or walk huge object graphs:

- `hasWarningText` now scans with `/\S/` instead of `trim()`-ing a (previously bounded) copy, and `warningMessage` uses it.
- All stored warning strings (`text`, `title`, `hint`, `source`) now pass through a single `boundedPrefix`/`boundedContent` primitive that truncates on code-point boundaries and starts at the first non-whitespace code point, so leading padding can no longer hide real content.
- `rawWarningFrame` first prunes the frame (`prunedForStringify`: per-string/per-key caps, array/key caps, depth cap, total node budget) before `JSON.stringify`, closing the whole-graph walk, and builds its accumulator with `Object.create(null)` so a wire key named `__proto__` survives.
- Tests exercise surrogate safety, pre-`Array.from` bounding, pre-`stringify` bounding, deep nesting, many keys, proxy enumeration, oversized key names, `__proto__`, oversized message/title/hint/source, and leading-blank misclassification.

The aggregate diff achieves the series' stated intent, and the tests exercise observable behavior rather than restating constants.

## Findings

**Low** — `appwire-client/typescript/reducer.ts:1132-1134`

After truncating a property name, the code writes it into `pruned` by that truncated form. Two distinct wire keys that share their first `RAW_WARNING_FRAME_MAX_FIELD_CHARS` (2000) code points therefore collapse to the same `boundedKey` (both become `prefix + "…"` or an identical prefix), and the second assignment silently overwrites the first. Concretely, a malformed frame like `{"extra":{"<2000 x's>a":1,"<2000 x's>b":2}}` renders only one of the two fields in the raw-frame fallback, so the field is silently invisible to anyone diagnosing the warning. Impact is confined to the message-less fallback display (the value is untrusted and already pathologically shaped), hence low.

Suggested fix: keep the keys distinct when they collide, e.g. track seen bounded keys and suffix a disambiguating index, or accumulate `[boundedKey, prunedValue]` pairs and construct the object afterward with a collision-safe key.
