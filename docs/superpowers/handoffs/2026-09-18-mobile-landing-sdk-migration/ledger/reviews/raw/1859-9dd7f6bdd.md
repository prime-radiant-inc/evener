- **Severity**: Low
- **Location**: `mobile/src/state/conversation.ts` warning case (`warning:${folded.title ?? folded.text ?? "warning"}`)
- **Problem**: The live-row id embeds the raw folded text, which for a message-less frame is the up-to-2000-char raw JSON fallback. ---
- **Severity**: Low
- **Location**: `appwire-client/typescript/reducer.ts` `foldWarningParams`
- **Problem**: `title`/`hint`/`source` are stored verbatim when they are strings, so whitespace-only values (e.g. `"   "`) persist in `ItemModel.warning` even though every consumer must treat them as absent via `hasWarningText`. This contradicts the documented string-or-absent contract and leaves future readers one missed guard away from rendering blank content.
- **Fix**: Normalize with the same check used for the text fallback, e.g. store `hasWarningText(value) ? value : undefined` (or a trimmed value).
## Summary
Consolidates warning folding and image-absence handling correctly with good behavioral tests, except for an unbounded live-row id and whitespace titles retained in the folded model.

- Tests updated/added across reducer, transcript projector, WarningItem, native live images, mobile projection, and the mobile store.

**Severity: low** — `appwire-client/typescript/reducer.test.ts:4805-4807`

The test `'warning with only {"warning":42} and no routing envelope renders that frame itself'` and its comment claim to cover a frame with "no threadId/ref wrapping at all," but the frame it actually feeds includes `threadId: "thr_t", ref: "ref_t"` (line 4815). A genuinely routing-less frame is dropped by `notificationTargetsThread` (both in the reducer and at `mobile/src/state/conversation.ts:2492`), so the stated case cannot render at all and is not what this test pins; it duplicates the existing `["number warning", 42]` case from the `test.each` directly above.

What goes wrong if not fixed: nothing functionally — but a future maintainer reading the name/comment would believe routing-less warning frames render, when the code intentionally drops them, and might remove or weaken the routing guard believing it is covered.

Suggested fix: either drop the `threadId`/`ref` from `params` if the intent is truly a routing-less frame (which would then assert the frame is dropped, not rendered), or correct the test name and comment to say it verifies the raw-frame fallback for a routed message-less frame.
