## Summary

The commit makes the native transcript footer derive its session token total from the shared package helper `sessionTokens(conversation)` instead of reading `conversation.usage` directly. This gives the footer the same "cumulative usage when present, otherwise sum the loaded turns" behavior as the web details panel, adds fork-child/legacy sessions (which have no persisted cumulative usage) a per-turn fallback, and introduces `tokenUnitLabel` so a total summed over a windowed (`olderCursor`) transcript is labeled `tokens (loaded turns)` rather than misrepresented as a whole-session figure. `accountingFor` still layers the cumulative `cacheReadTokens`/`totalTokens` breakdown onto the derived input/output pair, and `TranscriptUsage` now prints the scope-aware unit. Tests cover cumulative preference, the loaded-sum fallback, the truncated-window label, and the label helper.

## Issues

**low** — `mobile-native/src/transcriptPresentation.ts:190-196` (with `tokenUnitLabel` application in `TranscriptUsage.tsx:6`)

The cache/total breakdown is pulled from `conversation.usage` independently of which source `sessionTokens` actually used. The comment at lines 22-25 asserts that `cacheReadTokens`/`totalTokens` "only ever comes from the thread's own cumulative usage ... so it is absent whenever sessionTokens fell back to summing turns," but the code never enforces that: it only checks `conversation.usage?.cacheReadTokens`/`?.totalTokens`. Because `sessionTokens` falls back to summing turns whenever the cumulative object's input/output pair is zero or absent (`threadUsage.ts:71-77`), a session whose cumulative usage carries only `cacheReadTokens`/`totalTokens` (e.g. `totalTokens: 500`, `inputTokens`/`outputTokens` absent) and a turn window with `olderCursor` takes the `"loaded"` branch: the input/output rows are the loaded-turn sum, while the Cached/Total rows are the whole-session cumulative figures, and `tokenUnitLabel` stamps all of them `tokens (loaded turns)`. Concrete harm: the footer reports the full-session cache/total figures as if they counted only the loaded turns, understating how much of the session was actually accounted for. The trigger requires a wire `EvenerUsage` with input/output unset but cache/total set, so the practical exposure is narrow, but the invariant the comment relies on is not guaranteed by the code.

Suggested fix: only attach the cumulative breakdown when the total itself came from the cumulative object, e.g. compute the cumulative path explicitly (or compare against `conversation.usage`) rather than unconditionally reading `conversation.usage?.cacheReadTokens/totalTokens`, so a turn-summed total with scope `"loaded"` never mixes in whole-session figures.
