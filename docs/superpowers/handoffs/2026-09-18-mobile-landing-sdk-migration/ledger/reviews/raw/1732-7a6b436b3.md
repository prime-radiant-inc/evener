## Review Summary

The series hardens how `warning` notifications are folded and rendered across the shared TypeScript SDK, web, and mobile:

- **SDK (`reducer.ts`)**: Introduces a single `boundedPrefix(s, maxCodePoints, start?)` primitive that safely truncates on code-point boundaries (with a UTF-16-sized pre-window so allocation stays bounded), and routes every string bound through it. `hasWarningText` switches from `value.trim() !== ""` to `/\S/.test(value)`, which is semantically equivalent (ECMAScript `\s` == `trim`'s WhiteSpace+LineTerminator set) but scans instead of copying. `prunedForStringify`'s per-field/per-key truncation now uses `boundedPrefix`. `foldWarningParams` bounds `text`, `title`, `hint`, and `source`, and uses `boundedContent` (bound starting at the first non-whitespace) so content after >2000 leading blank code points is kept rather than being misclassified/padded. `rawWarningFrame` bounds its JSON before code-point expansion.
- **Web (`WarningItem.tsx`)**: Guards `item.text` through `hasWarningText` so a malformed/blank value can't render an empty body or clash with a raw-frame fallback, and adds tests for whitespace-only and non-string title/hint.
- **Mobile**: `warningFallbackText` now composes message + hint (matching web/live-row rendering) instead of `||`-picking one, and the live warning row id drops the embedded title (`warning:${serial}`), keeping ids/ownership keys short. A comment-only clarification is added to the attachment-replacement path.
