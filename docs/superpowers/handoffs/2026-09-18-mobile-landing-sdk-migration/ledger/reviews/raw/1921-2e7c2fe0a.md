## Summary

The commit is a test-only fix for a flake (#1879). The production session namer runs in its own goroutine (`launchInitialPromptNamer` / `launchCompactionNamerGated` in `agent/session_namer.go`) and correctly reports itself as an `autonomous` retirement blocker until it settles. `assertRetirementEvidenceEligible` — used by ~50 retirement tests right after a turn returns — previously read evidence immediately, racing that goroutine and intermittently seeing the settled owner as ineligible. The fix adds `c.root.sendersWG.Wait()` to the shared helper and adds `TestRetirementEvidenceEligibleAwaitsInFlightNamer` as a regression test. The change is confined to test code; the production behavior (namer = autonomous blocker while in flight) is unchanged and correct, and `finishSessionNamer` decrements `naming.pending` and releases the mutation before `sendersWG.Done()`, so the join is a valid happens-before for reading evidence.

## Findings

**Low** — `agent/session_retirement_evidence_test.go:1411`

The new regression test releases the namer (`close(release)`) before calling `assertRetirementEvidenceEligible`, so it only exercises the helper's wait after the namer is already unblocked. Its comment claims it "fails every time before the fix," but without the fix the outcome is scheduling-dependent: once `release` is closed, the test goroutine can reach `TryClaim` before the namer goroutine finishes `applySessionNameResult`/`maybeAutoSave`/`finishSessionNamer`, in which case the test passes for the wrong reason. On a fast/unloaded machine the guard can silently fail to detect a future removal of the `sendersWG.Wait()`.

Concrete harm: a regression test for a race can itself be racy, so it may not protect the fix it was added for.

Suggested fix: assert the deterministic blocked state while the namer is still held, then release and assert eligibility:

```go
<-held // namer provably in flight
assertRetirementEvidenceBlocked(t, c, "autonomous") // deterministic before the fix
close(release)
assertRetirementEvidenceEligible(t, c)
```

This exercises both transitions without depending on goroutine scheduling. (Not a correctness issue with the fix itself.)
