## Summary

The two commits finalize the "SDK image folding + warning text" work (part 2/3 of #1731). The package reducer now mirrors the hub's merge semantics for input images (`appwire.MergeInputImages`: an empty/absent input list says "unchanged", never "removed") and for warning frames it now (a) prefers a real message, (b) falls back to the raw, rune-bounded frame only when there is no message/title/hint, and (c) coerces non-string `title`/`hint` to `undefined`. Consumers were updated accordingly: the web `WarningItem` uses the newly exported `hasWarningText`, the transcript projector guards `.trim()`, and the mobile store/projector read the reducer-folded item for attachments and warning text. Tests cover the hydration, `item/completed`, `turn/completed` full, warning-fallback, surrogate-boundary, and attachment-preservation paths.

## Issues

**Low** — `appwire-client/typescript/transcriptProjector.test.ts:178-181`

The comment on the new projector test claims "reducer.ts folds `params.title` straight through with no runtime coercion", but the same change set added exactly that coercion in `appwire-client/typescript/reducer.ts:1737` (`typeof params.title === "string" ? params.title : undefined`). The test itself still passes (it builds an `ItemModel` directly), but the rationale is now false: a maintainer reading it will believe the reducer can emit non-string `title` values and may keep—or start removing—guards on that premise. Update the comment to say the guard is defense-in-depth for `ItemModel`s not produced by the reducer's `warning` fold.

Suggested fix: reword to note the reducer now coerces, so this test pins the projector's own guard against a hand-built/legacy model rather than a reducer output.

---

**Low** — `mobile/src/state/conversation.ts:2856-2858`

The live warning row computes `title` as `(usesFold ? foldedItem.warning?.title : params.title) ?? "Warning"`. `foldedItem.warning?.title` is only type-coerced, not blank-coerced, so a frame with a whitespace-only title (`"   "`) yields `title: "   "` instead of the generic `"Warning"` that the web renderer (`WarningItem.tsx`, via `hasWarningText`) and the mobile projector path (`warningFallbackText`, which trims) use. Concretely, the phone shows a visually blank title in the live failure row while a reread of the same session projects a properly labeled activity row, so the live and projected presentations disagree for the same frame.

Suggested fix: use the package's `hasWarningText` (already exported by this change) in the ternary, e.g. `title: hasWarningText(foldedItem.warning?.title) ? foldedItem.warning.title : ... ?? "Warning"`, or reuse a shared helper rather than re-implementing the trim rule.
