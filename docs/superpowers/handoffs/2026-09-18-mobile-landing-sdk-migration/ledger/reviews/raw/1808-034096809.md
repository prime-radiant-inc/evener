## Summary

The commit series extracts the checkpointed-draft machinery out of `keybindingsStore.ts` into a new generic `draftCheckpointPort.ts` (`DraftPort<Checkpoint>`, `createDraftRepository`, `discardStoredDraft`, `UnreadableDraftError`), and migrates the keybindings draft editor onto it. It then:

- Adds atomic `insertIfAbsent` and `replaceIf` to the port, the native backend (`NativePreferencesProvider`), and the test doubles, and makes `deleteIf` report whether it actually removed a record.
- Threads those booleans through the repository and the store, so `persistDraft`, `discardDraft`, and `settleWrite` detect a compare-and-swap refusal (another writer replaced the record) and adopt what is on disk instead of reporting a storage failure or blindly overwriting.
- Introduces a synchronous `directWrite` reservation so the direct (`patchOverrides`) and checkpointed (`saveDraft`) write paths share one write token without one fencing out the other's reply, and adds `lostHub` to the generation fence to settle a write whose support went away.
- Refines the refresh/settle sequence (`applyHubOverrides`'s deferred `settle`, `applyHubOverridesSettling` publishing even on a reconciler throw) and adds extensive regression tests plus shared test fakes.

I traced the new CAS logic, the `classification`/`rawFrom` bookkeeping, the `directWrite` reservation lifecycle (including supersede, generation end, and reset), the settle/refresh interaction, the native port round-trip key ordering, and the removed/changed tests and call sites. The behavior matches the stated intent, the port contracts are implemented consistently by every backend, and the new tests exercise the meaningful race/failure modes rather than restating constants.
