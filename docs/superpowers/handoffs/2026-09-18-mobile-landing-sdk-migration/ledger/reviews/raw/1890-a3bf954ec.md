- **Location**: `internal/plugins/marketplaces.go:321`

## Summary

######## member 2 (pi default)
## Summary

The series scrubs absolute plugin-store paths out of client-facing errors for marketplace/registry save failures, centralizing the scrub in `saveRegistry` and new `saveFailed`/`storeChangeRollbackFailed`/`cloneRemovalFailed` helpers; reorders `RemoveMarketplace` to persist the unregistration before deleting the clone; and introduces `ErrMarketplaceUnregisteredCloneRemains` plus a retry path (`notFoundOrCloneRemains`) so a lookup miss after litter is distinguishable from a never-registered name.

---

**Severity: high — arbitrary directory deletion via path traversal in the new lookup-miss branch**

`internal/plugins/marketplaces.go:320-331` (`notFoundOrCloneRemains`), reached from `RemoveMarketplace` at `internal/plugins/marketplaces.go:358`.

`RemoveMarketplace` never validates `name` with `validNameComponent` (unlike `AddMarketplace`/`EditMarketplace`). On a lookup miss, the new code now derives a filesystem path from that unvalidated name:

```go
present, err := pathPresent(m.marketplaceDir(name))
...
if err := marketplaceRemoveAll(m.marketplaceDir(name)); err != nil {
```

`marketplaceDir` is `filepath.Join(m.marketplacesDir(), name)`, and `filepath.Join` cleans `..`. For an unrecorded `name` such as `../../../../../../etc`, the derived path is not `<root>/marketplaces/../../../../../../etc` but the cleaned absolute path `/etc`. `pathPresent("/etc")` returns true, and `marketplaceRemoveAll("/etc")` then recursively deletes it. Every production caller passes the caller-supplied name straight through: `cmd/evener/plugincmd.go:142` (CLI: `evener plugin marketplace remove ../../...`) and `cmd/evener-hub/app_plugins.go:267` (RPC; `appwire.MarketplaceNameParams.Name` has no validation, `appwire/types.go:3596`). Before this diff a lookup miss returned `ErrMarketplaceNotFound` without touching disk, so this is newly introduced. The migration barrier only refuses *recorded* legacy names — the existing test at `cmd/evener-hub/app_plugins_test.go:579` covers a traversing name that is recorded, so it does not exercise this branch.

Fix: validate the name before deriving any path, e.g. at the top of `RemoveMarketplace` (or inside `notFoundOrCloneRemains`) return `validNameComponent("marketplace", name)`'s error (classified as `InvalidParams` by `marketplaceRefusalToWire`). Add a test that calls `RemoveMarketplace` with an unrecorded traversing name and asserts `ErrInvalidName`/`ErrMarketplaceNotFound` and that no directory outside the store is touched.

---

**Severity: low — `notFoundOrCloneRemains` still leaks the absolute store path on a stat error**

`internal/plugins/marketplaces.go:321-323` returns `pathPresent`'s error verbatim, and `pathPresent` builds `fmt.Errorf("checking %s: %w", path, err)` (`marketplaces.go:827+`), embedding the absolute path. The rest of this series exists to keep that path out of client-facing errors; if the stat fails for a permission/I/O reason, `RemoveMarketplace` hands the absolute store path to the RPC caller. Fix: at that return, log the raw error server-side and return a scrubbed message (matching `saveFailed`'s pattern), rather than returning `err` directly.
