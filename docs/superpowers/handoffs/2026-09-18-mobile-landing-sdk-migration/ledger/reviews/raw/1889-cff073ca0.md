######## member 2 (pi default)
## Summary

The two commits harden error reporting in `internal/plugins` so that filesystem write failures no longer leak this machine's absolute plugin-store path to RPC/CLI callers. They add two shared scrub helpers — `saveFailed` (marketplace file writes) and `storeChangeRollbackFailed` (operation + rollback both failed) — route `saveRegistry`, `ensureFetched`, `AddMarketplace`, `EditMarketplace`, `RefreshMarketplace` and `saveRename` through them, log the raw error to `m.stderr()` instead, and preserve the `errStoreBetweenNames` sentinel across scrubbing so migration recovery logic still works. Tests in `install_test.go`, `marketplaces_path_scrub_test.go` and the updated migration test exercise each scrubbed boundary with a real `*fs.PathError`. The design is sound and the sentinel-identity handling in `saveFailed`/`storeChangeRollbackFailed` is correct.

## Issues

**medium — `RemoveMarketplace` still returns the raw store-write error naming the absolute path**

`internal/plugins/marketplaces.go:316`

```go
delete(mk, name)
return m.saveMarketplaces(mk)
```

`RemoveMarketplace` is a mutation reachable directly over RPC (`cmd/evener-hub/app_plugins.go:266`, wired at `app_rpc.go:1294`) and from the CLI. When `saveMarketplaces` fails, it returns `atomicWriteFile`'s own error, whose text contains absolute paths like `creating temp /home/<user>/.evener/plugins/known_marketplaces.json.tmp.123.abcdef: ...` (see `internal/plugins/atomic.go:32-60`). `hubPluginsController.RemoveMarketplace` passes that straight to `marketplaceRefusalToWire`, which returns it unchanged for non-sentinel errors (`app_plugins.go:242-250`), so the absolute store path is serialized to the client. This directly contradicts the series' stated goal that store write failures never name the store path, and it is the only RPC-reachable mutation left unscrubbed (every other `saveMarketplaces`/`saveRegistry` caller was converted in this diff). No path-scrub test was added for it, so the omission was not caught.

Fix: mirror the other callers, e.g.

```go
if err := m.saveMarketplaces(mk); err != nil {
    return m.saveFailed(name, marketplacesFileName, err)
}
return nil
```

and add the corresponding `TestRemoveMarketplaceSaveFailureNamesNoPath` assertion that the returned error contains neither `m.marketplacesFile()` nor the store root.
