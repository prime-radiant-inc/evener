## Summary

The series makes three related client-side robustness changes for the AppWire SDK plus its two hosts:

1. **Ask resolution** (`deriveAskQuestions.ts`): `liveAskQuestions` now treats `ThreadModel.askPending` (the wire's own flag) as the authoritative gate and returns early when it is false. "Which questions" is still derived by scanning the transcript, but the boundary is broadened from "last userMessage" to any resolution item — a plain `userMessage`, a `steering` item with `steeringKind: "interrupted"`, or a user steer (`source === "user"`).
2. **Image folding** (`reducer.ts` input-image path): an empty/absent input-image list now means "unchanged", so a settle that omits images keeps the item's existing attachments; output images retain their explicit nil/non-nil-empty removal semantics.
3. **Warning text** (`reducer.ts`, `WarningItem.tsx`, `transcriptProjector.ts`, mobile projections): a message-less frame only falls back to the bounded raw JSON when there is also no title/hint; non-string title/hint are folded to `undefined`; the fallback text is bounded by code points before and after `Array.from`; mobile now surfaces title/hint-only warnings.

The aggregate diff achieves the stated goal. Server behavior referenced in comments (interrupt → `clearAskPending` + `SteeringKindInterrupted`; human-note/user steers entering as `EntryUserInput`; `stampAskPendingOnStatusChange`) checks out against `agent/session_lifecycle.go`, `agent/session_queue.go`, and `server/appwire_runtime.go`.

Two low/medium findings follow.

---

**Severity: medium** — `mobile/src/state/conversation.ts:2856-2859`

When `usesFold` is false (no active turn, so the reducer dropped the warning item), the row falls back to raw `params.title`/`params.message`. Both are typed `string?` but the wire value is unchecked, exactly the malformed-frame class this series fixes in `reducer.ts` (`title: typeof params.title === "string" ? ... : undefined`) and `WarningItem.tsx` (`hasWarningText`). `mobile-native/src/TimelineItem.tsx:166-167` renders these directly as `<Copy>{item.title}</Copy>`/`{item.detail}`, so a frame like `{ method: "warning", params: { title: {…}, message: {…} } }` with no active turn produces "Objects are not valid as a React child" and blanks the conversation. The reducer guard added in this same diff does not cover this path because the store builds its own failure row when the fold appends nothing.

Suggested fix: apply the same guard here, e.g. `const title = (usesFold ? foldedItem.warning?.title : hasWarningText(params.title) ? params.title : undefined) ?? "Warning";` and guard `params.message` with `typeof ... === "string"` before placing it in `detail`.

---

**Severity: low** — `appwire-client/typescript/transcriptProjector.test.ts:175-178`

The comment states "reducer.ts folds params.title straight through with no runtime coercion", but the same aggregate diff changed `reducer.ts` to coerce `params.title`/`params.hint` (`typeof params.title === "string" ? params.title : undefined`) before they ever reach an `ItemModel`. The test still has value as a direct-construction guard, but the stated rationale is now false and will mislead the next maintainer about where the invariant is enforced.

Suggested fix: reword the comment to say the projector guard is defense-in-depth for directly-constructed/migrated `ItemModel`s, since the reducer now folds non-string values to `undefined`.
