## Summary

The two commits rework the mobile transcript footer's session-usage accounting. `accountingFor` now derives the footer's input/output pair through the shared package `sessionTokens` helper (preferring the daemon's cumulative `EvenerThread.usage`, falling back to summing the loaded turns, and scoping a truncated window as `"loaded"`), while reading `cacheReadTokens`/`totalTokens` straight off `conversation.usage` and merging them in unconditionally. A new `usageRows` helper (used by `TranscriptUsage.tsx`) labels the derived Input/Output rows with the derived pair's own scope and always labels the cumulative Cached/Total rows plainly, so a loaded-window sum no longer mislabels the whole-session cache/total figures. The tests cover the fork-child turn-sum fallback, the loaded scope, sparse cache-only/total-only breakdowns, and the scope-independence of Cached/Total.

I verified there is no correctness or regression issue in the final aggregate: the fallback path preserves the previous `conversation.usage` behavior for the common case, the sparse-cumulative handling matches the `EvenerUsage` contract documented in `threadUsage.ts`, `EvenerUsage`/`SessionTokens`/`sessionTokens` are all exported from the package root, and the type changes don't introduce exactness problems.
