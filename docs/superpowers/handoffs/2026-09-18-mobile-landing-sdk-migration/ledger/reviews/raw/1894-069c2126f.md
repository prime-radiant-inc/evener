## Summary

The five commits harden the warning-frame fold in `appwire-client/typescript/reducer.ts`:

- `hasWarningText` now answers "is there non-blank content?" with a non-allocating `/\S/.test(value)` scan instead of a bounded-then-trimmed copy, so real content past `RAW_WARNING_FRAME_MAX_CHARS` leading blanks is no longer misclassified as blank.
- A single `boundedPrefix` code-point-safe primitive backs every string bound (per-field, per-key, and the outer `boundedCodePoints`), preserving surrogate pairs.
- `rawWarningFrame` now prunes the frame **before** `JSON.stringify` with per-field (2000), per-array (50), per-object-key (50), depth (6), and total-node (500) budgets, so `JSON.stringify` never walks a transport-sized frame.
- Object keys are also length-bounded, and the accumulator uses `Object.create(null)` so a wire key literally named `__proto__` is preserved instead of invoking the prototype setter.
- `foldWarningParams` applies `boundedCodePoints` to `text`, `title`, `hint`, and `source`, closing the unbounded-message/title/hint/source path.
- Extensive new tests cover field-level surrogate safety, pre-stringify bounding, deep nesting, many-key objects, key enumeration cost, oversized property names, `__proto__`, per-field bounds, and the no-trim/no-copy behavior.

I traced the pruning budget (every child value, including primitives, decrements the shared budget; key-name length is itself bounded), the code-point slice guarantee (a `2N`-unit prefix contains ≥ `N` code points even after stripping a trailing lone high surrogate), the `__proto__` accumulator, key ordering equivalence with the prior `JSON.stringify(params)` for small frames, and the `hasWarningText`/`trim` semantic equivalence. No correctness, security, or regression issue was found.
