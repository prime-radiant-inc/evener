**Severity: medium** — `mobile/src/state/conversation.ts:2042` (interacting with `appwire-client/typescript/threadUsage.ts:98`)

The new code sets `conversation.olderCursor` to `nextCursor ?? undefined`, but `nextCursor` is deliberately forced to `null` whenever the retained-item cap is hit (`const nextCursor = atCap ? null : (result.nextCursor ?? null)`, line 2027). `sessionTokens` uses `olderCursor` as its signal that the loaded turns are a truncated suffix, so once the cap ends paging while `result.nextCursor` still reports more history, `conversation.olderCursor` becomes `undefined` and the turn-summed fallback is returned with `scope: "session"` even though earlier turns were never requested. `usageRows` then renders the derived Input/Output rows plainly as whole-session figures (the Cached/Total rows are unaffected because they are cumulative), which is exactly the overstatement this feature exists to prevent.

Concretely: a long session with no cumulative usage (fork child / older daemon / usage-omitting source) whose first read already returns ~`RETAINED_ITEM_CAP` items, or that reaches the cap while more history remains, will show the loaded-window sum of Input/Output under a whole-session label after the user taps "load earlier". Before this change `conversation.olderCursor` was never cleared on `loadOlder`, so the figure stayed conservatively labelled `"loaded"`; this change makes it possible to overstate.

Suggested fix: only clear the scope signal when paging ends because history is exhausted, not because the cap stopped it. For example:

```ts
const moreHistory = result.nextCursor !== undefined && result.nextCursor !== null;
olderCursor: atCap && moreHistory
  ? (currentConv.olderCursor ?? cursor)
  : (result.nextCursor ?? undefined),
```

A regression test driving `loadOlder` to `RETAINED_ITEM_CAP` while the service still returns a `nextCursor`, asserting `sessionTokens` over the resulting conversation yields `scope: "loaded"`, would pin this.
