## Summary

This 51-commit series extracts the shared checkpointed-draft machinery into a new `appwire-client/typescript/draftCheckpointPort.ts` (`DraftPort`, `createDraftRepository`, `discardStoredDraft`), moves the ready-generation fence's write-disposition logic into `readyGenerationFence.lostHub`, migrates the native draft backends onto shared fakes/helpers, and adds an "unreadable stored draft" recovery path. The keybindings store's draft now carries its own ready `generation` so staleness survives a hub replacement that coincidentally reuses a revision number; writes compare-and-swap through `removeIf`/`replaceIf`; settles adopt a checkpoint replaced under them and publish even when the local reconcile throws; and native gets offline/store-free discard plus tagged handling of stored-JSON-null vs. unparseable bytes. The final aggregate state is internally consistent with the tests and the commit intent.

## Findings

**Severity: low** — `mobile-native/src/NativePreferencesProvider.tsx:114` (and the context value at line 238)

`offlineStorageUnavailable` is declared, maintained by both the probe effect and `discardUnreadableKeybindingsDraft`, and published on the context — but nothing consumes it (`grep` finds no reader; `KeybindingPreferencesScreen.tsx` only reads `offlineDraftUnreadable`). Because `discardUnreadableKeybindingsDraft` catches a genuine port failure internally and returns `null`, the screen's offline handler (`if (clearsErrorAfterOfflineDiscard(outcome)) setError(null)`) neither clears nor sets an error. Concrete harm: if `Storage.getItemSync`/`removeItemSync` throws while the user taps "Discard unreadable draft" offline, the action silently does nothing — the notice stays up, the button stays enabled, and no message tells the user the port failed (as opposed to the record merely still being unreadable). Suggested fix: either consume `offlineStorageUnavailable` in the screen (surface an error/disable the action) or return a distinct signal from the store-free discard for a port failure instead of `null`, so the existing catch path can report it.
