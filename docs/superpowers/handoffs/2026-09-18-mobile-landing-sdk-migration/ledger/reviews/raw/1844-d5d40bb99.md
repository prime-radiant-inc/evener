######## member 1 (codex default)
## Review Findings
- **Severity**: Medium
- **Location**: `mobile-native/src/NativePreferencesProvider.tsx:209`
- **Problem**: The store-free discard re-reads the port twice: `readDraftOutcome(storage, ...)` loads once for classification, then `decodeKeybindingDraftFields(storage.load())` loads again to decode. The second `load()` is outside any `try/catch` and can throw a genuine storage failure, escaping the handler without setting `offlineStorageUnavailable`. It also introduces a TOCTOU race where the record changes between classification and decode, so a `readable` classification can decode a different record.
- **Fix**: Load once and reuse the value: have the outcome helper return the loaded value alongside the classification, or wrap the second `load()` in `try/catch` and handle `storageUnavailable` the same as the follow-up read path.
---
- **Severity**: Low
- **Location**: `appwire-client/typescript/draftCheckpointPort.ts:103`
- **Problem**: `DraftRepository.save()` doc claims nothing classified yet, or classified as absent, has no existing record to race against and always succeeds, but the implementation uses `insertIfAbsent()` which can return `false` when a concurrent writer created the first record.
- **Fix**: Update the doc to state `save()` can refuse via `insertIfAbsent` and callers must handle `false` as a conflict, matching `persistCheckpointedDraft` behavior.
