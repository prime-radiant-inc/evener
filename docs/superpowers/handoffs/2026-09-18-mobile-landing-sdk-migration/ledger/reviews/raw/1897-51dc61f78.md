## Summary

The series hardens error reporting in `internal/plugins` so that absolute plugin-store paths never reach RPC/CLI callers, while the raw error still goes to the hub log. It does this by adding scrub boundaries (`saveFailed`, `storeChangeRollbackFailed`, `cloneRemovalFailed`, `migrationFileSaveFailed`), making `saveRegistry` scrub, and by scrubbing `markerAfterFailedMove`/`markerLeftForRecovery`/`saveRename` errors. It also reorders `RemoveMarketplace` to save the unregistration before deleting the clone and introduces the typed `ErrMarketplaceUnregisteredCloneRemains` outcome with a retry path (`notFoundOrCloneRemains`). The path-scrub logic, sentinel preservation (`errStoreBetweenNames`), and updated tests are internally consistent.

---

**High — `RemoveMarketplace` can `os.RemoveAll` an arbitrary directory outside the store for an unregistered name**

File: `internal/plugins/marketplaces.go:358` (caller) and `internal/plugins/marketplaces.go:320-331` (`notFoundOrCloneRemains`).

`RemoveMarketplace` never validates its `name` argument. On a lookup miss it now calls `notFoundOrCloneRemains(name)`, which derives `m.marketplaceDir(name)` and, if that path exists, calls `os.RemoveAll` on it:

```go
func (m *Manager) notFoundOrCloneRemains(name string) error {
	present, err := pathPresent(m.marketplaceDir(name))
	...
	if err := marketplaceRemoveAll(m.marketplaceDir(name)); err != nil {
		return m.cloneRemovalFailed(name, err)
	}
	return nil
}
```

`marketplaceDir` is `filepath.Join(m.marketplacesDir(), name)` (`paths.go:125`), and `filepath.Join` cleans `..`. So `name = ".."` resolves to the store root itself (`Root/marketplaces/..`), and `name = "../.."`, `"../../..."` escape into the store's parent directories. Because the name is unvalidated (the hub controller `cmd/evener-hub/app_plugins.go:266`, the CLI `cmd/evener/plugincmd.go:142`, and the exported manager API all pass the caller string straight through), a caller can reach this with a name that is not recorded and receive success while the directory tree is deleted.

Concretely: `RemoveMarketplace(ctx, "..")` deletes the entire plugin store (`Root`), including `installed_plugins.json`, `known_marketplaces.json`, all marketplace clones and all plugin caches, and returns `nil`. Previously the lookup miss returned `ErrMarketplaceNotFound` without touching disk, so this is a regression introduced by this diff. The existing wire test only covers a *recorded* traversing name (which `lockStore`'s migration renames first, so the miss resolves to a path that does not exist), which is why it does not catch this.

Suggested fix: refuse a name the store cannot carry before deriving any path from it — e.g. at the top of `notFoundOrCloneRemains` (or before the lookup in `RemoveMarketplace`):

```go
if err := validNameComponent("marketplace", name); err != nil {
    return fmt.Errorf("marketplace %q: %w", name, ErrMarketplaceNotFound)
}
```

(or `ErrInvalidName` to match the other verbs). Add a regression test that calls `RemoveMarketplace` with `".."` / `"../.."` against a non-empty store and asserts the store survives and `ErrMarketplaceNotFound` is returned.
