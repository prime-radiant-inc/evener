## Summary

This series is a large SDK/store refactor for the keybindings draft editor. It extracts shared primitives out of `keybindingsStore.ts` into three new modules (`draftCheckpointPort.ts`, `checkpointedDraftEditor.ts`, `settingsHubGeneration.ts`), makes the draft repository track the exact on-disk identity it classified, threads a per-draft ready-generation stamp so a hub replacement that coincidentally reports the same revision is still flagged stale, adds an `UnreadableDraftError` / `draftUnreadable` recovery path with a store-free offline discard, gives the native backend an atomic `replaceIf`, and unifies both write paths behind a single write token. The native mobile screen/provider gain an "unreadable draft" notice and discard action, with a shared test double replacing the old keybinding-only one. The implementation is carefully ordered and heavily tested; I found no high- or medium-severity correctness, security, or regression issues.

---

**Severity: low** — `appwire-client/typescript/tsconfig.build.json:116-117`

The two new modules `checkpointedDraftEditor.ts` and `settingsHubGeneration.ts` are imported by `keybindingsStore.ts` (which `index.ts` publishes) but are not added to `tsconfig.build.json`'s `files` list — only `draftCheckpointPort.ts` was added. TypeScript includes and emits files referenced by listed files, so those two are still compiled into `dist/` and shipped, but the repo's packaging gates enumerate "shipped modules" from exactly this list: `cmd/evener-hub/frontend/scripts/package-coverage.mjs:37,81` (coverage floor) and `appwire-client/typescript/scripts/qualify-package.mjs:40,846` (reachability assertion). `docs/superpowers/handoffs/2026-09-16-mobile-landing-sdk-migration/phase-d-worksheet.md:16` states the rule explicitly: a module missing the `files` entry "passes the gate silently."

Concrete harm: these two modules carry the editor's central discard/persist/settle logic, and neither the coverage floor nor the package qualification walks them. If a later change drops or weakens their tests, or they acquire a load-time browser/Node dependency, every gate stays green while the package ships unverified code — the same class of gap closed as #1224.

Suggested fix: make the shipped set and the `files` list agree. Either keep these as internal modules but extend `package-coverage.mjs`/`qualify-package.mjs` to enumerate the transitive import graph from the listed entries (so referenced modules are still gated), or publish them via a declared subpath/`index.ts` re-export so they can be listed and satisfy the existing reachability assertion — whichever matches the intended public surface.
