## Summary

This series (pieces 2/3 and 3/3 of #1731) makes pending-ask detection wire-authoritative and hardens warning rendering:

- `liveAskQuestions` now gates on `ThreadModel.askPending` (wire snapshot + `thread/status/changed`) before scanning the transcript, and treats an interrupt/`source: "user"` steering item as a resolution boundary alongside plain user messages.
- The mobile live store now derives attachment rows from the reducer-folded `ItemModel` (so "absent/empty input images means unchanged" from `mergeItemImages`/`MergeInputImages` is honored), and warning rows read the folded title/hint instead of `params.message` alone.
- Warning handling is hardened: `hasWarningText` is exported and used by `WarningItem.tsx`, the projector guards non-string `warning.title`, and `rawWarningFrame` bounds the raw-frame fallback to 2000 code points without splitting surrogate pairs and without expanding the whole (up to 128 MiB) frame via `Array.from`.
- Mobile reasoning projection now reads `joinedReasoningParagraphs` so live deltas (which accumulate in `reasoningSummaries`, not `text`) still render.
- Tests/fixtures across web, mobile, and the package were updated to stamp `askPending` and cover the new behavior.

The aggregate is coherent and the ask-resolution/attachment logic matches the Go-side contracts (`appwire.MergeInputImages`, `processOneInput`'s `askPending = nil` at accepted-turn entry).

**Severity: medium** — `mobile/src/state/conversation.ts:2856` (title) and `:2859` (detail)

The new warning row routes through the reducer-folded item when a warning item exists, but the fallback branch — used whenever there is no active folded warning, which includes the intentional "warning with no active turn still shows a failure row" path (pinned by `conversation.test.ts:7004`) — still reads raw wire values: `params.title` and `params.message` are cast to `string` but never runtime-checked. A malformed warning frame with, e.g., an object/array title or message produces a non-string `MobileTimelineItem.title`/`detail`, which `mobile-native/src/TimelineItem.tsx:163-168` renders as `<Copy>{item.title}</Copy>` inside a React Native `<Text>`. Passing an object as a React child throws "Objects are not valid as a React child", crashing the transcript render. This is exactly the class of value the series guards against elsewhere (reducer `typeof params.title === "string"` fold, `hasWarningText` in `WarningItem.tsx`, `transcriptProjector.ts`'s `typeof rawTitle === "string"`), so the guard is incomplete on this branch. Concrete harm: a malformed/hostile warning frame received with no active turn takes down the mobile timeline.

Suggested fix: coerce the fallback the same way, e.g. `typeof params.title === "string" ? params.title : undefined` and `typeof params.message === "string" ? params.message : ""`, and add a no-active-turn non-string-title case to the mobile warning tests.

- **Severity**: Low
  - **Location**: `appwire-client/typescript/reducer.ts:1239`
  - **Problem**: A UTF-16 prefix of exactly twice the code-point limit can end on a high surrogate after 1,999 preceding astral code points. `Array.from` then counts the orphaned surrogate as the 2,000th code point, so the truncated frame can still end with an unpaired surrogate.
  - **Fix**: Slice to `RAW_WARNING_FRAME_MAX_CHARS * 2 + 1` before `Array.from`, then retain the first 2,000 code points; cover this with an astral-code-point-dense truncation test.
