## roborev: Combined Review (`1a0b754`)

**Verdict: Two medium and two low issues found; the core cutover is sound but two untrusted-field guards are incomplete.**

## Medium

- **Warning `title`/`hint` `.trim()` called without type check** — `mobile/src/conversation/project.ts:505`
  `title` and `hint` flow from the unvalidated `n.params` wire map straight into `ItemModel.warning`, yet the projection filter calls `part.trim()` unconditionally. A non-string value (number, `null`, object) throws a `TypeError` inside `projectItem`; since the reducer stores it and the phone re-projects on every publish, one malformed frame permanently breaks that thread's transcript. The web side already guards this with `typeof part === "string"` in `WarningItem.tsx`. Filter with `typeof part === "string" && part.trim() !== ""`, and apply the same guard to the `warning?.title`/`hint` reads. *(Reported by two reviewers.)*

- **Answer submission reads truncated display copies instead of canonical refs** — `mobile/src/conversation/project.ts:961-965`, `mobile/src/conversation/project.ts:915-923`, `mobile-native/src/questionAnswers.ts:11-18`
  Question labels, headers, and fallback text are bounded for display, but native answer composition (`pendingQuestions` → `screens.tsx`/`QuestionSheet.tsx`) reads `conversation.items` — the already-truncated rows from `capAndTruncate`. If an option `label` or `header` exceeds `MAX_ITEM_BYTES`, the submitted answer carries the truncated label the agent never offered, and client-side validation passes because it compares against the same bounded list. The `boundQuestion` comment at line 915 asserts answers don't read bounded copies, but that invariant is not enforced. Either compose answers from canonical `liveAsksFor(model)` refs, or don't bound the fields that feed answer composition (at minimum option labels). *(Reported by two reviewers; one rated Medium, one rated Low — kept at the higher severity.)*

## Low

- **Unused `isInProgressStatus` import** — `mobile/src/conversation/project.ts:30`
  The two local functions that used it were replaced by the package `isActiveItem`; nothing else in the file references it. `make test-native` passes `tsc` without `noUnusedLocals` and Biome isn't run over `mobile/src`, so nothing catches it. Remove it from the import list.

- **Attachment filenames bypass the display bound** — `mobile/src/conversation/project.ts:984-988`, `mobile-native/src/TranscriptImages.tsx:104-116,140`
  `AttachmentRef.name` is inserted fully into accessibility labels and modal text, letting an unbounded tool-provided filename evade the intended row limit. Bound `AttachmentRef.name` while preserving the unmodified image `src`.
