## Medium

- **Uncertain-write settle swallows storage-unavailable signal** — `appwire-client/typescript/keybindingsStore.ts:969-980` (cited as `:979` by second reviewer)
  When `replaceClassified()` throws while an authoritative refresh settles an uncertain write, the catch only publishes `draftError`. The old `persistDraft` path also set `storageUnavailable: true`; the direct replacement path does not, so `writeUncertain` stays true, discard is disabled, and `refreshOverrides` skips its storage-restore recovery path.
  **Fix:** Return `{ storageUnavailable: true, draftError: DRAFT_SAVE_FAILED_MESSAGE }` from the catch while preserving the uncertain checkpoint, and add a test using a `replaceIf` implementation that throws. *(Reported by Reviews 1 and 4.)*

- **Native TypeScript typecheck failure from `deleteIf` parameter narrowing** — `mobile-native/src/nativePreferenceDrafts.ts:15-18`, `mobile-native/src/nativePreferences.test.ts:353`
  The shared backend now requires `deleteIf` to accept `TranscriptDraftCheckpoint | KeybindingDraftCheckpoint`, but the transcript test backend accepts only `TranscriptDraftCheckpoint`. Under the repo's strict settings this function is not assignable and the native typecheck fails.
  **Fix:** Widen the test backend parameter to the union/`unknown`, or parameterize the backend interface by checkpoint type.

- **`removeIf`/`replaceIf` identity typed as `Checkpoint` but raw unknown value passed** — `appwire-client/typescript/draftCheckpointPort.ts:17`
  The port types identity arguments as `Checkpoint`, but the unreadable-record recovery deliberately passes the raw unknown value returned by `load()`; the native backend can therefore receive an unparseable string. A conforming implementation may validate the checkpoint and reject that raw value, causing the advertised unreadable-draft discard to fail despite the runtime cast.
  **Fix:** Type identity arguments as `unknown` (or a dedicated raw-record identity type) in `DraftPort`, `KeybindingDraftStorage`, and the native backend interfaces, then remove the runtime casts. Test the path with a malformed raw record through a custom typed port.

## Low

- **`discardStoredKeybindingDraft` drops the boolean from `discardStoredDraft`** — `appwire-client/typescript/keybindingsStore.ts:333`
  A host clearing a record with no store cannot tell whether anything was removed, despite the underlying contract reporting it.
  **Fix:** Return the result: change signature to `: boolean` and `return discardStoredDraft(storage);`.

- **"Discard unreadable draft" action is a silent no-op when offline** — `mobile-native/src/KeybindingPreferencesScreen.tsx:177-193` (interacting with `run` at `:109-112` and `discardStoredKeybindingDraft` at `appwire-client/typescript/keybindingsStore.ts:333`)
  The new action's `onPress` is `if (model) run(() => model.discardKeybindingsDraft())`, and `run` early-returns on `!scope.connected || !model`. Its `disabled` prop only checks `loading`/`saving`/`writeUncertain`, not `!preferences.connected`, so unlike the neighboring refresh action the button renders enabled but does nothing. When the connection drops, `NativePreferencesProvider` disposes the model (`model` → `null`) while retaining the snapshot (so `domain.draftUnreadable` stays true), so the branch stays visible. A user whose stored draft became unreadable while offline sees "Discard it to continue editing shortcuts" with an enabled button that silently fails — the one recovery path the change was added to provide is unusable, and no error is shown. The exported host-side recovery (`discardStoredKeybindingDraft`, documented for "no connection...") is never wired into any host (only a test calls it).
  **Fix:** Route the local discard through the store-free path when there is no live store/model (e.g. call `discardStoredKeybindingDraft(keybindingStorage)` from the provider/host and update the local snapshot), or at minimum stop advertising an enabled action when it cannot run and surface why. A UI/store-level test that the unreadable record is clearable while disconnected would pin the intended behavior.
