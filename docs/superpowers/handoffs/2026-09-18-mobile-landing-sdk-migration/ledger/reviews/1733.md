### Medium

- **Package-global resolver manager selector is unsafe with multiple live servers**
  - `cmd/evener-hub/app_rpc.go:519-524`, `cmd/evener-hub/app_threadlifecycle.go:45-92`
  - `hubResolvePluginManagerFor` is a single package-global function variable installed by every server construction and never scoped or cleared. With more than one hub `WebServer` alive in the process, the last construction wins: a `thread/start` or `evener/spawn/slashCatalog` on the other server calls `hubPluginResolveManager(cfg.PluginRoot)`, which either (a) matches no root in the winner's closure and silently falls back to `plugins.NewManager(pluginRoot)` — an unwired manager, so the migration broadcast is lost — or (b) matches a root the winner recognizes and runs the write through the other server's `Manager`, broadcasting `evener/plugin/updated`/`evener/marketplace/updated` to the *other* server's clients. This is reachable in-repo: `TestHubRecoveryRequirementSurvivesRecreation` (`cmd/evener-hub/app_recovery_persistence_test.go:64`) constructs a second `NewWebServer(cfg)` while the first is still live, and the app_rpc comments explicitly contemplate "a hub server recreated in-process".
  - **Fix**: Inject the wired `*plugins.Manager` per server (e.g. as a field on `WebConfig`/server or a parameter already threaded through the thread-lifecycle handler) instead of selecting through a package global, and add a regression test with two active servers sharing a plugin root. If the global must stay, clear it on server shutdown and key it by server identity rather than by root string.

- **Store hooks emit duplicate notifications alongside existing manual broadcasts**
  - `cmd/evener-hub/app_rpc.go:1290-1368,1388-1406`, `cmd/evener-hub/app_plugin_autoupgrade.go:89-124`
  - Store hooks are added alongside existing manual broadcasts, so successful mutations emit duplicate notifications; marketplace edits emit each notification twice, and auto-upgrades can emit per-write notifications plus an aggregate notification. Clients increment `pluginRevision` and may trigger redundant refetches for each duplicate event.
  - **Fix**: Make the store-change hook the sole notification path for wired managers, or suppress the manual notification when the hook already handled the write.

### Low

- **Unsynchronized read of `hubResolvePluginManagerFor` in test**
  - `cmd/evener-hub/app_spawn_slashcatalog_test.go:421`
  - `origManagerFor := hubResolvePluginManagerFor` reads the variable the PR just placed behind `hubResolvePluginManagerMu` without taking that mutex, and `t.Cleanup` writes it back via the setter. Any concurrent server construction (`NewWebServer` → `setHubResolvePluginManagerFor`, which many `t.Parallel()` tests do) would make this an unsynchronized read/write pair on the exact field the mutex was added to protect, producing a `-race` report. It currently doesn't overlap because Go runs sequential tests before parallel ones, but it re-arms the race for any future `t.Parallel()` on this test or a leaked background constructor.
  - **Fix**: Read the previous selector under `hubResolvePluginManagerMu.RLock()` (or add a `hubResolvePluginManagerForTest()` getter) rather than touching the variable directly.

- **Test doesn't isolate ambient launch/config home**
  - `cmd/evener-hub/app_spawn_slashcatalog_test.go:414`
  - The new test calls `hubSpawnSlashCatalog` without isolating the ambient launch/config home. A malformed global `launch.toml` or an ambient `enabled_plugins` selection can make the test fail on a developer machine.
  - **Fix**: Set `LaunchConfigRoot` and `XDG_CONFIG_HOME` to temporary directories before invoking the catalog.

- **Comment references nonexistent `registerRPCHandlers`**
  - `cmd/evener-hub/app_threadlifecycle.go:50`
  - The comment refers to nonexistent `registerRPCHandlers`; the selector is actually installed by `newHubAppServerWithNavigationAndTrace`, and much of the new commentary narrates PR/review history rather than the current contract.
  - **Fix**: Name the actual constructor and rewrite the comments around the current synchronization and selection invariants.
