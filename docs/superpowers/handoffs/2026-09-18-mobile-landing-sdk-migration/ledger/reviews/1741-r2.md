## roborev: Combined Review (`ff46047`)

## Verdict: Approve with findings — the draft-checkpoint extraction is solid, but three medium issues around concurrent-draft deletion, a breaking port API, and write-queue bypass need addressing.

### Critical

None.

### High

None.

### Medium

- **`draftCheckpointPort.ts:139` — empty initial load lets `discardClassified` delete a concurrent draft.** If the repository initially loads no draft, `hasLastClassified` stays `false`. A later `discardClassified()` then reloads and removes whatever another window wrote meanwhile, so `discardDraft()` can delete a concurrent draft. Track an initial empty load as a classification and return `false` without reloading; reserve fresh-load deletion for standalone `discardStoredDraft()` use.

- **`keybindingsStore.ts:66` & `mobile-native/src/nativePreferenceDrafts.ts:10` — breaking port API change.** Changing `removeIf`/`deleteIf` from `void` to `boolean` and adding a required `replaceIf` breaks any existing custom `KeybindingDraftStorage` or native backend implementation, which now fails to compile or silently misses the new method. Make `replaceIf` optional with an unconditional-save fallback for old ports, or ship as an explicit major breaking change with migration notes.

- **`keybindingsStore.ts:1261` — `saveDraft` bypasses `writeQueue`.** The direct write can supersede an in-flight or queued `patchOverrides`; its reply is fenced and may return stale state even if the hub applied it, and queued direct writes can be rejected later because `saving` became true. Serialize `saveDraft` with direct writes through the same write queue (or track an active direct write and refuse/queue the draft save), revalidate the draft and revision when the queued save executes, and add a test covering a direct PATCH followed by a draft save.

### Low

- **`keybindingsStore.ts:955-957` (`settledWrite` catch) — `storageUnavailable` not set when `replaceClassified` throws.** The settle path moved from `persistDraft` (which caught port failures by setting `setState({ storageUnavailable: true })` then throwing) to `drafts.replaceClassified(...)`, but the new catch only returns `{ draftError: DRAFT_SAVE_FAILED_MESSAGE }`. A `replaceIf`/`decode` throw during an authoritative refresh is no longer recorded in `storageUnavailable`, which is inconsistent with the conflict branch at `keybindingsStore.ts:~1331`. Since `refreshOverrides` keys its recovery on that flag and the native domain projects it to the UI, a disk error on `Storage.setItemSync` reports only `draftError`, skips the restore attempt, and re-runs the same failing replacement on every refresh. This is a recovery/observability regression, not incorrect results. Return `{ storageUnavailable: true, draftError: DRAFT_SAVE_FAILED_MESSAGE }` (matching the conflict branch), or route the failure through a shared helper so both settle paths record it identically; add a behavioral test using a throwing `replaceIf`.

- **`keybindingsStore.ts:392`, `keybindingsStore.test.ts:398`, `mobile-native/src/nativePreferenceDrafts.test.ts:6` — comments reference history instead of domain invariant.** Comments cite round numbers, PR numbers, and finding numbers rather than the domain reason, which dates the code and obscures the invariant for future readers. Reword to state the invariant alone (e.g. "settling must not overwrite a newer checkpoint") without history references.

- **`keybindingsStore.ts:327` — `discardStoredKeybindingDraft` discards `discardStoredDraft`'s boolean result.** A concurrent replacement can make the operation a silent no-op that the public caller cannot detect. Change the specialized helper to return `boolean` and propagate the underlying result.
