## roborev: Combined Review (`8c0c444`)

**Verdict:** Extraction is sound, but concurrent-writer handling and unreadable-record recovery have gaps — 4 Medium, 2 Low.

### Medium

- **Unreadable record locks the settings section** — `appwire-client/typescript/keybindingsStore.ts:624-636, 1088-1099, 1216-1224`
 An unreadable stored record sets `storageUnavailable`, which prevents hub refreshes and blocks `discardDraft()`. The new standalone discard helper is not wired into the live store/native UI, leaving the settings section unrecoverably locked. Track unreadable records separately, allow hub refresh and discard to proceed, then clear the raw record and reset related state.

- **`save()` unconditionally overwrites storage** — `appwire-client/typescript/draftCheckpointPort.ts:95-103`
 When `settledWrite()` re-saves an uncertain draft, another store/window may have replaced that checkpoint meanwhile, so the replacement is silently clobbered. Add an atomic `replaceIf(expected, next)` operation and adopt the replacement when the compare-and-swap fails.

- **`removeIf()` reports no outcome** — `appwire-client/typescript/draftCheckpointPort.ts:11-16, 114-119`; `appwire-client/typescript/keybindingsStore.ts:1200-1224`
 Callers clear the in-memory draft even when a concurrent writer replaced it and removal was refused, hiding the replacement until remount. Return whether removal succeeded and reload/adopt the replacement instead of clearing state unconditionally.

- **`load()` clears `hasLastClassified` on empty storage** — `appwire-client/typescript/draftCheckpointPort.ts:115`
 A later external write followed by `discardClassified()` takes the fresh-reload fallback and deletes a record this repository never classified. Track "has classified" separately from "classified record exists"; after `load()` observes absence, make `discardClassified()` a no-op. Add a test covering empty load → external save → discard leaving the new record intact.

### Low

- **`save()` does not update `rawFrom`** — `appwire-client/typescript/draftCheckpointPort.ts:106`
 If a checkpoint returned by `load()` is saved again, `removeIf()` still uses the pre-save raw identity and can fail to remove the normalized record `save()` just wrote. After a successful `storage.save(decoded)`, set `rawFrom.set(checkpoint, decoded)`, and test the load → save → remove sequence with an extra-field record.

- **`lastRemoveIf()` is mistyped** — `appwire-client/typescript/testing/draftStorage.ts:22`
 Typed as `Checkpoint | null`, but `discardStoredDraft()` now deliberately passes raw unreadable values through `removeIf()`, so the accessor can return values outside `Checkpoint`. Type it as `unknown | null` to match what the port actually receives.

Two of four reviewers found no issues; the remaining two agree the extraction and test coverage are well-structured but flag the gaps above.
