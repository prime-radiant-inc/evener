# Web panes: Spawn, Composer, ProviderConnection, transcript scroll (design record)

## Summary

Four web files each hold one giant unit of state and effects. Measured on origin/main today (W1-44 and W1-45 have not landed yet, so nothing has shrunk):

| File | Lines | Unit |
|---|---|---|
| `panes/spawn/Spawn.tsx` | 3,279 | `SpawnForm` is lines 281-3259, about 88 hook calls |
| `panes/session/composer/Composer.tsx` | 1,824 | one `Composer` function from line 192 |
| `panes/settings/sections/credentials/ProviderConnection.tsx` | 2,131 | `SelectedConnection` from line 474, about 1,650 lines |
| `panes/session/transcript/flow/useTranscriptScroll.ts` | 2,449 | hook from line 1081, about 1,370 lines |

Their tests are just as big: `Spawn.test.tsx` 11,489 lines, `Composer.test.tsx` 7,498, `ProviderConnection.test.tsx` 4,805, `useTranscriptScroll.test.ts` 4,876. Spawn has 11 copies of `setBusyStartedAt(null)`, seven bespoke "host changed" refs, and a slash-completion state machine copied from Composer. Also one duplicate export name (`captureTranscriptView`), one Legacy/Provider component fork, and four "endpoint changed" constants.

End state: small duplicated pieces become shared helpers first (behavior-preserving, guarded by existing tests). Then each giant is split along seams that those helpers expose. Net about -1,000 lines, about 9,000 lines moved. The payoff is that a change to Spawn stops re-reading 3,000 lines (58 commits in 60 days) and tests can mount smaller units.

This is the riskiest web entry. I recommend landing it in three independent tracks (Spawn, transcript scroll, small cleanups) and deferring ProviderConnection and Composer splits until the earlier tracks prove the method. See questions.

Note: W1-45 says "The SpawnForm split is W2-13". W2-13 in the roadmap is hub state and config. The SpawnForm split lives here. Fix that cross-reference when W1-45 is written up.

## Proposed structure

Rules for all tracks: widget library only, no new widget or widget prop (AGENTS.md). Hooks and pure modules stay inside their pane directory. No file imports from a sibling pane except through an existing shared location.

### Spawn
```
panes/spawn/
  Spawn.tsx                 shell: owns draft, composes the hooks below, renders
  spawnLaunch.ts            pure: resolveSpawnBuiltinLaunch(...) -> {none | block(kind) | scalars}
  useSpawnBusy.ts           busy flag + finishBusy(): the single teardown
  useSpawnHostScope.ts      host-scoped state resets built on useHostEpoch
  useSpawnCatalogs.ts       harness/schema/model catalog effects (:1513-1795)
  useSpawnProviderGate.ts   providerConnected + completion fencing (:1213-1311)
  useSpawnSubmit.ts         doSpawn, handleSpawn, handleCreateConfirm
shared/ (or stores/)
  useHostEpoch.ts           monotonic epoch for the submitted host + isCurrent(epoch)
session/composer/
  useSlashCompletion.ts     shared by Composer and Spawn, beside SlashCompletionMenu
```
Boundaries: pure launch resolution never imports React or toasts; it returns a reason kind, the caller owns the toast. Host-scoped hooks take `submittedSource` and never read another hook's refs. `Spawn.tsx` is the only place that wires hooks together. The final file names can shift in the split PRs, but each hook owns one concern from the list in web-panes-b-1 (host fallback, provider completion, catalogs, slash, attachments, plugin preview, effort ladder, submit, create-directory dialog, view fencing).

### Transcript scroll
```
flow/
  viewAnchor.ts             pure anchor + focus capture/restore (current 125-490)
  useTranscriptViewRegistration.ts   (current 490-875, moved)
  scrollPredicates.ts       pure predicates (current 925-1080)
  useTranscriptScroll.ts    hook only, then split by concern (follow-ups, scroll-to-end, attention, wheel/input)
```
Element-level `captureTranscriptView` in `viewAnchor.ts` is renamed `captureElementView`. `transcriptViewRegistry.ts` keeps `captureTranscriptView(id)`. Nothing else changes names.

### ToolCallItem
One `ToolCallItem` that calls `useTranscriptRenderContext()` always. `thread` stays a prop from the parent so rows do not each subscribe to the threads store (verifier note). Delete the `renderContext` prop and the Legacy/Provider branch.

### Endpoint changed (credentials)
Share only claim/holds logic (`DestinationClaim`, `claimHolds`, versus the `draftIdentity` equivalent in `InstanceSheet`). Copy stays local per surface.

### ProviderConnection and Composer
Same method as Spawn after the first tracks land: extract pure helpers, then hooks for each ref cluster. Detailed file lists are written in a follow-up record once Spawn proves the pattern, because the cut lines depend on what W1-44 leaves behind.

## Risks and containment

- Spawn host-switch races (A-B-A): the seven refs encode subtle ordering. PR 11 migrates one ref per commit, adds a stale-answer test first, and can be reverted per commit.
- Busy/teardown regressions: a missed exit path leaves Start disabled forever. PR 9 pins every exit path before the change.
- Provider completion fencing (`completionOwned`, `providerCompletionGeneration`, `credentialChangeGenerationRef`): touched at 414-1311 and 1700-1730. PR 12 moves it as one unit with no logic edit and keeps `useProviderSetup.test.tsx` and the onboarding tests (#4821) green. The product rule applies: onboarding must return the user to the draft automatically.
- Transcript scroll reading position and the prepend measurement loop (#4918, #4706): PR 4 is the dangerous one. Pure moves go first; the hook split runs the existing `useTranscriptScroll*.test.ts*` suites plus `make test-web-browser`.
- Session-activity boundary: scroll changes must not alter subscription lifetimes. No PR touches transcript or activity subscriptions; PR 4 keeps the hook's inputs and outputs identical, and a PR description lists them.
- Widget rules: no PR adds a widget or widget prop. If a split wants one, stop and ask Jesse.
- Shared slash hook (PR 10) could regress Composer. Both panes' tests run in the same PR; the option defaults to current Composer behavior.
- Rebase churn: Spawn changes 58 times in 60 days. Land Track C PRs fast and in order, one author at a time.
- Review size: moves of about 9,000 lines. Every move PR states "pure move" and the reviewer checks `git diff --color-moved`; add a name-only diff against main after any rebase.
- Per repo convention, tests run in CI (`make test-web`) with typecheck; do not rely on a green vitest alone.

## Rejected alternatives

- Split `SpawnForm` first, dedupe later: the seven refs and 11 teardowns cross every proposed hook boundary, so the split would copy the duplication into each hook.
- Replace `useTranscriptScroll` with a reducer or state machine: a rewrite, and the scroll contract tests in `docs/web-ui/parity/` pin current behavior.
- Delete the `thread` prop in ToolCallItem and subscribe per row: adds one threads-store subscription per row.
- One `endpointCopy.ts` for the four endpoint-changed constants: the wording differs by context (key, value, save, confirm).
- Global `useHostEpoch` adoption across the app now: out of scope; Spawn first.
- Delete CSS-grep tests outright: some may be the only guard for a layout rule until `spawnguard` coverage is checked.
