# Split session tool files and share one tool-argument decoder (design record)

Measured on origin/main 7887662c9f, 2026-10-26.

## Summary

Three files in `agent/` hold most of the session tool code, and each one mixes unrelated jobs.
`session_tools_worktree.go` is 3,787 lines (was 3,798), with a 398-line `worktreeRemove` (2376-2774) and three prune sweeps named `Sweep1/2/3`.
`session_tools_jobs.go` is 2,843 lines (was 2,888) and carries six tools plus about 52 lines mentioning "stable".
`session_tools.go` is 1,822 lines and holds dispatch, the vision side channel, delegate create/send, the tool-definition cache and the task/goal store accessors.
Separately, argument decoding has no shared home. There are 11 helpers across four files (`stringArg`, `optionalIntArg`, `optionalStringArg`, `optionalBoolArg`, `optionalWholeIntArg`, `watchIntArg`, `watchStringArg`, `stringArrayArg`, `jobStatusArrayArg`, `jobTypeArrayArg`, plus `optionalTimeArg`), three near-identical `[]any`-of-strings loops, and 7 inline `.(float64)` sites in `session_tools_shell.go` (203, 207, 211, 866, 872) and `session_tools_model_list.go` (21, 24).
End state: files of 300 to 1,000 lines named for one tool or lifecycle step, one `session_tool_args.go` for decoding, `execTool` and `worktreeRemove` broken into named steps, and no change in what any tool accepts or returns.
Worth it because each of these files is where agents and reviewers get lost, and a move-only split makes later edits reviewable.
Net LOC about -300 to -400. Moves about 8,000 lines.

Decoder behavior today (read from source):
- `optionalStringArg`, `optionalBoolArg`, `optionalWholeIntArg` (`session_tools_find.go:280-325`) are strict and return `invalid_request: ...`.
- `stringArg` and `optionalIntArg` (`session_tools.go:1791-1812`) are lenient (wrong type reads as empty or nil, and `optionalIntArg` truncates).
- `watchIntArg` and `watchStringArg` are strict with their own messages. `watchStringArg`'s comment says coercing would watch the wrong source.
- The three array helpers differ in one detail. `stringArrayArg` treats a `null` value as absent, and the status and type helpers return an error for `null` because `raw.([]any)` fails.
- The shell and model_list clamps (`> 0` or ignore) are lenient on purpose.
- The registry validates schema types first, so model-visible drift is smaller than it looks (verifier note).

Docs that name these files: `docs/product/subsystems.md` row S13 (line 159, links `session_tools_worktree.go`) and row S14 (line 191, links `session_tools.go`). `docs/architecture.md:215,225` refers to `session_tools_*.go` by glob, so it survives a split.

## Proposed structure

All stays in `package agent`. No new package (verifier: keep it in `agent/`). Splits follow lifecycle for worktree and tool for jobs. Names below are proposals.

Worktree (from 3,787 lines):
- `session_tools_worktree.go`: registration, `worktreeGuard`, op dispatch, result types. About 650 lines.
- `session_worktree_state.go`: snapshot, project and root resolution, git runner and control env, lock and porcelain helpers, managed-dir path helpers, `liveWorkUnder*`. About 1,100 lines.
- `session_tools_worktree_create.go`: create, delegate lane create, rollbacks. About 450.
- `session_tools_worktree_switch.go`: switch, adopt, exit. About 600.
- `session_tools_worktree_remove.go`: `worktreeRemove` and its guard helpers. About 400.
- `session_tools_worktree_list.go`: list and formatters. About 260.
- `session_tools_worktree_prune.go`: `worktreePrune`, `laneSweepPolicy`, `prunePolicy`, the three sweeps, own-marker helpers, branch helpers. About 760.
- Renames: `worktreePruneSweep1` to `collectRegisteredLanes`, `Sweep2` to `reconcileOrphanSidecars`, `Sweep3` to `pruneGitRegistry`. These match what their doc comments say they do.
- `worktreeRemove` becomes an orchestrator calling named guards in the same order (resolve target, confine to managed dir, live-work check, lock check, dirty check, merge check, delete). The exact guard list comes from the existing "Step N" comments, which I did not read in full.
- One `mergeCheckSkip(dErr)` helper replaces the two `"merge check failed: "` closures.

Jobs (from 2,843 lines):
- `session_tools_jobs.go`: registration, shared accessors (2124-2200), output limits. About 350.
- `session_tools_job_watch.go`: 141-540 plus watch arg decoding, formatting, DTOs. About 900.
- `session_tools_job_list.go`: list, projection, rendering, DTOs. About 600.
- `session_tools_job_status_stop.go`: status, stop, their DTOs. About 500.
- `session_tools_delegate_send.go`: `delegateSendResult` and formatting. About 200.
- Delegate create and send handlers from `session_tools.go` (97-250) join `session_tools_delegate.go`.
- Rename `stableDelegate*` and friends to `delegate*` in a separate mechanical commit, only where no collision exists.

Session tools core (from 1,822 lines):
- `session_tools.go`: `execTool`, tool-name mapping, rerun, result append. About 750.
- `session_tools_vision.go`: lines 295-675. About 380.
- `session_tool_definitions.go`: 1422-1690. About 270.
- `session_tools_delegate.go`: 97-250.
- Task/goal store accessors (1727-1790) go to `session_tools_task.go` and `session_tools_goal.go`, which already exist.
- `execTool` gains `errorResult(call, msg)`, `runPreHooks`, `runPostHooks`. The lock-ordered emit/close block stays inline in `execTool`. The inline cancelled-end at 972-984 differs deliberately (the response side-effects lock is already held there), so it stays distinct or becomes `emitToolEnd(locked bool)`.

Decoder (new `agent/session_tool_args.go`):
- Boundary rule: every tool-argument helper lives here. Tool files call it. It imports nothing from tool files. It holds no session state.
- Contents: `stringArg`, `optionalStringArg`, `optionalBoolArg`, `optionalWholeIntArg`, `optionalTimeArg`, `optionalIntArg`, and one generic `stringListArg[T ~string](args, key, validate func(string) (T, error))`.
- `stringArrayArg`, `jobStatusArrayArg`, `jobTypeArrayArg` become thin callers of the generic helper, keeping their own enum validation.
- `watchStringArg` and `watchIntArg` call the strict set where their messages and semantics permit. Where they cannot, they stay and say why.
- The lenient shell and model_list clamps stay as they are.

Small remaining items:
- Replace `jobToolRegistrar`/`jobToolRegisterFunc` with a `register func(tool.RegisteredTool) error` parameter, matching `session_tool_registry.go:508-514`. This changes the fault-injection fake in `jobs_seed100_fuzz_test.go`.
- Comment cleanup: rewrite the roborev, "round" and test-name comments (about 15 sites) to state the invariant, folded into the moves. Leave plain issue-number pointers.
- `spec §` comments: keep for now (the verifier says keep until an evergreen doc exists).

## PR sequence

Each PR is mechanical enough to review with `git diff --color-moved`. CI runs the suites (project rule: tests in CI). Locally run `go build ./agent`, `go vet ./agent` and `go vet -tags evenerfuzz ./agent`.

1. Characterization tests for the decoders. Behavior-preserving, test-only. For each tool that uses the strict helpers, table tests with inputs `1.5`, `"3"`, `null`, `-1`, `NaN`-like, wrong type, absent. They assert accept or reject and which field is named, not message text (AGENTS.md copy rule). Include the `null` array difference. Deps: none.
2. Pure move: `session_tools.go` split into vision, delegate, tool definitions, task/goal accessors. Pure move. Proof: `git diff --color-moved` shows only moves, build and vet pass, existing suites unchanged. Update `subsystems.md` S14 links in this PR. Deps: W0-12 landed.
3. Pure move: `session_tools_jobs.go` split into watch, list, status/stop, delegate send. Pure move. Same proof. Deps: PR 2 (so delegate send lands once), W0-02 landed or its edits to these files rebased.
4. Pure move: `session_tools_worktree.go` split by lifecycle. Pure move. Same proof, plus update `subsystems.md` S13 links. Deps: none beyond W0-12. Can run in parallel with 2 and 3 since the files differ.
5. Mechanical rename: `stableDelegate*` to `delegate*` and `Sweep1/2/3` to purpose names. Pure rename with `gofmt -r` or a scripted rename, no logic change. Proof: build, vet with and without `evenerfuzz`, and a diff that contains only identifier changes. Deps: 2 to 4. Gated on Question 1.
6. Decoder consolidation, step A: move `stringArg` and the `optional*Arg` helpers into `session_tool_args.go` (pure move). Deps: PR 1, 2.
7. Decoder consolidation, step B: generic string-list helper under the three array helpers; `watchStringArg`/`watchIntArg` call the strict set where messages allow. Behavior-preserving refactor. Proof: PR 1 tests pass unchanged. Deps: PR 6.
8. Replace `fmt.Sprint(args[k])` only where the schema marks the field required (13 sites today). Behavior-preserving, but for an absent key `fmt.Sprint(nil)` gives `"<nil>"` and `stringArg` gives `""`. Red-first: a test for the absent key on each site shows the current value, then the change. If any site's required status is unclear, leave it. Deps: PR 7.
9. `execTool` extraction: `errorResult`, `runPreHooks`, `runPostHooks`. Behavior-preserving refactor. Proof: existing checkpoint tests (`session_skill_delivery_test.go`, `session_communicate_test.go`), plus a characterization test I would add for hook-deny and updated-input paths before touching. No reordering. Deps: PR 2.
10. `worktreeRemove` into guard helpers, plus the shared merge-check closure. Behavior-preserving refactor. Proof: existing `session_tools_worktree_remove_test.go`, `_livework_test.go`, `_errors_test.go`; add a refusal-order characterization (each guard fails alone, and when two fail the same one wins as today). Deps: PR 4.
11. Replace `jobToolRegistrar` with a register func. Behavior-preserving refactor. Proof: `jobs_seed100_fuzz_test.go` adapted and still hitting the Nth-registration-fails case. Deps: PR 3.
12. Comment cleanup in files touched by the moves. Comment-only. Can be folded into PRs 2 to 4 as a last commit each if the diff stays readable. Deps: 2 to 4.

Deferred, not in this entry: removing the mirror DTOs. Needs the state JSON consumers checked first (Question 2).

## Risks and how each PR contains them

- A "pure move" that drifts. Containment: one move per commit, `--color-moved` review, no edits inside moved bodies, rename PR separate.
- Merge conflicts, since other work edits these files daily. Containment: land PRs 2 to 4 quickly, each as a single commit, and rebase over main right before merge. Move PR 3 after any in-flight W0-02 edits to `session_tools_jobs.go`.
- Doc links rot. Containment: PRs 2 and 4 update `subsystems.md` S13 and S14 in the same change, as AGENTS.md requires.
- Decoder changes alter what the model sees. Containment: characterization first (PR 1), lenient clamps untouched, the `null` array difference pinned and kept unless Jesse says otherwise.
- `execTool` and `worktreeRemove` carry lock and ordering invariants. Containment: leave the emit/close block and lock-phase code in place, extract only the pre and post bodies, no reordering, existing suites as proof.
- Build-tag helpers. Containment: vet with `-tags evenerfuzz` on every PR, since some helpers exist for tagged harnesses.
- The prune sweeps have two callers (`worktreePrune` and `session_worktree_sweep.go`). Containment: the rename PR touches both call sites and the policy struct stays unchanged.

## Rejected alternatives

- New subpackage `agent/toolargs`. The verifier says keep it in `agent/`. Helpers are tiny and the package would need exported names for no outside user.
- A table-driven or reflection-based argument decoder (struct tags). New mechanism, not needed for 11 small helpers. YAGNI.
- Rewrite `worktreeRemove` as a state machine. Behavior risk with no test net. Guard extraction in the same order is enough.
- Merge the three prune sweeps into one generic sweep. They differ in scope and failure contract (`abortOnError`), so a shared function would need flags. Rename by purpose instead.
- Unify all lenient and strict helpers into one strict set in one pass. Changes what models can send. Left behind Question 3.
- Delete the `spec §` comments during the split. The spec exists and checks them. Keep until an evergreen doc replaces it.
