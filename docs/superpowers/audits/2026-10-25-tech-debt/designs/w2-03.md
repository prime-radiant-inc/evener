# Extract Session-free leaf packages from `package agent` (design record)

Measured on origin/main 7887662c9f, 2026-10-26.

## Summary

`package agent` has 176 non-test files and 104,893 lines (the audit said 105,781; Wave 0 trimmed it), plus 958 test files that all compile into one test binary. Most of that is `Session`. A few clusters never name `Session` and touch the rest of the package through a handful of symbols. Those can leave without a redesign.

The end state is three small leaf packages inside the agent module: `agent/hostresources` (cgroup and host resource probe), `agent/memorypages` (memory page parse, index render, legacy index migration), and a write-side addition to `agent/internal/frontmatter`. A fourth package, `envsnapshot`, is optional and I recommend deciding it separately (Q1).

Honest payoff: the first three moves take about 2,200 source lines (2.1% of the package) and about 2,600 test lines out of `agent`. That is small. The value is boundaries, not size: the memory page code gets a 14-symbol interface (today it is a hand-kept island among 170 files), the memory frontmatter editors get a proper home beside `Split`/`Parse`, and `resourceCapsFromEnv` stops sharing a namespace with `Session`. The verifier says to justify each move by a boundary and to measure test-binary build time in CI before and after. This plan does both.

Rule for the whole entry: `Session`, `retirement.go`, `status.go` and `sandbox_delegate.go` never move here. Steps 4-5 of the audit (`transcriptview`, `artifactread`) stay out until their exported surface shrinks (W1 entries on those helpers). Nothing in this entry changes behavior.

## Proposed structure

```
agent/hostresources/   CapsFromEnv(env) *schema.ResourceCaps and the cgroup reader.
                       Imports: execenv, schema, stdlib. Nothing else.
agent/internal/frontmatter/   existing Split/Parse (read side)
                       + YAMLField(key, value) and SetField(raw, line)  (write side, generic)
agent/memorypages/     page, index_render, scope_pages, write_page, migrate (legacy MEMORY.md).
                       Imports: execenv, internal/frontmatter, yaml.v3, stdlib.
agent/ (root)          Session, session_memory.go, session_tools_memory.go call memorypages.
```

Boundary rules:
- New packages never import `agent`. Enforce with a `go list -deps` check in the PR that creates each package (the roadmap's test line), and keep it in `make lint` only if an existing lint hook for import rules exists. I did not find one, so do not add a new gate here.
- `memorypages` is public, not `internal`. `ListMemoryScopePages` is used by `tools/prompt-eval`, outside the agent module. Exported surface: the 14 root-used symbols (renamed exported), plus `ListScopePages`/`ScopePage`. `memscope/main.go` and the `memcheck.py` comments change to the new name in the same PR. No alias left behind (no backcompat without Jesse's say).
- Memory state ownership does not move. The session still owns `memoryMu`, per-scope baselines, refresh and retirement-drain (docs/product/memory.md, S24). `memorypages` is stateless functions over an environment.
- `repairMemoryFrontmatter` stays in `memorypages` (it names the memory keys). `YAMLField` and `SetField` go to `internal/frontmatter` because they are generic key-line editors. `memorypages` is inside the agent module, so it can import `agent/internal/frontmatter`; no need to make that package public (W0-04 removed the only outside consumer).
- `memory_write_page.go`'s `stringArg` use becomes a signature change: `PageFromFields(when, body string)`. The caller in `session_tools_memory.go` does the arg decoding. This keeps W2-06's decoder consolidation independent.
- `collapseWhitespace`: `memorypages` keeps its own unexported copy because it is the main user. The root keeps a copy only if `session_tools_jobs.go:1058` has no shared helper to switch to. Grep for the shared helper (`internal/runetrim`, `agent/activitybound`) before copying, per AGENTS.md. Journal the duplicate with `internal/tool/breaker.go:554` rather than fixing it here.
- Tests move with their subject. A test that builds a `Session` stays in `agent` (`memory_write_page_test.go` has two Session references; `git_snapshot_test.go` three). Shared fixtures that moved tests use from other agent test files are the main unknown (see Risks).

## Risks and containment

- **Hidden test fixtures.** Moved test files may call helpers defined in other `package agent` test files (the package has 958 test files and `testkit_test.go`). I checked non-test coupling only. Containment: each move PR compiles the package with `go vet` locally (allowed: build and vet, tests go to CI per Jesse's rule); a missing helper is copied into the new package's `_test.go` only if tiny, otherwise the test stays in `agent` and tests the new API through the exported surface.
- **Exported surface grows without a second consumer.** `memorypages` exports 14 symbols with one real consumer pair (the session files) plus `memscope`. Containment: this is the verifier's "justify by a boundary" check. The boundary is the 16-identifier interface I measured, small enough to review; if the export count grows past about 20 in the PR, stop and ask.
- **Merge conflicts.** `session_memory.go` and `session_tools_memory.go` get small import edits. W2-01/02/05 touch job and delegate files, not these. Land PR 3 quickly after PR 2.
- **Import cycles.** New packages must not import `agent`. The `go list -deps` check runs in the PR; CI compile catches the rest.
- **Recovery and preservation contracts.** The legacy `MEMORY.md` migration and its backup/restore paths (S24, Q1 says migration stays) are moved byte for byte; their alternation, ctx and property tests move with them and must run unchanged in CI. No test text is edited.
- **Product docs drift.** AGENTS.md requires evergreen docs in the same change. Each PR carries its docs edits (subsystem rows link to new paths).
- **Pre-existing: coverage floors.** `testing-budget.json` is a wall-time ratchet per package; a new package without a row reads as "no budget yet" (warn-only), so add rows in the same PR.

## Rejected alternatives

- **Move everything in the audit's steps 1-5 at once.** `transcriptview` needs 20 exported helpers and findings 3, 11, 14, 26 first; verifier marked it contingent.
- **Make `agent/internal/frontmatter` public as `agent/frontmatter` (the raw finding's step a).** The only outside consumer was the root `/frontmatter` package W0-04 deleted. Staying internal keeps the surface smaller.
- **Put `repairMemoryFrontmatter` in `frontmatter` too.** It names the memory keys `description`, `evidence`, `when`; that belongs to the memory package.
- **Put the legacy migration in a separate package so it can be deleted whole.** Its sunset needs Jesse's call (finding 16, Q1 keeps it). A single `migrate.go` inside `memorypages` is just as deletable.
- **Leave a type alias or thin wrapper in `agent` for moved names.** Backward-compat code needs approval and no outside caller needs it.
- **Split `Session` or the notification-retry state as part of this.** The raw report and verifier both say that needs its own design.
- **Hub package split (`hubconfig`, `navigation`, `hostmanage`).** Counterpart finding hub-root-rest-10 is routed to W2-10 by the roadmap; the verifier says not a standalone PR.
