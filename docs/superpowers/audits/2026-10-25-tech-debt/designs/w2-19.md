# Split oversized test files (design record)

## Summary

Test files have grown into grab bags. Measured on origin/main today:

- 43 test files exceed 2,000 lines (the audit said 27; it counted web only).
- The worst are `mobile/src/state/conversation.test.ts` (20,788 lines, 416 tests, 91 `describe`), `cmd/evener-hub/app_rpc_test.go` (13,456 lines, 215 tests), `Spawn.test.tsx` (11,489 lines, 282 tests, no `describe`), `threads.sessionActions.test.ts` (10,661), and `AppShell.test.tsx` (8,974 lines, 165 tests, no `describe`).
- `agent/execenv/glob_budget_test.go` moved to `agent/execenv/` is 3,096 lines, 75 tests. The audit path `agent/internal/execenv/` no longer exists.
- Hub tests build config by hand: 1,308 `WebConfig{` literals against 286 `NewWebServer(` calls in `cmd/evener-hub`.
- sshconn tests lean on a fake runner that parses shell text: 479 `runFn` refs in 79 files, and `fakes_test.go requireProtocolUpgrade` matches script fragments.

The end state is topical files of roughly 300 to 1,500 lines, with shared helpers in one sibling helper file per area, and the same tests passing before and after. The payoff is reviewability and merge conflicts: huge files make every PR that touches them a conflict magnet, and agents read 10k lines to add one test.

Most of this is pure move. Two parts change test logic (the hub fixture defaulter, the sshconn `fakeHost`) and get their own PRs. Phrase-assertion cleanup is not here. It belongs to W1-50, and round-label renames to W1-55.

## Proposed structure

Rules for every split:
1. One topical file per cohesive group. File name states the behavior (`app_rpc_deletion_fence_test.go`), never a round, pass, or coverage label (AGENTS.md).
2. Shared helpers go in one `<area>_helpers_test.go` / `<area>Fixtures.ts` next to the tests. A helper used by one topical file stays in that file.
3. Test functions keep their names and bodies. A split never merges, deletes, or rewrites a test.
4. Where a file has `describe` blocks, a block moves whole. Where it has none (`Spawn`, `AppShell`), group by the first noun in the test names and add the `describe` in the new file only if the group already shares a `beforeEach`.
5. Imports go one way: topical test files import the helpers file. Helpers never import topical files. No cross-imports between topical files (if two need one helper, it moves to helpers).

Targets, by area:
- Hub RPC: `app_rpc_test.go` becomes `app_rpc_items_test.go`, `app_rpc_threadlist_test.go`, `app_rpc_deletion_fence_test.go`, `app_rpc_relay_test.go` (the 29 relay tests plus the relay helpers), `app_rpc_replay_items_test.go`, `app_rpc_resume_test.go`, `app_rpc_test.go` (what remains: initialize/upgrade/misc), and `app_rpc_helpers_test.go` (the four server helpers). Aim for no file above 2,500 lines.
- execenv: split `glob_budget_test.go` by the concern in test names (budget, ignore-set loading, refusals). The 18 near-clone `Refuses*` tests stay as they are in the move PR. Collapsing them into a table is a separate go-tests-agent-11 change, not part of this entry.
- Spawn: files by test-name group (start/submit, model and slash commands, access mode, host picker, drafts and URL prefill, error toasts). Fixtures/mocks to `spawnTestHarness.tsx`. Follows W2-16's source extraction boundaries where they exist.
- AppShell, threads.sessionActions, Composer, Session: same method, by `describe` or name noun.
- Phone `conversation.test.ts`: whole `describe` blocks to files named for the store concern. Fixtures such as `outbox()` that are declared mid-file go to `conversationTestFixtures.ts`.
- Phone screens: `ConversationScreen.send.*`, `BoardScreen`, `PluginsPage` by the sibling pattern already used.
- sshconn: add a test-only `fakeHost` in `fakes_test.go` with an argv-to-operation classifier (verifier's revised plan). Port `manager_test.go`, `version_test.go`, `deploy_test.go` in slices of one file each. Production exports are added only when a non-test caller needs them. Real-shell `remoteinstall` script tests stay.
- Hub fixtures: one `newTestWebServer` that defaults every root to `t.TempDir()`. Tests that need a shared root say so explicitly.

## Risks and containment

- Silent loss of a test during a move. Contained by the name-list diff in every PR, attached to the description. A test count equal and a name set equal is the gate.
- Helper moves change visibility in TS (`export` needed) or Go (same package, no change). The compiler catches both. Rule 5 prevents import cycles.
- Hub shard balancing: CI shards 12 ways with a cost survey. I did not read how shard keys are computed. PR 3 should confirm the shard script lists tests by name rather than by file, and fail the PR if not.
- Merge conflicts: other lanes edit these files all the time. Mitigation: one file per PR, land fast, tell active lanes. A move PR that conflicts is redone by script rather than hand-resolved.
- Huge diffs hide a real edit. Mitigation: the PR must show `git diff -M --stat` with every file `100%` similar except the new helper file and the trimmed original; a reviewer can check by `git diff --color-moved`.
- vitest module-mock hoisting (`vi.mock`) can change behavior when mocks move between files. Mitigation: mocks move with the tests that need them, and the harness file is imported before the code under test.
- PR 10 changes which tests see a shared root. Mitigation above. Failures go to a fix, not a revert of the defaulter.
- No local full runs: workers build and vet locally and let CI run suites (memory: tests in CI).

## Rejected alternatives

- One mega-PR per language. Unreviewable and a conflict magnet.
- Splitting by test count (N tests per file). Produces files with no topic, so nobody finds anything.
- Converting `Spawn.test.tsx` and similar to `describe` trees in place instead of splitting. Keeps the file size problem.
- Exporting production operation kinds from sshconn for the fake runner (go-tests-rest-15). Adds production API only for tests; the verifier recommended a test-only classifier.
- Merging tests while moving them (collapsing the 18 `Refuses*` clones). Breaks the count-equality proof, so it stays a separate change.
- A lint gate on file length. See Question 3.
