# Session lifecycle: turn loop, runtime release, lock contract (design record)

Roadmap entry W2-07. Findings: agent-session-core-2, -7, -8, -10, -12; agent-session-features-7, -8, -9. Re-measured against origin/main today.

## Summary

The session lifecycle code works but is hard to change. Three giant functions carry it:

- `processOneInput` is 678 lines (`agent/session_lifecycle.go`).
- `processInputKindWithProvenance` is 596 lines (same file).
- `releaseRuntimeOnce` is 379 lines, with 16 `retirement` / `!retirement` tests.

The same file resets and sets `sessionEndEmitted` in about ten places. The `Session` struct (`agent/session.go`, 2,771 lines, 22 mutexes) documents its lock contract in a comment whose `mu guards` list is stale. `testConfig` is 484 lines of test seams inside `agent/session_config.go`. `agent/session_notes_rpc.go` is 1,294 lines holding four jobs.

End state: the same behavior, in smaller named pieces. One helper owns the session-end bookkeeping, with the emit-once rule tested. Terminal close and retirement release are two methods calling shared steps in the same order. The lock comment matches the code. Test seams live in their own file. The notes file is split by job.

Worth it because every recent session fix (`a3fd75a6d4`, `50d535faea`, `936cd32398`) touched these same 3 functions and had to reason about flag resets by hand. Net about -500 lines, about 4,000 moved. Risk is high, so the PRs are small and moves come first.

## Proposed structure

Stay in `package agent`. No new packages. Splitting the package would force exporting internals, which the verifier called speculative.

Files after the work (all `agent/`):

- `session_lifecycle.go`: input processing only (`processInputKindWithProvenance`, `processOneInput`, accept helpers).
- `session_close.go`: `Close`, `close`, `closeTerminal`, `releaseForRetirement`, and the shared release helpers. `session_retirement_release.go` keeps the policy type and fault injection.
- `session_end.go`: one small helper pair owning `sessionEndEmitted` (see PR 5). It is the only place that reads or writes that field.
- `session_testhooks.go`: `testConfig` and its types, moved out of `session_config.go`.
- `session_notes_rpc.go` splits into `session_notes_mutations.go`, `session_notes_context.go` (render, escape, canonicalizer), `session_notes_projection.go` (committed cut, projection), `session_notes_selfecho.go` (steering origin, self-echo).

Boundary rules:

- `sessionEndEmitted` is touched only in `session_end.go`. Callers ask "may I emit end?" and "re-arm for the next input". Lock rule stays: the field is guarded by `mu`; the helper takes and releases `mu` the way today's call sites do.
- `closeTerminal` and `releaseForRetirement` call the same ordered helper methods. No `releaseStep` slice (verifier: new mechanism, and ordering is the spec).
- Rest fields stay under `mu` in this plan. The lock contract comment is rewritten to list every `mu`-guarded group and every ordered lock pair in one block; `docs/architecture.md` Session lock contract mirrors it.
- Awaiting-vs-idle: no new derivation layer. If the property test finds a divergence, fix that divergence. Extract a shared final predicate only if the test shows the live and restore tails are literally the same facts-to-state step.

## Risks and containment

- **Lock order or lock-phase drift** (PRs 6, 7, 12). Containment: helpers take the same locks in the same order; no code moves across an unlock; reviewer checks each extracted helper's lock state in its doc comment ("called with mu held" or "takes mu").
- **Emit-once regression** (PR 7). Containment: characterization test lands in the same PR before the refactor commit; mutation check by commenting out one reset and watching the test fail.
- **Close ordering** (PR 6). Containment: order-recording table test for both policies; PR 5 is a pure move so the split diff is reviewable alone.
- **Hidden live-vs-restore divergence** (PR 9). Containment: it is a test-only PR first. Any fix is its own PR and goes to Jesse because it changes what users see after a restore.
- **Merge conflicts** with in-flight session fixes. Containment: moves go first and are fast to rebase; each PR touches one function.
- **Product rule check.** Nothing here adds a restriction. Retirement still releases only process-local resources and keeps durable records resumable (`docs/daemon-idle-retirement.md`). No recovery path changes.
- **CI speed.** The `testing.Testing()` forks stay, so test speed does not change.

## Questions for Jesse

1. Which long functions are worth the churn? My pick: `prepareModelRequestWithError` (369) and `stageCompactionEffects` (261) only, skip the rest unless a change needs them. The others are long but each is mostly linear.
2. Do you want the rest fields peeled into a `restState` struct? The audit assumed it has its own mutex. It does not: those fields are guarded by `mu`, and `restMu` guards only the transition plus its emit. A peel with its own lock would change locking (a behavior and deadlock risk). My recommendation is to skip the peel and just document the fields in the contract (PR 1).
3. `SimulateCrashMidExecutionForTest` is called from package `server`, so it cannot become a `_test.go` file. Keep it as an exported production method, or move the one `server` test to an `agent`-side test? I would keep it unless you want the exported surface smaller.

5. Canonicalizer in the notes file (`neutralizeNotesFraming` through `escapeNotesContextBlock`, about 140 lines): it guards a model-visible framing boundary. The plan only moves it. OK to defer any rewrite indefinitely?

## Rejected alternatives

- Generic `releaseStep` table for close: new mechanism, and order is the spec (verifier).
- Four sub-structs for `Session` (about 600 lines moved): speculative; no change today needs it.
- One pure `restingState(facts)` function absorbing restore: restore derives from transcript history, live uses counters, so one function over booleans cannot cover both.
- New package for session lifecycle: forces exporting internals for no reader benefit.
- Removing `testing.Testing()` forks: slows CI for no behavior gain.
