## Proposed structure

All of this stays in the packages that own it. No new package is created. `cmd/evener-hub` is package `main`, so file moves there need no import changes.

**Relay** (package main, new files, no new package):
- `app_relay_types.go`: handle/state types and free functions from lines 1-468. Pure move.
- `app_relay.go`: `type hubRelay struct { server; cfg; sources; logf; retryClock; mu sync.Mutex; relayed; pending; canonical; generations }` plus `newHubRelay(...)` and the public methods (`startRelay`, `readThread`, `startTurn`, `stopRelay`, ...).
- `app_relay_state.go`: the 13 `*Locked` helpers as methods. Rule: only this file touches the four maps. Other files call these methods under `r.mu`.
- `app_relay_fanout.go`, `app_relay_session.go`, `app_relay_start.go`: `startAcknowledgedFanout`, `acquireRelaySession`, and `startRelayOnce` as named phases.
- `hubRelayFunctions` stays as the facade `registerThreadHandlers` takes until the last relay PR, then becomes `*hubRelay` or a small interface of the same 7 methods (see Q1).

**Tree**: in `tree.go`/new `tree_live.go`, a `treeLive` value built once from the inputs with the `*For(id)` lookups as methods, and one `overlayLive(node, st)` that sets `Kind="session"` and `State` once. `buildTreeAtWithProjects` becomes about five calls: index inputs, build live view, build project nodes, roll up subagents, build needs-you tier.

**Roster**: `classifyMissedProbe(prev, e, identity, previousUnconfirmed) missOutcome` (a small enum plus the entries to retain), one `subagentStatesFromDelegates(diagnostics)` in `prober.go` used by both `ReadSpawnedThread` and the prober.

**Host manager** (pure moves, package main): `app_host_config.go` (config + constructor), `app_host_store.go` (`hostStore`), `app_host_toml.go` (writer, mirror, stash), `app_host_attach_state.go`, `app_host_boot.go` (reconcile passes), `app_host_compensation.go`, `app_host_rows.go` (rows, List, Status), `hostNotificationBroadcaster` moved to its own `app_notification_broadcast.go`. Boundary rule: `hostStore` code does not import attach state, and the reverse.

**sshconn** (pure moves, after W1-34): `manager.go` keeps types, `New` and small accessors; `ensure.go`, `supervise.go` (supervisorLoop, lossWatchingTransport, linkMonitor), `hostlock.go`, `hooks.go`, `channel.go`. The seven maps stay as they are.

**Instances/force-stop/fork**: in place, as named phase functions in the same files. One `mutate(opts, fn)` for the instance preamble with an optional pre-lock key resolve. Lock order stays: key resolve, `c.mu`, `credMu`.

## Risks and containment

- **Relay concurrency.** Moving state onto a struct can change lock scope or goroutine capture by accident. Containment: PR 4 changes ownership only (same bodies, `r.` prefix), one closure group per commit; PR 7 splits one phase per commit; no PR changes a lock order; `go test -race` on `app_relay*` and `app_rpc` runs in the CI race lane (not locally, per repo memory).
- **Hidden closure capture.** Closures capture `cfg`, `logf` and `retryClock` at construction ("fence against the lookup captured here", :472). The struct must capture the same values at `newHubRelay`, not read live seams later. A test already covers the background fence; PR 4 adds a line in the PR body listing each captured value.
- **Tree output drift.** Golden and agreement tests pin it. PR 10 adds the overlay table before touching overlays, since the `Kind="session"` re-set after `liveFieldsFor` is easy to drop.
- **Roster probe-miss.** The crash-versus-reused-PID logic is subtle (comments :843-880). PR 9 extracts without editing branch bodies and pins the four outcomes first.
- **Move PR conflicts.** Big moves collide with in-flight edits in the same files. Containment: do PRs 2 and 3 in a quiet window, one file per commit, rebase on `origin/main` right before merge (per the AGENTS merge rule).
- **Crash-safe commit engine.** The two-phase commit and recovery paths in `app_host_manage.go` (mirror, stash, compensation) are moved verbatim and not edited. Moves are whole-function, keeping comments.
- **Test seam removal breaks tests.** PR 8 touches the 38 callers and 80 observer references. It lands after PR 4-7 so each diff is small; tests change only in how they build the relay, not in what they assert.
- **Instances lock order.** PR 12's lock-order test comes first; the optional pre-lock key resolve stays optional because `SetModelDisabled` and `SetDefault` skip it (hub-app-rest-12 verifier).

## Rejected alternatives

- **Extract `lockAliasGroup`** for force-stop, fork, retire and resume: refuted by the verifier; the callers differ in ordering and reservations on purpose.
- **Move the relay to its own package**: it depends on package-main seams (`deletionTargetState`, `hubLogfFor`) and would need an interface for each. A file split in `main` gets the readability win without that.
- **Fold the seven sshconn maps into one per-host record now**: the verifier says only if W1-34's helpers make it fall out. It would touch the restart recovery contract.
- **Rewrite `pendingRestartState` as a kind enum**: speculative, deferred by the verifier (hub-sshconn-10).
- **One PR per file for the hub moves**: too many PRs; one PR per subsystem with one commit per file reviews fine.
- **Delete `roster_other.go`**: breaks the windows vet lane.
