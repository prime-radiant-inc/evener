# Fold `mobile/` into `mobile-native/src` and split the phone screens (design record)

Measured on origin/main 7887662c9f (2026-10-26). Line numbers below are today's and sit about 24 lines below the audit's in `conversation.ts`.

## Summary

Three phone files hold most of the risk. `mobile/src/state/conversation.ts` is 3,697 lines with one 3,050-line closure (`createConversationStore`, 610 to about 3660). `mobile-native/src/screens.tsx` is 4,027 lines with one 3,615-line component (`ConversationScreenView`, 413 to 4027; 121 hook calls, 36 `useEffect`). `mobile-native/src/board/BoardScreen.tsx` is 1,994 lines with a 1,088-line `Board()` and six render-time ref writes. The `mobile/` directory is a pseudo-package: 12 files, no `package.json`, and 157 `mobile-native` files reference it. It also imports back from `mobile-native` (`projectedRows`, `transcriptPresentation`), so the layering is a cycle.

End state: one tree (`mobile-native/src`), imports run one way, the store closure is split into modules that each own one kind of state, and the two big views are composed from named hooks and sub-views. Worth it because every phone change touches these three files, their tests total about 36,000 lines, and nobody can review a diff inside a 3,000-line closure.

This record recommends the fold direction (git mv), moves first, and a behavior-preserving split. Behavior should not change; the only possible copy change is merging the two shutdown prompts (PR 7, question 3).

## Proposed structure

Direction: fold. Reason: `mobile/` has no package identity, one consumer tree, and a back-edge. Moving two native files into it would keep the pseudo-package and require the same config edits in the other direction (S03 would still say "shared").

Target:
- `mobile-native/src/conversation/` (new dir; `mobile-native/src/newSession.ts` already exists so a flat drop would collide)
  - `services/` conversation, newSession, (activity if W1-43 has not removed it)
  - `store/conversationStore.ts`: the thin `createConversationStore` that wires modules and exposes the state shape
  - `store/rowTransforms.ts`: pure functions (`reconcileCrossTurnReissues`, `splitClusterAtAnchors`, `activityRunRow`, `arrivalAnchor*`, `truncateItem`, `trimBoundary`)
  - `store/transientWarnings.ts`: a small class owning `transientWarnings`, `liveNoticeSerial`, `seat`, `reanchor`, and prune
  - `store/boundedText.ts`: the `boundedText` cache with `capAndTruncate`
  - `store/pendingMutations.ts`: the pending-port binding and snapshot
  - `store/rehydrate.ts`, `store/trailingReread.ts`: later phase
- `mobile-native/src/conversationScreen/` (screen split):
  - `ConversationScreen.tsx` (route shell, `useFocusAfterModal`), `ConversationScreenView.tsx` (composition only)
  - hooks, each owning its refs and effects: `useReaderScroll`, `useComposerDraft`, `useSessionControls`, `useFindInSession`, `useRecoveryActions`, `useForkAction`
  - `ReaderCell.tsx` as a module-level component
- Board: `board/BoardLeaves.tsx` (the seven leaf components), `board/boardDialogs.ts` (`confirmShutDown`, `promptRename`, `NAME_MAX_CODE_POINTS`), `board/useBoardScroll.ts`, `board/useBoardSearch.ts`.

Boundary rules:
1. `conversation/` may import the package, `projectedRows`, `transcriptPresentation` and other native leaf modules. It never imports `screens.tsx`, `board/BoardScreen`, or any `*.tsx` view.
2. Store modules receive state through arguments or own it in a class. No module reads another module's `let`. State lives in exactly one module: the transient-warning state in `transientWarnings.ts`, the text cache in `boundedText.ts`, pending-port state in `pendingMutations.ts`.
3. Screen hooks own their refs. A ref is written in an effect or handler, never during render (fixes the six Board writes as it moves them).
4. No new widgets or widget props. Existing widgets are untouched, so the AGENTS.md design-system rule is not in play.

Product contracts to keep (subsystems S03, `message-recovery.md`, `session-activity.md`): one shared session binding per (hub, ref), additive thread leases, retry gating by latest own failure plus outbox, draft and uncertainty preservation. The split moves code and does not alter owners. Update the S03 "shared mobile services" link and "Native README" in the same PR as the move.

## Risks and containment

- Import churn across 157 files. PR 1 is a rename with mechanical rewrite and nothing else; conflicts with in-flight native PRs are resolved by rebasing the rename last. Land it when native lanes are quiet.
- Closure state hidden in "pure" functions. PR 3 only moves what reads no closure state, enforced by tsc. PR 4 passes state explicitly.
- Render-count regressions from hook extraction. The `ConversationScreen.memoization` test guards; PR 8 splits stop if it moves.
- Recovery regressions in `rehydrate`. 5c is last among store extractions and gated on reconnect and multi-page tests.
- Stale line numbers. Every PR re-measures with grep, not the audit's numbers.
- Config drift. PR 1 includes the Go audit tests (`hooks_test.go`, `packageimportpaths_audit_test.go`) so `make lint` fails if a path is missed.
- Tests run in CI, not locally (memory: tests-in-ci-not-local). Workers typecheck and lint locally and push.

## Rejected alternatives

- Several routed conversation screens: changes navigation and lease behavior, which AGENTS.md says to discuss.
- Rewrite the store as a reducer or class: rewrites working recovery code; the split above keeps the same behavior and can be reviewed move by move.
- Generic `runMutation` over all three of send, queue, interrupt: `interrupt` differs materially (verifier note).
- A shared Subscribable first: low value per file, so it follows touches, not leads.
- Splitting `conversation.test.ts` here: W2-19 owns it, and moving tests while moving source doubles the review diff.
