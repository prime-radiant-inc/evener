# Hub state, config bags and registry parallel lists (design record)

Entry: W2-13. Binding input: Q20 in DECISIONS.md. Measured on origin/main at 7887662c9f (2026-10-26).

## Summary

`hub.toml` is two things at once. It is the operator's config (`[[hosts]]` plus scalars) and a machine database (ten reserved record sections the hub rewrites on every host mutation). The code that serves those records is `app_host_*.go`: 14,101 non-test lines and 32,753 test lines, beside 9,666 lines in `internal/hostops`. Two files, hub.toml and the hostops store, stay in step through a hand-built protocol: `pending_store_sync`, `mirror_commits`, a stash copy of hub.toml, and a five-phase compensation record.

Q20 fixes the end state. `hub.toml` keeps `[[hosts]]` and scalars. Every machine record moves into the `hostops` store. The two-file protocol goes away. Existing files migrate once at boot. Of the 26 `host_*` keys, 3 stay and 23 fold into one internal defaults value; a file that still sets a removed key starts with a warning.

Three smaller parts ride along because they share the disease (one fact listed in several parallel places): `launchconfig` (31 `nonEmpty = true` blocks in `merge.go`, a 14-case switch in `runtime_defaults.go`), `WebConfig` (about 107 field lines, 18 of them retention knobs), and `llm/registry` (a 257-line resolver with two copies of the layer-order replay, and `write.go` repeating schema tags 28 times).

Expected size: about -800 lines net, matching the roadmap. Risk is high only for Part B. Parts A, C and D are low risk and can run while Part B is reviewed.

## Proposed structure

### Boundary rules (Part B)
1. `hub.toml` owns what an operator may type: `[[hosts]]`, scalars, and the 3 kept host keys. The hub rewrites only `[[hosts]]` and never a record.
2. `hostops` owns every machine record. A new file in `internal/hostops` (name settled in B3) holds one record family with eight maps: host records, generations, receipts, tombstones, pruned markers, staged markers, remnants, attempts. It reuses the store's single mutex and single atomic write, so one write changes any subset of maps.
3. `cmd/evener-hub` reaches records through one interface, `hostRecordStore`, defined in B2 and backed by hub.toml first, then by hostops after B4. After B2, no `app_host_*` code touches `Config.HostRecords` and its siblings except that one implementation.
4. The record types and their validators move with the store in B3.
5. Custody and quarantine cover the new family, so a corrupt store recovers records the way it recovers operations.

### Commit order for a host mutation
Proposed order, using only fields the protocol already has (staged marker, fingerprint, pinned teardown target):
1. Store write: staged marker, provisional receipt and the new generation triple (the intent).
2. hub.toml write: `[[hosts]]` change only. The fingerprint check stays (`checkOwnFingerprint`).
3. Store write: finalize the receipt, clear the marker.

Boot rule: a staged marker whose `[[hosts]]` change is present in hub.toml rolls forward; one whose change is absent rolls back. The marker already carries `ReconcileFingerprint` and the pinned entry (`stagedMarker`, `app_host_commit.go`). `pending_store_sync`, `mirror_commits`, the generation-mirror reconcile, the hub.toml stash and `pendingCompensation` have no job left and are deleted in B5.

### Retention (Part A)
`hostRecordPolicy` gets one `defaultHostRecordPolicy` value. `WebConfig` keeps `HostProbeTimeout`, `HostMinFreeSpaceBytes`, `HostTombstoneRetention`. Tests that shrink caps set the policy on `hostManagerConfig` directly. Removed keys are found through `metadata.Undecoded()` and logged as a warning that names the key (Q20).

### launchconfig (Part C)
Add `mergeScalar` and `mergePtr` generics. Keep `app_replay_size`, system prompt modes, env, mcps, model_fallbacks and enabled_plugins explicit (verifier plan). Replace the 14-case switch with three helpers (`defaultString`, `defaultIntPtr`, `defaultBoolPtr`) and a table from `WireField` to a `*Layer` field accessor. Leave `args.go` alone unless a table measurably shrinks it.

### registry (Part D)
One helper, `replayLayerPositions(rec, visit)`, in `resolve.go`, owns the snapshot, overlay, config interleave. Resolve and `modelDisabled` pass their own visitors. `canonicalRow` stays alone (verifier). `write.go` struct-tag encoding is a spike behind a round-trip test and is dropped if output order or an empty `api_key_env` changes.

## Risks and containment

- **Lost records or reused identity (B4, B5).** A reused generation breaks pagination cursors and receipt replay. B1 asserts monotonic generations across every crash cut. Migration is import-then-strip with a marker, and the sections stay in hub.toml until the store write is durable. Q2 asks about a backup copy.
- **Store unavailable at boot.** Today a failed store open logs and serves with host operations unwired (`main.go` near `:1061`), and a corrupt file quarantines. With records in the store, that failure also hides identities. Plan: hosts from `[[hosts]]` keep serving with in-memory identities; mutations refuse with a retryable error until the store opens; the next boot finishes any pending import. Q4.
- **Operator edits to hub.toml.** The fingerprint check stays for `[[hosts]]`. Operators stop seeing machine tables in the file they edit.
- **Size of B4.** B4 stays one PR: the import, the switch of reads and writes to `hostops`, and the strip all land in one deployment. Splitting it lets a mutation made between the halves update TOML after the import marker is written, and the second half would then strip that newer record. B2's single seam and B3's store-only tests are what make one B4 reviewable.
- **Downgrade.** An older build reading a stripped hub.toml mints fresh incarnations and ignores receipts. Q2 covers whether that is acceptable.
- **Knob removal (A1).** A user who tuned one key keeps working and gets a warning. Retention changes only for that user, and only to the default.
- **Docs drift.** A1 and B6 carry their doc edits in the same PR as the code, per AGENTS.md.
- **Parts C and D churn.** Each conversion has a guard test that lands before it (C1, D1, D3, D4).

## Questions for Jesse

1. Should the warning for a removed `host_*` key fire at every boot, or once after upgrade? Every boot needs no state. Once needs a marker.
2. Should the migration keep a one-time copy of the original hub.toml (for example `hub.toml.pre-records`) so a bad import or a downgrade is recoverable by hand? It costs one extra file and a cleanup rule. Without it the sections are gone after the strip.
3. For `WebConfig`, stop after deleting the 18 knob fields (no test-literal churn), or also group the 11 `RemoteHost*` callbacks into one struct? Go composite literals cannot name promoted fields, so embedding would not keep the 215 test lines valid. I recommend stopping.
4. When the hostops store cannot open, should the hub keep serving `[[hosts]]` with in-memory identities and refuse host mutations until it recovers (my proposal), or keep today's "host operations unwired" behavior?
5. Commit order for a host mutation: store intent first, hub.toml second (my proposal), or hub.toml first, store second? The first matches how the staged marker works today. Confirm before B4.

## Rejected alternatives

- **Keep records in hub.toml and only split the code.** Q20 ruled this out, and it leaves two files in a hand-built protocol.
- **A new sqlite or JSON file for records.** Adds a third file. The hostops store already has the mutex, atomic write, quarantine and custody.
- **Dual-write during a transition.** Needs two authorities and a drift check. Import-then-strip has one authority at every step.
- **Delete the migration after one release.** DECISIONS.md Q1 says on-disk migrations stay.
- **Reflection-driven generic merge for launchconfig.** It hides the six fields that stay explicit. Small typed generics stay readable.
- **Rewrite `resolveLayersModeLive` as a struct pipeline.** Larger than the duplication it removes. The shared replay helper removes the drift risk with one function.
- **Embed sub-structs in `WebConfig` to shrink it.** Test literals cannot use promoted fields (Q3).
