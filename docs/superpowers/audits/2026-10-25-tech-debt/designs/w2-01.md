# Split `agent/job_watch.go` (design record)

Roadmap entry W2-01. Findings: agent-jobs-1, x-error-handling-slop-1/-2 (the file-level part only). Measured on origin/main at 7887662c9f.

## Summary

`agent/job_watch.go` is 6,390 lines with 284 funcs (the audit saw 6,564 and 291; Wave 0 deletions already took about 175 lines). 14 commits touched it in the last 30 days. It holds at least ten concerns in one file: config and validation, send-token plumbing, clear and budget teardown, registry events, history and projection, the three fire paths, expiry and restart notices, timers, the send rail (about 1,400 lines), Session-level child driving, frame rendering and notification routing. Readers cannot find entry points, and every watch PR collides with every other.

End state: about a dozen `watch_*.go` files in the same package, none over roughly 1,500 lines, plus the Session child-drive block (about 530 lines) living beside its siblings in `session_jobtree_drain.go`. Zero logic change, zero new packages, zero new seams. The payoff is reviewability: W2-02 (skeleton dedupe, high risk, lock-protected state) cannot be reviewed in a 6,000 line file.

This is a pure-move entry. It adds no abstraction.

## Proposed structure

All files stay in `package agent`. No exports change. No signature changes. File names use the `watch_` prefix; `agent/delegate_tree_watch.go` and `agent/session_activity_watches.go` do not collide.

| File | Owns | Approx lines |
|---|---|---|
| `watch_types.go` | messages, `watchKey`, `watchConfig`, `watchArgs`, source/send/result types | 480 |
| `watch_config.go` | normalize, validate, `configureWatch*`, target validation, `newWatchConfig`, hash and clone helpers | 800 |
| `watch_send_token.go` | token resolve, claim, settle (479-672) plus snapshot and restore (1473-1636) | 360 |
| `watch_clear.go` | clear paths, breaker, budget teardown, `closeWatchConfig` | 560 |
| `watch_registry.go` | registry events, history record | 200 |
| `watch_projection.go` | list, inspect, status rows, summaries | 800 |
| `watch_fire.go` | `onSessionEvent`, output feed, attach scan, terminal catch-up | 530 |
| `watch_expiry.go` | expiry, restart end notices | 240 |
| `watch_timers.go` | progress timers | 220 |
| `watch_send_rail.go` | delivery state machine 4186-5555, possibly split in two (`watch_send_rail.go`, `watch_send_settlement.go` for the stable-settlement retry block at 4811-4980) | 1,400 |
| `watch_frame.go` | frame rendering, notification builders and routing | 360 |
| `session_jobtree_drain.go` (existing) | the Session child-drive block 5557-5984 | +430 |

Boundary rules:

- Same package, so no import-direction rules apply. The rule is about file ownership. A function lives in the file of the concern whose state it mutates. Projections read only (`watch_projection.go` takes snapshots, never writes watch state).
- `jm.mu` still guards all watch state. No state moves between structs. The `jobManager` struct and its watch maps stay in `jobs.go`.
- Session child-drive code goes to `session_jobtree_drain.go` because it already owns drain and kick for the tree and its tests are in the same families. The alternative is a new `session_watch_drain.go`; see question 1.
- Test files keep their names in this entry. Renaming 58 test files is churn with no review value.

## PR sequence

Landing rule: each PR is a single mechanical move produced by a script (function-set diff attached: the sorted list of `func` and `type` names in the old file equals the union of the new files, and `git diff --stat` shows only deletions from `job_watch.go` and additions elsewhere). Land them back to back, one per CI cycle, and tell other watch work to rebase. Use `git blame -C -M` friendly moves (whole contiguous ranges, imports fixed by `goimports`).

Common proof for every move PR: `go build ./agent`, `go vet ./agent` with and without `-tags evenerfuzz` (fuzz files share these symbols), `make lint`, and the full job/watch suite in CI. The name-set check: `grep -h '^func \|^type ' agent/*.go | sort` before and after must be identical. No characterization tests are needed for a move that the compiler and symbol set check. A move changes no behavior.

## Risks and containment

- Merge conflicts on a 259-commit file. Contained by landing PRs 1-8 within one short window, one move per PR, and asking other watch-touching work to rebase after each. Each PR is mechanical, so a conflicting author re-derives their change in the new file.
- A silent logic change hidden inside a move. Contained by the scripted name-set check, the requirement that moved ranges are byte-identical (diff of the removed hunk against the added hunk after sorting is empty), and no hand edits in the same commit.
- Source-parsing tests going green for the wrong reason. `job_watch_timer_identity_test.go` fails loudly when the function leaves the file (it says so at `:239`), which is the desired signal. PR 5 retargets it. `job_watch_condition_fire_guard_test.go` scans the whole directory and needs no change.
- Build-tag drift. `evenerfuzz` files in `agent/` use these unexported symbols. PRs must run `go vet -tags evenerfuzz ./agent`. Tags any other file uses are found by `grep -l '^//go:build' agent/*.go` at PR start.
- Stale line citations in docs and comments. PR 9 moves them to symbol names, which survive future moves.
- Product rules: AGENTS.md asks for evergreen docs in the same change. Moves change responsibilities in the S12 row only by file list, so PR 9 covers it. No product behavior, recovery path or activity scope changes, so the session-activity guide is untouched. No UI work, so the widget rules do not apply.

## Rejected alternatives

- Split into a sub-package (`agent/watch`). The code touches `Session`, `jobManager` and unexported state throughout. A package needs an interface seam first, which is W2-03 territory and a design change, not a move.
- Do the split and the W2-02 dedupe together. Moves and logic changes in one diff cannot be reviewed by symbol-set check. The roadmap orders them for this reason.
- One mega-PR with all files. Too big to review even as a move, and one conflict blocks everything.
- Split by line count with no concern boundaries. It would leave the same tangles with different names.
- Leave the file and add a table of contents comment. The merge-conflict cost remains.
