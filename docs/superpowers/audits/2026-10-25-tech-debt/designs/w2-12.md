# Server and appserver runtime files, W2-12 (design record)

Measured on origin/main today (fetched 2026-10-26).

## Summary

Three files hold the AppWire server side, and each mixes unrelated jobs:

| File | Lines | Problem |
|---|---|---|
| `server/appwire_runtime.go` | 2,986 | 107 funcs: identity, event recording, task projection, status stamping, ~25 request handlers, thread projection. 27 `s.mu.Unlock()` sites. |
| `internal/appserver/server.go` | 2,299 | Config, connection I/O, hydration, subscribe/unsubscribe, request queue and slots, dispatch. Seven locks. |
| `appwire/types.go` | 5,897 | 365 types, 137 `Method*` consts in one file. |

Tests are large: `server` 22,763 test lines, `internal/appserver` 10,385. Those suites are the safety net.

End state: each file splits by responsibility into same-package files (no new packages, no import changes). Three small cleanups ride along: one subscription-admission resolver instead of two, one unsubscribe target under one context key, and `handleAppThreadClear` rewritten as a short decide-then-act function over a journal type. Net ~-300 lines, ~11,000 lines moved. The payoff is smaller review surface per change and fewer merge conflicts in files that 68-commit-a-month features keep touching.

Two audit worries are settled by reading code. The type generator does not need a single `types.go`. The `routedSeq` closure is safe (see Risks).

## Current structure

### `appwire/types.go`
- Generator is `internal/appwirets/emit.go`, run by `//go:generate` in `appwire/doc.go:29` into `appwire-client/typescript/types.gen.ts`.
- It reads the Go types by reflection and walks `appwire.Methods` and `appwire.Notifications`. For field comments it parses every non-test `.go` file in the package directory (`emit.go` `parsePackageFieldDocs`). It sorts names (`sort.Strings`, line 615). So file layout inside the package cannot change the output.
- One real coupling: `appwire-client/typescript/errors.test.ts:5` imports `../../appwire/types.go?raw` and regex-matches `json:"name"` tags (line 92). A split breaks that test until it reads the new file.
- Method constants already live outside `types.go` in three files (`keybindings.go:13`, `agents_doc.go:9`, `transcript_display.go:12`).
- `ValidateMutationParams` (`appwire/protocol.go:317`) rebuilds its method-to-fields map on every call. It lists `MethodUrlsRemove`; `retrySafeMutationMethods` (`appwire/errors.go:923`) does not.
- File has natural bands: initialize/archive/session (1-700), thread and item types (700-2000), turn and mutation results (2000-2900), jobs/activity (2900-3300), models/update/navigation (3300-3960), auth/commands/spawn/marketplace (3960-4900), hosts (4900-5897).

`handleAppThreadClear` shape: validate and trim (cheap), take `appMutationGate`, then lock `s.mu` and run a chain of cases (journal broken, stale ref, replay of a recorded clear, crash-recovery of a reserved record, stale instance, blocked work, no clear func). Then reserve in the journal, unlock, call `clearFunc`, relock, then record applied. Every branch unlocks by hand. Journal persistence is `server/thread_clear_journal.go` (168 lines), which has its own copy of the "sync unsupported" predicate (`journalSyncUnsupported`, `:155`).

## Proposed structure

All splits stay inside the existing package. Rule: a file split moves declarations only, with identical names and bodies.

### `appwire/` (package `appwire`)
New files by band, named for the domain: `types_session.go`, `types_thread.go`, `types_turn.go`, `types_jobs.go`, `types_models_nav.go`, `types_auth_commands.go`, `types_hosts.go`. Method constants move with their param/result types. `types.go` is deleted when empty. The registry (`protocol.go`) stays the one list of methods. `ValidateMutationParams` map becomes a package var.

### `internal/appserver/`
- `config.go`: `ServerConfig`, `SubscriptionAdmission*` types.
- `server.go`: `Server`, `NewServer`, shutdown, registry, `Broadcast`, `initialize`.
- `connection.go`: `Connection`, send path, `HandleMessage`.
- `hydration.go`: finalizers, `AfterResponseWritten`, `RunAfterResponseWritten`.
- `subscribe.go`: `Subscribe*`, `Unsubscribe*`, `Capture*`, `captureSubscription`, context keys.
- `dispatch.go`: inbound queue, worker, slots, `executeOrdered`, recovery.

Boundary rules: files only share package-private names within `appserver`. No file may take a lock out of the order `hydrationMu`, `projectionMu`, `deliveryMu`, `admissionMu`. The lock order goes in a comment on `Server` once (from `:1284-1295`).

### `server/`
- `appwire_identity.go`, `appwire_record_events.go`, `appwire_task_projection.go`, `appwire_status_stamps.go`, `appwire_read_handlers.go`, `appwire_turn_handlers.go`, `appwire_thread_clear.go`, `appwire_thread_settings.go`, `appwire_jobs_models.go`, `appwire_thread_projection.go`.
- State stays on `Server` and under `s.mu`. No new type owns state except the journal below.

### Thread clear
- A `threadClearJournal` type in `thread_clear_journal.go` owns `clearRecords`, the path, and persist/rollback (`reserve`, `markApplied`, `restore`). It holds no lock; `Server.mu` still guards it, as today.
- The handler splits into `decideThreadClear` (runs under `s.mu`, returns one of: reject with error, replay response, recover reserved record, proceed with reservation) and `runThreadClear` (unlocked work and the final record). Lock and unlock then appear in two or three places instead of 27.
- Persist uses the shared durable writer from W1-01..03 (Q4) and deletes `journalSyncUnsupported`.

## Risks and containment

- **Generated output drift (PR 3).** Contained by the byte-identical `go generate` check and the freshness test. Comment-only differences matter, so the doc-comment parse must see all files; it does.
- **Stale `types.go` references.** TS comments and `errors.test.ts` name the file. PR 2 fixes the test. Comment references in TS (`reducer.ts:2465`, `4994` and others) are stale prose and get a sweep in PR 3's follow-up, not in the move.
- **Merge churn.** Three big moves while 68-commit-a-month features land. Land PRs 3, 4, 5 on separate days, each rebased on a fresh main, and announce the freeze for those files. A pure move re-applies quickly if it conflicts.
- **Lock order (PRs 4, 8).** No code changes in PR 4. PR 8 runs under the race lane in CI only (local stress is off the table).
- **Two resolvers differ on purpose (PR 7).** The characterization tests in PR 6 pin both behaviors before any deletion.
- **Thread clear recovery (PR 10).** The nine paths include crash recovery. PR 9 pins every path first; PR 10 may not change a test.
- **Doc links.** `session-activity.md:468` and the subsystems S05 row link these files. Every move PR updates them in the same change.

## Questions for Jesse

1. Should the local resolver start returning `Invalid` for an undecodable `thread/read` body, as the hub does, or keep today's silent not-subscribe? The first is a small product change (an error reaches the client instead of an ignored subscribe).
2. Should `urls/remove` be retry-safe? `ValidateMutationParams` requires its mutation id, but the Go and TS retry-safe lists omit it (`errors.go:923`, TS `dispatcher.ts:313`). If it is intentional, I add a comment and a test. If not, the lists change on both sides.
3. Is a seven-way split of `types.go` OK, given every file you open to find a type now needs a grep by name? I think yes because the generator and registry do not care, but it is your call on navigability.

Generic `hook[T]` and shrinking the 50-method `serveServer`-style interface are out of scope here (the verifier deferred them; `serveServer` is a test seam used by 10+ test files).

## Rejected alternatives

- **Leave `types.go` whole because the generator reads it.** The generator reads the whole package directory, so the premise is false.
- **New packages for `appserver` pieces.** The pieces share unexported state and lock order. A package boundary would force exported accessors and add API for no reader.
- **Rewrite `handleAppThreadClear` in one PR with the move.** Mixes a nine-path lock rewrite with 2,000 moved lines. Characterization first, then rewrite.
- **Add a `retrySafeMutation` middleware here.** That is W1-20.
- **Delete `serveServer`/shrink the 50-method interface.** Large test migration, deferred by the verifier.
- **Wrapper compatibility for the removed V1 resolver.** `ServerConfig` has two in-repo users and no outside ones. Q1 gives no reason to keep V1.
