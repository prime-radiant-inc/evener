# Split appwire-client reducer.ts and the credentials closure (design record)

Roadmap entry W2-14. Measured on origin/main (7887662c9f), 2026-10-26.

## Summary

`appwire-client/typescript/reducer.ts` is 5,181 lines (audit said 5,168) and holds five jobs: item/image hydration, tool-call fold merge, the session cache codec with its validators, versioned history with the live overlay, and the notification fold with the warning fold. Its test file is 9,096 lines. `state/credentials/instances.ts` is 1,298 lines with 616 comment lines and one 947-line closure (351-1297). Four store files each declare `*_REFETCH_DEBOUNCE_MS = 250`, a fifth copy is private at `instances.ts:317`, and a sixth lives in web at `stores/credentials.ts:474`.

End state: `reducer.ts` shrinks to the notification fold (about 750 lines). Six leaf-first sibling files own the rest. Each move is a pure move. The credentials closure stays one closure, but its test-only reset, repeated tails and narrating comments go. One debounce constant. Barrels name their exports.

Worth it because every transcript change today edits a 5k-line file and its 9k-line test. Net LOC is about -500 and moves are about 4,000. No behavior changes in the split.

Two audit claims did not survive re-measurement:
- `resetForTests` is not test-only for web. `cmd/evener-hub/frontend/src/stores/credentials.ts:77` calls it from `resetCredentialsStoreForTests`, which 22 web files call. Deleting it breaks the web suites (Question 1).
- The revision helpers are not unused. `createListRevision`, `readRevisioned`, `writeRevisioned`, `createKeyedRevision`, `createStoreLifecycle` and `attachLifecycle` are used inside `plugins.ts`, `launchLayer.ts`, `marketplaces.ts` and `authStatuses.ts`. What has zero callers is the outside world. Deleting the code is wrong. Un-exporting it is the real change (Question 2).

W1-13 (generated key arrays for the validators) has not landed: `ITEM_MODEL_KEYS` is still at `reducer.ts:1395`. W1-42 (shared field list, `notificationTouchesTranscript`, `laterActivity` delete) has not landed either. Both edit `reducer.ts`.

- 1161-1190: `hydrateThread`.

- 2413-3433: `threadFields`, turn coalescing/weaving (2548-2760), fold coverage rules (2830-3330), `mergeTurnHistory*`, `mergeOlderItemPage*`.

Consumers: `index.ts:495-555` re-exports about 45 names. Ten package files and three `..`-relative files import `./reducer` directly, mostly tests, plus `transcriptProjector.ts`. `testing/reducerHooks.ts` does not touch the reducer despite its name.

Tangles worth knowing:
- The validators (1373-2216) only read `unknown` and `types.gen` types. They are already a leaf in practice. `isRecord`, `isFiniteNumber`, `isNonNegativeInteger` are used about 40 times each inside it.
- `foldWarningParams` is used at one internal site (`reducer.ts:5133`). The warning code imports only `warningText` and `types.gen`.
- `threadModelFromCache` and `cachedSessionRecord` need history constants from the 3433+ region (`EMPTY_HISTORY`), and the tool-fold cluster is split across two line ranges (414-1160 and 2830-3430). This is where an import cycle could form. I did not build a full import graph. PR 1 is the check.

`state/credentials/instances.ts`:
- 1,298 lines: types and listing helpers (52-350), closure `createCredentialInstancesStore` (351-1297), `resetForTests` at 1286.
- Four mutations end in `if (!applied) scheduleRefetch(); return applied;` (lines 1107, 1120, 1135, 1150).
- Shares `requestVersion`, `connection`, `localMutations`, echo markers across the whole closure. This is the real constraint on splitting it.
- `REFETCH_DEBOUNCE_MS` at 317 feeds its own timer at 659-671. The four extension/credential stores pass their constant to `createStoreLifecycle({ debounceMs })`.

Exports: `state/extensions/index.ts:7-13` and `state/credentials/index.ts` use `export *`. `state/navigation/index.ts:20-26` forbids it. The subpaths are public (`package.json` exports), pinned by `scripts/qualify-package.mjs:700-728` and the README (lines 524-540). Two mobile tests import `MARKETPLACE_REFETCH_DEBOUNCE_MS` and `AUTH_STATUSES_REFETCH_DEBOUNCE_MS` by subpath.

Comments: 17 `renderer.js`/`renderer-format` pointers in 8 production files (`askAnswers.ts` 4, `toolCallText.ts` 4, `taskListStep.ts` 3, `sendQueueAvailability.ts` 2, `client.ts`, `deriveAskQuestions.ts`, `steeringNotifications.ts`, `reducer.ts` 1 each). That is a comment-only cleanup.

## Proposed structure

New files in `appwire-client/typescript/`, leaf first. Arrow means "may import".

| File | Owns | Approx lines | May import |
|---|---|---|---|
| `warningFold.ts` | `foldWarningParams`, `joinWarningParts`, `WarningFold`, `RAW_WARNING_FRAME_*` and the bounding helpers | 250 | `warningText`, `types.gen` |
| `transcriptValidators.ts` | `isRecord`-family guards, `valid*` shape checks, `ITEM_MODEL_KEYS` | 850 | `types.gen`, `model` types |
| `transcriptItems.ts` | stable delegate helpers, image mapping, text-presence/identity-only marks, `wireItemToModel`, tool id predicates | 400 | `model`, `types.gen` |
| `turnHistoryMerge.ts` | tool-fold context, page/turn merge, coalescing, fold coverage, `mergeTurnHistory*`, `mergeOlderItemPage*` | 1,600 | `transcriptItems` |
| `transcriptHistory.ts` | history state, versioned merges, overlay display, read dispositions, `applyReadResponse`/`applyReadModel` | 1,100 | `turnHistoryMerge`, `transcriptItems` |
| `transcriptCache.ts` | cached record types, encode/decode, `currentTranscriptState`, `threadModelFrom*`, `cachedSessionRecord` | 350 | `transcriptValidators`, `transcriptHistory`, `transcriptItems` |
| `reducer.ts` (kept) | history/overlay notification folds, escalations, routing keys, `applyNotification*` | 750 | all of the above |

Boundary rules:
- Direction is one way, in the table's order. `reducer.ts` is the only file that imports everything. No file imports `reducer.ts` except `index.ts`, tests and `transcriptProjector.ts`.
- Module-level state: the only singletons are symbol keys (`ITEM_TEXT_PRESENCE`, `ITEM_IDENTITY_ONLY`) and the `displayTurnSources` WeakMap. Each moves with its single owner. Neither may be duplicated across files.
- `index.ts` keeps exporting the same names. Test imports of `./reducer` are rewritten to the new file in the PR that moves the symbol. No re-export shim stays behind (AGENTS.md: new compatibility code needs a removal condition, and this has none to offer).
- The final `turnHistoryMerge.ts` is still large at 1,600. Splitting tool-fold from coalescing is a possible later step. It is out of scope here because the two ranges share `ToolItemMergeContext`.

Credentials and extensions:
- `state/credentials/listing.ts` takes the pure listing helpers (`listState`, `listingOf`, `listingChanged`, `foreignListingChange`, about 60 lines). The verifier called these safe to move.
- The closure stays whole. The verifier asked for a demonstrated state-passing seam before splitting echo markers or `refreshModels`. None is demonstrated, so none is proposed.
- One refetch constant, `REFETCH_DEBOUNCE_MS`, in `state/refetchDebounce.ts`. `storeLifecycle.ts` and `instances.ts` import it. Web `stores/credentials.ts:474` switches to the package export only if Question 2 allows a new export.
- Barrels: `extensions/index.ts` and `credentials/index.ts` list names explicitly, like navigation does.

## PR sequence

Every PR runs `make test-api-package`, `make test-web` and the native check for consumers (tests run in CI per Jesse's rule; locally only typecheck and targeted vitest).

Add one test that imports every `index.ts` reducer export and asserts each is a function/constant of the expected kind (shape, not phrasing). Record the intended import direction in the package README. Run a one-off import-graph check of `reducer.ts` regions to confirm the table before moving anything. Deps: none. Proof: new test green on main.
2. **Move `warningFold.ts`.** Pure move. Covered by the existing `foldWarningParams` tests in `reducer.test.ts:6039` and `:6386`; move those tests alongside. Deps: none. Does not conflict with W1-13 or W1-42.
3. **Move `transcriptValidators.ts`.** Pure move. Deps: W1-13 (it rewrites `ITEM_MODEL_KEYS` and the `valid*` functions; moving first would force a rebase on the heaviest conflict). If W1-13 stalls, move first and tell W1-13 the new path. Proof: `currentTranscript.test.ts` and the round-trip tests.
4. **Move `transcriptItems.ts`.** Pure move. Deps: W1-42 (it deletes `laterActivity` in this range). Proof: reducer tests unchanged.
5. **Move `turnHistoryMerge.ts`.** Pure move of two line ranges. Proof: `reducer.history.test.ts`. Deps: 4.
6. **Move `transcriptHistory.ts`.** Pure move. Deps: 5. Proof: the same suites plus `tokenFlood` bench still imports.
7. **Move `transcriptCache.ts`; `reducer.ts` is now the notification fold.** Pure move. Deps: 3, 6. Split `reducer.test.ts` (9,096 lines) by the same seams in the PR that moves each group, so tests follow code. Splitting tests is a pure move too.
8. **Barrels and constants.** Behavior-preserving. Replace `export *` with named exports. Add `refetchDebounce.ts` with one constant; the four stores and `instances.ts` use it. Update `qualify-package.mjs:716-728` and the two mobile tests if names change. Depends on Question 2 for which names stay. 9. **Credentials tails.** Behavior-preserving. One `settleMutation(applied)` helper replaces the four `scheduleRefetch` tails (1107, 1120, 1135, 1150). 10. **`resetForTests`.** Behavior change, depends on Question 1. Red first: whatever replaces it needs a test that the web singleton returns to initial state between tests.
11. **Comment pass.** Comment-only. Remove the 17 `renderer.js` pointers and the round/RoboRev/kata mentions in `reducer.ts` (6) and the narrating comments in `instances.ts`. Keep comments that state an invariant. Review as a diff-only PR.

Net: PRs 2-7 are the pure moves and can run without Jesse once their Wave 1 deps land (PR 2 and PR 1 have none).

## Risks and containment

- Import cycles after moves (the audit flagged this). PR 1 checks the graph first. Each move PR runs `tsc` through `make test-web` (typecheck covers both trees).
- Merge conflict with W1-13 and W1-42 in the same lines. Both are ordered before the affected moves.
- Module-level symbols and WeakMap duplicated by accident. Each stays with one owner. A duplicated `ITEM_TEXT_PRESENCE` would silently break text-presence marks, which the reducer tests exercise.
- Consumers importing by path. Web and native import by package name (AGENTS.md). Only package tests use relative paths. `make lint-package-imports` guards.
- `index.ts` surface drifts. PR 1's export-shape test plus `qualify-package` catch it.
- Declaration emit and `declaration-reachability.mjs` can fail when a type moves to a non-exported file. `make test-api-package` runs it per PR.
- Un-exporting public symbols breaks external readers. Gated on Question 2 and called out in the PR description.
- `resetForTests` deletion silently breaks 22 web test files. PR 10 does not land without the replacement.

## Questions for Jesse

1. Web tests reset the credentials singleton through the package's `resetForTests` (`stores/credentials.ts:77`, 22 files use the wrapper). Which do you want: keep the reset on the store and rename it to `reset()` to match `HostLifecycle`, move web to a per-test store factory, or keep `resetForTests` as is?
2. Should the revision/lifecycle helpers (`createListRevision`, `createKeyedRevision`, `createStoreLifecycle`, `attachLifecycle`, `readRevisioned`, `writeRevisioned`) and the four `*_REFETCH_DEBOUNCE_MS` names leave the public subpaths? They are used internally and pinned in `qualify-package.mjs` and the README. Mobile tests import two of the constant names. I lean toward un-exporting the helpers and keeping one exported constant.
3. Is the first extraction order fine (warning fold, validators, items, merge, history, cache), with `reducer.ts` staying as the notification fold? Or do you want `reducer.ts` renamed once it shrinks?

## Rejected alternatives

- Splitting `instances.ts` closure into sibling modules now. The closure shares `requestVersion`, `connection`, `localMutations` and echo markers. The verifier required a shown seam first.
- Deleting the revision/lifecycle helpers. They are live code inside four stores.
- A re-export shim at `reducer.ts` for old import paths. It would be permanent compatibility code with no removal date.
- One mega-PR for the split. Seven reviewable moves cost more PRs and much less risk.
- Splitting `reducer.test.ts` before the code. Tests follow the code they cover.
