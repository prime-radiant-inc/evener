# Split contextmgr/context_manager.go and unify journal rollback (design record)

## Summary

`agent/internal/contextmgr/context_manager.go` is 2,819 lines with about 104 top-level funcs (origin/main today; the audit said 2,838). It mixes at least eight concerns: the Manager type and context keys, pressure math, the compaction orchestrator, observation masking, the deterministic checkpoint, partner-message carry, summary prompts and validation, and the fold itself. Its test file `context_manager_test.go` is 3,487 lines with 122 tests. The end state is about ten files of 150 to 450 lines each, in the same package, moved with no logic edits. Reviewers can then check each PR with a function-set diff instead of reading 2,800 lines.

The second half of the entry is a shared rollback helper for `jobstore` and `delegatestore`. After reading both, my recommendation is to drop it. The two copies are about 25 lines each, differ in the ways that matter (cursor invalidation, seek target, injected file ops, error text that tests match), and a shared package would need an ops seam plus a latch type to save perhaps 20 lines. Question 1 asks Jesse to confirm.

W1-66 (delete the four experimental strategies) has NOT landed on origin/main yet. `strategy_obs_mask.go`, `strategy_checkpoint_pred.go`, `strategy_memory_crystals.go` and `strategy_recursive_distill.go` are all still there (190, 274, 187, 219 lines). This work waits for it, so we do not move dead code.

## Proposed structure

Same package, same exported API, no new packages. Files after the split:

| New file | Owns |
|---|---|
| `manager.go` | `Manager`, `NewManager`, `CompactionMeta`, usage accessors, `handleCompactionTurn` |
| `fold_context.go` | the `With*` context keys and their readers (`metaFor`, `currentBaseline`, `reportPostFoldInjection`) |
| `pressure.go` | profile swap, token measurement, window, pressure, `ApplyThresholdScale` |
| `compact.go` | `MaybeCompact`, `ForceCompact`, assumed-window disclosure |
| `observation_mask.go` | `maskObservations`, `clearThinking`, `summarizeToolResult` |
| `tool_output.go` | the 2738-2819 parsing helpers and `findToolCallArgs`/`parseCommunicateArgs` |
| `checkpoint.go` | deterministic checkpoint collect and format (`checkpoint_format.go` stays as the markdown layer) |
| `partner_carry.go` | partner-message fitting, condensing and carry |
| `summarize_route.go` | `summarizationModels`, fallback rules, `completeSummarization` |
| `summary_prompt.go` | prompt constants, reply checks, `buildSummaryPrompt` |
| `elicit.go` | `ElicitNote` and render helpers |
| `summarize_fold.go` | `summarizeWithLLM`, `summarizeWithLLMSteered`, `summarizeFold`, `safeCutoff` |

Boundary rules inside the package:
- Dependency direction: `compact.go` and the strategies call `summarize_fold.go`; `summarize_fold.go` calls `checkpoint.go`, `partner_carry.go`, `summary_prompt.go` and `summarize_route.go`; those do not call back up into `compact.go`. Lock-holding code (`cm.mu`) lives only in `manager.go`, `pressure.go` and `compact.go`.
- `checkpoint_format.go` keeps pure string rendering. `checkpoint.go` reads history and builds data. This matches the split that already exists.
- Test files follow the code. The 122 tests in `context_manager_test.go` move to `*_test.go` files named for the same concern. Fuzz and seqfuzz files are left where they are.

Rollback helper (only if Jesse says yes to question 1): a small unexported-by-convention package `agent/internal/journalrollback` with one function `Rollback(file, offset, ops)` and a `Latch` type. I recommend against it; see Rejected alternatives.

## Risks and containment

- A move silently edits logic. Containment: every move PR carries the function-set diff and `git diff --color-moved=dimmed-zebra` shows only moves; PR descriptions say "pure move"; no edits to comments except package-level doc.
- Two PRs touch the same file in flight. Containment: strict order above, and `context_manager.go` shrinks monotonically so rebase conflicts are deletions only.
- Other branches edit `context_manager.go` while we split. Containment: merge `origin/main` before each push; announce the window; keep PRs 1 to 5 within one day so rebases stay trivial.
- Test split loses a test. Containment: `go test -list` name set equality in PR 6.
- Layers 1 and 2 look dead and tempt deletion mid-move. Containment: they are used by `strategy_session_log.go:94,110`; the design says move, do not delete.
- Session-activity and product docs. This package is S09 only and does not touch activity reads, client surfaces or recovery ownership, so no product-behavior change.
- Rollback helper (if built) changes durability behavior in two stores. Containment: do not build it without question 1.

## Rejected alternatives

- A new subpackage per concern (`contextmgr/summarize`, `contextmgr/checkpoint`). The pieces share `Manager`, `CompactionMeta` and unexported helpers; a split into packages forces exports and an import cycle risk for no reader benefit.
- Keep one file and add section comments. It leaves the 2,819-line review problem.
- A generic journal `Appender` over jobstore, delegatestore, sessionlog and transcript. The verifier rejected it: sessionlog has no rollback or latch, and transcript has a richer protocol (`ErrRollbackFailed`, positionUnknown) that is not a copy.
- A generic `layer` interface for the compaction pipeline. New mechanism for three callers; two small helpers do the job.
- Moving before W1-66. We would move about 870 lines of strategy code that is then deleted.
