# Split delegate_runtime.go (design record)

Entry: W2-05. Measured on origin/main today (2026-10-26). Design only; nothing in the repo changed.

## Summary

`agent/delegate_runtime.go` is 3,563 lines (audit said 3,568). It holds 40 `Session` methods, 18 `delegateRuntime` methods and 9 `delegateTreeController` methods. It mixes five jobs: activity reporting, the quiet-watch ticker, attention drive and restore, the send path, and create/restore/bootstrap. The quiet-watch hub keeps a process-global registry (`delegateQuietWatchHubs`, `delegate_runtime.go:341`) and a global test hook (`delegateQuietWatchTickDone`, `:355`). Three functions are too long to review: `delegateRuntime.send` (302 lines), `prepareSubagentRunFromSelection` in `subagents.go` (507), `drainJobTreeWith` (484).

End state: the file becomes about eight files of 250 to 700 lines, split by lifecycle stage, all still in package `agent`. The quiet-watch hub owns its state instead of using a global. The fresh-versus-restore child config is covered by a differential test. The drain loop loses its repeated guards without changing read order.

Why it is worth it: the file took 86 commits since 2026-08-25 (verifier count), so every delegate change reviews against a 3.5k-line diff context. Product docs link into it with line anchors that are already stale (`friction.md:620-621` points at `#L2905`, `#L3069`; `restoreIdle` now starts at 2702).

Net LOC is about 0 for the moves. The later steps remove roughly 100 to 200 lines (narration comments, repeated blocks). I did not measure that more tightly.

## Proposed structure

Everything stays in package `agent`. These are methods on `Session`, `delegateRuntime` and `delegateTreeController` that reach unexported fields, so a sub-package would force exports. No new package, no new interfaces.

Target files (names are proposals; see Question 1):

| File | Owns | Approx lines |
|---|---|---|
| `delegate_runtime.go` (kept) | `delegateRuntime`, shared types, context keys, consts | ~150 |
| `delegate_activity_report.go` | `ReportActivity`, `ReportIntent`, `ReportActivityPhase`, publish consts | ~120 |
| `delegate_quiet_watch.go` | hub, attach/detach, serve loop, `BeginQuietAttention`, `CompleteQuietAttention`, claim type | ~450 |
| `delegate_attention_drive.go` | `bindStableDelegateActivity*`, `driveStableDelegateAttention`, `drivePendingStableDelegateAttention`, cold restore of attention runtimes | ~450 |

| `delegate_send.go` | `send`, result population, send failure helpers, drive guards | ~560 |
| `delegate_create.go` | `create`, `describe`, `prepareIsolation`, `construct`, `adopt`, `failCommittedStart` family, `stableDelegateResult` | ~800 |

| `delegate_bootstrap.go` | `bootstrapDelegateResources`, `emitStableDelegateUpdate`, reconcile, restore-input checks, store close | ~350 |

Boundary rules:
- Files only group code. Ownership stays where it is: the controller owns delegate state and its mutex, the owner `Session` owns runtime lifetime, `delegateRuntime` is a stateless view over `owner`.
- Controller methods stay in controller-named files where they already are; the two controller methods that sit in `delegate_runtime.go` today (`ReportActivity*`, `BeginQuietAttention`) keep the same receiver, only the file changes.
- After step 2 below, quiet-watch state lives on its owner `Session` (a hub pointer guarded by a small mutex), the tick-done observer lives in `cfg.testOnly` beside the other 33 hooks, and no package global remains in the delegate files.
- Lock order is unchanged. The existing registry-then-hub-mutex order disappears with the registry; the hub mutex stays leaf.

## PR sequence

Merges are serialized through the shared lock (DECISIONS.md, Wave 1 merge rule). The file is hot, so PR 1 should land quickly after it is rebased on main.

1. **Pure move, one PR, one file per commit.** Moves every block in the table above to its target file. Zero logic change; imports are the only edits. Same PR updates docs: `docs/product/friction.md:620-621` (drop the stale line anchors and link `delegate_restore_idle.go`), `docs/product/subsystems.md` S12 row, `docs/product/session-activity.md:293` (update routing now points at `delegate_activity_report.go`), `docs/job-control.md:629`, `docs/subagent-runtime-contracts.md:96,266`, and stale line-number comments in `agent/delegate_runtime_covtest4_test.go`, `delegate_resource_supervision_test.go:3459,3627`. Proof: a throwaway tool (not committed) that parses package `agent` and prints `name + sha256(body)` per function, run on base and head; the sorted outputs must be identical. Plus `git diff --name-only` against the base to catch anything unintended, and `go build ./... && go vet ./agent/`. Tests run in CI. Deps: none beyond a clean main. Prefer to land after W1-22(a) and W1-24 have merged if they are close, to avoid rebasing them over a move; W1-22 touches `construct` (the `stableController` set) and W1-24 touches other files, so a conflict is small either way.
2. **Characterization test for the quiet-watch hub.** Behavior-preserving, tests only. `delegate_quiet_hub_test.go` already reads the global registry; extend it so each assertion goes through behavior (one ticker per session with K leases, detach of the last lease stops the ticker, detach plus re-attach races do not strand an entry, tick coalescing). It must pass unchanged before and after PR 3. Deps: PR 1.
3. **Quiet-watch hub onto Session (behavior-preserving refactor).** Replace `delegateQuietWatchHubs` with a field on the owner session, move `delegateQuietWatchTickDone` to `cfg.testOnly`, simplify attach to lookup-or-create under one mutex (the ~110-line lock dance exists to get registry-then-hub atomicity; one mutex per session removes the gap cases), delete the "Previously..." narration. Proof: PR 2 tests unchanged and green; `-race` run on CI. Deps: PR 2, Question 2.
4. **Differential test: fresh versus restore child config.** Tests only. Build a child through `prepareSubagentRunFromSelection`, freeze its descriptor, restore through `restoreIdle`, compare `spawnConfig` and the other descriptor-derived `SessionConfig` fields one by one, excluding live pointers (clock, stores, callbacks). Red-first is not applicable until drift is found. If a field differs, each difference is a separate TDD bug fix PR (behavior change, failing test first). If none differ, the test stays as the guard and nothing else changes in this area (verifier: "do not unify the whole config"). Deps: PR 1; W1-22(c) preferred so the fresh path has one branch.
5. **Send path: one extraction per commit (behavior-preserving).** (a) one helper for the inline-wait block (`WithTimeout`, `delegateInlineWaitReady` observe, `waitForDelegateInline`, `TimedOut`) used by `send` at 1888-1905 and `stableSendFailureOutcomeAfterDispatch` at ~2025-2043; (b) one helper for the `durableStatus`/`durableReason` overlay used at ~2036-2044 and ~2084-2093; (c) drop the two one-line wrappers `failStableSendStart` and `stableSendFailureOutcome` (13 call sites) in favor of the `*AfterDispatch` forms. Characterization first: existing send suites in CI plus a table test pinning the outcome for each failure point before and after dispatch. Race-sensitive; no reordering across the waiter lifecycle. Deps: PR 1.
6. **Drain loop: move first, simplify second.** Behavior-preserving, simplification only (the function is already in one place, so there is no move step): replace the repeated `if skipKick { re-kick once }` blocks (4 sites) with one local closure, and the five `takeDrainWake` calls with one named step, with the wake-then-verdict-then-kick order untouched. The existing seed100 and drain suites are the characterization; add a test per return path that asserts a skipped-kick pass re-kicks once before returning (the comment at 1136-1148 promises it). Then deleting `kickDriveTreeWith` means editing `session_jobtree_drain_seed100_more_test.go:81,88,114` and `session_jobtree_drain_test.go:301`; do that only if the simplification leaves it a one-line wrapper. Deps: PR 1 only (different file), W1-22 is irrelevant here.
7. **`prepareSubagentRunFromSelection` (507 lines) split.** Behavior-preserving, only after W1-22(c) removes the `!preparedEnv.stableController` gates, since they sit inside it. Pull coherent phases into helpers without reordering lock phases. Needs PR 4's test green. Deps: W1-22, PR 4. Candidate to defer; see Question 3.

PRs 3, 4, 5, 6 are independent after PR 1 and can run in parallel in separate worktrees.

## Risks and containment

- Merge conflicts in a 86-commits-in-two-months file. PR 1 is the first and only big move, kept to function-granularity commits; rebase right before merge and re-run the function-hash comparison after the rebase (a bad conflict resolution is the main way a pure move can lose code).
- Silent semantic change in a "pure" move. Function-body hashes catch it. Go init order is not affected because `var`/`const` only move between files of one package, but the hash tool also compares package-level `var` initializers.
- Hub rewrite (PR 3) is the one real concurrency change. PR 2 pins behavior first, PR 3 does not change tick delivery, coalescing or detach semantics, and CI runs it under `-race` repeatedly (no local stress loops, per the no-heavy-local-stress rule).
- Send path (PR 5) is race-sensitive: one extraction per commit, each commit green on its own.
- Drain loop (PR 6): the wake-before-verdict order is the PRI-2441 flake guard. The PR keeps lines in order and only collapses guards; reviewers check order by diff, not by tests alone.
- Recovery behavior: none of these PRs change restore, retry, or give-up policy. PR 4 only surfaces drift. Any fix it finds follows AGENTS.md (recovery over lockdown) and gets its own PR and discussion.
- Doc drift: PR 1 updates the S12 row and links in the same change, as AGENTS.md requires. Ownership statements in S12 do not change because no ownership moves.

## Questions for Jesse

2. Should the quiet-watch global registry go away by putting the hub on the owner `Session` (my recommendation: one hub per session matches today's behavior exactly), or onto the `delegateTreeController` (one ticker per tree, which changes which goroutine ticks which leases)? Keeping the global is the third option and is cheapest.

## Rejected alternatives

- Move delegate code into a sub-package (`agent/delegates`). The methods touch unexported `Session` fields; exporting them widens the API for no user benefit.
- Merge the runtime into the controller type. The controller is already 1,231 lines plus six `delegate_tree_*` files, and the runtime depends on `Session` lifetime that the controller does not own.
- One shared constructor for fresh and restored child config. The two paths start from different bases (parent struct copy versus descriptor), the verifier found no drift, and a shared builder would be a larger behavior risk than the duplication.
- A generic step table for the drain loop or send path. New mechanism for code whose problem is length, not variety (the same call the verifier made on `releaseStep` in W2-07).
- Keep the global and just document it. Cheap, but the registry's only justification is a file-organization comment, and it forces tests to reach into process-wide state.
