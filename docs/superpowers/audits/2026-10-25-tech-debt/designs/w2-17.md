# Rail and AppShell (design record)

Entry W2-17. Measured on origin/main today. Frontend root is `cmd/evener-hub/frontend/src`.

## Summary

`shell/rail/Rail.tsx` is 2,132 lines. Its `NavigationRail` component alone runs from line 1009 to 2130 (about 1,120 lines, 9 `useRef`, 7 `useEffect`, 8 `useCallback`). Lines 463-950 hold a data adapter that still carries a "compatibility" path for resources with no normalized graph. Production cannot produce those resources: the only writer of resource state is `appwire-client/typescript/state/navigation/store.ts` (`resources.set` at :467), and every decoded snapshot, delta, or gone reply sets `normalized` (:503-518). The compat path lives on only because `Rail.test.tsx` (3,617 lines) seeds raw data without a graph through a `resource()` helper (about 100 matching call sites with the related helpers).

`shell/AppShell.tsx` is 1,136 lines. Lines 638-843 are one `useEffect` that holds the whole "live session next/previous" demand state machine, with about a dozen round and PR citations in comments. Its tests are inside `AppShell.test.tsx` (8,974 lines, 165 tests).

Three small duplications ride along: `shell/dockHostChunk.ts` (216 lines) is a private copy of `shell/chunkRetry.ts` (256 lines); `CommandPalette.tsx` `HELP_ROWS` (:115-~175) hand-lists chords that the registry already knows; `needsYouActions.ts` repeats the next-ref rule three times.

End state: Rail.tsx splits into an adapter file, a few hooks and two dialogs, with no compat branch. The live demand machine becomes `shell/liveSessionController.ts` with injected reads and its own tests. The dock chunk is a 40-line wrapper like `railHostChunk.ts`. Expected net about -700 lines, with about 3,500 more moved. Worth it because both files are the two places every shell change collides.

Scope note: roadmap finding web-shell-widgets-6 (wire state to family mapping) is owned by W1-38. This record does not touch it.

## Proposed structure

All under `shell/`, no new packages.

Rail:
- `rail/railResources.ts` (new): everything from `summarySession` through `adaptNavigationResources` plus `withArchivedLists`, `nonEmpty`. Graph-only. Owns the WeakMap caches. Imports `stores/navigation/selectors`, `railNodes` types, `railPending` types. Imports no React. Rail.test.tsx's `adaptNavigationResources` tests move to `railResources.test.ts` with it. I put it in `rail/` and not `stores/navigation/` (the verifier's suggestion) because `RailSession`/`RailProject` live in `rail/railNodes.ts`; a store importing from shell would invert layering.
- `rail/useRailReveal.ts`: reveal refs and effects (:1081-1160). Takes navigation store and a setExpanded callback.
- `rail/useProjectRootLoads.ts`: `rootLoadsInFlight`, `loadProjectRoot`, retry callbacks (:1178-1255).
- `rail/RailDialogs.tsx`: delete-project dialog plus section rename and delete dialogs and their token refs (:1704-1807). Built from `widgets` barrel only.
- `Rail.tsx`: composition, `runAction`, `rowActions`, render. Target under 900 lines.
- Boundary rules: `railResources.ts` imports nothing from `Rail.tsx` or hooks. Hooks import `railResources` types only. `Rail.tsx` is the only importer of the hooks and dialogs. Nothing outside `rail/` imports them.

AppShell:
- `shell/liveSessionController.ts` (new, no React, no DOM globals): `createLiveSessionController(deps)` returns `{ next(), previous(), dispose() }`. Injected reads: `getNavigationState()` (for `selectLiveRows`, `selectSectionRemaining`, `selectSectionCanDemand`, `selectNextSectionOffset`, `loadSection`, `clientGenerationID`), `focusedPaneId()`, `focusedSessionRef()`, `routeEpoch()`, `paletteOpen()`, `modalOpen()`, `editableFocused()`, and `openLiveSession(ref)`. The controller owns the intent counter, owner map, freshness check and completion guard. It does not read stores or `document` itself.
- `AppShell.tsx` keeps the render-phase route epoch ref, builds `deps` from `navigationStore`, `workspaceStore`, `paletteStore`, `focusedSessionRef`, `isEditableTarget`, `openSessionRoute`/`openTopLevelSession`, and registers actions. `sessionNext/Previous` and `settingsOpen` stay in AppShell.
- `needsYouActions.ts`: one local `resolveNextRef(state, focused)` replaces the three copies.
- Guard sharing is not part of the base plan (see Q1).

Chunks and help:
- `dockHostChunk.ts` becomes a `createChunkRetryLoader` wrapper with the same exports (`loadDockHost`, `isStaleDockHostChunkError`, `setDockHostImporterForTests`, `resetDockHostLoaderForTests`, types). `chunkRetry.ts` header comment drops the "keeps its private copy" sentence.
- `palette/helpRows.ts` (new, small): `HELP_ROWS` = static palette-local rows plus rows built from the registry for the app-global chords. Cheatsheet keeps its own grouping.

## Risks

- **PR 5 reseeding exposes hidden compat reliance.** Mitigation: PR 5 lands before any deletion, so a failing test is isolated and the compat code is still there to compare against. Triage each failure as test bug vs adapter bug.
- **Cache semantics in `railResources`.** WeakMap caches key on object identity (`summary`, `normalized.graph`). A pure move keeps identity behavior; PR 6 removes a cache mode, so the existing referential-stability tests in Rail.test.tsx must stay and are the gate.
- **Live controller timing.** The route epoch must still bump in render, not an effect. PR 9 keeps the ref in AppShell and injects a getter; a test for the leave-and-return round trip (PR 8) pins it.
- **Mobile.** The effect returns early on `isMobile`; the registration stays in AppShell so this does not move.
- **Chunk wrapper.** Vite chunk regexes must still match `DockHost-*.js`. PR 1 keeps `dockHostChunk.test.ts`, which appends fake Vite assets and checks the retry URL and CSS preload; run `make test-web` once, since a production build is not exercised by vitest.
- **Rail bundle.** `railHostChunk.ts` says RailHost ships as its own chunk. New files under `rail/` are imported only from `Rail.tsx`, so they stay in that chunk. Check the built chunk list once after PR 7.
- **UI rules.** `RailDialogs.tsx` uses only the `widgets` barrel; no new widget or prop. Anything that seems to need one stops and asks Jesse.
- **Local test load.** Per AGENTS.md and memory, workers typecheck and run only targeted vitest files locally (`Rail*.test.tsx`, `liveSessionController.test.ts`, `dockHostChunk.test.ts`, `needsYouActions.test.ts`); CI runs the full suite.

## Rejected alternatives

- **One shared controller for Live and needs-you.** The verifier's note stands: Live pages both directions and has an unloaded-section previous path; needs-you has a populated retry and refusal states. Forcing one machine makes both worse. Share only the guard, if Q1 is yes.
- **Delete `adaptNavigationResources` export.** About 24 test hits use it as the seam. It moves with its tests instead.
- **Move the adapter into `stores/navigation/`.** Needs shell types; wrong layering.
- **Split NavigationRail before deleting compat.** More code to move, and reviewers would read dead branches inside moved files.
- **Rewrite Rail tests rather than reseed.** Reseeding the one helper leaves the call sites alone.
