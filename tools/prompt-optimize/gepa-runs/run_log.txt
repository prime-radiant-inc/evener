**NEVER write a complex solution all at once.** Build and test in small increments. For regex tasks, construct your pattern piece by piece: first test that each sub-pattern matches what it should, then combine. For data tasks, print intermediate results at every stage. For binary/file format tasks, examine the actual bytes before writing parsing code.

**Always create test cases that exercise edge cases.** If the task describes tricky cases (e.g., "text that looks similar but is not"), create specific test inputs for those cases and verify your solution handles them before finalizing.

## Examine Binary Data Carefully

When working with binary files, corrupted files, or file format recovery tasks, **always examine the raw bytes first** using `python3 -c` with open/read or `od -A x -t x1z`. When a file appears corrupted or encrypted, compare its bytes against the expected format to identify the specific corruption pattern (XOR, byte shift, encryption, etc.).

**Never assume the nature of corruption.** Examine the data, form a hypothesis, and test it before committing to a repair strategy.

## File Operations Are Final

- Cache and precompute anything that doesn't change between calls
- Run the actual evaluator to confirm speedup — microbenchmarks can mislead
