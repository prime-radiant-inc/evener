**Implementation plan (step by step)**

Given your constraints (single C file, no deps, `<5000 bytes`, compile with `gcc -O3 -lm`, read `.ckpt` + `.bpe`, and generate next 20 tokens), I would implement a **minimal GPT-2 argmax runner** with these design choices:

1. **Use TF checkpoint reader logic directly in C (minimal subset).**  
   Parse the TensorFlow v2 `.ckpt` shard format just enough to:
   - iterate variable records,
   - map variable name → tensor metadata (dtype, shape, offset),
   - load only GPT-2 tensors needed for inference.

2. **Hardcode GPT-2 124M architecture constants** inferred from tensor shapes:
   - `n_layer=12`, `n_head=12`, `n_embd=768`, `n_ctx=1024`, `vocab=50257`.
   - Confirm via loaded weight shapes at runtime; abort if mismatch.

3. **Load BPE merges and byte encoder/decoder.**
   - Parse `vocab.bpe` merges into rank table.
   - Recreate GPT-2 byte-to-unicode mapping.
   - Implement tokenization:
     - regex-like pre-token splitting approximation in plain C,
     - apply BPE merge loop on symbol pairs using rank lookup,
     - map final pieces to vocab ids via loaded encoder map.
   - Implement detokenization via decoder map + byte-decoding table.

4. **Weight handling strategy (memory-tight but simple).**
   - Read all required float tensors into heap once:
     - token embeddings, positional embeddings,
     - layernorm params,
     - QKV / proj / MLP weights+biases for each block,
     - final LN and LM head (shared with token embedding if tied).
   - No external BLAS; handwritten dense matvec loops.

5. **Forward pass per token with KV cache.**
   - For prompt tokens: run full causal progression while filling per-layer K/V cache.
   - For generation steps (20 tokens): single-step decode using cache.
   - Each layer:
     1. LN
     2. QKV projection
     3. causal self-attention over cached keys
     4. residual
     5. LN
     6. MLP (gelu)
     7. residual
   - Final LN + logits projection; choose `argmax`.

6. **Sampling behavior.**
   - Deterministic argmax only.
   - Append each chosen token to output text and continue exactly 20 tokens.

7. **Code-size minimization tactics (<5000 bytes target).**
   - Aggressive identifier shortening.
   - Minimal error text.
   - Reuse buffers.
   - Skip generality and only support 124M layout.
   - Implement very compact parsing (assume well-formed files).
   - Avoid full regex engine; use compact splitter compatible enough for GPT-2 style.
