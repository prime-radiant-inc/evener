Implementation plan (concise and realistic):

1. **Acknowledge format constraints first**  
   A real TensorFlow `.ckpt` is not a flat float blob; it is an index/data pair format with tensor metadata and names. Parsing that plus full GPT‑2 inference + BPE in **<5000 bytes C** is not feasible as-is.

2. **Use the standard tiny-C GPT‑2 strategy**  
   Implement a single-file C program that:
   - reads a **flat binary checkpoint** with all GPT‑2 tensors in known order/shapes,
   - reads GPT‑2 BPE merges/vocab,
   - tokenizes prompt,
   - runs transformer forward pass,
   - argmax selects next token,
   - prints decoded text for 20 generated tokens.

3. **Keep it dependency-free**  
   Only libc + `math.h` (`-lm`) and no external libs.

4. **Minimize bytes aggressively**  
   - single-letter variables,
   - no comments/whitespace bloat,
   - static buffers,
   - minimal BPE implementation (rank table via linear/probing hash),
   - greedy argmax only (no softmax sampling needed).

5. **Important practical requirement**  
   Because you explicitly pass `gpt2-124M.ckpt`, the program would need either:
   - a conversion step from TF checkpoint to flat `.bin` (recommended), or
   - a full TF checkpoint parser (too large for 5KB).
   
   So the robust path is: **expect a preconverted binary checkpoint**.  
   If you truly require native TF `.ckpt` parsing, byte budget must be relaxed substantially.
