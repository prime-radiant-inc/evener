## Practical implementation plan (works, but exceeds 5KB)

If you relax the 5KB limit, this is the robust approach:

1. **Checkpoint format**
   - Prefer converting TF checkpoint to a simple binary tensor pack first (name + shape + float32 data), once offline.
   - In C, memory-map/load that flat format.

2. **Tokenizer**
   - Implement GPT‑2 byte encoder (bytes to visible unicode mapping).
   - Parse `vocab.bpe` merges and rank map.
   - Greedy BPE merge per tokenized “word piece”.
   - Load `encoder.json` (needed for token->id mapping).  
   > Note: `.bpe` alone is insufficient; GPT‑2 also needs `encoder.json`.

3. **Model forward pass**
   - Load all weights for 124M config (`n_layer=12, n_head=12, n_embd=768`).
   - For each generated token step:
     - token + positional embedding
     - for each block:
       - ln_1
       - qkv projection, split heads
       - causal self-attention + softmax
       - out projection + residual
       - ln_2
       - MLP (fc, gelu, proj) + residual
     - final ln_f
     - logits via tied embedding matrix
   - Argmax over vocab for next token.

4. **Generation**
   - Encode prompt to tokens.
   - Run autoregressive loop for 20 new tokens.
   - Decode tokens back to bytes/string and print continuation.

5. **Build**
   - `gcc -O3 gpt2.c -lm`
