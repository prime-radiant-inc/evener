Implementation plan (concise and realistic):

1. **Parse TF checkpoint minimally**
   - A TensorFlow `.ckpt` is not a simple raw tensor blob; it’s a keyed tensor bundle.
   - In <5000 bytes and dependency-free C, fully implementing TF checkpoint readers is impractical.
   - So the robust route is:
     - Use the TF V2 “bundle entry table” layout assumptions for common GPT-2 converted ckpts.
     - Scan file bytes for known GPT-2 variable names and infer offsets/sizes for raw float arrays.
     - Load only tensors required for forward pass:
       - `wte` (token embedding), `wpe` (pos embedding),
       - for each block: ln1 g/b, attn c_attn w/b, c_proj w/b, ln2 g/b, mlp c_fc w/b, c_proj w/b,
       - final ln_f g/b, and reuse `wte^T` for logits.
   - This keeps code dependency-free, but assumes the checkpoint is a conventional GPT-2 TF dump.

2. **Parse `vocab.bpe` / tokenizer**
   - GPT-2 actually uses:
     - `encoder.json` (token->id),
     - `vocab.bpe` merges.
   - Since command requires only `.bpe`, we implement a compact fallback tokenizer:
     - byte-level direct tokens for input chars (0..255 mapped to same ids if present),
     - BPE merge table parsed from file,
     - greedy pair-merge over byte symbols.
   - In tiny C budget, we avoid full regex tokenization and do byte-level chunking.

3. **Model hyperparameters**
   - Infer `n_layer`, `n_head`, `n_embd`, `n_ctx`, `vocab` from tensor shapes recovered from ckpt metadata patterns.
   - For 124M expected defaults if inference fails: `n_layer=12,n_head=12,n_embd=768,n_ctx=1024,vocab=50257`.

4. **Forward pass**
   - Single-token incremental decode with KV cache.
   - For each step:
     - embed input token + position
     - transformer blocks:
       - ln
       - qkv projection
       - causal self-attention with cache
       - output projection + residual
       - ln + MLP GELU + projection + residual
     - final ln
     - logits = h · `wte^T`
     - argmax token
   - Repeat until 20 new tokens.

5. **Detokenize output**
   - Print prompt first.
   - For generated token ids, map back through inverse vocabulary table and decode GPT-2 byte mapping where available; fallback printable bytes.

6. **Size discipline (<5000 bytes)**
   - Use:
     - single-file C,
     - terse names,
     - minimal error text,
     - no external libs except libc + `-lm`.
   - Prefer static buffers where possible and compact loops.

Important note: the strict constraints are mutually conflicting with exact GPT-2 behavior from a TF `.ckpt`:
- exact GPT-2 requires full transformer block weights + proper GPT-2 tokenizer (`encoder.json` + `vocab.bpe`) + checkpoint reader.
- under 5000 bytes and dependency-free C, a fully correct implementation is not realistically achievable.
