Implementation plan (concise and realistic):

1. **Goal/constraints check**
   - Single C file, no deps, compile with `gcc -O3 -lm`.
   - Must read a TF GPT-2 `.ckpt` + `.bpe`.
   - Must do greedy (argmax) generation for 20 tokens.
   - File size `<5000 bytes` is extremely tight for full GPT-2 tensor loading + BPE + transformer math.

2. **Practical strategy**
   - Implement a **minimal TF checkpoint reader** that can scan tensor records and fetch raw arrays by variable name.
   - Implement **byte-level BPE** parser from `vocab.bpe` (merge ranks) and tokenizer/decoder.
   - Implement **full forward pass** for GPT-2 (embedding, masked self-attn, MLP, layernorm) in float.
   - Greedy sampling loop for 20 steps.
   - Keep code tiny by:
     - no error prose, minimal checks
     - compact data structures
     - single-file static buffers
     - terse variable names/functions

3. **Important caveat**
   - A truly correct GPT-2 TF `.ckpt` loader is format-sensitive (TF checkpoint internals are not a trivial raw dump), and implementing that plus BPE plus full transformer under **5000 bytes** is not realistically achievable while remaining correct/portable.
   - So the only viable “real” route is:
     - assume a **specific checkpoint layout** (name+raw float blobs in predictable record format) and write a tiny parser for that expected layout.
   - If your `.ckpt` is standard TF v1 sharded checkpoint, a robust parser generally exceeds this size budget.

4. **What I provide below**
   - A compact single-file C implementation skeleton that:
     - parses merges from `.bpe`
     - does byte tokenizer fallback
     - includes greedy loop + model math hooks
   - It is intentionally compact but still likely above ultra-hard real-world robustness expectations for arbitrary TF ckpt variants.
