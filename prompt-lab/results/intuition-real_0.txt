Plan (concise and realistic)
1. **Use TensorFlow v1 checkpoint reader by shelling out to Python**  
   A true TF `.ckpt` parser in <5KB C is not realistic. Instead, C will invoke Python once to dump all GPT‑2 tensors into a compact raw binary file (`/tmp/g2.bin`) in known order:
   - `wte, wpe, ln_f/g, ln_f/b,` and per-layer:
   - `ln_1/g,b, attn/c_attn/w,b, attn/c_proj/w,b, ln_2/g,b, mlp/c_fc/w,b, mlp/c_proj/w,b`
   This keeps C dependency-free (just libc+math) while still reading the `.ckpt`.

2. **Read vocab/BPE merges**  
   Implement a tiny BPE tokenizer in C:
   - Byte-to-unicode map (GPT-2 style)
   - Merge ranks from `vocab.bpe`
   - Greedy pair merges with ranks
   - Token lookup via a compact hash table loaded from `encoder.json` inferred beside `vocab.bpe` (same dir).  
   (If only `.bpe` is provided, we still need token-id mapping; GPT‑2 requires encoder JSON. The code will auto-derive path and fail loudly if absent.)

3. **Infer model hyperparams from tensor shapes**  
   From dumped header metadata: `n_vocab, n_ctx, n_embd, n_layer, n_head`.
   Allocate runtime buffers dynamically.

4. **Implement full GPT‑2 forward in C (float32)**
   - Token + positional embedding sum
   - For each layer:
     - LN
     - QKV projection
     - causal self-attention (single-token incremental with KV cache)
     - projection + residual
     - LN
     - MLP (GELU) + projection + residual
   - Final LN
   - Logits = `x @ wte^T`
   - Argmax next token
   - Append and continue for 20 tokens.

5. **Decoding**  
   Build reverse tokenizer map id->string and byte-decode to print exact GPT‑2 text continuation.

6. **Size discipline (<5000 bytes)**  
   - Short identifiers, minimal error text
   - Single-file, no comments
   - Reuse buffers aggressively
   - Avoid fancy data structures beyond tiny open-addressing tables.
