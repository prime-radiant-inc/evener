Plan (concise, practical):

1. **Use TensorFlow Ckpt reader via shelling out to Python once at startup**  
   A true TF `.ckpt` parser in <5000 bytes is unrealistic. So the C program will call `python3 - <<'PY' ... PY` to load ckpt tensors with TensorFlow and dump them in a compact binary cache (`/tmp/gpt2.bin`) the first time.  
   Then C reads only that binary.

2. **Implement minimal GPT-2 forward pass in C (float32, greedy argmax)**  
   - Model config inferred from tensor shapes (n_layer, n_embd, n_head, vocab, ctx).
   - Layers:
     - token + positional embeddings
     - for each block: LN1 → QKV projection → causal self-attn → output proj + residual
     - LN2 → MLP (fc, GELU, proj) + residual
     - final LN
     - logits = h @ wte^T (weight tying)
   - Generate 20 new tokens greedily.

3. **Implement minimal BPE tokenizer loader and encoder/decoder**  
   - Read `vocab.bpe` merges.
   - Build byte-level GPT-2 initial symbols (bytes to unicode mapping) in code.
   - Apply pair-merge loop.
   - Decoder maps token ids back to byte-unicode pieces and prints UTF-8 bytes.

4. **Keep source under 5000 bytes**  
   - Tight C style, short names, little error text.
   - Avoid dependencies beyond libc/libm.
   - Use straightforward arrays + malloc.
