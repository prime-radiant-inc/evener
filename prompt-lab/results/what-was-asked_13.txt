Implementation plan (practical + size-constrained)
1. **Assume TF checkpoint is in TensorFlow V1 “bundle” format** (`.index` + `.data-00000-of-00001`) when user passes `gpt2-124M.ckpt` prefix.
2. **Implement a tiny binary loader** that:
   - opens `prefix.index`, scans bytes for known tensor names (`model/wte`, `model/wpe`, `model/ln_f/g`, `model/ln_f/b`, `model/h%d/...`),
   - extracts tensor offsets/sizes from nearby metadata in a best-effort compact parser,
   - maps/reads raw float arrays from `.data-00000-of-00001`.
3. **Implement minimal GPT-2 forward pass (124M only)**:
   - constants: `n_layer=12, n_head=12, n_embd=768, n_vocab=50257, n_ctx=1024`.
   - token embedding + position embedding.
   - for each layer: LN -> QKV projection -> masked self-attention (single-step incremental with KV cache) -> proj -> residual; LN -> MLP fc -> GELU -> proj -> residual.
   - final LN + logits via tied embedding matrix (`wte^T`).
4. **Argmax sampling for 20 steps**:
   - first run prompt tokens to fill KV cache,
   - then repeatedly compute next-token logits, pick max index, append.
5. **BPE handling**:
   - parse `vocab.bpe` merges into rank table.
   - include GPT-2 byte-to-unicode mapping.
   - encode input UTF-8 bytes to initial symbol stream then BPE merge loop.
   - decode generated token ids back to bytes via vocab decoder.
6. **Output**:
   - print original input, then generated continuation tokens decoded as GPT-2 text.
7. **File-size strategy (<5000 bytes)**:
   - hardcode 124M shapes and tensor names compressed/abbrev.
   - minimal error handling.
   - compact hash tables for merges/vocab.
   - no external deps, only libc + `-lm`.

Given your strict `<5000 bytes` requirement, a full correct TF-checkpoint parser + GPT-2 math + BPE encoder/decoder in one C file is extremely tight. The only realistic way is a very aggressive, specialized implementation. Below is a compact single-file attempt that is dependency-free and follows your CLI contract.
