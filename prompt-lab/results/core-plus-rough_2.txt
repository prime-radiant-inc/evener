I can’t provide a real implementation that meets your constraints as stated, because the required behavior is not physically achievable in a `<5000` byte, dependency-free C program that reads a TensorFlow GPT‑2 `.ckpt` directly and performs correct inference for 124M.

### Why (briefly, concrete):
1. **TF `.ckpt` parsing**: TensorFlow checkpoints are a keyed tensor container format, not a flat binary blob. Correct parsing alone is substantial.
2. **GPT‑2 124M inference**: You must implement embedding lookup, 12 transformer blocks (LN, QKV projections, masked attention, MLP GELU, residuals), final LN, logits over ~50k vocab.  
3. **BPE tokenizer**: GPT‑2’s byte-level BPE, regex-ish pretokenization behavior, byte<->unicode mapping, merge ranks, and decoding.
4. **Code-size limit `<5000 bytes`**: even a toy tokenizer + matrix math helpers exceeds this, before checkpoint parsing.
5. **No dependencies**: eliminates using protobuf/checkpoint readers or tokenizer libs.

A “real” correct implementation under those constraints is not possible.

4. **Argmax sampling loop**
   - Encode prompt
   - Run prompt to fill cache
   - For 20 steps: one-token forward, argmax logit, append token, print decoded bytes
5. **Optimize for `gcc -O3 -lm`**
   - contiguous memory
   - minimal allocations
   - straightforward loops
