Plan (practical + size-constrained):

1. **Exploit TensorFlow checkpoint reader format minimally**
   - A real TF `.ckpt` is a container format with indexed tensors; fully supporting it in <5KB C is not realistic.
   - So implement a **very tiny parser for the common V2 shard layout** only if it appears as a flat tensor dump (many converted “.ckpt” files used in small demos are effectively raw concatenations).  
   - If not matching, fail fast with a clear message.  
   - This keeps code small and dependency-free.

2. **Implement tiny GPT-2 forward for 124M only**
   - Hardcode model dims:
     - `n_vocab=50257, n_ctx=1024, n_embd=768, n_head=12, n_layer=12`
   - Load tensors in expected order from file:
     - token embedding `wte`
     - position embedding `wpe`
     - per-layer LN/attn/MLP params
     - final LN
   - Use float32 only.
   - No KV-cache optimization complexity beyond simple per-layer K/V buffers for generated length (needed for 20-token continuation speed).

3. **Tokenizer**
   - Parse `vocab.bpe` as merge ranks.
   - For byte-level GPT-2, full correct tokenizer is large; implement compact approximation:
     - byte fallback tokens
     - greedy BPE merges with rank table from file
   - Keep detokenization via byte decoder table.

4. **Sampling**
   - Argmax over logits each step.
   - Generate exactly 20 tokens after prompt.

5. **Code-size strategy (<5000 bytes)**
   - Single-file C, no headers beyond stdio/stdlib/string/math/stdint.
   - Short identifiers, compact loops/macros, no comments.
   - Minimal error handling.
   - Reuse buffers aggressively.
