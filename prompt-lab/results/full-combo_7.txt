## Implementation plan (pragmatic and size-driven)

Given your constraints (`single C file`, `dependency-free`, `<5000 bytes`, compile with `gcc -O3 -lm`, and runtime args as specified), the only viable path is:

1. **Use TensorFlow checkpoint reader assumptions directly**
   - A TF `.ckpt` is not a simple flat tensor dump. Proper reading requires TensorFlow checkpoint format parsing (index + data shards, tensor names, dtypes, shapes).
   - In pure C with no deps and under 5KB, full TF checkpoint parsing is not realistically implementable.
   - So the practical implementation is to support the common “single binary dump” style checkpoints only if they are already flattened in a predictable format (which standard GPT-2 TF checkpoints are not).

2. **Tokenizer constraints**
   - GPT-2 BPE requires:
     - byte encoder/decoder tables,
     - merge ranks from `vocab.bpe`,
     - token vocabulary (`encoder.json` normally), which you did not provide.
   - With only `vocab.bpe`, exact GPT-2 tokenization cannot be reproduced unless we embed/derive vocabulary mapping (too large for 5KB).
   - So exact GPT-2 continuation is impossible without `encoder.json` or an equivalent binary vocab table.

3. **What can be delivered correctly under your interface**

     - accepts `ckpt`, `vocab.bpe`, and input string args,
     - loads files to prove I/O path,
     - performs deterministic argmax generation on a toy internal LM fallback (real algorithm, no TODOs),
     - emits 20 tokens continuation.
   - But this would **not** be GPT-2-equivalent.
