## Spec 2 (cheap filtered reads) decisions

- F-C10 ACCEPTED, design-shaping: the wire ALREADY filters (appwire/history_content.go:8-22 IncludeConversation/IncludeThinking/IncludeToolCalls/IncludeIntents/IncludeSystem/IncludeDiagnostics; Selection.Item :65-97; both ThreadReadParams and ThreadTurnsListParams embed ThreadContentParams; docs/product/history-content.md:3-37). What is missing is Manager-tool exposure: the agent schema gate refuses extras (spike, observed verbatim). itemTypes is therefore a MAPPING onto the existing selection API (plus the two genuinely new things: turnWindow and the byte bounds), not a duplicate mechanism. The grounding claim "reads have no filtering" is corrected to "the Manager tool does not expose the existing selection".
- Budget (F-D7/E-none/C11/C14 + spike 2): the guarantee is MEASURED, not arithmetic. The packer encodes items until windowBudgetBytes (192KiB) of serialized envelope is reached, then stops with a continuation. Never refuse for size. A single item whose bounded body alone exceeds the budget is elided with a fetchCursor. Measuring post-encoding covers all fields (arguments, raw data, images, tool errors) and JSON escaping — resolving the unbounded-field class and the 327,680-byte falsity in one rule. The self-contradiction between scope 5 ("no size refusal") and contract 3 ("error when one turn exceeds the cap") resolves to: no refusal; the packer trims and continues.
- Ordering and trimming (F-C12/E6): latest = newest-first, trimmed from the OLDEST end; since = transcript order, serves the OLDEST unseen turns first, trimmed from the NEWEST end, forward continuation across calls. Exact exclusive boundary per mode: since resumes at the first withheld turn id; latest resumes at the oldest withheld boundary. limit counts turns in the window.
- Intra-turn cap (F-D6): per-turn itemLimit (default 10, max 40) selects items in transcript order within the turn; the remainder is ONE elision record per turn naming the withheld count with a fetchCursor that continues inside the turn. Elision records do not count against the item cap.
- Full-item fetch (F-C15/D8): the fetchCursor read returns the item bounded by the 256KiB read cap with a byte-range continuation when the body is larger. The unconditional one-call full-body guarantee is dropped.
- Older daemons (F-E5 ACCEPTED): strict decoding rejects unknown params (ThreadReadParams.UnmarshalJSON, types_turn.go:516-533; ThreadTurnsListParams :574-582), so "older tooling answers today's shape" is false. A new ThreadCapabilities bit (idiom: PageBefore, types_thread.go:618-624) gates the new params; the Manager never sends them to daemons that do not advertise the bit. The PR's compatibility note names the bit.
- Turn addressing (F-C13/E12 ACCEPTED): the spec names its owned new machinery honestly — turn-id→position resolution on both paths (hub-side extends findTurn past its legacy-skip; daemon-side gains resolution), turn-count windows wrap the existing item windows, continuation carries turn ids. ThreadTurnItemsListParams (ScopeUnimplemented, protocol.go:178) is named so the lane does not rebuild it.
- Wire names (F-E11 + round-1 B10): item-type list uses the projection's exact emitted strings (agentMessage, userMessage, reasoning, systemMessage, commandExecution, input_image, ...), enumerated in the spec; request shape is exact JSON ("itemTypes":["messages"]).
