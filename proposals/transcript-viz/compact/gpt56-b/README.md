# Compact realtime transcript visualization proposals

These are intentionally small companion components embedded beside a dimmed transcript, not reduced dashboards. All transport controls sit in page chrome outside the measured visualization footprint; each component starts at 250+ accumulated turns and runs a finite synthetic stream of tool, delegate, job, compaction, retry, chapter-close, and quiet events. Every HTML file is standalone and works from `file://` with inline CSS and JavaScript only.

## Idea 1 — Narrative Spine

**Realtime comprehension question:** In a five-second glance, what is the story so far, which chapter stratum is still being written, what is the current attempt, and what changed last? The rail encodes every chapter as a labeled vertical stratum, uses a hatched cyan stratum for provisional work, reserves only three synopsis lines, and pins one living attempt sentence plus one change receipt at the bottom. Events increment the live stratum, flash the changed chapter, add a ninth handoff stratum, update active count, and eventually switch from receiving to honest live-quiet state. Six never-collapsing circular pins sit in their owning chapter strata; each represents one `user_input` or steering turn and scrolls/highlights that exact prompt in the mock transcript with one click. Scaling is bounded by chapter count rather than turns, and the exact footprint is **156px wide × `calc(100vh - 82px)` high** (vertical rail, no internal scroll).

## Idea 2 — Storyline Strip

**Realtime comprehension question:** What is the whole narrative arc, where is the live edge, and what is the agent doing now without looking away from the transcript? The 96px dock gives 238px to a three-line synopsis, the center to an ordered proportional chapter ribbon, and 292px to one attempt sentence and one latest-change line; the current segment is hatched and explicitly labeled LIVE. Each durable event grows or flashes the current segment, revises only the bounded synopsis and live sentence, records compaction on the segment edge, and opens a ninth handoff segment when verification closes. Six persistent diamond markers are overlaid on their owning ribbon segments; none aggregate away, and each one-click scrolls/highlights its exact `user_input` or steering turn in the mock transcript. It scales because 250+ turns change segment proportions instead of adding rows; the exact footprint is **`calc(100vw - 32px)` wide × 96px high** (horizontal strip, no internal scroll).

## Idea 3 — Story Stamp

**Realtime comprehension question:** Can a corner element explain the session arc, current chapter, attempt, and last change without occupying a primary layout region? The stamp uses a nine-row chapter stack as a tiny table of contents, three synopsis lines, one current-chapter seal, one three-line living sentence, a context hairline, and a two-line change receipt. Events flash the affected chapter, advance active/context counts, add the handoff chapter, and settle into a live-quiet state without fabricating motion. Six always-visible prompt dots live inside the chapter stack, including separate dots for two prompts in Verification; each dot one-click scrolls/highlights the corresponding `user_input` or steering target. It scales by keeping one row per narrative chapter and never materializing individual non-prompt turns; the exact footprint is **312 × 232px** (corner/badge element, no internal scroll).
