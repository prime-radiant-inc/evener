# Compact realtime transcript visualizations

Each page places one tiny live component in a dimmed transcript workspace. Playback controls are deliberately outside the measured component, and every simulator opens with 250+ historical turns before incrementally adding tool starts/completions, waits, cost and latency changes, context pressure, and compaction.

## Idea 1 — Pulse Ribbon

**Realtime question:** Is the agent working or waiting now, and is the latest rhythm a healthy burst, a stall, or an expensive/slow trend? The full session runs left-to-right as a latency-colored tool waveform; compactions are amber cuts, the bottom hairline is cost burn, the top rail is context pressure, and the live dashed tail grows toward a fixed NOW edge with its elapsed seconds. Simulation events append new waveform marks or lengthen the active/empty tail without rebuilding the visual grammar. A dedicated top prompt rail draws every `user_input` as a pale triangle and every steering turn as an amber diamond; markers are never clustered, the full-axis scale renormalizes as the session grows, and clicking one scrolls and highlights that exact prompt card in the mock transcript. Older non-prompt turns keep one subpixel-scale beat each while prompt markers retain individual indexed draw and hit-test entries and the current tail receives a reserved 104px focus zone. **Exact footprint: 1120 × 92px horizontal strip.**

## Idea 2 — Rhythm Spine

**Realtime question:** How has the whole session spent wall-clock time, and is the present bottom edge moving, waiting, overheating, or nearing a fold? Turn history flows top-to-bottom: sideways bar width is tool cadence, color temperature is latency, visible vertical gaps are waits, a cyan edge trace is cost, and the 3px right rail is context pressure; the live needle below the history grows until completion. Each event extends the bottom needle, converts it to history on completion, or opens a widening amber wait gap; compaction cuts horizontally across the spine. A dedicated left prompt track gives every `user_input` a pale arrow and every steering turn an amber diamond at its exact session position; each keeps its own click target while the full-height scale renormalizes, and jumps the transcript rail to the matching prompt. The full 250+ turn run remains a single vertical trace beside the transcript, with non-prompt activity compressed freely but prompt markers never aggregated or discarded. **Exact footprint: 148 × 760px vertical rail at a 1000px viewport (720px tall only below an 880px viewport).**

## Idea 3 — Tempo Puck

**Realtime question:** In one corner, can I tell whether work is moving, how long the current action has run, whether latency/cost are warming, and whether context is about to fold? The outer circumference is one tick per durable turn colored by latency; the adjacent arc is context pressure with an amber fold threshold, the thin inner orbit is the whole-session burn trajectory, recent tempo is thirty beads, and the center shows RUN/WAIT plus elapsed seconds and current burn/context. Live events extend the center arc, add a turn tick on completion, leave an amber wait state, and reset the context arc when compaction fires. A separate outer prompt orbit draws every `user_input` as a pale bead and every steering turn as an amber diamond; each bead retains a unique prompt index and click hit target while the orbit renormalizes to the session length, then scrolls the mock transcript to the exact source step. Rings preserve all 250+ turns while non-prompt history may visually compress, but prompt beads are iterated and drawn one-for-one and never clustered. **Exact footprint: 304 × 220px corner badge.**
